## What happened

Both scripts are the first thing a developer runs after a build, and both handed a
half-checked environment to Java. Ten findings, two root causes: the wrapper did not
validate what it was given, and it did not validate what it was about to use.

**The bootstrap was parsed twice, differently (`P6-296`).** `show-ticks.sh` split
`FLUSS_BOOTSTRAP` with `%:*` and `##*:` to feed the TCP probe and then passed the
*unsplit* value to Java. For `myhost` the probe dialled `myhost:myhost`; for
`[::1]:9123` it dialled host `[`; for `h1:9123,h2:9123` it dialled a truncated host
while the viewer dialled the list. So pre-flight could fail on a host the viewer never
contacted, or pass on one endpoint while the viewer needed another. The parse now
happens once, in a `case` that knows the IPv6 bracket form, and the forms this probe
cannot speak to are refused with exit 2 and the offending value quoted, instead of
being probed as something else.

**The probe proved less than it claimed and hid the reason (`P6-297`).** It ran
unbounded — an unroutable address hangs for the TCP SYN timeout — and sent stderr to
`/dev/null`, so the one line that says *why* (`Connection refused`, `Temporary failure
in name resolution`) was discarded and the user got "Local Fluss is not running" for a
name-resolution typo. The probe is now wrapped in `timeout "$PROBE_TIMEOUT_SEC"`
(default 3, overridable) and keeps the captured reason in its message. The comment
records what it does not prove: TCP reachability only, and Fluss can still stop
between the probe and `exec`.

**Two ways to call the viewer wrong (`P6-695`, `P6-696`).** A second argument was
ignored silently, so `./show-ticks.sh 20 --bootstrap other:9123` displayed the default
20 rows against the default endpoint and looked like it worked. The limit's only check
was `^[1-9][0-9]*$`, which accepts a 19-digit number that Java then rejects. Both are
now shell-level refusals with a usage line; the upper bound is `TickTableViewer`'s own
`MAX_LIMIT`, and a test asserts the two numbers stay equal, so the wrapper can never
refuse a value the viewer accepts.

**A missing JDK was reported as a cluster problem (`P6-697`).** `command -v java` is
now checked before the probe: the user is told the JDK is missing instead of waiting
for a network round trip to be told Fluss is down.

**`smoke-test.sh` overwrote its caller (`P6-687`, `P6-688`, `P6-689`).** The exports at
the top of the file were unconditional, so `FLUSS_BOOTSTRAP=remote:9123 ./smoke-test.sh`
silently wrote to localhost, and the throwaway `ARROW_APP_SECRET`/`ARROW_TOKEN` replaced
real credentials for any embedded caller. All seven are now `${VAR:-default}`, with the
credential lines marked local-smoke-only. `RAW_TABLE_NAME` is overridable too, and the
header now says what the run does — bootstraps that table and appends 10 ticks to it.

**No preflight at all (`P6-293`, `P6-857`).** The missing jar surfaced as a Java
loading error, missing `target/test-classes` as a `NoClassDefFoundError`, a stopped
cluster as a connection stacktrace. Each is now one line naming the artifact and the
command that produces it, plus the same bounded TCP preflight as `show-ticks.sh`. The
`cd "$DIR"` gained a guard that cannot fail silently, and the classpath notes that `:`
is Unix-only.

## Judgement calls

1. **The limit bound is 10000, not the 1000 the finding suggested** — it is
   `TickTableViewer.MAX_LIMIT`, the number Java actually enforces. A second, smaller
   bound would refuse values the viewer accepts; the cross-artifact test pins the pair.
2. **`show-ticks.sh` refuses a bootstrap list; `smoke-test.sh` probes the first
   endpoint and says so.** The viewer's read path is what P6-296 was about — a green
   preflight on one endpoint while the viewer dialled another is the bug — and the
   probe cannot speak to a list. `smoke-test.sh` is the write path: a multi-endpoint
   list is legitimate there, so it is accepted, the first endpoint is what gets probed,
   and the message names it rather than pretending the list was checked.
3. **TCP-open is not readiness, and the TOCTOU window is not closed.** Both comments
   say so. Closing it is impossible from a wrapper that `exec`s the JVM; the probe
   shortens the path to a clear message.
4. **`PROBE_TIMEOUT_SEC` as an override seam** (default 3) so a test can exercise the
   bounded path without waiting out the default, following the `FLUSS_READY_TRIES`
   precedent from CHG-159.
5. **`RAW_TABLE_NAME` keeps its fixed default (P6-689).** A unique-per-run name would
   remove the collision by leaving a new table behind on every run — the same pollution
   the finding complains about, only unbounded. The default stays, the override is the
   escape hatch, and the header states the side effect.
6. **The `cd` guard and the Unix note are asserted as source text (P6-857).** `DIR` is
   derived from the script's own path, so a `cd` failure would mean the script could not
   be read at all; the test says so instead of pretending to trigger it.
7. **The hint message no longer says `docker compose up -d`.** Naming the compose form
   in prose made `test_compose_form_contract.py` report a new, unregistered invocation
   site — the test is right that it cannot tell prose from a call. Reworded to
   `./start-all.sh` rather than registering a row for a message it does not run.
8. **No shared probe library.** The two scripts are standalone operator tools and the
   tree has no shell lib to source (CHG-159 kept the same helpers inline in
   `start-all.sh`). A third copy is where extraction earns its keep; not now.
