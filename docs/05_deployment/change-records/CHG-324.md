## What changed

| Piece | Change |
|---|---|
| `day_run.py` (new) | Runner: pure decisions (universe contract, posture violations, SignalJob singleton, I1-I9 evaluator, session clock) + read-only `Collector` probes (compose ps/config, Flink REST, the maintained passive `FlussReadLagProbe` via `listOffsets`, JM state listing, bounded log scans) + native actions (`make up`, `make rollout-savepoint RECOVERY_PATH=...`, `make down`) |
| `day-run.sh` (new) | Thin entry, execs `day_run.py` |
| `Makefile` | `day` target: exports `DAY_COMPOSE='$(COMPOSE)'` (single source of the compose invocation) and calls `day-run.sh $(ARGS)` |
| compose ingestion | `ARROW_HFT_MULTI_CONNECTION_APPROVED: ${...:-false}` passthrough so the daily universe can be selected from the shell; fail-closed default, both CHG-323 (Java) and CHG-320 (Go) still enforce |
| Preflight | `image_staleness_check.py` (native content stamps) must be FRESH before `start` (`REBUILD=1` runs `make images`); live-enablement flags refuse `start` (exit 3); `UNIVERSE=full` refused in production |
| Runbook | `docs/06_operations/01-runbooks.md` §Daily single-command runner: contract, invariant→recovery table, first-morning procedure |

## What did NOT change

- SignalJob lifecycle: restore goes through `rollout-savepoint.sh`
  (`RECOVERY_PATH` mode); the runner never submits a second job, never
  re-derives the pinned env, and its fresh path stays behind `ALLOW_FRESH=1`.
- Execution flags/defaults: gateway `EXECUTION_ENABLED=false`, bridge
  `EXECUTION_BRIDGE_MODE=disabled`, executor boots HALTED; the runner only
  starts the profile and audits the flags (DEC-044 / live-readiness gates).
- The profiler and its purge behavior: never called from the daily path.
- Production policy: single-socket, unchanged (CHG-320).

## Findings from the dry run (kept as evidence)

- The first dry run caught a **stale compose image** (`01_docker-ingestion`
  built 2026-09-25, before CHG-320/322/323): the old bridge refused the
  3-socket plan with the pre-CHG-320 message. The runner now refuses `start`
  on stale build stamps and names `make images`; the image gate is what
  `make check-image-stale` reports.
- The runner's SignalJob wait originally keyed on a checkpoint field Flink
  does not return (`latest.completed.end_time`); it now reads
  `latest_ack_timestamp`/`trigger_timestamp` (unused before). The restore
  itself had succeeded (job RUNNING, 32 checkpoints, restored from
  `chk-6`), so the second dry run only needed the corrected wait.
