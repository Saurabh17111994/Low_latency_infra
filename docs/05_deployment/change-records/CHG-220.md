# CHG-220 — the gate names its skips, or it fails

- **Status:** recorded — fixed (2026-09-18)
- **Filed:** 2026-09-18
- **Source:** closing the certification-hygiene batch. The certificate quotes
  `OK (skipped=11)` and nothing in the record says *which* eleven tests skipped, so an
  accepted live-cluster refusal and a quietly disabled test are indistinguishable. Found
  while itemizing run 6's skip count for CHG-217.

## What happened

unittest's summary line carries a count and no names. Gate step 3 ran the suite without `-v`,
so the certificate's own log could not be itemized at all — `make test-audit-r2` runs verbose
(`Makefile` L210), the gate did not, and the difference stayed invisible until somebody tried
to explain a `skipped=N` that had moved (9 → 11 between the certificate and the closing
gate-fast run).

## The change

Three edits in `run-monday-gates.sh`, one helper, its tests, and one dated correction in
CHG-217:

```
python3 -m unittest discover -s "$SCRIPT_DIR/tests" -p "test_*.py" -v      # was: no -v
SKIP_LINE="$(python3 "$SCRIPT_DIR/skip_inventory.py" "$PY_LOG" 2>&1)"
python3 -m pytest "$SCRIPT_DIR/tests" -q -rs -p no:cacheprovider -p no:unittest
```

- `skip_inventory.py` counts the `... skipped 'reason'` lines, sorts by count then reason, and
  prints one bounded line — `SKIPS: 11 — 5× …, 3× …, …`, reasons truncated at 60 characters.
- It **fails the step** when the summary claims a count the verbose log cannot name, and when
  the log carries no summary line at all. A count nobody can itemize is not evidence: that
  refusal is the point of the change, not a side effect.
- The parse is anchored on ` ... skipped`, so test chatter mentioning the word is never
  counted (the CHG-201 lesson, applied to a new pattern).
- `-rs` gives the pytest half the same visibility in its own log. Its console line stays
  count-free, so no certificate ever quoted an unauditable pytest share.

## Verification

- `python3 -m unittest discover -s code/01_platform/04_scripts/tests -p 'test_skip_inventory.py' -v`
  → `Ran 11 tests … OK`. Legs cover per-reason counts, tie ordering, a reasonless
  `SkipTest()`, truncation, the chatter negative control, a red suite that still itemizes, and
  both refusal paths (over-claiming summary, unreadable log).
- Against the **real** closing gate-fast log: `skip_inventory.py /tmp/gatefast2.log` printed
  `SKIPS: 11 — 5× live registry check: set DIGEST_PIN_LIVE=1 to run, 2× W34_PRE_FIX_SRC not
  set — red leg skipped, 2× census withheld — census read 23 rows but Fluss reports 27, …`
  with rc=0 — the itemization CHG-217 had to reconstruct by hand.
- `bash -n` and `shellcheck -S warning -x` clean on the patched script.
- The **first** `--steps 3` attempt after the change (`logs/soak/monday-gates-20260918-185716`,
  `SUBSET RESULT: FAIL`) failed for a reason worth keeping: the assignment shape
  `if ! SKIP_LINE="$(…)"` is invisible to `test_gate_variable_scoping.py`, which requires each
  step to assign what it reads — precisely so a `--steps` run cannot abort on `set -u`. Fixed
  by moving the assignment to line start with `|| { …; gate_fail; }` (the script's own idiom,
  `set -e`-safe). The guard was right and was not touched.
- That same failed run's gate-produced verbose log (`-v`, the new invoker) itemized as
  `SKIPS: 12 — 5× live registry check …, 2× W34_PRE_FIX_SRC …, 2× census withheld — census read
  23 rows but Fluss reports 27, 1× census withheld, so no table was reported …, 1× live
  IngestionService is up …, 1× suite runs under the gate, so the audit is legitimately exem…`
  (rc=0) — the count moved 11 → 12 between runs, and this line says why: one leg exempts
  itself when it runs under the gate.
- End-to-end after the fix, in a real gate console (`--steps 3`,
  `logs/soak/monday-gates-20260918-190225`): `PASS: python unit suites (Ran 1487 tests)`, then
  the new line `SKIPS: 12 — 5× live registry check: set DIGEST_PIN_LIVE=1 to run, 2×
  W34_PRE_FIX_SRC not set — red leg skipped, 2× census withheld — census read 23 rows but Fluss
  reports 27, 1× census withheld, so no table was reported …, 1× live IngestionService is up —
  the bench refuses double-run b…, 1× suite runs under the gate, so the audit is legitimately
  exem…`, `PASS: python pytest-only suites (278 passed)`,
  `SUBSET RESULT: PASS — 1/1 verified, 0 skipped`, exit 0. 1487 = the 1476 the suite held plus
  this change's 11 legs.
- `-rs` does what it says: the same run's pytest log now names its own skip —
  `SKIPPED [1] code/01_platform/04_scripts/tests/test_bench_throughput_wave33.py:58:
  unittest.case.SkipTest: live IngestionService is up — the bench refuses double-run by design;
  re-run with the stack down`.
