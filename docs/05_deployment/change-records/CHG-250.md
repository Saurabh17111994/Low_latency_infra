# CHG-250 — Fluss listeners are real: literal binds, named adverts, fixed internal ports

## Why

The CHG-249 rehearsal left the Fluss coordinator boot-looping: the stack bound
`bind.listeners` to the coordinator's own service name, which Swarm cannot resolve
before the task is Running (`Failed to start Netty server on endpoint
INTERNAL://fluss-coordinator:0`, caused by `UnresolvedAddressException` at Netty
`checkResolvable`, task cycling in Starting). The fix binds the wildcard literal
`0.0.0.0` and advertises the service name, which becomes resolvable exactly when the
task reaches Running. A fresh create (run7, deploy rc=0) proved the bind fix: the
coordinator held Running 6+ minutes with no bind failure and 14/14 deployed-spec
assertions passed.

The same watch exposed one layer deeper (D-A): the INTERNAL listener, which carries
server-to-server traffic (`internal.listener.name: INTERNAL`), had port 0 and no
advertised entry. An unset advertised listener defaults to the bind value, so tablet-1
registered `INTERNAL://0.0.0.0:40917` and the coordinator dialled 0.0.0.0 at all three
tablets and was refused, ongoing (`Failed to establish connection to server
0:0:0:0:0:0:0:0%0:36715`, `AnnotatedConnectException: finishConnect(..) failed:
Connection refused`). Same bootstrap circle, ephemeral port instead of a name. The
server documentation confirms the mechanism: `advertised.listeners` defaults to
`bind.listeners` when unset and is required whenever the bind address is not
reachable. INTERNAL therefore gets a fixed adjacent port (9122 coordinator, 9125
tablets, overlay-only) and an advertised service name, exactly like CLIENT.

## What changed

- **`code/01_platform/01_docker/docker-stack.yml`** — the four Fluss `bind.listeners`
  bind `0.0.0.0` (CLIENT :9123 coordinator / :9124 tablets, INTERNAL :9122 / :9125);
  every `advertised.listeners` entry keeps the service name. Rationale comments on the
  coordinator block, pointers on the three tablet blocks.
- **`code/01_platform/04_scripts/tests/test_09_stack.py`** —
  `test_fluss_binds_a_literal_and_advertises_a_name` pins both halves plus the D-A
  rules: fixed bind ports (no `:0`) and `internal.listener.name` naming a declared
  listener. Green unmutated; fails all four drift mutations (bind-the-name,
  advertise-a-literal, ghost internal name, ephemeral port).
- **`docs/01_project/04-decisions.md`** — DEC-051: no service binds its own name in
  order to start; bind a literal, advertise a name.
- **`docs/05_deployment/PROD_VM_PROVISIONING.md`** — runbook section 2 rule 7 states
  the same rule for operators.

## Limitation

Single-node rehearsal only. The tiering behind the listeners is still rehearsal-only
(`file://` local paths via the rehearsal generator; the repo keeps `s3://`), so a full
Fluss data-path proof needs real R2 or the rehearsal tiering that run8c uses. Tablet
inter-replica fetch over INTERNAL inherits the same fix and is exercised only as far as
registration and coordinator dialling reach in the watch window.

## Rehearsal result (run8c)

Deploy rc=0 on a fresh create; 19/19 spec assertions ALL_PASS (ZK liveness, all four
Fluss literal binds and named adverts, no ephemeral ports, JM file:// storage, no
placeholder leaks). Runtime watch (6 min): coordinator and all three tablets held 1/1
throughout; the live coordinator log shows `Start auto partitioning for 0 tables` and
tablet connections by name on the fixed INTERNAL port (`fluss-tablet-1/10.0.2.16:9125`),
so server-to-server traffic provably flows on the D-A registration. An early
`already registered in Zookeeper, retrying` loop was stale state from previous runs
(ZK volumes survive `stack rm`); it self-cleared once old sessions expired, and the
rehearsal teardown now wipes data volumes (D-G) so replays converge immediately.

Run8d (after the D-G wipe and the D-H marker fix) registers cleanly on the first
attempt, and the registration payload is the proof this change wanted:
`Registered leader CoordinatorAddress{id=…, endpoints=[INTERNAL://fluss-coordinator:9122,
CLIENT://fluss-coordinator:9123]}` and `Registered tablet server 1 at path
/tabletservers/ids/1 with registration TabletServerRegistration{endpoints=
[INTERNAL://fluss-tablet-1:9125, CLIENT://fluss-tablet-1:9124]}` - the fixed INTERNAL
ports and service-name adverts are what ZooKeeper now holds, so no peer can receive
`0.0.0.0:<ephemeral>` to dial. Coordinator, tablets and ZooKeeper held 1/1 for the
whole watch; the only services still 0/1 were the jobmanager (D-F, below) and
ingestion (documented DDL sequencing, CHG-251).

re-run9 (fresh create, after CHG-253/255) re-proved the same assertions on the deployed stack:
`coordinator binds literals`, `coordinator advertises names`, `3 tablets bind literals`,
`3 tablets advertise names`, `internal name wired x4`, `no ephemeral ports` — and the jobmanager
that run8c watched at 0/1 was Running 1/2 with leadership granted by run8f.
