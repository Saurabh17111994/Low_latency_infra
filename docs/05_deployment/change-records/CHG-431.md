## Notes

- **The mask was the finding.** The audit saw the comment-only option; the deeper defect was that the apply engine's
  parser treated the comment as the option — so the table would have been created with v2 "from a comment" while the
  manifest said otherwise. Both parses now strip comments with the same quote-aware rule (M6-1's Python twin), and the
  corpus scan showed 29 was the only file where a commented option differed from the real option set.
- **Two-stage failing-first, deliberately:** stage A proves the parser tests catch the comment leak while the corpus
  invariant stays masked; stage B proves the invariant catches the DDL once the parser is truthful. One run would have
  shown a green invariant and hidden the causal chain.
- **The prediction change is additive for the corpus:** every composite-KV DDL in the tree has a single-field subset
  bucket key + v2, so the apply's predicted-limitation list does not change for today's 27 tables — it changes for the
  next table that forgets the option (it now lands in `PASS_WITH_LIMITATION` + ack instead of failing the raw-client smoke).
- **Manifest regeneration also healed L5-3's checksum drift:** CHG-428 edited `10_positions.sql` without regenerating the
  manifest; the parity test would have failed at the next gate. The single regeneration the plan asked for covers both
  DDL edits; `test_schema_manifest_parity.py` is green on the result.
