# CHG-156 — The halted-path gate cannot false-PASS anymore

- **Status:** recorded — all 8 wave-19 findings fixed
- **Filed:** 2026-09-15
- **Source:** P6 ops/scripts/tests/chaos audit, wave 19 ("Halted-mode e2e"): P6-175/176
  (high) and P6-509…P6-512 + P6-772/773 (medium/low) in
  `code/01_platform/04_scripts/run-b4-halted-e2e.sh` (the two-leg Maven proof that a
  halted gate stops execution — where a false PASS means an unproven fail-closed wall).

## What happened

The script normalised (parse mode, default the bootstrap), measured (run both Maven legs),
then reported (ALL PASS) — and at each step a partial or empty run could print as full
success.

**Empty runs printed PASS (`P6-175`, `P6-176`).** Both legs ran `mvn -o test -Dtest=… -q`:
a renamed/missing/skipped test class (0 tests matched, profile skip, build-helper
filter) still exits 0 and fell through to `echo … PASS`, with `-q` hiding the Surefire
summary that would have shown it. On a HALTED-path gate that means the fail-closed wall
was never exercised but reported green. Both legs now pass
`-Dsurefire.failIfNoSpecifiedTests=true -DfailIfNoTests=true` and run without `-q`, so
skipped/empty runs fail loudly and stay visible in CI logs.

**Failures hid the second half and lied in the footer (`P6-509`, `P6-511`, `P6-512`).**
Under `set -e` a gateway failure skipped compute (second invocation to triage), while
`--gateway-only` printed `[1/2]` and the same `ALL PASS (non-market half of B4.2…)` as a
full run — dashboards could mistake one leg for full B4.2 coverage. `set -e` is dropped
(`set -uo pipefail`); each leg runs with `|| leg_status=$?`, step labels derive from the
requested legs (`total=$((run_gw + run_cp))`, so single-leg runs print `[1/1]`), per-leg
PASS/FAIL lines go to the right stream, and the footer prints ALL PASS only for
mode=both with both statuses 0, `<mode> PASS (single leg only; not full B4.2 coverage)`
for single legs, and `FAIL (gateway=N compute=M mode=…)` + exit 1 otherwise.

**Prereqs paid Maven startup before failing (`P6-510`, `P6-772`).** The header documents
a 26-table DDL precondition, but the script jumped straight to Maven: a dead Fluss or a
malformed bootstrap (`missing :port`, empty host, non-numeric port) died deep in Java.
Bootstrap shape validates right after defaulting (POSIX `case`, not `[[ =~ ]]` — this
script is read by `/bin/sh` tooling too) and a `timeout 5 … /dev/tcp/host/port` probe
(same idiom as tiering-smoke.sh) fails before Maven with a `make ddl` hint. The 26-table
count itself stays advisory: no Fluss SQL CLI exists in the repo to count against, and
the Java tests already fail explicitly on missing tables — reachability is the hard gate.

**Typos ran the default (`P6-773`).** `mode="${1:-both}"` ignored everything past `$1`,
so `--gateway-only typo` ran the gateway leg as specified; the usage text also rejected
the valid `both`. Surplus args now exit 2, and usage lists all three modes.

## Judgement calls

1. **P6-510 ships the TCP half of the suggested fix, not the table-count half.** The
   finding's TODO presumed a `fluss sql --execute "SHOW TABLES"` CLI; no such CLI exists
   in the repo or scripts (only sql-client.sh for file applies). Counting tables would
   mean inventing a client; the Java tests already assert tables explicitly. Recorded as
   a deliberate partial: advisory hint, not a hard gate.
2. **P6-509 keeps the suggested `|| status=$?` shape verbatim** (not a trap/ERR cleanup):
   two legs, two statuses, footer arithmetic — the simplest shape that runs both.
3. **Dead first-arm `case` of mine removed before committing** (a no-op `: ok`/`: invalid`
   classifier the two real checks below already subsumed) after shellcheck SC2221/2222
   flagged the overlap — the warning was right.
4. **One test bug of mine, fixed pre-commit:** the static pin compared `/dev/tcp/`
   against the class-name string, which the P6-510 *comment* quotes first — pinned
   against the `mvn -o test -Dtest=` invocation line instead.
