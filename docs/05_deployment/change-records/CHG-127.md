# CHG-127 — Order-status report filters are accepted but not applied

- **Status:** recorded (no code change) — known limitation, narrowing deferred
- **Filed:** 2026-09-14
- **Source:** P3-200 note; carry-over queue item "order-status filter"

## What the contract implies

`GenerateOrderStatusReports` carries filters (instrument, time window). A client
answering a report request is expected to honour them.

## What the code does

`code/02_services/04_executor/src/execution/client.rs` implements the command but
ignores `cmd` entirely and reports every order the client knows about.

## Why this is a record and not a fix

The behaviour is deliberate and self-documented at `client.rs:1004-1006`: "unlike
the five stubs beside it this method IS implemented — it just ignores the
command's filters … Narrowing the filter is separate work; it is not an error
path." Over-reporting is compatible with paper-trading use because callers filter
downstream, and it touches no correctness or safety path. Narrowing the filter is
a behaviour change on a report surface and needs its own test.
