## What changed

| Site | Change |
|---|---|
| `FeatureView` | Read-only strategy-facing view: `latest(int, Timeframe)` + name convenience; NaN means "not ready", unknown name throws (wiring error). |
| `PerInstrumentFeatures` | Implements `FeatureView`. Values stay per `(feature, timeframe)` for CLOSE features; TICK values are tf-independent. |
| `SignalStrategy` | New default overloads `onLiveTick(RowData, FeatureView, Collector)` and `onClosedCandle(RowData, FeatureView, Collector)`; the defaults delegate to the legacy two-argument methods, so N7/stub-smoke are untouched. |
| `StrategyHostFunction` | `HostSlot.features` (one `PerInstrumentFeatures` per instrument); tick/close updates before the fan-out; counters `compute.features.updates.tick`, `compute.features.updates.close`, `compute.features.failed`; fail-open guard with a warn log; test accessors (`featuresForTest`, `featureTickUpdatesForTest`, `featureCloseUpdatesForTest`, `featureFailuresForTest`). |

## Findings recorded (not fixed here)

- Feature updates happen before the fan-out, so a strategy always sees the value for the event it
  is handling; the update cost is O(active features) with no allocation (S1 contract).
- Feature state is heap-only by design (same amnesia contract as strategy instances); it is not
  part of the checkpoint, and a restore rebuilds it from replayed candles.
- A malformed closed row (unknown tf) is counted as a feature failure and still delivered to
  strategies — the feature layer can never block signal delivery.
