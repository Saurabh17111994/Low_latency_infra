## What changed

### XC-11 — `fused_timeline.py`: the RocksDB fill expires too

The G11 XC-6 fix bounded the Prometheus fill but left the RocksDB path
(`_fetch_rdb_signals`) carrying its last value to the grid's end. It now uses
the same `forward_fill(grid, by_t, "max")` helper; a guard test pins the call.

### XC-12 — `fluss-client-metrics.py`: bounded sample age

`_at_or_before()` returned the newest sample ≤ g with no age bound (its own
docstring cites fused_timeline as the model, which now expires). Added
`max_age_s=120`; a series that stopped scraping goes blank instead of being
carried. Test pins expiry + the in-bound case.

### XC-13 — `r2_legal_hold_check.py`: every audit prefix is chain-checked

`--audit-prefix` is documented as comma-separated, and `check_bucket_lock`
validated all prefixes, but retrieval/hash-chain read only `prefixes[0]` — a
run with `audit/,orders/` could PASS while orders/ manifests were never
listed, fetched, or chain-checked. Every prefix is now retrieved and checked;
`retrieval_verdict()` aggregates (any BROKEN/TAMPERED fails; unbound roots are
named) and `build_evidence` requires all prefixes valid.

### XC-14 — `seed_alerts.py`: an unreadable catalog fails closed

A 200 whose body was unparseable (or of an unexpected shape) silently became
`existing = {}`: dry-run printed "create" for every alert and a real run
re-POSTed existing alerts as duplicates, contradicting P6-778. It now exits 3
with an "unknown catalog" message; the non-200 warn path is unchanged.

### XC-15 — `disaster_drills.py`: evidence sections match their headings

`render_evidence` pairs `sections[i]` with `EVIDENCE_HEADINGS[i]` positionally,
but `drive` built the list starting at `documented_expectation` and put the
fault commands at index 1 — every rendered drill file showed the expectation
under "## Scenario" and the fault commands under "## Documented expectation".
`build_sections()` now emits `[title, documented_expectation, env, fault
commands + injected-at, …]`; a unit test pins the first four slots.

### XC-16 — `stale_table_kind_scan.py`: the count-drift gate sees current truth

`TEST_COUNT_TRUTH` / `C6_TRIPLE_TRUTH` / `SUITE_TRIPLE_TRUTH` were stale at
489/285/419 while the foundation C6 truth read 771/564/695. The gate therefore
reported genuinely current counts as stale and treated rows matching the old
truth as current — the live `00-start-here.md` status row (285/489,
C6 489/285/419) went unreported. Constants updated; `TruthFreshnessTests`
parses the foundation line and fails if the scanner's truth drifts from it
again. The two stale doc rows are fixed (00-start-here.md to current truth;
12-version-compatibility-evidence.md annotated as the 2026-08-24 capture).
`stale_table_kind_scan.py --upstream` is back to exit 0 over a tree that
contains no live stale claims.

### XC-17 — `split_manifest.py`: a chunk/row mismatch is fatal both ways

`rows < sum(chunks)` only warned, wrote fewer slot files than requested, and
exited 0 (a header-only input wrote slot1.csv and stopped); over-supply failed
only after the loop. Both are refused up front; the now-unreachable trailing
check is gone. Three tests pin under-supply, over-supply, and the exact case.

### XC-18 — `deployed_artifact_verify.py`: cp-failure cleanup

The `docker cp` failure return skipped the `shutil.rmtree` the docstring
promises ("always cleanup"), leaking a temp dir per failed copy. Fixed; a test
mocks the failure and asserts no leaked dir.

### XC-19 — `holistic-analyze.py`: offset-mode rows are valid rows

`collect_rows(..., with_offset=True)` makes the reader print `"@<offset> <row>"`
lines, but the post-read validation kept only lines starting with `"("` — so
the mode could never return a row and always reported a failed read. The filter
now accepts the offset marker when the mode asked for it; a test drives it
through a mocked subprocess. (No live caller used the mode.)

### XC-20 — `reconcile-compare.py`: the sentinel is not a vanished token

`vanished = set(pre) - set(post)` included the Fluss `-1` sentinel, although
`extra` and `raw_nonzero` already exclude it (P6-625) and its presence is
mode-dependent — losing it between pre and post produced a false FAIL. Filtered;
a test pins the sentinel-vanishing case.

### XC-21 — `day_run.py`: dead constants removed

`COMPANION_JOB_NAMES`, `EXIT_USAGE`, `EXIT_BUSY` had zero references anywhere
(grep across py/md/Makefile). Removed; a guard test asserts they stay gone.

### XC-22 — `tablet-orphan-sweep.py`: duplicated unreachable check removed

`zk_ls()` repeated the `returncode != 0` raise after the "Node does not exist"
return; `CompletedProcess.returncode` cannot change, so the second check was
unreachable. Removed; a source guard pins a single copy.

### XC-23 — `version_matrix_verify.py`: dead pin blockers removed

`"latest" in version.lower()` always matches before
`version.upper() in PIN_BLOCKERS`, so `LATEST`/`LATEST_FORWARD` in the set were
unreachable (the verdict still failed via the first branch; only the message
differed). The set now holds only `TO_BE_PINNED`; a test pins the shape.
