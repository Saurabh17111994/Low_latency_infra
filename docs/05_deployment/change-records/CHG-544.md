## What changed

1. `code/01_platform/04_scripts/stage-capture.sh` — in the pre-run block (next to the existing
   "fail NOW, not after DURATION_S" liveness legs), after the vertex map is frozen:
   - **Topology gate (hard, no knob):** for `STRATEGY_HOST_ENABLED:strategy-host`,
     `MULTITF_ENABLED:multi-tf-aggregator`, `EXECUTION_INTENT_ENABLED:execution-intent-producer` —
     if the flag is literally `true` and its vertex is absent from the running job graph, `exit 1`
     naming the flag, the vertex and the recipe. An unset flag is a deliberately reduced arm and
     stays legal.
   - `run-meta.txt` gains `topology_flags_requested=` next to the derived
     `topology_branches=`/`topology_flags_source=` lines, so a silently reduced run is visible in
     its own evidence.
   - **Read-path expectation (warn by default):** only when `strategy-host` is deployed, probe
     `candle_features` with the same `FlussKvProbe` argv the read legs use, polling up to
     `READ_EXPECTATION_TIMEOUT_S` (default 180 s; `PROBE_TIMEOUT_S` per attempt). No readable row ⇒
     `!! WARN … no readable row …` and the capture continues; `READ_EXPECTATION_STRICT=1` makes it
     `exit 1`. Both outcomes land in `run-meta.txt` (`read_expectation=`).
2. `code/01_platform/06_stage_profiler/stage-profile.sh` — `submit_job()` now exports
   `MULTITF_ENABLED STRATEGY_HOST_ENABLED EXECUTION_INTENT_ENABLED`, so the capture can compare
   what was requested against the graph the job runs.

## Why the split (hard vs warn)

The topology check compares two facts the run already has (requested flags, observed vertices) and
cannot false-fire. The read check is timing-dependent — a row exists only after the first candle
window seals — so making it fatal by default would replace one silent-failure mode with a new
false-failure mode. The end-of-capture presence gate remains the authority on read evidence.

## Not changed

- `pipeline-lib.sh` flag defaults (an unset flag still means a reduced deployment — that is a
  legitimate mode).
- No new `make gate` step, no new dependency, no change to any deploy artifact.
