## What happened

CHG-029 (2026-08-18) documented 6 latent failures that surfaced when the env-gated live
compute tests first ran on the current topology/JDK: a Kryo/JDK-17 surefire argLine gap (4
failures), a stale pinned-UID contract (1), a faketool path-resolution error (1), and one
un-isolated watermark-stall assertion. This record applies and verifies the four fixes.

## Fixes

**1. Kryo/JDK-17 argLine gap (CHG-029 root cause 1).**
Added `--add-opens=java.base/java.util.concurrent.atomic=ALL-UNNAMED` to the compute surefire
`argLine` (the existing block already opened `java.nio` and `java.util`). Any live job that
serializes Flink `BinaryRowData` via the Kryo fallback (candle output through the late-drop
side-output) crashed with `InaccessibleObjectException` on `AtomicBoolean.value`; the add-opens
clears the module-access wall for the whole fork. Test-JVM-only — production job config
untouched.

**2. Pinned-UID contract 10 → 14 (CHG-029 root cause 2).**
`SignalJobOperatorUidTest.EXPECTED_OPERATORS` now pins the 4 forming-bar operators added by
Slice 2.2 on 2026-08-16 — `forming-bar-builder`, `forming-bar-detection`, `forming-bar-writer`,
`forming-bar-sink` — matching the live 14-operator graph (verified: every operator carries a
UID that equals its `.name()`). This closes the CHECKPOINT-RESTORE-001 savepoint-anchor drift.

**3. E2E faketool path resolution (CHG-029 root cause 3 — no code change).**
Confirmed the binary exists; the failure was the test's RELATIVE `FAKETOOL_BIN` default
resolved against the surefire fork's cwd. The canonical runner
(`run-signal-chain-e2e.sh`) always exports an absolute `FAKETOOL_BIN` plus the computed
`INGESTION_CLASSPATH`. The full E2E was run through the runner (30-min, faketool broker) and
passed — no fix code needed; CHG-029's root-cause 3 was corrected to state this.

**4. Forming-bar-scoped assertions — option (b) (CHG-029 root causes 4 + 5).**
Since Slice 2.2 (2026-08-16) the tick-driven forming-bar placeholder detector
(`CANONICAL_FORMING_RULE_ID`) fires candidates into the same signal LOG/KV sinks as the
window-driven breakout rule (`CANONICAL_RULE_ID`). Three P6/P4.3 tests counted EVERY LOG row in
their `candidateIds`/signal-count helpers, so their pre-forming-bar expectations broke
(replay: 36 vs 2; stall: 5→3 vs 0; rocksdb restore: 30 vs 2). Per user decision (option b),
the assertions now scope to the window-driven rule only:

- `CandleGraphReplayIntegrationTest` — `signalLogRows`/`candidateIds` filter to
  `CANONICAL_RULE_ID`; the KV current-state comparison is scoped to the two canonical w22
  candidates (the window-driven id at w22 end or the forming-bar id fired mid-w22) with a
  settle-before-read helper, because the two producers union into the KV sink and the final
  last-upsert per token is interleaving-dependent — the assertion pins convergence (same keys,
  canonical w22 content) instead of a non-deterministic order.
- `CandleFailureInjectionIntegrationTest` — `candidateIds` filters to `CANONICAL_RULE_ID`;
  the flat-window stall assertion now reads "no window-driven (breakout) signal".
- `CandleRocksDbRestoreIntegrationTest` — `candidateIds` filters to `CANONICAL_RULE_ID`.

The forming-bar branch itself is unchanged and covered by its own unit tests
(`FormingBarDetectionFunctionTest` et al.).
