## Why this shape (verified before implementing)

- `CandleAccumulator.lastIngestTs` already existed and is maintained on every
  accepted close-setting tick (`CandleAggregateFunction`), explicitly as an
  observability seam "so a monitor can report `output_now - lastIngestTs`" — it
  had simply never left the aggregator.
- The live/forming row is in-memory + network only: its only consumer is the
  strategy host (`SignalJob`: `multiTfLive` / `LIVE_TICK_TAG`), no Fluss sink
  since W-C5a. A trailing probe column therefore costs no storage and no write
  path.
- The first 15 columns of the live row mirror the merged-table candle prefix
  (`35_candle_features.sql`), pinned by `CandleLiveColumnsAgreementTest`; the
  probe is deliberately outside that pin.

## What did not change

- `compute.latency.tick_to_strategy` and `ingest_to_monitor`: byte-identical
  behavior and names; the broker-anchored number stays the business "signal
  age".
- No DDL edit (`35_candle_features.sql` untouched), no Fluss table/sink, no
  `SignalJob` wiring, no operator state or accumulator fields, no write path.
- Nothing is added to the stage-profiler report (the durable probe carries the
  number); that remains an optional follow-up.

## Semantics

- Start: `raw.ingest_ts` (the ingestion service's accept wall-clock, same host
  clock domain as the TMs today; a multi-VM deploy needs NTP or skewed samples
  are skipped).
- Stop: host read of the canonical `FIFTEEN_S` forming row — the same stop as
  `tick_to_strategy`, one sample per tick.
- Covers admission/decode/fingerprint -> Fluss append+ack -> Flink source read
  -> raw-validation -> dedup -> aggregation -> host read. Does not cover the
  broker -> our-socket leg (unmeasurable from this side) or the strategy
  fan-out work (Flink tracker / sink metrics cover those legs).
