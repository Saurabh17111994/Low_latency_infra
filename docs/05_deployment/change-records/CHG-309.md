## What changed

Fluss 1.0 refuses a write whose partition is older than the table's auto-partition retention
(`InvalidPartitionException`: "Partition value '...' is out-of-date. The earliest retained partition
is '...'."). The row can never be accepted, so retrying is useless and halting is wrong: a bad feed
timestamp must not stop ingestion.

1. **`RetryClassifier`** gains a third classification, `REJECTED`, matched narrowly: class name
   contains `InvalidPartition` **and** the message contains `out-of-date`. Every other
   invalid-partition/spec failure keeps the R-285 fail-closed rule; a fatal cause anywhere in the
   chain still wins (money-safety first); a rejection beats a retryable wrapper because a retry can
   never succeed.
2. **`RawTickWriter`** drops the record on `REJECTED`: releases the backpressure reservation, counts
   it in `errorCount`, logs `append SERVER-REJECTED -- record dropped`, and emits a new terminal
   outcome `Status.SERVER_REJECTED` (packet identity threaded like FATAL). No retry, no halt.
3. **`IngestionService`** handles the new outcome: counts it, increments the
   `append_server_rejected` decode-error metric, logs it — and does **not** call `requestFatalStop`.
   The FATAL path is untouched.

## Notes

- Before this change the same input exited the process (B5's measured log: `raw-writer: FATAL append
  error (class=InvalidPartitionException)` -> `ingestion: FATAL append ... exiting nonzero after
  FAIL-FAST`), leaving recovery to the container restart policy.
- This closes the "server rejected this record" gap B5 named; the existing FATAL guards
  (stale handle, auth, schema) are unchanged and still covered by `FailFastGuardsTest`.
