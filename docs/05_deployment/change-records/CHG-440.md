## What was wrong

The per-checkpoint phase attribution was missing, not just unreadable. The shared
`stage-capture.sh` (deliberately not modified — the stage profiler's reuse-by-invocation contract)
reads `/jobs/:jid/checkpoints`, a summary model that does not carry per-subtask phases. The
2026-09-26 ad-hoc probe parsed the wrong endpoint and wrote a file of nulls.

A first version of this tool assumed `/checkpoints/details/:cpId` returns `subtasks`. It does not
in Flink 2.2.1: `CheckpointStatistics.generateCheckpointStatistics` builds task-level
`TaskCheckpointStatistics` only. The real per-subtask model is served one level deeper, one vertex
per request, at `/jobs/:jid/checkpoints/details/:cpId/subtasks/:vertexId`
(`TaskCheckpointStatisticsWithSubtaskDetails`). The first smoke run found this and **failed
closed** (`logs/stage-profile-20260929-190228`), before any record run.

## What changed

- **New tool** `code/01_platform/04_scripts/cp_phase_capture.py`: polls the summary for completed
  checkpoints, fetches the details + one subtask payload per vertex, and appends a compact record
  per checkpoint to `<stages>/cp-phases-detail.jsonl` (`sy`/`as`/`sd`/`al`/`ab`/`ua` per subtask;
  `al`/`ab` null only when the subtask ran no alignment). Fails closed (rc=1) when any completed
  checkpoint lacks a phase record; a live one-shot against the running babysitter job returned
  rc=0 with 0 nulls before the smoke re-run.
- **Wiring** `stage-profile.sh`: sampler starts after job submit, ends at capture completion via a
  stop file, is waited on before teardown, killed by `stop_fleet`, and its non-empty output is a
  phase precondition (`checkpoint phase capture: N checkpoints`).
- **Docs**: profiler README evidence layout; plan CT-1/CT-2 markers.
