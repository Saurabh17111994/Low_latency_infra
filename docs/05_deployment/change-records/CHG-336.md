## Why

The reporter is armed only when `GATEWAY_ENDPOINT` + `GATEWAY_SHARED_SECRET` +
`EXECUTION_PARTITION_ID` are all present, and the gateway refuses a report whose
`account_scope_id` / `execution_partition_id` differ from its own config. Both decks already
had the gateway values; the executor service had neither, so a deployed nautilus would have
kept approving process-locally and the `Execution_Gate` row would still never appear.

## What changed

| Piece | Change |
|---|---|
| `docker-compose.yml` (nautilus) | `EXECUTION_PARTITION_ID: ${EXECUTION_PARTITION_ID:-dev-partition}` + `ACCOUNT_SCOPE_ID: ${ACCOUNT_SCOPE_ID:-dev-scope}` — the same expressions the gateway service uses, with the mismatch/absent-partition consequences documented inline |
| `docker-stack.yml` (nautilus) | The same two keys pinned to `dev-partition` / `dev-scope` (the stack's other execution settings are literals; the gateway service in the same file carries the matching values) |
| `01-runbooks.md` §Execution mode hop | The durable-gate paragraph: `/v1/gate` reports, `durable_gate` must be `true` before reading `gate_epoch`, 30 s lease / 10 s renew / halt-on-loss, expired lease → gateway defers; step 3 of the paper drill now checks `durable_gate` first |
