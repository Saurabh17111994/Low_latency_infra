## What changed

1. **`MergedCandleFeaturesColumns`** (new): DDL 35's 17-column contract —
   `candle_closed`'s 15 columns in order + `features MAP<INT,DOUBLE>` +
   `sealed BOOLEAN` — with `ROW_TYPE_INFO` and the class-load tripwire, same
   pattern as `CandleClosedColumns`/`FeatureValuesColumns`.
2. **`MergedCandleRows`** (new): pure converter — copies the candle columns
   by type (nulls preserved) and appends the feature snapshot + seal flag.
3. **`StrategyHostFunction`**: new `MERGED_ROWS` side output; `mergedRowsEnabled`
   from `config.mergedCandleFeaturesEnabled()`; on the live path a forming row
   (`sealed=false`) per cadence, on the close path the terminal sealed row —
   both after the feature update, before the strategy fan-out, failures counted
   (`compute.merged.rows.emitted` metric + test seam).
4. **`SignalJobConfig`**: `MERGED_CANDLE_TABLE` (default `candle_features`,
   non-blank validation) + accessor.
5. **`SignalJob`**: when the flag is on, wires `MERGED_ROWS` to a Fluss KV
   upsert sink (`RowDataSerializationSchema(false, false)`, same builder as the
   candle sinks) named `candle-features-sink`. Off by default: the old
   candle/feature sinks stay authoritative.
6. **S4 follow-up pin**: `CandleClosedColumnsAgreementTest` still asserted DDL
   33's `table.datalake.enabled = 'true'` — flipped to `'false'` (DEC-060), as
   the S4 definition flip intended.
