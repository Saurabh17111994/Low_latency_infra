# CHG-261 — the EOD dispatch tests stop depending on the day they run

## Why

Two tests in `test_eod_controller_wave45.py` had been failing since 2026-09-20, and the cause was
the calendar, not the code:

```text
E   AssertionError: 1 != 0 : eod-controller-test: phase=main run-date=2026-09-20 evidence=…
E   eod-controller: RESULT=VERIFIED EXIT=0 TABLES=1 DAYS=0
E   !! FAIL main: EOD cycle rc=0 records=0 (want 1/0)
```

The harness decides whether the cycle recorded the day by counting lines of the form
`eod-controller:   day $RUN_DATE` in the controller's `status` output
(`eod-controller-test.sh:344-346`), and the script defaults `RUN_DATE` to **today in Asia/Kolkata**
(`eod-controller-test.sh:37`). The sandbox's fake `python3` prints those day lines for a hard-coded
`2026-09-19`. Tests that call an extracted function go through the `harness()` helper, which pins
`RUN_DATE=2026-09-19`; the two dispatch tests run the **whole script** with only
`EOD_TEST_PHASE=main|smoke`, so the script took today's date, counted zero matching lines, and
failed. They were green on the day the fake was written and red every day after.

Nothing in the product was wrong: an operator running the tool wants today's date, and counting the
recorded day is the right assertion. The test was the part that was not deterministic, so the test
is what changed.

## What changed

- **`code/01_platform/04_scripts/tests/test_eod_controller_wave45.py`** — a named constant
  `FIXTURE_DAY = "2026-09-19"` with the coupling written down (the fake's day lines, the script's
  today-default, and the count that links them), a comment at the fake's day line pointing at it, and
  `RUN_DATE=FIXTURE_DAY` on the two whole-script calls (`test_main_phase_is_dispatched`,
  `test_smoke_phase_is_dispatched`), which the sandbox's `env(**extra)` already supports.

## Note

A wall clock inside an assertion is the failure mode to watch for: this one hid for a day and read
like a product bug ("the cycle recorded no day") in a suite that was otherwise green. The fix keeps
the assertion — the harness still proves that exactly one day record exists for the run date — and
moves only the date into a named constant the test controls.
