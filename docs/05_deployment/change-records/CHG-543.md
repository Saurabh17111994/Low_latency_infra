## What changed

1. `.env.vm.example` (tracked production VM template) + local `.env.vm`: `UNALIGNED_CHECKPOINTS=false`
   — `day_run.py load_vm_env` loads it into the submit environment; `pipeline-lib.sh` forwards it
   to the SignalJob.
2. `docker-stack.yml`: the hybrid `aligned-checkpoint-timeout` line removed (never deployed).
3. `docker-compose.yml`: the dev shared-anchor hybrid line removed.

## Why (evidence, full 900 s @ 10 s cadence)

| Metric | Unaligned (old) | Aligned-only | Hybrid (verified, not adopted) |
|---|---|---|---|
| Wave samples (async > 50 ms) | 618 | **0** | 9 (tail noise) |
| Worst latency spike | 359 ms | **115 ms** | 120 ms |
| Ingest max | 113 ms | **89 ms** | 91 ms |
| Saves completed / speed | 94/94 · 4,865 | 94/94 · 4,865 | 94/94 · 4,866 |

## Known trade-off (accepted by the operator)

- Aligned saves wait for the checkpoint marker. Under real backpressure the wait can grow and a
  save could hit the 30 s save timeout; the hybrid's auto-fallback would have covered exactly
  that. Production has shown no backpressure, and the re-upgrade to hybrid is one line (CHG-542).

## Verification at the production start window

- First saves report type `CHECKPOINT` (not `UNALIGNED_CHECKPOINT`); no save failures;
  throughput/presence parity. Rollback = `UNALIGNED_CHECKPOINTS=true` (+ JM/TM recreate if the
  hybrid line is re-added).
