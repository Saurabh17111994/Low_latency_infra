# CHG-235 — the EOD controller test fails loud (wave 45)

- **Status:** recorded — fixed (2026-09-19)
- **Filed:** 2026-09-19
- **Source:** audit map wave 45 (`eod-controller-test.sh`, 17 findings, session e9f995f4).
  Eight of the 17 (P6-070…073, P6-359…362) are the audit's own `DRAFT` duplicates
  of P6-075/074/077/076/365/364/366/363 — 9 unique issues, matching the header's
  "9 HIGH".

## What was found

`feed_and_cycle` reported a failed EOD cycle with `bad()` and then fell through to
`return 0`, so its `|| rc_total=1` at both call sites never fired; the final
`exit "$rc_total"` ignored the `fail` counter entirely — a run could report
failures and exit 0. `EOD_TEST_PHASE=main` matched neither `case`, and an unknown
value ran zero phases and still exited 0 *after purging the live state table*.

Teardown was `pkill -f faketool` / `pkill -f ingestion.jar`. It appeared to work
only because container JVMs are host-visible by command line and the lib's
`docker logs -f` mirrors match the same pattern — while also matching unrelated
processes and other runs' containers. Those mirrors are started inside a
`bash -c` subshell, so their PIDs died with it and nothing recorded them.

G-EOD-2 slept a fixed 2s and then assumed the background run still held its
lease; if the mock run finished first the lease was released and the check could
pass for the wrong reason. Its `wait` had no bound. `purge_state` read
`PIPESTATUS[0]` of `( … ) | tee | grep -q`, which is the subshell's (i.e. `tail`'s,
always 0) status, so a table that was never purged still returned 0; the fixture
was a fixed `/tmp/EodPurge.java` and javac's stderr was discarded. Both status
helpers ended in `|| echo 0` / `|| true`, so a controller crash looked like "0
days" and G-EOD-0/G-EOD-1 could pass against a dead controller. There was no
EXIT/INT trap, so a signal mid-feed left containers, mirrors and fixture dirs
behind.

**P6-074/P6-071 is premise-wrong, not a bug.** It claims G-EOD-4's second mock
run should be refused with exit 5 and is flaky for not being. A completed run
releases its lease: `logs/eod-test/eod-test-20260912-002000.log` shows
`RESULT=VERIFIED EXIT=0 … DAYS=1` then `RESULT=VERIFIED EXIT=0 … DAYS=0`, and the
script's own header documents the no-op. The run pair is strictly sequential, so
no race exists. The actionable half (assert the second run's exit code instead of
inferring from `DAYS=0`) is implemented.

## What changed

- **Dispatch**: phases validated (`guards|smoke|main|all`), `main` dispatched,
  unknown values fail loudly *before* any cluster work, and the final purge only
  runs for a valid phase.
- **Exit status**: gated on `fail` as well as `rc_total`, set before the summary
  so the printed rc is the one returned.
- **`feed_and_cycle` returns non-zero** when the cycle check fails (teardown still
  runs first).
- **Teardown by identity**: the feed subshell writes the lib's own
  `FAKETOOL_LOG_PID`/`INGESTION_LOG_PID` and container names to a state file;
  `stop_feed` kills exactly those PIDs, `docker rm -f`s exactly those container
  names, cancels the Flink job by jid, then removes the state file so a later trap
  cannot signal a recycled PID. No pattern kill anywhere.
- **EXIT/INT/TERM trap** removes fixture dirs and calls `stop_feed` on any exit.
- **G-EOD-2**: bounded poll for the day record (bound 30s), then `SIGSTOP` on the
  controller JVM so the lease cannot be released under the check, then the
  concurrent run must be refused with rc=5, then `SIGCONT` and a bounded reap. If
  the holder cannot be observed the check fails loudly instead of passing by luck.
- **`purge_state`**: `$?` under the already-active `pipefail` instead of
  `PIPESTATUS[0]`; a private `mktemp -d` fixture; javac failures reported with
  their stderr.
- **Status helpers** propagate the controller's exit code as `STATUS_FAILED rc=N`
  while keeping their output contract (`days_on_file` still prints a bare number).
- **G-EOD-4** asserts that run's exit code directly.

Two defects in the first version of these fixes were caught by the new tests
before commit and corrected: `days_on_file` returned `DAYS=0` instead of `0`
(breaking its callers' comparison), and the cycle flag was inverted
(`cyc_ok=1` → `return 1`).
