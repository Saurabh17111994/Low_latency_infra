# CHG-302 — Fluss 1.0.0 upgrade: certifying 19/19 gate on a frozen tree

## Summary

This record files the certificate for the Fluss `0.9.1-incubating` → `1.0.0` upgrade. A single
unargumented `make gate` ran on a frozen tree and a live cluster and returned
`GATE RESULT: PASS — 19/19 verified, 0 skipped`. It is the first clean end-to-end timing captured
after the gate optimization, so it also replaces a projection with a measurement: **83.4 min →
28.1 min (2.97×)** against the predecessor certificate at `f2faf565`.

Nothing was changed by this record. It records a measurement and states what the measurement does
and does not cover.

another 3× is available.

## What this certificate does not cover

- **Tiering to R2 on 1.0.0 is unverified.** The run was captured with
  `remote.log.task-interval-duration=0s` (`FACT-018`, the gate-speed override), which disables
  remote tiering in the certified configuration. `FACT-011` stays `LIVE` and scoped to the 0.9.1
  measurement, with the 1.0.0 re-verification recorded as outstanding. The certificate therefore
  makes no claim about tiering, and must not be quoted as if it did.
- **No native 1.0.0 capability is covered.** `DEC-053` sequences those after the certificate
  (`docs/plans/2026-09-22-fluss-1.0-native-adoption.md`). A certificate answers "does the same
  behaviour work on the new version"; it does not answer "does new behaviour work".
- **The certificate is bound to `1d3c2c9a`.** A later commit does not invalidate it, but the next
  certifying gate must run again before any claim moves past that tree.

## Verification

- The verdict, step markers, per-step timings, fingerprint, catalog count and tree state above are
  read from the run's own output and `preflight.log` — not inferred.
- `git status --short` was empty at run time, which is what let `make gate` certify: it refuses a
  dirty tree.
- The run is unargumented. A `make gate --steps …` subset prints `SUBSET RESULT` and never
  certifies; no subset run is cited here.

## Rollback

Nothing to roll back. This record changed no code, no config, no DDL and no cluster state — it is a
filing of a measurement plus a doc-accuracy update to the gate-state block. The upgrade itself
remains reversible as a pin revert for as long as no clean lake table exists (see `CHG-301`).
