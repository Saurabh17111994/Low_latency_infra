  (22 findings across three files). Two of the fixes are consequence-changing:
  the token-count probe was reading a **different column** than it named, and
  a token-only secrets file previously reached the JVM instead of failing in

## What was found

Three files, 22 findings, all re-verified as still reproducing before fixing
(0 stale of 22).

### The probe counted the wrong column

`*_raw_table_1.sql` declares `instrument_token` **fifth** (index 5), after
`event_day` was added as column 0 by schema v3:

```text
idx 0 event_day             idx 3 connection_id
idx 1 event_fingerprint     idx 4 connection_epoch
idx 2 fingerprint_version   idx 5 instrument_token   <- the token
```

The probe passed `4` to `scanLog`, so it counted `connection_epoch`. Because
the DDL's hardcoded-index claim ("Columns: raw_table_1 instrument_token = 4")
was in the probe's own header, the index looked intentional. The token column
is now resolved by name from the live table schema and its type checked.

### The token-only path failed late instead of early

`ARROW_TOKEN` was removed on 2026-08-24 (commit `96c0b186`), which deleted it
from the launcher's export list **deliberately** — `IngestionConfig` rejects a
non-blank `ARROW_TOKEN` outright. What that commit left behind was the guard
`if [ -z "${ARROW_TOKEN:-}" ]`, which *skipped* all three TOTP checks whenever
`ARROW_TOKEN` was set. A token-only secrets file therefore passed the launcher
and failed inside the JVM. The audit reported this as "accepted but never
exported"; the fix it implied — re-adding the export — would have broken
ingestion, because the JVM rejects the variable on sight. The launcher now
fails fast with the same reason the JVM gives, and both launchers agree.

## What changed

| Area | Change |
| :--- | :--- |
| TOTP-only | Both launchers reject `ARROW_TOKEN` with the removal reason; the stale branch and the outdated header template are gone |
| Secrets file | Symlinks refused; mode 600 **or 400** accepted; owner must be the current uid; BSD/macOS `stat -f %Lp` handled |
| Credentials | `set -a` around `source`, plus an explicit export, so the execed child actually inherits them |
| Overrides | `FLUSS_BOOTSTRAP`, `FLUSS_BOOTSTRAP_SERVERS` and `ARROW_HFT_LATENCY_MS` use `:=` so an operator can set them |
| Manifest | Checked before it is parsed (a missing path used to surface as a raw `cut` error); default is derived from `REPO_ROOT`, not an absolute `/home/<user>/...` path |
| Fluss probe | Timed TCP connect instead of bash `/dev/tcp` (which had no timeout and broke on IPv6); explicit `host:port` validation |
| Run log | Filename includes `$$`, so same-second launches cannot share and interleave one log |
| Duplicate guard | Runs **before** the stale-bridge cleanup, so a refused launch no longer kills the live JVM's bridge first |
| Process handling | `PID` initialised before the traps (an early signal used to abort on `set -u`); the JVM's exit code is captured instead of being replaced by errexit's; tee is joined |
| Scan correctness | Token index resolved by name and type-checked; null tokens counted in their own buckets instead of colliding with token `-1`; the 1e9 row cap removed; `totals[slot]` honoured; the end-of-log wait is bounded so an empty bucket fails instead of spinning |
