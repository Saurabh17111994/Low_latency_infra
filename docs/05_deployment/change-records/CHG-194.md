# CHG-194 — the zero-loss parity proof reads the live candle table (wave 36)

- **Status:** recorded — fixes a pre-existing defect found during wave 36
- **Filed:** 2026-09-17
- **Source:** found in run 11 (2026-09-17 11:04) of
  `code/01_platform/04_scripts/holistic-measure.sh` — the first run in the wave
  to pass the smoke phase, the inject gate, G8, **and** complete the main
  measurement phase.

## What happened

Run 11 passed every pipeline gate and still exited 1. The analyzer's verdict:

```text
- G7c parity: 0 fully-closed (token,window) pairs compared candle-vs-raw, 22528 mismatches
!! G7c: window 1789623675000 token 25: NO final candle (expected 150 ticks)
!! G7c: ...and 22518 more window mismatches
!! GUARD FAILED — this run FAILS (see failures above)
!! LATENCY GUARD FAILED (analyzer rc=1) — run marked FAILED
=== HOLISTIC_RC=1 ===
```

Every *pipeline* gate in the same run was exact: the inject gate dropped
200/200 duplicates and 20/20 injected late frames, G7a recounted 400 duplicate
extras against a counter delta of 400, G7b counted 40 late rows against 40
injected, F6 saw zero raw-validation rejections, F8's ordering jumps equalled
the late rows, and F4 found no orphaned tentatives.

## Defect 1 — the parity proof had an empty candle side by construction

`holistic-analyze.py` carried:

```python
final_rows = []
failures.append("G7c: final-candle parity leg UNAVAILABLE — feature_candles_15s retired ...")
```

G7c's zero-loss proof compares every fully-closed `(token, 15s window)` in
`raw_table_1` against the final candle's `tick_count` and `volume`. With
`final_rows` hardcoded empty, the candle side was **structurally** empty, so
every closed window was reported as missing its candle. The 22 528 mismatches
are not a measurement of the pipeline — they are 1024 tokens × 22 closed
windows, i.e. *all* of them.

The patch that produced this was itself correct in intent: `feature_candles_15s`
(DDL 03) was retired with the 2026-09-05 multi-timeframe cutover, and reading a
dropped table would have been worse than admitting the gap. What it got wrong is
scope — only the **latency** half of G7c needs the retired table's `output_ts`.
The **parity** half needs `tick_count` and `volume`, and the live `candle_closed`
(DDL 33) carries both:

```text
instrument_token · tf · window_start · window_end · volume · tick_count
PRIMARY KEY (instrument_token, tf, window_start) NOT ENFORCED
```

Same root cause as CHG-191 and CHG-193: the 2026-09-05 cutover rebuilt the
topology and updated the Java, the DDLs and the docs, but touched **no file
under `04_scripts/`**, leaving the measurement layer describing a retired world.

## Defect 2 — "cannot measure" was reported as "the pipeline is broken"

Three legs are genuinely unmeasurable in this topology:

| leg | why it cannot be measured |
| --- | --- |
| G6 preview latency | preview table retired (DDL 30); the live candle pair has no write timestamp |
| G7c window-close → committed | `candle_closed` has `window_end` but no write timestamp |
| F4 signal settlement | `Signal_Candidates` has **no writer** while `STRATEGY_HOST_ENABLED=false` |

All three were appended to `failures`, and a non-empty `failures` *is* the
analyzer's exit code. The consequence: the analyzer exited 1 on every run no
matter how clean the pipeline was — run 11 is the proof, passing every pipeline
gate and still failing. A harness that cannot pass is not a gate; it is a
light that is always red, and it trains its reader to ignore it.

## The fix

**1. Parity reads the live table** (`holistic-analyze.py`). New
`read_candle_closed_rows()` (`L565`) reads `candle_closed` through the existing
`fluss-probes/FlussPrefixReader`; new `candle_parity_map()` (`L279`) turns the
rows into `{(token, window_start): (tick_count, volume)}`.

Two details carry the fix:

- **The candle table is a primary-key (KV) table**, so the log reader the raw
  path uses cannot read it (`LogFullRead` subscribes to a LOG's buckets). The
  prefix reader does `lookupBy(instrument_token)`, which **requires an explicit
  token list**: its `*`/empty wildcard means "no filter" only on the LOG path,
  and on the KV path `*` is parsed as a token, fails, and prints `__END__ 0` — a
  silent empty read (the P6-082 class). The call therefore passes the tokens the
  raw recount actually saw.
- **The 15s family is selected by window WIDTH, not by the `tf` label.** `tf`
  holds an enum code (`FIFTEEN_S`, `Timeframe.java`), so a rename would silently
  empty the candle side — the exact failure shape being fixed here. The widths
  (15s/30s/1m/3m/5m/15m) are unique by construction.

The side is keyed by **column name**, not by index: the retired parse read
`f[3]`/`f[9]`/`f[10]` of a 15-field layout, and the probe resolves names from the
live `TableInfo` (P6-371).

**2. A failed read is a failure.** `read_candle_closed_rows` returns
`(rows, ok)` where `ok` requires the probe's `__END__` sentinel;
`g7c_measurement_guard(raw_read_ok, compared, candle_read_ok)` (`L313`) rejects
`candle_read_ok=False` explicitly, so a dead read can never be read as "the
table holds no candles".

**3. `unavailable` is a separate, rc-neutral channel** (`L663`, exit at `L1768`).
The three unmeasurable legs are printed and counted but do not fail the run. The
split is **fail-closed**: only the legs named above travel this channel, so an
unmeasurable leg outside that set still fails. The F4 exemption additionally
requires the strategy host to be off (`strategy_host_enabled()`, `L300`); with
the host wired, `Signal_Candidates` has a writer and an unreadable table is a
real defect that must fail. `holistic-measure.sh` (`L127`) exports
`STRATEGY_HOST_ENABLED` so the analyzer reads the value that was submitted
rather than an inherited default.

## Rejected

- **Reading the retired `feature_candles_15s`.** Dropped on 2026-09-05; the
  reader burned its missing-table timeout on every drill run.
- **Restoring the latency legs by inventing a timestamp** (`window_end` as a
  write time). It would report a latency that was never measured. Reviving those
  legs needs a landing-timestamp column on `candle_closed` (a product DDL +
  writer change) — its own task, falsified on a live drill.
- **Failing the run on the unmeasurable legs.** That is the *current* state and
  it is what makes the harness unable to pass.
- **Making every unmeasurable leg rc-neutral.** An unfiltered exemption means a
  newly broken read passes as "unmeasurable" forever; the channel is therefore
  an explicit allowlist.
- **Filtering the candle family by the `tf` string.** See above — it is the same
  rename-fragile shape as the defect being fixed.

Two notes from writing those mutations, both kept because they are the kind of
thing that makes a suite look greener than it is:

- The empty-token test **first passed for the wrong reason.** It asserted only
  `ok is False`, which an unfiltered read also produces (`__END__ 0`), and the
  real `javac` was failing on the fake classpath. It now also asserts that
  `java` was never launched, which isolates the guard.
- The sentinel mutation is caught by the **positive** test, not the negative one:
  deleting the recognition leaves `ok` False in both cases, so only the clean-read
  assertion distinguishes them. The pairing in the table above is the one that
  actually holds.

## Blast radius

- `holistic-analyze.py` — the analyzer, and only the analyzer.
- `holistic-measure.sh` — one export + note.
- `fluss-probes/FlussPrefixReader.java` — **reused, not modified**. It had zero
  callers before this change.
- The pipeline, the DDLs and the Java are **untouched**.

## Residual risk

- The F4 exemption keys off `STRATEGY_HOST_ENABLED` from the environment. A
  caller that runs the analyzer directly without exporting it gets the
  host-off assumption; the note printed in the report names the state, and
  `holistic-measure.sh` exports the submitted value.
- The two latency legs remain unmeasurable by design. The harness's run exit is
  green while they are unavailable, so the report's `~~ UNAVAILABLE` count is the
  only signal — it is printed on every run for that reason.
- Parity tolerates a **partial first window per token** (LATEST-mode source
  startup) and windows not yet fully closed at the event horizon. That tolerance
  predates this change and is unchanged; it is not a hole this fix widened.

## Why this is a change record

The trigger list in `docs/08_implementation/01-foundation.md` (L323-336) includes
*gate-behavior*: `failures` non-empty decides the analyzer's exit code, and this
change moves three legs out of that list while turning the G7c parity proof back
on. The artifact under change is the acceptance harness's verdict, not the
pipeline.

**The limitation, stated plainly:** a green run now coexists with four legs that
were not measured (G6 preview latency, G7c window-close → committed latency, F4
signal settlement, and the G6 e2e-sample cascade). Those legs are printed as
`~~ UNAVAILABLE` with a count on every run for exactly that reason — the harness
reports them rather than hiding them — but a reader must not treat a green run as
evidence about preview latency or signal settlement. The G7c parity proof, by
contrast, is measured again, and it is the leg that decides whether ticks were
lost.
