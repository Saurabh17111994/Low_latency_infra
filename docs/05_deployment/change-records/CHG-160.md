## What happened

**CHG-158's fix for P6-189 broke both named pins.** The wave-21 change set
`-Dsurefire.failIfNoSpecifiedTests=true` on two steps, to stop a renamed class from
passing as BUILD SUCCESS. Run for real, that value aborts the build in the `common`
module: both steps use `-pl <service> -am`, `-am` pulls `common` into the reactor, the
`-Dtest` pattern matches nothing there, and surefire fails that module — `Failed to
execute goal ...:test (default-test) on project common: No tests matching pattern
"BridgeShutdownRegressionTest, BridgeShutdownHookTest" were executed!` — so step 13 (and
step 12, same shape) would have failed on every gate run, on a healthy tree, with a
message pointing at `common`. The wave-21 hermetic tests could not see this: they assert
the flag's text and drive a stub `mvn` that exits 0.

The flag is back to `false` and the strictness moved to a new `require_class_ran`, which
greps surefire's per-class closing line `[INFO] Tests run: N, Failures: F, Errors: E,
Skipped: S, Time elapsed: T s -- in <FQCN>` for every class named in the `-Dtest`
pattern and requires `N >= 1`. That is strictly stronger than the old
`require_tests_run` (maximum non-zero count), which cannot see a partial rename: one
surviving class keeps the maximum positive. A renamed, moved or dropped class now fails
the gate, which is what P6-189 asked for.

A second surprise came with the real logs: Maven colourises its output even when stdout
is a file (`TERM=xterm-256color`, no `.mvn/maven.config`), and it bolds the class name
itself (`-- in com.trading.ingestion.<ESC>[1mBridgeShutdownHookTest<ESC>[m`), so the
per-class line cannot be matched without stripping SGR sequences first. `strip_ansi`
does that, with `grep -c` rather than `grep -q` so `pipefail` cannot read sed's SIGPIPE
as a failure.

**The real JVM shutdown-hook path ran.** CHG-159 asserted that a SIGTERM reaches the
bridge because `IngestionService` installs a JVM shutdown hook; the classes were never
executed during wave 22. Step 13's pin now ran for real (offline): both classes report
one test each, and `BridgeShutdownHookTest` is the one that spawns the driver, sends a
real SIGTERM and asserts exit 143 with the final tick report drained.

**P6-861's umask window is observable now.** CHG-159 verified it by reading the source,
because the end state (mode 600) is the same with and without `umask 077` — the defect
was a window, not a final mode. The wave-22 test now installs a `cat` stub that reports
the mode of the redirect target at the moment `cat` runs (the shell creates the file
before exec, so that is the creation mode). The stub duplicates the real stdout as fd 3
first: inside a command substitution fd 1 is the substitution's pipe, and reading
`/proc/self/fd/1` there reports `pipe:[...]` with mode 300. Against the pre-fix script
the probe reports 664 on this box (umask 002) against 600 after the fix.

**The four non-discriminating tests discriminate.** CHG-159 judgement 7 named them; all
four now fail against the pre-fix script, for the right reason:

- `test_template_is_private_from_creation` — via the fd probe above.
- `test_running_tablet_makes_the_open_port_ready` — additionally asserts the docker stub
  was asked for `ps -q --status running fluss-tablet`; the pre-fix script only opened a
  socket, so the call is absent.
- the staleness tests are merged into
  `test_up_to_date_outputs_skip_and_stale_sources_rebuild`, which drives both directions
  in one test: skip on fresh artefacts, rebuild after touching the sources. The pre-fix
  script rebuilt unconditionally, so the skip leg fails; a script that skipped
  unconditionally would fail the rebuild leg.
- `test_flags_split_once_without_globbing` — the previous version used values without
  metacharacters, and the pre-fix unquoted expansion produced the same argv for those.
  The test now plants `flagtrap` in the bridge directory and passes `flag*`: pre-fix the
  word is pathname-expanded to `flagtrap`, post-fix it arrives as `flag*`.

## Judgement calls

1. **The `=true` value is not recoverable with `-am`.** The alternatives were to drop
   `-am` (the pin would then resolve `common` from the local Maven repository — a stale
   or missing artifact, and a different thing than the reactor builds) or to keep `=true`
   and accept a gate that is red on healthy trees. Neither is acceptable, so the flag
   stays `false` and the per-class leg carries the strictness. Recorded because the
   finding's own remedy ("avoid `failIfNoSpecifiedTests=false`") is not implementable in
   that shape.
2. **`require_class_ran` duplicates the class list in two places** (the `-Dtest` pattern
   and one call per class). Deliberate: the point is that the pin and the check are
   independent statements, and the wave-21 test now asserts they agree for every pattern
   in the script, so a future edit that adds a class to one side and not the other fails
   the helper suite.
3. **`strip_ansi` is a new shared helper, not inlined.** The gate has more than one
   `-Dtest` pin and the tests need the same behaviour; the helper keeps escape handling
   in one place and `test_strip_ansi_removes_sgr_only` asserts it directly.
4. **The unquoted-expansion fix for P6-703 does not make quotes work.** `read -r -a`
   splits on IFS, so `GO_FLAGS='-ldflags="-s -w"'` still arrives as two broken words;
   what the array form actually guarantees is no pathname expansion. The source comment
   claimed "a multi-word or quoted flag survives", which overstates the code, so the
   comment now names the real guarantee and says quotes are not interpreted. No
   behaviour change was needed for the finding as written ("use arrays after splitting
   once"), and the test asserts what is true rather than what was claimed.
5. **The `cat`-probe caveats are named, not hidden.** The probe observes the mode of the
   file the shell created for `cat`'s stdout. It cannot observe a mode on a filesystem
   that ignores `umask` (FAT, or NFSv3 with a non-default policy), and it needs
   `readlink`/`stat` from coreutils. Both hold on the platforms this gate runs on.
6. **The offline suites were re-run; the cluster steps were not.** Gate steps that need
   a live Fluss cluster (the integration flags in the full module run) were not executed
   in this follow-up — the dev cluster is down on this box — so the claims here are
   limited to: the real step-12 pin (20 tests, BUILD SUCCESS), the real step-13 pin
   (2 tests, BUILD SUCCESS), the plain `common` + `ingestion` module suite
   (`common` 722/0/0/2 skips, `ingestion` 470/0/0/8 skips, BUILD SUCCESS), and the
   helper suite.
