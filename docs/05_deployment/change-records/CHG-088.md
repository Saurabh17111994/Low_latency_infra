## Summary

`make gate` (run-monday-gates.sh) step 8 (`bg_4` ingestion-int suite) failed on
`FullStackE2ETest.fullStackFakeBrokerToFluss` with a core regression caused by
the TOTP migration (commit `70058b0`): the Go bridge now AutoLogins against the
real Arrow API in every mode, but the E2E harness passes fake `e2e-user`
credentials → real API `"user not found"` → `BRIDGE_CRASH exitCode=2` ×2 → the
test's `event=disconnect` marker never arrives, ticks=0.

Fix (test-only, production unchanged):

* `go-bridge/main.go`: `ARROW_FAKE_BROKER=1` env mode — skips AutoLogin,
  `client.SetToken("fake-token")`, no-op `refreshAuth`; production path
  (flag absent) untouched: fail-closed trio → AutoLogin → reconnect.
* `FullStackE2ETest.java`: sets `ARROW_FAKE_BROKER=1` in the broker env.
* `run-monday-gates.sh:203`: step-8 `mvn` stdout/stderr now redirected to
  `$JAVA_LOG` — previously unredirected, so `java-suite.log` was never created
  and gate diagnosis lost the surefire output entirely.
* `test_stale_table_kind_scan.py`: silent-path fixtures derive from
  `s.SUITE_TRIPLE_TRUTH`/`s.C6_TRIPLE_TRUTH` instead of re-typed literals
  (third occurrence of truth-bump breakage would otherwise recur).
* `test_execution_network_check.py`: injected key `ARROW_TOKEN` →
  `ARROW_APP_SECRET` (ARROW_TOKEN no longer exists in `ORDER_ARROW_ENV`).

## Decisions

- **Fake-broker mode in the bridge, not the vendored SDK**: SDK tree is
  pinned/off-limits; the flag is test-only and absent in all production
  launches, so fail-closed production auth semantics are preserved exactly.
- **Gate does not re-verify what the user reported**: after the fix, the
  isolated E2E passed (`Tests run: 1, Failures: 0, Errors: 0`, 15.3 s,
  `finalTicks=25 errors=0 restarts=0`, env
  `INGESTION_INT_TEST_E2E=true`) and the full `bg_4` four-flag suite then
  passed 247/247 (0 F, 0 E, 1 known env-gated skip).
- **Evidence**: `logs/soak/monday-gates-20260824-124159/` (python fail, 12:41)
  and `logs/soak/monday-gates-20260824-145119/` (step-8 fail, 14:51 —
  java-suite.log absent due to the redirect bug, now fixed).
