## Notes

- **Why the bug survived:** the regex was "correct" for every DDL whose comments never
  contained `);` — one file did, and the truncated parse produced a plausible value
  (`lake_policy: "off"`) rather than an error. The parity test is the guard that turns
  "plausible" into "must equal a fresh parse".
- **Fail-closed, not best-effort:** the datalake refusal means a future parser regression
  stops the manifest write instead of silently recording the lake as off.
- **Quote-aware both ways:** a `);` inside a quoted value cannot truncate, and a `--`
  inside a quoted value is not a comment. Both are pinned by unit cases.
- **No wider diff:** the regeneration touched exactly the one expected line; the other
  seven lake-off entries have no datalake option in their DDLs, so "off" is correct there.
