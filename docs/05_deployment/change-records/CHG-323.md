# CHG-323 -- Subscription capacity and multi-socket policy fail at Java startup with the effective numbers

- **Status:** landed 2026-09-26 -- failing-first red (test-compile) -> green
  (`make test` rc=0, common 743 / ingestion 516 surefire); static-check 0
  failures; docs-audit all pass.
- **Filed:** 2026-09-26
- **Source:** CHG-320 moved the multi-socket policy into the Go bridge and Java
  `IngestionConfig`; capacity (`tokens <= slots x 1024`) stayed a bridge-plan
  check only (`subscription_plan.go`). A configuration the bridge refuses
  therefore failed after Java startup -- the bridge exits and Java records a
  bridge crash -- and the message never named the effective token count,
  capacity, or the fix (e.g. the 2 433-row manifest on the default one socket).

## What changed

| piece | change |
|---|---|
| `SubscriptionPreflight` (new) | pure `violation(tokens, connections, perConnection, production, approved)`: policy first (production stays single-socket; dev multi-socket requires approval), then capacity (`tokens <= connections x perConnection`); the message names the effective numbers and the fix |
| `IngestionService.main` | step 4b: run the preflight after the manifest load, before the service and bridge start; FATAL + exit 1 on violation |
| `IngestionConfig` | exposes `production` (parsed once from `DEPLOYMENT_ENV`/`DEPLOY_ENV` -- single source of truth for the policy) |

## What did NOT change

- Go bridge gates (`BuildSubscriptionPlan` capacity,
  `multiSocketAllowedByPolicy` CHG-320) -- they remain the last line of
  defense; the bridge source is untouched.
- Config validation ranges/pins, `DEPLOYMENT_ENV` requiredness, manifest
  loading semantics.
- Runtime behavior for a valid configuration: the preflight is a pure check
  that returns immediately.
