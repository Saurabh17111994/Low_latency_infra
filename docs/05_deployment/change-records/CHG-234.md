# CHG-234 — the pipeline-lib guard suite asserts per function (wave 44)

- **Status:** recorded — fixed (2026-09-19)
- **Filed:** 2026-09-19
- **Source:** audit map wave 44 (`test-pipeline-lib.sh`, 18 findings, session e9f995f4).

## What was found

The CRITICAL: G19's wiring loop iterated over five function names but grepped the
**whole file** for the preflight guard, so all five iterations passed or failed
together — the loop asserted nothing per function and would have stayed green
with the guard missing from four of the five. The same whole-file blindness sat
under G17/G18 (readiness tokens), G12/G13 and G22.

The rest: G3 joined every line of the submit body (`sed 's/\\$//' | tr -d '\n'`),
so a comment spliced into the continuation chain still satisfied every needle;
G4b's `continue` skipped the `in_cont` state update, so the line *after* a
trailing comment was misjudged; G10 re-implemented the fingerprint gate's grep
over its own fixture instead of running the gate; G19's negative tests could
drive the real stack when the guard they test is missing; the runtime half and
the wiring half checked different function sets; `${LIB_COMPOSE_DIR}` was read
unbound under `set -u`; G14's `jar cf` was unchecked and leaked `LIB_JAR`; G21g's
first alternative (`_operator_`) was vacuously true; G28d's rocksdb keys were
unescaped regexes; G28e used a fixed, shared `/tmp/g28-empty-cap`; G22b ran the
validator twice; G26f's profile match was whitespace-fragile; G4's PASS was
suppressed by any earlier failure; and `submit_block=` (unbalanced quoting, never
read) was already gone — **P6-588 is stale**, verified by `rg submit_block` =
no match.

## What changed

- **Per-function bodies via `declare -f` in one helper** (`lib_fn_body`), not a
  `sed` range: this lib contains here-docs whose bodies include col-0 braces
  (28 col-0 `fn() {` openings vs 34 col-0 `}` closers), so the range the audit
  proposed can truncate or overrun. G17/G18/G19 all use it now.
- **G17/G18 assert each token in the function that must contain it**: preflight
  must *call* `pipeline_wait_for_fluss_ready` and the probe; the ports,
  `FLUSS_READY_TIMEOUT_S` and the metadata check live in
  `pipeline_wait_for_fluss_ready`; `FlussReadyProbe` lives in the probe
  functions. Measured with `declare -F` before writing the assertions.
- **G19 wiring is delegation-aware**: `pipeline_purge_raw_table` is a three-line
  wrapper whose guard is transitively enforced by `pipeline_purge_table`, so the
  audit's literal-text requirement would have reported a false MISSING.
- **One canonical list** (`G19_GUARDED_FUNCS`) for the runtime refusals and the
  wiring check, with the missing `pipeline_purge_table` runtime case added.
- G3 joins only continuation lines; G4b falls through to the state update and
  strips trailing whitespace; G10 extracts and *runs* `fingerprint_gate`;
  G19's negative tests run behind a `docker` PATH shim (COMPOSE is an array whose
  first word is `docker`), scoped to that block; G14 checks both fixture builds
  and restores `LIB_JAR`; G21g requires the literal operator prefix; G28d uses
  `grep -F`; G28e uses `mktemp -d` plus one EXIT trap over every fixture dir;
  G22b runs the validator once and keeps its output; G26f tolerates legal YAML
  variants; G4 snapshots the failure count; the G2 definition check moved into a
  subshell so the suite sources the lib once (G14), where a function is first
  called; `ROOT` resolution now fails loudly.
- `PIPELINE_LIB_UNDER_TEST` / `PIPELINE_COMPOSE_UNDER_TEST` (both defaulting to
  today's paths) let the mutation tests aim the suite at a doctored copy.
