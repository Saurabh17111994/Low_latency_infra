# CHG-225 — catalog-guard names the drift instead of only counting it

- **Status:** recorded — fixed (2026-09-18)
- **Filed:** 2026-09-18
- **Source:** the DDL apply timing investigation; the drift provenance it had to establish by hand.

## What happened

`catalog-guard.sh` reported `catalog has MORE tables than the manifest describes (33/27) — extra
tables are drift, not health` on every `make up`, and there the report stopped: a count says how
much drift there is, not which tables. Establishing the six extras took a hand-run ZK listing —
four `chg100_sweep_*` (leftovers of a drill run interrupted on 2026-09-17, two tables per run × two
runs), a probe's `probe_tbl_1`, and a lowercase `signal_candidates` next to the real
`Signal_Candidates`.

## The change

- New `code/01_platform/04_scripts/catalog_drift.py`: `diff(live, manifest)` returns
  `(extras, missing)` as exact sets, sorted; the CLI prints `extra:`/`missing:` lines and exits 0 —
  naming is its job, deciding what to do about it is the caller's.
- `catalog-guard.sh` gains `drift_lines()` and calls it in both drifted branches (over-count →
  extras, plus a `--cleanup-prefix` hint for dropping one that nothing references; partial →
  missing). Best-effort by construction: a helper that cannot run must not turn "the catalog is
  drifted" into "the guard crashed".
- The header's item 7 documents the naming.

## Verification

- Test-first: `DriftDiffTest` (3 legs) green — sorted extras and missing; a healthy catalog reports
  no drift; and a lowercase twin is drift, not a match (the real case: `signal_candidates` alongside
  `Signal_Candidates`).
- `bash -n` and `shellcheck -S warning -x` clean on `catalog-guard.sh`.
- Live: with the catalog mid-apply by a concurrent smoke run, the over-count branch named real live
  tables (`extra: ddlsmoke1789749035640732_instruments`, …) — the plumbing works on real data. On a
  quiet catalog with only the *expectation* moved (`EXPECTED_TABLES=30`) the helper correctly
  reported no drift while the guard reported PARTIAL, because there the mismatch is the expectation
  rather than the table set.
- The six extras were dropped with the DDL tool's own `--cleanup-prefix` (the hint the guard now
  prints); afterwards the guard reports `catalog probe: 27/27 tables` → `catalog healthy — nothing
  to do`.
