## Problem

G6 (levers map): "who gets told, how fast" — nothing. The CHG-093 routing
proof landed all 46 alerts on a dev-webhook destination whose receiver
logged deliveries to container stdout: every alert (including live crits
like `SIGNAL-crit-taskmanager-down`) vanished into `docker logs` ephemerality.
No record, no query, no classification, no way to answer "when did the
alert fire and was it delivered". Additionally, the volume lever (G1) had
no rule at all — `SIGNAL-error-source-stalled` only fires at exactly
0 rec/s, so a partial feed degradation (broker throttling, partial
subscription) stayed silent.

## Change

- **`alert-consumer.py`** (replaces `webhook-receiver.py`): persistent
  single-webhook consumer. Every O2 delivery is classified
  (`severity` crit/error/warn from the name infix, pos-state → warn;
  `class` ing/signal/infra/pos-state from the prefix) and appended to
  `/data/alerts/alerts.jsonl` on the new `alert-store` volume — durable
  across container restarts. HTTP surface: `POST *` (delivery; malformed
  body → 400 so delivery failures are visible in O2, never a crash),
  `GET /alerts?limit&severity&class`, `GET /stats`, `GET /healthz`.
  Stdlib only, threaded server, tail-bounded reads (512 KB).
- **Compose**: service `webhook-receiver` → `alert-consumer` (same netns
  sharing with O2, same port 9999, same destination URL — zero O2-side
  churn); `alert-store` volume added.
- **Swarm (4-VM target)**: same rename + the script now ships as a Swarm
  config. Fixes a latent defect: the old `webhook-receiver` swarm service
  ran `/app/webhook-receiver.py` with NO mount of that file — it would have
  crash-looped on the real stack. Also `ALERT_BIND=0.0.0.0` (overlay
  network; loopback unreachable cross-netns) and the destination URL must
  be `http://alert-consumer:9999/noop` in swarm (documented in
  03-alert-routing.md).
- **`SIGNAL-warn-source-volume-drop`** (o2-provision.py): source <
  5,000 rec/s (50% of the 10,240/s design rate) for 5 min while the job
  runs — the partial-degradation gap. Same quiesced-feed caveat as
  source-stalled (fires by design when the feed is stopped). The ideal
  relative-drop-vs-rolling-median form needs an O2 recording rule
  (v0.91.5 lacks it); documented for revisit.
- **Mechanical guard** (standing rule gotcha-15):
  `make alert-routing-test` → `alert-routing-selftest.py`: healthz →
  negative proof (malformed POST → 400, consumer survives) → temporary
  always-firing probe alert → poll the durable record → assert
  classification → delete the probe (cleanup runs even on failure).
