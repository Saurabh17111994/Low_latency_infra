# CHG-320 -- native multi-socket approval policy in the Go bridge (2 433 x 3 sockets)

- **Status:** recorded -- landed 2026-09-26 (Go suite green; profiler bring-up
  dry run PASSED with `multi-socket approved: slots=3` and 2 433 tokens
  subscribed across 3 sockets)
- **Filed:** 2026-09-26
- **Source:** the real-broker profiling workstream needs the full
  2 433-instrument universe on the real broker channel. One bridge connection
  caps at 1 024 tokens (`MaxHFTTokensPerConnection`), so the universe needs
  3 sockets (3 x 811). The plan builder, per-slot supervisor and tests already
  existed, but `runHFT` refused any plan with `len(plan.Slots) != 1` — the
  dossier called this "a policy gate, not a design gap"
  (`03-ingestion.md`). The 2026-09-26 profiler bring-up dry run hit exactly
  that gate (`FATAL: … approved for exactly one Arrow HFT socket; planned=3`).

## What changed

| piece | change |
|---|---|
| `main.go` `runHFT` | the unconditional `len(plan.Slots) != 1` FATAL became an approval check via `multiSocketAllowedByPolicy()`; refusals keep the original message and the `single_socket_policy_violation` disconnect emit |
| `multiSocketAllowedByPolicy()` | mirrors the Java `IngestionConfig` gate: `ARROW_HFT_MULTI_CONNECTION_APPROVED=true` **and** non-production `DEPLOYMENT_ENV`/`DEPLOY_ENV`; blank fails closed; `prod`/`production` refuse; junk refuses |
| `multi_socket_policy_test.go` | 10-case approval matrix |
| docs | `03-ingestion.md` policy section + `ARROW_HFT_CONNECTIONS` row; SIG-PERF-001 blocker notes amended (decision landed); ING-UNIT-020 row corrected to the real assertion (`=4 → must be in range 1..3`) |

## What did NOT change

- `BuildSubscriptionPlan` capacity bound (`slots x 1 024`), the per-slot
  supervisor, slot/connection/epoch routing, dedup, the raw-table contract, the
  Java reader — all untouched.
- Production remains single-socket: `ARROW_HFT_MULTI_CONNECTION_APPROVED=true`
  is rejected in `prod` on both the Java and the Go side.
