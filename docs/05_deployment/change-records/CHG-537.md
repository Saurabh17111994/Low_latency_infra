## What changed

`read_inject_counts(path)` is the new single reader for `faketool.log`:

- `FileNotFoundError` → `(0, 0, None)` — the expected injection-less run,
  parity-only by design (CHG-198). Unchanged behavior.
- Any other `OSError` → `(0, 0, "IsADirectoryError: ...")` — the leg was not
  measured. The G7 section appends an `UNAVAILABLE` note carrying the error
  and prints `faketool.log UNREADABLE (...) — INJECT counts unknown; G7a/G7b
  skipped as UNAVAILABLE`, instead of the misleading "no injection
  configured". This is the same discipline XC-5 introduced for unsampled
  counter TSVs (`counter_leg_note`): an unmeasured counter is not a clean
  zero.
- Success → the summed INJECT counts. Unchanged.

The G7c parity + clean-feed checks still run in all three cases (the zero-loss
proof does not depend on the inject log).

## Why

The 2026-10-03 blind audit was run precisely to test whether the 506
false-positive/won't-fix verdicts were verified rather than assumed. It
confirmed 46 of 47 sampled verdicts, confirmed both fix spot-checks, and
found this one real gap. Fixing it converts AS-035 from won't-fix to fixed;
the other two `except OSError: pass` sites in the file were re-checked and
left as-is (the counter TSV is covered by `counter_leg_note`/UNAVAILABLE;
the G7c reader prints a loud `!! ... no __END__ sentinel` failure before
returning False).
