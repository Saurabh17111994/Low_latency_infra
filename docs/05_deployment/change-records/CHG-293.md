## Why

B6a established on 2026-09-21 that no service emits a security signal, that `o2-provision.py` provisions
47 rules and no rule in either provisioner names a security fact, and that each of the eight security
areas is held by a cap, a lock, a rotation or a build-time gate instead. That conclusion was *recorded*;
nothing kept it true. A later rule added over a security stream would have made the table wrong silently —
the exact "armed but unwired" shape the area was written to prevent.

## What C19 checks

Over `docs/08_implementation/10-observability.md`'s "Alert catalogue" section, in both directions:

- A row whose **Runtime alert** cell is not a denial must name a rule that a provisioner actually defines.
  Denials are `no …` and `build-time, not runtime` — measured over all eight real rows, those are the only
  two shapes present.
- A provisioned rule carrying the `SEC-` prefix must be named by some row, so a security rule cannot be
  armed without the table saying so.
- The section's own measured sentence — "`o2-provision.py` provisions 47 rules — 20 `SIGNAL-*`, 18
  `ING-*`, 9 `INFRA-*`" — is checked against the provisioner it names. It is the evidence the eight areas
  rest on, so it is the first thing that should fail when it drifts.

Rule names come from `o2-provision.py`'s `ALERTS` list read with `ast` (quoted prose cannot produce a
false match — the approach `test_alert_threshold_parity.py` already uses) and from
`openobserve/alerts/position-state-alerts.json`. The check fails closed when the section, the rows, or the
provisioned set is missing.

## The mis-scope the live test caught

The first live run failed, and the check was wrong, not the document: the count sentence names
`o2-provision.py`, so it is a claim about that file's 47 rules — the position-state JSON's 3 rules are a
different provisioner. C19 compared the sentence against both (50) and reported a drift that did not
exist. The scope is now explicit in the code and pinned by a test that asserts the combined set *does*
look like a mismatch, so the guard cannot be quietly dropped.

## Known ceiling

The security-rule predicate is the `SEC-` prefix, which is what the plan's must-fail control uses; a
security rule that does not carry it would not be caught by the second direction. And C19 checks
*agreement*, not whether a claimed rule can fire: a rule over a stream nothing writes is still caught only
by the counter-first discipline, not here.
