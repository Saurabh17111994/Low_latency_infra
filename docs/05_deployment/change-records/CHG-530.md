## What changed

Six handlers in `holistic-analyze.py` (baseline lines; G2 shifted the current
file by -1/-2) now read `except OSError as exc:` and append the caught error
to the existing message:

| Baseline | Message |
|---:|---|
| L961 | signal-path latency: `tm-prom-latency.tsv absent: {exc}` |
| L1282 | `diskstats.tsv absent (A2 unavailable): {exc}` |
| L1323 | `tm-throttle.tsv absent (A5 unavailable): {exc}` |
| L1374 | `tm-prom-rocksdb.tsv absent (A1 unavailable): {exc}` |
| L1425 | `proc-io.tsv absent (A2b unavailable): {exc}` |
| L1465 | `gc.log absent (D6 guard skipped - legacy evidence dir?): {exc}` |

## Why

- The G3 group is failure visibility: previously any `OSError` was reported as
  "absent", so an unreadable/permission error was mislabeled as a missing
  optional file. Including the caught error distinguishes absent from
  unreadable without changing the continue-on-absence behavior.
