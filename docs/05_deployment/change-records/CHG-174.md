## 1. The gate could not fail (P6-001, P6-032)

The bench generates 20,480 frames/s — 1024 subscribed ids at 20 Hz — and the
gate that was supposed to prove it read `if [ "$rows" -lt 15000 ]`, with
`rows_s=$(( rows / 60 ))` underneath it. The floor was therefore an effective
250 rows/s: roughly 82x below the offered load, and the divisor was a constant
whatever the window actually cost. A historical result file shows what that
means in practice — `logs/soak/bench-20260831-212352/bench/result.txt` records
20,483 / 20,472 / 20,479 rows per second and a PASS, while the same file would
have passed just as happily at 2% of that rate. The benchmark's PASS line was
not evidence of throughput.

The floor is now derived from the rate and the window that was measured:
`rows >= MIN_RATE x EXPECTED_RPS x elapsed_s`, with the elapsed time taken
around the sleep (`date +%s%3N`) rather than assumed. The threshold scales with
the same measured width, so the gate means the same thing whether a window
costs 60s or 75s — and the closing timestamp is read after the samples, so the
divisor can only be a shade larger than the true counter span. That makes the
gate slightly stiffer than intended, never laxer.

`EXPECTED_RPS` defaults to 20480 and `MIN_RATE` to 0.90, which is about a 10%
margin over the historical 20,483 rows/s: the recorded run still passes
(1,228,980 rows against a 1,105,920 floor). All four values are overridable
(`BENCH_EXPECTED_RPS`, `BENCH_MIN_RATE`, `BENCH_WINDOW_S`, `BENCH_WINDOWS`), and
those seams are what let the tests exercise the arithmetic without paying three
minutes of wall clock.

## 2. Latency evidence that was not evidence (P6-031, P6-033)

Two separate defects sat behind the same two column headings. The fallback for
a missing quantile divided lifetime-cumulative `SUM` by lifetime-cumulative
`CNT_END`, both read at one instant, so the number printed as p50/p99 was the
mean of the whole process uptime — recent tail dilution included. It now uses
window deltas of both, and the p50/p99 gauges are queried first, as the header
always claimed they were (a mid-edit state briefly dropped the gauge path; the
tests cover it).

The second is worse. A latency sample that could not be read was substituted
with `-1`, and the check was `[ "$p99" -ge 1000 ]` — which `-1` fails, so the
window PASSED with no latency evidence at all. An unmeasurable latency is now a
FAIL, and the TSV records `-1` only when the verdict is already FAIL.

## 3. Credentials on the command line (P6-028, P6-029)

`awk -F=` returned everything before the value's first `=`, so a base64 secret
ending in `=` or `==` lost that padding and every request 401'd; surrounding
quotes and a trailing CR survived too. Measured: `c2F1cmFiaDpwYXNz==` came back
as `c2F1cmFiaDpwYXNz`. The live `secrets.env` value happens to be 44 chars with
no `=`, so the defect was latent rather than active — which is the only reason
this did not present as a bench that could not read its own metrics. The
reader is now `run-full-suite.sh`'s `read_o2_auth`, verbatim.

The same value was passed to `curl -H "Authorization: Basic $O2_AUTH"`, which
puts it in the process's argv where any local user can read it from `ps` or
`/proc/<pid>/cmdline` for the duration of the call. It now travels in a 0600
config file (`curl -K`), created under `umask 077` and removed by the EXIT
trap, matching the precedent in `run-full-suite.sh` (P6-179).

## 4. Teardown reported success while the result said FAIL (P6-030)

`cleanup()` detects real failures — the broker would not die, port 8899 stayed
busy — and sets `FAILED=1`. It then ran `exit "$rc"`, where `rc=$?` is the
status the script had already exited with: on the PASS path that is 0. CI read
a green build while `result.txt` said FAIL, and the failure was discovered
precisely on the path where nothing else could overrule it. The trap now forces
rc to 1 when `FAILED=1` and rc is 0.

The test for this was green in the red leg for the wrong reason, and was
tightened after measuring: pre-fix, the broken credential reader left every
window "unavailable", so the script exited 1 early and still printed the
busy-port line — satisfying the assertions without ever reaching the exit-0
path the finding is about. It now asserts the script reached its own
`=== RESULT: PASS (all windows)` first.

## 5. Preflight and gate checks that could not tell (P6-309…P6-316, P6-711…P6-713)

- **P6-309** — the manifest was a hardcoded absolute path that exists on one
  machine. It is now derived from the checkout and honours the same
  `INSTRUMENT_MANIFEST_HOST_PATH` variable `docker-compose.yml` uses, so the
  check guards the file the soak compose file actually bind-mounts.
- **P6-310** — `O2_BASE` and `INGESTION_CONTAINER` are overridable
  (`O2_BASE_URL`, `INGESTION_CONTAINER_NAME`, with a `COMPOSE_PROJECT_NAME`
  fallback for the container).
- **P6-311** — `port_open` ignored its `$1` and grepped `ss` output, matching
  any interface; it also reported "closed" when `ss` was absent. It now
  connects to the host it was given via `/dev/tcp`, with `2>/dev/null` because
  callers ask about ports they expect to be closed.
- **P6-312** — the broker was checked once at startup. A faketool that died
  mid-run made all three windows report throughput and latency failures, which
  blames the pipeline for a dead load generator. The loop now checks
  `kill -0 "$FAKETOOL_PID"` per window and stops with the real cause.
- **P6-313** — `docker inspect -f '{{.State.Health.Status}}'` errors on a
  container with no HEALTHCHECK, normalises to "none", and failed the gate
  forever on a container that was up. The template now reports
  `running=<bool>` when there is no health field, and both are accepted.
- **P6-314** — the ack pattern was `acknowledged[=:][[:space:]]?1024`, which
  also matches `acknowledged=10240`, and `grep -c` counted matching lines
  rather than acks. Now anchored on the token with `\b` and counted per match.
- **P6-315** — an unavailable baseline was echoed and ignored, so an
  OpenObserve that answered nothing still burned the full three minutes
  failing window after window. It fails before the first window.
- **P6-316 / P6-713** — the TSV header had five columns against six printed,
  and windows skipped early reached neither the TSV nor the failures list.
  Both are recorded now, with a `SKIP` verdict.
- **P6-711** — `num()`'s character-class test accepted `-`, `.`, `1.2.3` and
  `--5` (printf coerced them to 0 or 1, silently) and rejected `1e6`, which
  OpenObserve can serve. Measured: `-` → 0, `1.2.3` → 1, `1e6` → empty. It is
  now a real numeric regex, still integral for the counter arithmetic.
- **P6-712** — `grep -q 'version "17'` rejected JDK 21 and 25. The gate now
  reads the major version and requires `>= 17`.

## 6. A metrics column that was silently empty (P6-369)

`fluss-client-metrics.py` writes a grid of whole-second UNIX timestamps
(`range(start - 15, end + 30, 15)`) and looked each series up with
`series[col].get(g)` — an exact key match. The timestamps come from the
Prometheus payload, where they are typed by the encoder rather than by the
script, so a fractional float or a string misses every key and the column came
out EMPTY while the run still printed success. For a diagnosis tool that is the
worst possible failure shape: the operator reads "no data" as "the metric was
flat", not as "the lookup is broken".

Keys are normalised with `int(float(t))` and the grid lookup takes the newest
sample at or before the grid point, which is what `fused_timeline.py` already
does in `_prom_range`. The forward-fill deliberately does not walk keys in
insertion order, so it does not depend on the payload being sorted.
