## What changed

- `PerInstrumentFeatures`: new `precomputeLive` mode and `closeLive` slab
  (`double[registrySize][]`, heap-only, allocated once per slot). Every forming
  event loops `FeatureRegistry.closeIdsFor(tf)` and stores
  `computer.previewOnForming(...)` — once per instrument, shared by every
  strategy. `latestLive` reads the slab (fallback: closed value);
  `onClosedCandle` finalizes the closed value and syncs the live slot to it;
  `snapshot` still reads closed slots only. A `liveValueForTest` seam exposes
  slab values to the unit tests.
- `SignalJobConfig`: `FEATURE_LIVE_PRECOMPUTE` (default **true**) +
  accessor; `StrategyHostFunction` passes the flag into the `HostSlot`
  constructor. `docker-compose.yml` anchor + `pipeline-lib.sh` submit arg
  plumb the same variable to the job.
- `FeatureComputer`/`FeatureView` Javadoc updated to the new contract; no
  signature or behaviour change with precompute off.

## Why

- "The board prints every feature every tick" must be true for all cadences
  without every strategy paying its own per-read computation. One precompute
  per instrument per tick makes a strategy read a plain array read, keeps all
  strategies of the instrument on the same value, and preserves closed-only
  storage: live and closed slots are physically separate arrays and sealed
  rows never carry live values.

## Residuals

- The live slab is transient heap state: a restore rebuilds it from live ticks
  (no checkpoint content) — intentional, pinned by the savepoint_impact line.
- Per-read fallback stays available behind `FEATURE_LIVE_PRECOMPUTE=false`;
  production default is **on** per the operator decision.
- Always-on cost scales with registry × tick rate. The next registry growth
  (more CLOSE features) should re-run the stage profiler before enabling.
