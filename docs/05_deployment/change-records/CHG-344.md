## Findings recorded (not fixed here)

- `docker-stack.yml` (prod deck) does not carry the multi-TF/strategy/execution keys at all (it has no `MULTITF_ENABLED` either). A production turn-on will need its own decision + change; production deploy remains unproven.
- The compose anchor comment on `MULTITF_ENABLED` says the values "must be in the JM/TM environment, not the launcher's"; under `flink run -d` (session mode) `SignalJob.main()` runs in the client JVM, so a launcher `-e` also reaches it. Both paths work today because the anchor feeds the exec'd client's environment; the comment was left as-is (it is the stricter contract).
