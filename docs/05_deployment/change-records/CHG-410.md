## Notes

- **M3-1 was a half-existing knob:** `ALLOWED_LATENESS_MS` parsed, validated and reached
  `config.allowedLatenessMs()` — but the aggregator never received it and hardcoded the default at
  the three sites that use it. The env override only ever worked by coincidence (the default).
- **M3-2 is an honest behavior change:** on the rare aligned processing-time fire the window no
  longer closes early; finalization always waits for the watermark (≤ configured out-of-orderness).
  The session-close path is event-time and unaffected; live-snapshot behavior is unchanged.
- **M3-3's throw is the fix, the warning is the diagnosis:** a deployment that sets the host
  without multi-TF is now refused at boot with both flags named, instead of starting a healthy job
  that runs no strategies.
- **M3-4's decision was already made in code:** the 500 ms default came from the measured
  2026-08-30 single-timeline work (the 5 s default added p95≈5.7 s end-to-end) and was pinned by
  `SignalJobConfigTest`; only the docs lagged. DEC-058 records it, and the new parity guard makes
  the next divergence fail in the gate instead of in a deploy.
