## Notes

- **Why the reader can never block:** enqueue is a non-blocking `ArrayBlockingQueue.offer`; the only
  lock (gate) is held for the offer itself, and the overflow callback runs outside it. The delegate
  call happens only on the daemon writer.
- **No lost wakeup at close:** the worker exits only when `!accepting && queue.isEmpty()`, re-checked
  under the gate, and enqueue offers under the same gate, so a record offered just as `close()` flips
  acceptance is either drained or counted — never silently stuck.
- **Abandonment is counted:** the deadline leftovers are `queued + in-flight` (an upper bound; an
  abandoned in-flight write may still land via the delegate's bounded flush). The delegate release
  still runs after an abandoned drain.
- **Instrument context:** both interface forms forward through the queue; the 6-arg path is covered
  by the drain test (the captured token survives).
