# CHG-490 -- ingestion transport: retire the unverified batch hash (proto field 6 reserved)

- **Status:** implemented -- schema retirement + regeneration + call sites + tests;
  Go and Java suites green, `make static-check` / `make docs-audit` green
- **Filed:** 2026-10-01
- **Source:** the hash-audit footnote (2026-10-01), same audit as CHG-488. The Go
  bridge computed a batch-level `sha256` over the concatenated `raw_payload`s
  (`batch_payload_hash`, proto field 6) that **no consumer ever verified or
  stored**. The per-event `payload_hash` (field 30) is verified in memory at
  admission (M4-6, `PayloadHashValidator`), so the batch-level digest was a
  second, orphaned integrity artifact -- CPU on every flush plus ~34 wire bytes
  per frame. Retired natively rather than re-wired: verifying it would duplicate
  the per-event check on the receive hot path for zero correctness gain.

## What changed

| piece | change |
|---|---|
| `proto/market_data.proto` | `bytes batch_payload_hash = 6;` deleted; replaced with `reserved 6;` + `reserved "batch_payload_hash";` and a note naming CHG-490 and the surviving per-event mechanism |
| `go-bridge/batch.go` | `flushLocked` no longer builds the concatenated-payload digest; the `RawPayload` carry comment no longer claims a batch hash. The per-event hash at `Add` (computed once, Q5) is untouched |
| generated code | regenerated from the schema via `make proto`: `marketdata/market_data.pb.go` + the Java transport classes. Regeneration also reconciled pre-existing field-30 comment drift in `TickEvent.java`/`TickEventOrBuilder.java` (the M4-6 admission-verification text was in the schema but missing from the committed generated Java) |
| tests | `batch_test.go` (presence loop + coverage check), `transport_test.go` (sha256-length check + header note), `marketdata_test.go` (fixture field), `TickEventContractTest.java` (set/get round-trip field) all dropped their batch-hash references |

## What did not change

- The **per-event** `payload_hash` (field 30): computed once in Go at `Add`,
  byte-exact on the wire, verified by Java at tick admission before any other
  gate (missing -> `MISSING_PAYLOAD_HASH`, mismatch -> `HASH_MISMATCH`, bad
  length -> `INVALID_SCHEMA`; never appended). It is the single verified
  integrity mechanism.
- No storage, Flink state, checkpoint content, DDL or runtime configuration.
- `event_fingerprint` and every stored row shape are untouched (CHG-488's scope).
- No pipeline rerun required: the effect is wire/CPU hygiene (one sha256 per
  flush + ~34 B/frame), with both binaries shipping together from one build and
  the change parse-compatible in both directions.
