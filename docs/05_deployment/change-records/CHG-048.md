## Summary

Implements the offline T4 foundation slice: a long-lived Rust execution/position authority crate that compiles against the pinned Nautilus revision and proves the three core safety boundaries offline, without yet wiring the LiveNode runtime or live broker. This closes the missing-change-record gap identified in the 2026-08-20 audit (commits 6d30467/128d44b had no CHG).

## What changed
- **Pinned service crate** `nautilus-execution-service` (Cargo.toml, Cargo.lock, rust-toolchain.toml 1.97.1) with all 8 Nautilus crates pinned to `74d57e7e055015a8d974a0cf047ac2e5139610b3` (nautilus-core, -common, -live, -execution, -model, -event-store, -portfolio, -risk) matching versions.pin NAUTILUS_COMMIT.
- **Retired Python scaffold** moved to `legacy_python/` (Dockerfile, main.py, requirements.txt preserved with retirement note).
- **Gate fencing** `src/gate.rs` — only sanctioned state transitions, cannot skip steps or silently regress, safety-halt returns to HALTED from any state, boots into HALTED and cannot execute.
- **Bridge protocol** `src/bridge/protocol.rs` — CommandEnvelope validation matches Go bridge, ReportEnvelope outcome parses, OrderCommand JSON round-trip; `src/bridge/fake.rs` — fake broker place/timeout/rejection/UNKNOWN classification.
- **Custom ExecutionClient** `src/execution/client.rs` (`BridgeExecutionClient`) implements the audited `ExecutionClient` trait with `Rc<RefCell>` non-Send safety, start/stop/connect/disconnect lifecycle, submit/modify, fill/report handling, and gate-state access.

## What did NOT change (remains open per plan T4)
LiveNodeBuilder/ExecutionClientFactory compile probe, LiveNode runtime (OMS/risk/portfolio/reconciliation/event-store, no market-data client), health/telemetry/shutdown modules, clean shutdown/event-flush/fence-release/unresolved-attempt recovery, restart tests, formatting/clippy/locked build, and live Compose wiring all remain. The binary `src/main.rs` is a bootstrap stub that verifies `PROTOCOL_VERSION` loads.
