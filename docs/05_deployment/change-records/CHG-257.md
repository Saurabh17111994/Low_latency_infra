# CHG-257 — the infrastructure agents exist, so the collector's host and container scrapes work

## Why

The deployed collector scrapes four targets. Two of them had no service behind them:

```text
warn  internal/transaction.go:137  Failed to scrape Prometheus endpoint
  {"target_labels": "{__name__=\"up\", instance=\"node-exporter:9100\", job=\"infra-host\"}"}
warn  internal/transaction.go:137  Failed to scrape Prometheus endpoint
  {"target_labels": "{__name__=\"up\", instance=\"cadvisor:8080\", job=\"infra-containers\"}"}
```

The receiver, the `metrics/prometheus` pipeline and the OpenObserve remote-write were all in place
(`otel-collector-config.swarm.yaml` lines 88–96 target `flink-jobmanager:9249`,
`flink-taskmanager:9249`, `node-exporter:9100`, `cadvisor:8080`). The stack declared only the Flink
pair, so both infrastructure jobs failed every 15 seconds while the deploy stayed green. That is the
failure mode of a scrape target: it warns, it never fails a deploy, and the panels it feeds stay
empty — which is why it survived several rehearsals. It was found by reading the running collector's
log, not by a test, so the test came with the fix.

The development stack has had both services since 2026-08-22; the production stack never did.

## What changed

- **`code/01_platform/01_docker/docker-stack.yml`** — two services, ported from the compose
  definitions with the same host mounts, flags and `--path.*` arguments:
  - `node-exporter` (host CPU/memory/filesystem through `/proc:/host/proc`, `/sys:/host/sys`,
    `/:/rootfs` and `--path.rootfs=/rootfs`; without that flag the collectors read the container's
    overlay as if it were the VM — P5-026);
  - `cadvisor` (container cgroups through `/var/lib/docker`, `/sys`, `/var/run`, `/dev/disk`).
  Both are `mode: global`, both pin to `node.labels.observability == true` like the other three
  observability services, both carry a **self-probe** healthcheck (`wget` against `/-/healthy` and
  `/healthz` — measured 200 on the images), both set `update_config.failure_action: rollback`, and
  both take their image from `${NODE_EXPORTER_IMAGE:-<digest>}` / `${CADVISOR_IMAGE:-<digest>}` so a
  mirror can override them without editing the file.
- **Two compose keys are deliberately NOT in the stack.** `privileged: true` (cadvisor) and
  `pid: host` (node-exporter) are compose-only in practice: `docker stack deploy` accepts them,
  reports `rc=0`, and the task runs with `privileged=false` and an empty pid mode — measured on the
  deployed tasks. Keeping them would have been security theatre, so the file states the measurement
  instead.
- **`code/01_platform/01_docker/runtime.lock`** — `NODE_EXPORTER_IMAGE` and `CADVISOR_IMAGE` pins,
  with provenance: the digests are the manifest digests Docker recorded at pull time and both were
  re-verified with `docker pull <repo>@sha256:<digest>`.
- **`code/01_platform/04_scripts/tests/test_09_stack.py`** — new `TestCollectorScrapeTargets`:
  `test_every_scraped_host_is_a_stack_service` harvests every `targets:` entry and every exporter
  `endpoint` host from the collector config and requires it to be a service in the stack (skipping
  bind addresses and loopback), and
  `test_infra_agents_report_on_the_host_not_the_container` requires global mode, a digest pin, a
  restart policy, the host mounts and the `--path.rootfs` flag. `cadvisor` joins the
  command-allowed list with the measured reason (`Entrypoint [/usr/bin/cadvisor -logtostderr]`,
  `CMD null`), and both agents join `OBSERVABILITY`, which is the placement-enforcing list.
- **`docs/05_deployment/PROD_VM_PROVISIONING.md`** — S5 says five observability services instead of
  three; S8 says where host and container metrics come from and that both agents self-probe; the S7
  trap list gains the silent-scrape-target case and the dropped-compose-key case.
- **`docs/04_contracts/openobserve.md` is unchanged on purpose** — the contract already said what the
  single pane contains; the stack is what did not deliver it.

## Limitation

The agents run only on the node carrying `node.labels.observability == true`, which in production is
VM4 — the same node as the collector and OpenObserve. Host metrics therefore cover the observability
host, not VM1–VM3. That is the existing S5 design ("observability services never take workload
capacity"), not a property of this change; giving the trading nodes their own agents needs a second
label and a change to the S5 label recipe, and is recorded as an open decision rather than done here.
`pid: host` and `privileged` being dropped also means cAdvisor sees cgroup and mount statistics but
not raw block-device data — measured as "less data", not "no data" (recovery of every container
succeeded within a second).
