# CHG-304 — a smoke phase that aggregated nothing is no longer a pass; the harness decides the session state

- **Status:** recorded — fixed and guarded (2026-09-23)
- **Filed:** 2026-09-23
- **Source:** the T6.2 end-to-end re-measure of the Fluss 1.0 upgrade
  (`docs/plans/2026-09-22-fluss-1.0-upgrade.md`), aborted run
  `logs/tracker-14/holistic-measure-20260923-174053`.

## What happened

`make holistic` printed `SMOKE PASS — proceeding to main measurement` while the smoke phase had aggregated
**nothing**: `smoke/metrics-final.txt` recorded `multi-tf-aggregator | 2,256,782 | 0` and every candle sink
`0 | 0`, so `compute.candles.late.dropped` could not move and the next gate failed on its late half
(`want dups=200 late=20; got dups=200 late=0` — the dedup half was exact). The harness had reported a
*pass* over a pipeline that produced no candle: the smoke phase only asserted that the containers stayed
alive, never that the candle path did anything.

The cause was the session filter, not the pipeline. Off-hours, `TimeframeBucket.isInSession` (09:15:00.000
inclusive → 15:30:00.000 exclusive IST) drops every tick *before any state is mutated*. The late counter is
owned by the monotonic gate, which needs a **newer** event time already in that token's slot: an injected
90 s-late frame is that token's *first* tick, and a fresh slot takes no lateness branch, so the counter
stays flat. Nothing can aggregate, and the gate's late half can never move — by construction, for any run
started off-hours.

This is not a 1.0 difference. The 0.9.1-era run `logs/tracker-14/holistic-measure-20260919-010036`
(01:05 IST) has the identical shape: aggregator out=0, all candle sinks 0/0, the late series flat across
all 8 subtasks. The last green inject gate (CHG-194, run 11, 2026-09-17 11:04 IST) was in-session. All
three runs whose evidence is still on disk started off-hours (`main` phase never ran in any of them:
`main=0`).

`SignalJobConfig` declares the knob for exactly this state — `MULTITF_SESSION_BYPASS`, default `false`,
*"against the 15s fake-broker feed OUTSIDE market hours (weekend / after close) … The soak harness sets it
ONLY for the dedicated soak run"*. `stage-soak-e2e.sh` sets it. `holistic-measure.sh` never did, and
`pipeline-lib.sh` passes an exported value through, so the job always ran with the filter armed.

## What changed

- `code/01_platform/04_scripts/holistic-measure.sh` —
  (a) the harness now decides the session state itself. `ist_minutes_now` (via `TZ=Asia/Kolkata date +%H%M`,
  `10#` arithmetic, loud failure if the clock is unreadable) and `session_is_open` (555–929 IST minutes,
  the same boundaries as `TimeframeBucket`) feed a config-block decision that **exports
  `MULTITF_SESSION_BYPASS`** before the job is submitted: `false` in-session (the measurement stays
  production-faithful) and `true` off-hours with a loud notice. An operator-set value is preserved. The
  decision is printed and written to `$OUT/session.txt`.
  (b) `smoke_produced_output` rejects a smoke whose aggregator emitted nothing. It reads the
  `multi-tf-aggregator` row of `metrics-final.txt`, fails with a message naming the session filter when the
  out-count is ≤ 0, **skips** below a 120 s phase (a window may legitimately not have closed in the 60 s
  quick phase), and prints `UNAVAILABLE` — never a silent pass — when the snapshot or the row is missing.
  (c) the driver runs that gate before printing `SMOKE PASS`, and skips the main measurement (exit 1) if it
  fails, so an aggregation-free run can no longer produce a "green" record.
- `code/01_platform/04_scripts/tests/test_holistic_session_gate.py` (new) — pins the session boundaries
  (0/554/555/929/930/1439), the gate's four outcomes (0 → fail, 47420 → pass, 60 s → skip, no snapshot →
  UNAVAILABLE), and the wiring order that makes the bypass reach the submitted job at all.
- `Makefile`, `docs/commands/COMMANDS.md` — the off-hours behaviour and the new failure mode, where
  operators read them.

## Known limitation

- The gate reads a *snapshot*: `metrics-final.txt` is scraped, so a scrape gap prints `UNAVAILABLE` and
  does not fail (the inject gate still applies to that run). It is a floor, not a substitute for the
  existing gates.
- 120 s is a hard floor: the 60 s diagnostic phase (`make holistic-quick`) still skips the check.
- An off-hours bypass run proves the candle path is zero-loss **with the filter out of the way**. It is not
  a fidelity claim about production traffic in those hours, where the filter is what actually runs; the
  production-faithful pairing remains an in-session run.
