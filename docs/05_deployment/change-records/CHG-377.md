## Notes

- **Why the gate lives in the writer, not `ProjectionApplier`:** the applier's stripe is keyed on
  `postbackEventId`, while the DDL key discipline is the full `(account_scope_id, broker_order_id)`
  composite. The versioned read and the per-key stripe must share one key; the gate owns both.
- **Why a missing halt sink is loud, not fatal:** warm-up/prewarm writers and offline integration
  writers construct without a `GateStateStore`; a conflict there still refuses the write and
  quarantines, and logs SEVERE so the missing durable halt cannot pass unnoticed. Production
  (`GatewayStartup.openStores`) always wires the store.
- **Why the state vocabulary is mapped at the gate:** the sync ack's `normalizedState` comes from
  the bridge (`ACCEPTED`, `COMPLETE`, Arrow spellings) and is not the closed
  `OrderLifecycleState` set; feeding it raw to `parseState` would have turned every happy-path ack
  into UNKNOWN → quarantine + halt. The mapping is a pinned, fail-closed table.
- **STALE is a WARN, not an append:** the ack image carries no audit section, so the available
  durable evidence is the log line (both versions) plus the unchanged row; the projector's
  `Postback_Projection_Ledger` already records the attempted event.
- **The 503 distinction is tested as a function:** `GatewayHttpServer.projectionFailureStatus`
  walks the cause chain for the lookup marker; the HTTP reply uses its result, so the retryable /
  permanent split cannot silently regress.
