## What changed

- `remote.data.dir` is parameterized in the canonical compose:
  `${FLUSS_REMOTE_DATA_DIR:-s3://${R2_BUCKET:?set R2_BUCKET for tiering}/remote-data}`. The
  default is still the shared R2 URI (PROD-013); the dev `.env` sets
  `FLUSS_REMOTE_DATA_DIR=/tmp/fluss-remote-data` because tiering is off there (nested compose
  interpolation verified with `docker compose config`).
- Both tiering lanes set the R2 URI inside their own recreate window (and restore it via their
  traps): `tiering-1.0-verify.sh`, `tiering-remote-read-verify.sh`. The read-verify lane also
  resolves the parameterized form in its prefix derivation, and both lanes hard-check the
  effective tablet config before their measurement phases.
- `tiering-remote-read-verify.sh` no longer leaks `rr_settle_*` tables: the settle loop drops
  `IF EXISTS` **first** (a failed DROP used to block every later CREATE on the same name), drops
  once after readiness, and the trap drops it defensively (5 leftovers had accumulated).
- `B4HaltedIntentConsumeDeferE2ETest` sweeps older `b4_halted_*` keeps at the end of each run, so
  at most this run's keep survives; the 2026-09-18 keep was dropped one time with operator
  approval (its writer JVM died that day).

## Why it is safe

- Local is only selected by the dev `.env`; a fresh/unconfigured environment still renders the R2
  URI, and the tiering lanes restore it for their windows. The gate preflight fails closed when a
  remote URI is live while tiering is off (CHG-313).
- With tiering off, nothing writes to the remote dir on this stack (`remote.log.task-interval`
  `0s`, KV snapshot interval `0s`), so a container-local path only changes the cost of the
  deletion probe.
- The B4 sweep drops only *older* `b4_halted_*` databases after this run's keep/drop decision; the
  only writer that can hold a pending batch belongs to this run (the 2026-09-18 Sender storm).
