# CHG-139 — The observability and ownership helpers stop publishing promises they do not keep

- **Status:** recorded — twelve findings fixed in code, one wording conflict recorded as open, one
  behavioural semantics change with no production caller, two doc claims corrected
- **Filed:** 2026-09-14
- **Source:** P6 ops/scripts/tests/chaos audit, wave 2 ("Logging, ownership and alert surfaces"):
  P6-274, P6-275, P6-276, P6-277, P6-278, P6-279, P6-280, P6-666, P6-667, P6-668, P6-669, P6-670,
  P6-671, P6-672, P6-673, P6-855

## What happened

Every finding was re-verified against the code before anything was edited. All sixteen were real;
where a finding's ask could only be met by inventing a number, the row now names its source instead
and the gap is recorded below.

**Redaction (`AuditLogger`)** — `P6-274` `REDACTED_FIELDS` held the concrete names
(`broker_order_id_secret`, `auth_token`, `api_key`, ...), which normalize to `authtoken`/`apikey`
under the containment check, so a field named exactly `token`, `key`, `clientToken` or `accessKey`
matched nothing and leaked verbatim. The set is now the generic roots the contract spellings
contain (`secret`, `token`, `key`, `password`); near-misses are deliberately over-redacted
(`monkey` contains `key`) rather than risking a missed credential. `P6-275` a null field name
returned the value unredacted — mandatory redaction now fails closed. `P6-668` the token
normalization ran per call; the pattern and the normalized set are computed once at class init.

**JSON (`Json`)** — `P6-276` the builder could not serialize nested containers at all: `obj(...)` /
`arr(...)` took no key, so nesting inside an object emitted `{"a":"1",{"b":"2"}}`, and the regression
test asserted that invalid document as the expected output. Object members are now keyed, array
elements are unkeyed, the builder tracks its container kind and rejects the mixed usage instead of
serializing it; the test parses the result with Jackson (already a test dependency). `P6-669` a null
key serialized as `""`; null and blank keys now throw.

**Log events and correlation (`StructuredLogEvent`, `StructuredLogger`)** — `P6-277` the contract
(`04_contracts/openobserve.md` §F) lists 12 required fields including `timestamp`, but `build()` only
checked the 11 String fields: `timestampMs = 0` built happily and emitted `timeUnixNano "0"`.
`P6-278` `withContext(null, ...)` threw a raw NPE, and a context entry with a null key or value
threw from `MDC.put` after part of the context was applied; the action and every entry are now
validated before the MDC is touched. `P6-670` `correlationId()` stringified null parts to the
literal `null` and accepted a part containing `/`, which makes the slash-joined id unsplittable;
every part must now be non-blank and slash-free.

**Ownership (`OwnershipMatrix`)** — `P6-279` `Rule` stored the caller's sets by reference (two rows
are built from mutable `EnumSet`s) and exposed them as public mutable fields, so a rule's builder
kept a handle on global enforcement; rules now validate their inputs and hold immutable copies.
`P6-280`/`P6-672` `canWrite` treated `soleOwner == null` as "anyone may write" and let a null actor
through, and both helpers dereferenced the rule and its sets unchecked; a null rule or actor now
denies (an enforcement path answers "no", it does not throw) and the open "Authorized components"
row denies — the new `isOpenOwnerRow` marks it so the caller applies its own authorization.
`P6-673` `logRule` granted read to all eleven components, prohibited nobody and relied on mutable
sets; it is now least-privilege (owner writes, `PLATFORM_HEALTH` and `STORAGE` read, every other
component is a prohibited writer) and validates its inputs. No production caller is affected: the
foundation doc records runtime consultation of the matrix as pending.

**Alert thresholds (`AlertThresholds`)** — `P6-666` the percentages existed only inside the
condition prose, so `"container_memory_pct >= 85"`, `JvmHeapReadinessGate.DEFAULT_BLOCK_AT_PERCENT`
(85) and `IngestionConfig.WARNING_PERCENT` (0.80) were three independent literals. The numbers are
named constants now, the condition text is built from them, and both consumers read them (module
direction `ingestion → common`, no new edge). `P6-667` every open-ended row names the value it is
implemented against. `P6-855` the javadoc promised that each alert fires after the
consecutive-breach window; the file holds the bound and debounces nothing, so the javadoc now names
the enforcers (the gate reads the constant, each provisioned rule carries its own `for 60s`), and
the two doc claims that said the same thing were corrected the same way.

## Judgement calls (review these)

* **No number was invented.** `MISSING_FILL`'s SLA is not pinned in the docs and `STALE_SIGNAL`'s
  numeric threshold is evidence-gated by DEC-028; both rows record that instead of a made-up value.
* **`CHECKPOINT_DURATION` has three boundaries** — the enum says `> timeout`, the 10-observability
  table says `p99 > 5 s`, the runbook says 80% of the pinned timeout (24 s). The conflict is now
  written into the javadoc as open; picking one is a requirements call, not a code cleanup.
* **`CHECKPOINT_FAILURE_RATE`'s published condition text changed** from
  `"checkpoint failure rate above threshold"` to `"any checkpoint failure"` so it matches the doc row
  ("Any checkpoint fails", critical, safety-halt request). The enum constant name is unchanged, so
  `alert.name` is stable. Nothing in the repo consumes `alert.condition`.
* **`canWrite` on the open row flipped from allow to deny.** The doc's "Authorized components" wording
  is a deferral, not an authorization this class can perform. Only tests called it.
* **`P6-671` doc-vs-code deviation is now reconciled in the doc row itself** (prohibited column:
  `Signal, Babysitter`), because the doc's `Signal, Executor` would prohibit the sole owner. If a
  governance-level sign-off is wanted, this needs a DEC row — a change record is not a decision.
