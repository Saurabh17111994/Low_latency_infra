## Notes

- **Why the old code never pruned:** `maybeCompactEmittedIds` matched `ruleId + "|"`, but
  `candidateIdFor` returns `UUID.nameUUIDFromBytes(rule|token|tf|windowStart|side)` — a plain
  UUID. No key ever matched, the count loop never broke, and the "fast path" was a full scan of
  the subtask map on every emission.
- **Why per-rule maps:** a single map mixes every rule's ids, so pruning one rule required
  scanning all of them. One map per rule makes the scan proportional to that rule's horizon and
  keeps the legacy map frozen as the pre-upgrade record.
- **The tests pinned the bug:** the old fixture emitted `rule|token|tf|seq` (pipe-shaped), which
  the retired compaction *did* match — the suite certified a code path real ids never took.
