## 1. `io-latency-probe.sh` — 11 findings

The probe runs `iostat -dx` under a `python3` parser and writes a TSV + JSONL pair of
"evidence". Nine of these findings are ways it produced evidence that was empty, wrong or
unobtainable while looking healthy:

| Finding | Was | Now |
|---|---|---|
| P6-119 | the device filter ran per row, so the documented "no match keeps ALL devices" fallback was unreachable — a renamed NVMe dropped every row and the run exited 4 with empty evidence | rows are held until an interval has reported its devices, then the filter is decided once; an empty filter keeps everything and still warns |
| P6-120 / P6-434 | `proc.wait(timeout=10)` in the `finally` block raised `TimeoutExpired` unhandled: the exception escaped, bash saw exit 1, the "evidence DEGRADED" verdict was never printed, and the hung `iostat` stayed alive | the wait is guarded, kills the child, and falls back to `rc=-9` when it cannot be killed |
| P6-429 | `DURATION_S` was never validated: `120s` evaluates to 0 in bash arithmetic (`SAMPLES=2`) and produced a silent two-sample "success" | validated before any side effect; exit 2 for bad caller input |
| P6-430 | `stderr=PIPE` was never drained, so 64KiB of iostat warnings could block the child forever | `stderr=DEVNULL` |
| P6-431 | the avg-cpu block was neither staged nor consumed per interval, so an interval without one made its rows inherit the previous interval's percentages | the block is staged and consumed once, at the interval's `Device` header |
| P6-432 | malformed rows were dropped silently | counted, the first three warned inline, and the total reported at the end |
| P6-433 | `_host_stats()` and `time.time()` ran per device row, so rows of one 2s sample disagreed on epoch and host stats | both are read once per interval |
| P6-749 | `mkdir` failure was ignored (no `set -e`): python then died with a traceback and exit 1 instead of the documented exit 4 | the stages dir and both redirects are guarded |
| P6-750 | `cpu_nice_pct` reached the JSONL but had no TSV column, so the two outputs disagreed on the cpu breakdown | the column is in both, and a test pins their agreement |
| P6-751 | the best-effort O2 push was unbounded: a hung `o2_ingest.py` blocked teardown after the evidence was already on disk | pushed under `timeout "$O2_PUSH_TIMEOUT_SEC"` |

Two further bugs were found by the new tests, not by reading: the filter was decided at a
capture's **first** `Device` header (before any row, so always "keep everything"), and the
avg-cpu reset only covered a malformed numeric line, not an absent block.

Seams added for testability: `IO_PROBE_STAGES_DIR`, `IOSTAT_WAIT_SEC` (default 10) and
`O2_PUSH_TIMEOUT_SEC` (default 60), normalised so a typo cannot become a traceback. Exit
codes are documented in the header: 0 = samples written (the O2 push may warn), 2 = bad
argument, 3 = `iostat` absent, 4 = degraded evidence or unwritable stages dir.

## 2. `prod_node_check.py` — 3 findings

- **P6-153 (HIGH):** the D1.2 gate ran `docker node ls` and `docker node inspect` on every
  node itself. Both are manager-only API calls; a worker answers with "This node is not a
  swarm manager", so **every worker FAILed on healthy infrastructure**. Identity now comes
  from `docker info --format '{{.Name}}|{{.Swarm.LocalNodeState}}|{{.Swarm.ControlAvailable}}|{{.Swarm.NodeID}}'`
  (any daemon answers it) and the node object is read on a manager, addressed by that
  NodeID; a manager reads its own. A worker with no manager in the inventory fails closed
  with that reason.
- **P6-764:** membership was matched against the inventory's `host` (an IP) or `name`
  (M1/W1) — neither is the swarm hostname, so a correctly joined node whose swarm hostname
  differs was reported "absent from swarm membership". Matching is by NodeID now, and the
  verdict names the swarm hostname and NodeID it inspected.
- **P6-763:** dropped the unused `socket`/`tempfile` imports; the docstring and the
  evidence `limitations` entry now describe the manager-mediated read.

`--self-check` resolves the manager the same way. Without that it demonstrated the wrong
failure ("no manager") while still exiting 0 — caught by a test that now asserts W1 fails
for the **label drift** it exists to illustrate.

## 3. `image_staleness_check.py` — 4 live findings + 2 closed by evidence

- **P6-109:** `dirty` was checked before the stamps, so any uncommitted edit returned
  DIRTY-WARN and masked what the stamp already knew — a genuinely STALE image, and even a
  MISSING one. Content now decides before the clock, and DIRTY-WARN is only the caveat on
  the timestamp proxy.
- **P6-413:** NO-HISTORY printed `[FAIL]` but was not counted, so the check printed a
  failure and **exited 0**. Failing statuses are one named tuple (`FAILING_STATUSES`) used
  by the accounting, and an AST test requires every status `verdict()` can return to be
  either FRESH/DIRTY-WARN or in that tuple.
- **P6-412:** the unparseable-`Created` fallback (`raw.split(".")[0]`) dropped the fraction
  and the timezone, so a fraction-less `...Z` timestamp — the shape Python <3.11 cannot
  parse — raised an uncaught `ValueError` and crashed the check. `_parse_docker_created`
  normalises `Z` to `+00:00`, trims the fraction to 6 digits keeping any offset, and returns
  None otherwise (a None `Created` is already a handled verdict).
- **P6-744:** `have_git_history` promised "every path exists and at least one has history"
  while its body returned on the first existing path. Renamed `any_source_path_exists`.
- **New GIT-ERROR:** a repository present but unreadable (corrupt `.git`, dubious ownership,
  no git binary) made every epoch None and `worktree_dirty` silently report "clean", which
  the check could only describe as NO-HISTORY. `.git` present + git refusing = GIT-ERROR
  (fail); no `.git` at all = an unpacked release tree, which keeps the NO-HISTORY path.
- **P6-414 (compose half):** an unlisted build service was checked against the compose
  context+dockerfile, which cannot see a Dockerfile's COPY list, so a service copying
  something else looked unchanged forever. It now reports UNDECLARED-SOURCES and points at
  `SERVICE_SOURCES`. All eight services in the compose file are declared (`ddl-apply` and
  `eod-controller` via `_platform_sources()`), so the gate step and `make images` behave
  exactly as before — verified by running both.

**Closed with evidence, no fix needed here:**

- **P6-415** was already fixed by `be8c1562` ("fix(gate): inspect the image compose actually
  builds, not a derived name"): `build_services` captures the declared `image:` and
  `image_ref()` prefers it. Three tests pin it (`test_declared_image_wins_over_derived_default`,
  `test_build_services_captures_declared_image`, `test_derived_default_when_no_declaration`).
- **P6-414's loadgen half** was already fixed by CHG-122 (2026-09-02); the `SERVICE_SOURCES`
  entry carries that provenance in a comment.

## Judgement calls recorded

1. **DIRTY-WARN is now strictly a timestamp-proxy caveat.** The alternative (fail the gate on
   any uncommitted edit) would make the gate unusable during development; the chosen rule is
   that the *stamp* answers the question when both sides have one, and the dirty warning
   covers the case where the clock is the only evidence.
2. **UNDECLARED-SOURCES fails closed on a missing declaration**, rather than warning. A
   declaration is a one-line, reviewable statement of a build's inputs; a silent verdict
   computed from inputs nobody verified is what P6-414 was about.
3. **GIT-ERROR keys off the `.git` entry, not git's message.** Git collapses every on-disk
   breakage (bad HEAD, unreadable objects, permission loss) into the same "not a git
   repository" text, so the message cannot distinguish a damaged checkout from a tarball —
   measured on this host before choosing the discriminator.
4. **The worker's node object is read on a manager, not fetched by the worker.** There is no
   worker-side API for role/availability/labels; the alternative (have the worker `ssh` to a
   manager itself) would move credentials and a second SSH hop into every node.
5. **`--self-check` resolves the manager too.** The first patch left it out, and the
   self-check passed while demonstrating "no manager" instead of the label drift it exists
   to illustrate. It was fixed in the same file, and a test now pins the drift reason.
6. **`IOSTAT_WAIT_SEC` / `O2_PUSH_TIMEOUT_SEC` seams, defaulted.** The teardown paths cannot
   otherwise be tested without waiting 10-60s per case; both are normalised so a typo cannot
   become a traceback.
7. **No shared probe helper between `show-ticks.sh` and `smoke-test.sh` (W23) or between
   these three host checkers (W24).** They disagree about interfaces, exit codes and
   preconditions; a shared "host probe" abstraction would have to be parameterised back into
   three copies.
