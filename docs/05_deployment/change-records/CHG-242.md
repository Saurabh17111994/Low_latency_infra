## Deviations from the audit's fix text

1. **P6-616 is docstring-only.** The audit offered "skip when docker is unavailable" or
   "correct the claim". Skipping would hide a real precondition *and* erase an
   inconsistency worth recording: the harness documents `exit 2 = BLOCKED (docker
   missing)` but its offline path reports `FAIL` = exit 1 (observation 1).
2. **P6-833 gained two cases beyond the audit's list** (divergence, empty-string
   `FLUSS_BOOTSTRAP`). Same untested-gate class, same block, four lines. Approved by the
   wave owner.
3. **P6-239's premise is narrower than stated.** The gate already bounds the file with
   `timeout 300` (run-monday-gates.sh:674), so it cannot hang forever; the defect is a
   five-minute blob instead of a named case. Also recorded: this file has **no `make`
   target** — it runs only in gate step 3b.
4. **P6-622's optional half was taken**: one case asserts the stream contract.
5. **The audit's `${@-}` remedy is wrong and was not used.** Measured: `"${@-}"` expands
   to **one empty argument** when called with no args (so `env` would receive an empty
   assignment), and it trips shellcheck's SC2068. `${@+"$@"}` expands to zero words and
   is shellcheck-clean, so that is what the suite uses.
6. **P6-831's premise is narrower than stated**: the entrypoint is already mode 0755 in
   git, so the `chmod` was a no-op here. It is still wrong on read-only mounts and in
   `core.fileMode=false` checkouts, so the fix stands.
7. **Two new env overrides** (`ENTRYPOINT`, `ENTRYPOINT_TIMEOUT`) exist so the guard
   module below can run the suite against fake entrypoints. Defaults are unchanged.

## Observations recorded, not fixed

1. `t9_order_sandbox.py` documents `exit 2 = BLOCKED (docker/daemon/stack missing)` but
   its `--offline` leg turns a missing docker into a reported FAIL (exit 1). One of the
   two is wrong; the fix belongs with the harness, not with this test wave.
2. Case 2b prints "skip" and continues when running as root (root bypasses `-r`). It is
   a printed line, not a unittest skip, so it does not enter the gate's skip inventory —
   deliberate, but worth knowing: a root-only CI would not exercise that branch.
3. The entrypoint suite's exit codes/messages are pinned; the *ordering* of the gates is
   documented in the header but only implicitly tested (each case satisfies the earlier
   guards). A gate moved above another would be caught only where messages differ.
