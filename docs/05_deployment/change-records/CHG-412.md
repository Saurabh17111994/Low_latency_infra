## Notes

- **Why a fixture:** the mock's dialect was unbound — no in-repo consumer read it and the test
  pinned the old keys, so a drift in either direction was invisible. The fixture is the single
  artifact both sides meet on: the Java test compares the live socket output to it, and the Go
  test proves it decodes into the same `Tick` the real feeds decode into.
- **`received_ms` deliberately absent:** it is a proto `TickEvent` field but not a Go `Tick` JSON
  tag — it is the *receiver's* T1 receipt time, which a fake broker cannot honestly fabricate.
  Including it would make the strict decode fail, so the fixture carries the Go-decodable subset
  (and the Python pin enforces both subset relations).
- **Values are plausible, not fixed:** the Go test checks presence/shape (core fields non-zero,
  five-element ladders), never a price — the mock randomizes within bands by design.
- **Framing untouched:** R-039/R-040 (raw TCP, one object per line, never an array) and R-071
  pacing stay exactly as they were; only the key names changed.
