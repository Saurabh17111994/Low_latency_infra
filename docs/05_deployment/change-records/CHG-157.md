## What happened

`digest-pin.sh` normalised (refuse pinned/untagged), measured (docker→skopeo→crane),
then reported (`img@digest`) — and at each step a wrong answer could pass as pinned.

**Untagged refs passed validation (`P6-064/P6-065`).** The `*:*` tag check matched the
registry-port colon, so `registry:5000/repo` pinned as `registry:5000/repo@sha256:…`
without a `:tag`. Only the name after the last `/` is checked now (`*:?*`, which also
rejects empty `repo:` tags).

**Warnings became digests (`P6-062/P6-066`).** Every resolver merged `2>&1` into the
digest variable, so one auth/platform notice on stderr turned a success into a false
hard failure at the defensive regex. Stdout goes to `digest`, stderr to a mktemp file
(removed after); failures report the captured stderr instead of a generic message.

**Human output was parsed as data (`P6-063/P6-067`).** The `Digest:`-line sed + `head -1`
could pin a per-platform digest instead of the multi-arch index digest. Deleted: any
non-`^sha256:64hex$` resolver output resets to empty and falls through.

**Malformed output never fell through (`P6-353/P6-356`).** The skopeo/crane gates tested
only `-z`, so non-empty garbage failed hard at the final regex. Every resolver output
is validated and reset, so the chain is genuinely tried in order.

**Refs parsed as flags (`P6-354/355/357/358`).** `crane digest "$img"` had no `--`;
`--format` rode after the image on docker/skopeo. All three resolvers now take options
first with `--` before the ref (a dash-led ref additionally dies earlier in
`validate_ref`, which demands a `:tag`).

`pin-check.sh` had the mirror defects on the verification side. **Versions
(`P6-138`):** `[^=]+$` blessed `*`, `^`, ranges, whitespace-only and `latest`-suffixed
values, and a missing file fell into a confusing grep error. Strict SemVer pins now
(`MAJOR.MINOR.PATCH` + optional `-`/​`+`/​`.` qualifier — the dot-only first attempt
wrongly rejected the repo's own `0.9.1-incubating`, caught by running the gate on the
real tree pre-commit), with explicit placeholder/range/SNAPSHOT/whitespace bans and a
missing-file FAIL. **Lock lines (`P6-139`):** `^[A-Z0-9_]+_IMAGE=` silently skipped
indented/`export`/spaced shapes from BOTH counts; a `norm()` sed normalises before both
greps. Case stays UPPER by decision: shell vars are case-sensitive and no consumer reads
a lowercase `_image` — counting it would bless a dead ref. **Digests (`P6-140`):**
`{12,64}` blessed mutable 12-hex local image-IDs; exactly 64 now — which the real
`runtime.lock` FAILS (four local-build short IDs), the intended gate behaviour, not a
regression. **Counting (`P6-141`):** `grep -c` without `|| true` aborted under `set -e`
on zero matches, and `OK: 0` would vacuous-pass; zero refs is now an explicit FAIL.
**P6-761 is stale:** the script already says Six checks with `[1/6]`–`[6/6]` everywhere;
pinned by test, no edit.

## Judgement calls

1. **DRAFT duplicates fixed once.** Six DRAFT-worded findings restate six saved ones;
   one code change each, all 17 ticked. No double-patching.
2. **P6-140 knowingly turns the gate red on the current tree** (four short-ID local
   builds). Mutable local IDs must fail until re-pinned — that is the finding's demand,
   not collateral. Re-pinning needs real `docker images` IDs from a built tree: separate
   task, not this wave.
3. **P6-139 ships normalisation, not case-insensitivity** (the finding's "and/or").
   Rationale above; documented in the script comment.
4. **R-223's index-Digest extraction deleted, not repaired.** Any human-format parse is
   the defect P6-063 names; multi-arch indexes now resolve via skopeo/crane raw digests.
5. **Two test bugs of mine, fixed pre-commit:** (a) static pins matched their own
   finding comments — pins now scan non-comment lines only; (b) lowercase-var fixtures
   asserted behaviour the fix deliberately does not have — fixtures use real shapes.
6. **Unrelated red fixed as its own commit (never bundled):** the full-suite rerun exposed
   `CleanupTest.test_cleanup_kills_children…` as flaky (~50% one-shot on a loaded box).
   Root-caused by isolation (60-case A/B: no-suite 60/60 clean, suite-sourced flaky through
   the byte-identical kill loop — scheduling latency, not code shape): `cleanup()`'s plain
   `kill` (SIGTERM) leaves children visibly ALIVE until the box schedules them, and the
   one-shot `ps` probe then reported STILL_RUNNING. Fix: `cleanup()` now does TERM → 0.5s
   grace poll → KILL, matching the TERM→KILL shape stages 2/3 already use (P6-178/183); no
   `wait` (the EXIT-trap shell exits right after cleanup so zombies are impossible, and
   `wait` on these pids hung 24/30 probes under the test's piped stdio). Probe hardened to
   count only `ps`-observed states (`CHILD_GONE`, no substring clash with `AUTH_GONE`):
   15/15 + 8×3/3 green, full suite 757 OK. Red run: the committed one-shot probe against the ORIGINAL `cleanup()` fails 10/12 (`STILL_RUNNING`) — the probe is discriminating, the fix is what makes it pass. Production behaviour on abort is unchanged
   except children are actually dead before the SUMMARY is written — the guarantee P6-178
   already promised.
7. **My own strict-version first attempt rejected the repo's pinned FLUSS_VERSION**
   (dot-only qualifier vs SemVer dash) — found by running the modified gate on the real
   tree before committing, fixed to `[-+.]`.
