# CHG-132 — Release gate: pin discipline, image build, mock-arrow suite (16 → 19 steps)

- **Status:** recorded — CI/release-gate shape changed; the certificate now covers three more things
- **Filed:** 2026-09-14
- **Source:** wave-4 close, open decision items 2, 3 and 6 (approved by the operator 2026-09-14)

## What changed

Three steps joined the certifying run of `code/01_platform/04_scripts/run-monday-gates.sh`
(`GATE_TOTAL` 16 → 18 → 19; the script's own banner-count check enforces the label/selection
agreement, so a missed renumbering fails the gate rather than passing quietly):

- **Step 17 — pin discipline.** `make pin-check` already ran in `gate-fast` (P3-418) but not in the
  certifying run, so a release certificate could be minted over a floating toolchain, corpus
  revision, base image or action tag — a change that alters what "green" means without touching a
  line of the tree. The step also refuses a run whose log does not contain `pin-check: PASS`, since
  `make` can exit 0 with nothing verified.
- **Step 18 — compose images built and stamped (all 8).** Until this step existed the certificate
  only checked the single service image the gate starts (step 8). A broken *image* therefore could
  not fail a gate: the missing `rstest` dependency in the executor image (E0463, 2026-09-13) was
  invisible until someone built that image by hand. The step runs `make images` (which refuses to
  build without a computed content stamp and re-checks `--require-stamps`) and then
  `make check-image-stale` over every image, and skips — never passes — when docker/compose is
  absent. Runs last: no earlier step may depend on a freshly built image, and an image failure must
  not mask a suite failure.
- **Step 19 — mock-arrow module suite.** `code/02_services/05_mock_arrow` is not in the `code/pom.xml`
  reactor, so its 7 tests ran only once, by hand, during wave-4 batch B3. The mock broker is the
  offline slice other suites depend on, so a broken mock now fails the gate.

Step 18 also removes a self-inflicted condition: the gate used to leave images unstamped, so a
release check would report `NO-STAMP` for images the gate itself had just exercised.
