## Why (measured)

- Failing run `logs/soak/monday-gates-20261001-164839`: step 15 `FAILED`,
  `nautilus-suite.log:851` `panicked ... AddrInUse ... transport.rs:1255`, and
  `test result: FAILED. 386 passed; 1 failed`.
- The holder was not our stack: `ss -ltnp` showed pid 2227213
  (`billion-context` node server, started 11:24) on 127.0.0.1:18787.
- Every other bind in the crate uses `127.0.0.1:0`; only these two tests used
  fixed ports, so the gate depended on the dev machine's port allocation.

## What changed

| piece | change |
|---|---|
| `bridge/transport.rs` | `serve_bridge` returns `(JoinHandle, SocketAddr)` (bound address from `listener.local_addr()`); both round-trip tests use `127.0.0.1:0` and connect to `http://{addr}` |
| `tests/test_executor_fixed_ports.py` | offline guard: no `TcpListener::bind`/`serve_bridge` literal may use a non-zero loopback port in the executor sources |

## What did not change

- No runtime behavior, no compose/stack file, no gate step, no retry/timeout
  semantics of the tests.
