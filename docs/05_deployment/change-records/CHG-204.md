# CHG-204 — flink-properties validator: duplicate keys fail, missing block reports clean (W37 slice 3)

- **Status:** recorded — fixed and guarded (2026-09-17)
- **Filed:** 2026-09-17
- **Source:** Wave 37 audit (`p6-ops-scripts-tests-chaos-audit.md` §10):
  P6-347 (MED), P6-722 (LOW) on
  `code/01_platform/04_scripts/check_flink_properties.py`.

## What happened

- Duplicate keys inside FLINK_PROPERTIES were not detected: the entrypoint
  merges last-wins, silently discarding the earlier value — the same
  silent-drop class as the prefix collisions this guard exists to catch —
  yet the validator passed.
- If the block regex ever failed (block moved last before EOF, following
  key re-indented), `extract_block` raised ValueError and `main()` died
  with an unhandled traceback instead of the tool's `FAIL:` + exit 1.

## What changed

- `code/01_platform/04_scripts/check_flink_properties.py` — check E:
  any key appearing 2+x fails with DUPLICATE KEY + why/fix; `main()`
  catches ValueError → `FAIL: ...` + exit 1; `main()` now calls
  `check(COMPOSE)` explicitly (was an implicit def-time default, which
  also makes the path patchable in tests); docstring lists E.
- `code/01_platform/04_scripts/tests/test_check_flink_properties.py` —
  `test_duplicate_key_fails` + `test_main_reports_missing_block_gracefully`
  (monkeypatched COMPOSE, capsys asserts FAIL on stderr, no raise).
