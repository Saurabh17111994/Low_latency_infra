## Why the fake feed mattered

Candle volume sums `volume_delta`, and the delta is only knowable against a
monotonic counter. The tracker already treats a backwards counter as unknown
(NULL) — correct for real feeds, but with the old fake frames most deltas were
NULL and the rest random, so a dev run could not show truthful candle volume or
exercise the `tick_type = TRADE only when volume_delta > 0` rule. Dev runs on
`ARROW_FEED=token` against the faketool, so the Q3(a) turn-on would have been
proven on wrong volume semantics.
