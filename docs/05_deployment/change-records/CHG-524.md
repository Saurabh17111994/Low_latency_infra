## What changed

- Current-layout counts: `44-column market section` → `51-column` and
  `42 values` → `49 values` in `MarketView` (class javadoc),
  `MultiTimeframeState`, `MultiTimeframeAggregateFunction` (MKT-row field,
  emit comment, `writeMarketSection`, `buildMarketRow`,
  `updateMarketSnapshot`), `StrategyHostFunction.decodeMarketSnapshot`,
  `SignalStrategy.onMarketUpdate`.
- `LiveSideOutputSerializationTest` assertion message `60-field market
  section` → the full `CandleLiveColumns` arity (67);
  `MultiTimeframeMarketSnapshotTest` `@DisplayName` 42 → 49 values.
- Dossier `docs/08_implementation/04-signal-job.md`: the snapshot paragraph
  (49 raw values, now naming the 7 CHG-516 extras), the canonical-row
  transport (`51 BIGINT NULL columns: 49 values + 2 clocks`), the 49 named
  `MarketView` getters, the test list (49 values, exhaustive 51-column
  decode, full `FIELD_COUNT` arity) and the flag table row
  (`STRATEGY_MARKET_TICK_ENABLED`: 49-value snapshot / 51-column section).
- Base-vs-extra wording where the count is historical: `FeatureRegistry`
  (42 base values; per-line helper no longer names a total),
  `RawTableColumns` (42 base values, extras cross-referenced) and
  `SignalAuditJson` (the audit carries the 42 base values; the seven
  CHG-516 extras are feature-only and deliberately not in the audit
  document — recorded so "complete" cannot be read back).

## Why

- CHG-516 appended 7 raw values after the two clocks specifically so every
  pre-CHG-516 index kept its meaning; the comments were not re-derived, so a
  reader could size the row wrong (the restore/market-section reasoning in
  particular depends on arity: a short row is pre-market-section data, not a
  truncated live row).
- The audit paragraph was the one place where "complete" was stronger than
  the code: `SignalAuditJson` never carried the extras. Corrected to name
  the 42 base values, leaving an audit-extension decision explicit rather
  than implied.
