## What changed

| Piece | Change |
|---|---|
| Gate check | `run_live` now reads `GET /healthz` (in-network) first: a non-`ENABLED` gate is refused with exit 3 (`LIVE-CHAIN-UNWIRED`, "approve first") **before** any envelope is signed or sent; the `gate_epoch` is read from the same response instead of hard-coded 0 |
| Fresh identity | Place uses a per-run `instruction_id` + `request_hash` (a re-used identity is answered from the durable attempt record, and same-instruction-different-payload is a contract violation — never a second order); cancel uses a **distinct** instruction id for the same reason |
| Poll | After a 202 the harness polls `Execution_Attempts` + `Order_Lifecycle` log-ends with the maintained `FlussReadLagProbe` (same host pattern as `day_run.py`: classpath from the ingestion target, `localhost:9123`), bounded to 30 s; `Fills`/`Positions` are reported optionally |
| Cancel + evidence | A 202 cancel ack is required; PASS writes `live-<run>-t9-order-sandbox.json` under `--out` |
| Classification | 202 = executed (bridge report parsed for `broker_order_id`); 503 with the gate `ENABLED` = FAIL (bridge UNKNOWN); 503 HALTED = exit 3; unreadable required table = BLOCKED (exit 2) |

## Why

The harness is the operator tool for both the paper drill and the funded sandbox
session; a stale classifier would have declared a successful paper order
"unwired" and blocked the hop workstream with a false negative. The offline
contract (t8 reuse, DDL poll columns, JVM signing parity, control envelopes)
is unchanged.
