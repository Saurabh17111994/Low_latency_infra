# CHG-232 — the Swarm runbook stops documenting an auth path the JVM rejects

- **Status:** recorded — fixed (2026-09-19)
- **Filed:** 2026-09-19
- **Source:** verifying the wave-41 landing (`8547b847`). The same `ARROW_TOKEN`
  reference W41 removed from the launcher and the smoke helper was still present
  in the deployment runbook.

## What was found

`docs/05_deployment/06-swarm-secrets.md` documented `ARROW_TOKEN` as a live auth
path in five places: the secrets table ("Go bridge (pre-generated token)"), the
`docker secret create` list, the ingestion service's `secrets:` list, the stack's
`external: true` block, and the entrypoint export. It also stated that a present
token "is used directly; otherwise autologin (...) is attempted".

Since 2026-08-24 (commit `96c0b186`) that is false: `IngestionConfig` rejects a
non-blank `ARROW_TOKEN` outright and `validate()` throws `IllegalStateException`
on any violation, so an operator following this runbook creates a secret whose
export fails ingestion before it connects. No tracked stack file declares the
secret either (`code/01_platform/01_docker/*.yml` has no `arrow_token`), so the
runbook was the last remaining source of the stale instruction.

## What changed

The five references and the token-first sentence are gone; the TOTP trio stays
documented, and the note now states the rejection so the runbook matches the
enforced contract.
