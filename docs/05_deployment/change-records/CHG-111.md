## What landed

Two environment fixes to the soak/bench load path (docker-compose.soak.yml),
both discovered by the PERF-AUDIT-001 smoke test on 2026-08-26:

1. **`ARROW_FAKE_BROKER: "1"`** — the bridge has a test-only fake-broker auth
   mode (`main.go isFakeBrokerMode`): skip AutoLogin, use a fake token, so
   bridge lifecycle tests/benches can run against faketool without hitting the
   real login API. It was set nowhere in the soak stack, so the bridge always
   ran the real AutoLogin path even against the fake broker → dummy creds →
   HTTP 400 `user not found` → bridge crash (exit 2) → 0 ticks.
2. **`OTEL_EXPORTER_OTLP_ENDPOINT: http://localhost:4318`** — the OTel
   javaagent's default protocol is `http/protobuf` (HTTP), so the endpoint
   MUST be the collector's HTTP port **4318**, not the gRPC port **4317**.
   Pointing HTTP at gRPC returns binary framing → OkHttp
   `EOFException: \n not found` → the agent exporter spins forever → the JVM
   reader loop never processes the bridge's NDJSON ticks → 0 appends (199x
   EOFException observed). The earlier `localhost:4317` value was introduced
   as an UnknownHostException fix for the host-network container but picked
   the wrong port; the collector publishes both (4317 gRPC + 4318 HTTP).

## Why

The bench-throughput.sh smoke failed twice for two independent pre-existing
bugs in the soak load path — neither is a product-code bug, but both block
any load/performance measurement (and any soak) from producing data. The
smoke test (run before the 30-min PERF-AUDIT-001) did its job: it caught both
before a wasted 30-minute run.

## Verification

- `docker compose -f docker-compose.yml -f docker-compose.soak.yml config --quiet` → OK
- bench-throughput.sh smoke #4 (after both fixes): `container health: healthy`,
  `subscription acks (acknowledged=1024): 1`, baseline `append_latency_ms_count=128522`
  (ticks flowed), `EOFException` count 0 (was 199).
- The measurement windows still produced no rows due to a separate harness
  process-group kill of the faketool child (see runbook "Bench/load tools:
  faketool dies mid-run" — launch via `bg_run`/`setsid`), which is documented
  as a follow-up, not part of this change.
