## What changed

### XC-6 — `fused_timeline.py`: the 120 s staleness bound actually expires now

P6-401 introduced the `(g - t) <= 120` bound but kept the previous grid point's
value in `last_val`, so once a metric stopped scraping the last value was
written to every later grid point anyway — the exact "forward-filled to the
grid's end" bug the P6-401 comment claims to have fixed. The loop is now
`forward_fill(grid, by_t, agg, max_age_s=120)`: no in-bound sample means the
grid point stays EMPTY. New `test_fused_timeline_forward_fill.py` pins the
expiry, the resume, and the newest-sample/aggregation choice (the expiry tests
were red against the pre-fix behavior).

### XC-7 — `IngestionService.java`: an unexpected loop failure is a crash, not exit 0

`runWithBridge`'s `catch (Exception)` logged "bridge process error" and broke
the loop without recording `fatalStopReason`; `main()` then exited 0, so the
container's `restart: on-failure:3` never fired and the documented crash
contract (`docs/08_implementation/03-ingestion.md`: BRIDGE_CRASH + DROP +
non-zero exit) was bypassed. This is reachable: `ProtoFrameReader.readLoop`
deliberately throws loud on a truncated header/body, an invalid frame length,
a bad payload, or an over-limit batch (P1-269/P1-270) — and every one of those
throws died in this catch. The catch now (unless a shutdown is already
requested) writes the DROP discontinuity via `recordBridgeExit` and records a
`BRIDGE_CRASH` fatal reason through the same `markBridgeFatal` helper the
TERMINAL exit path uses. New E2E test `truncatedFrameIsFatalNotCleanExit`
scripts a bridge that emits one valid frame then a 1-byte partial header and
asserts the fatal reason, the log, and the DROP row.

### XC-8 — `stage_capture_parse.py`: one window/percentile implementation

`b2_consumer_read_report` and `b2_closed_read_report` carried verbatim copies
of the bucketing + p50/p95/p99 code (only the TSV name, header labels, and
absent-file note differ). Both now call `_window_percentile_report`; a
delegation test pins that both legs use it.

### XC-9 — `t9_order_sandbox.py`: dead transport removed, probe compile path deduped

`HostTransport` had zero references (the T8 profile never publishes a host
port) and both Fluss probes carried identical `_classpath` loaders and javac
prologues. The dead class is deleted; `_probe_classpath` and
`_ensure_probe_class` are the single implementation for both probes.

### XC-10 — `holistic-analyze.py`: the retired-table parse loops are gone

The preview/final-candle reads were replaced by `prev_rows = []` /
`final_rows = []` when the tables were retired, but their parse loops (and the
`prev_re` regex feeding them) stayed behind — unreachable code computing
values that could never exist. Deleted; the `unavailable` notes and the
downstream empty-list handling are unchanged. The now-unused empty
assignments themselves were removed too (they had kept the loops looking
live; ruff F841 flagged them once the loops were gone). Guard test asserts the
names cannot return.

### Comment — `SignalJob.java`

The T3 G3 comment said "the 0.4 fraction above" while the code sets 0.6
(L541); corrected to 0.6.

## Why

- XC-6 fabricates latency points for a dead scrape — perf evidence must show
  the hole, not a carried value.
- XC-7 is a fail-open exit: a crashed/truncated bridge read as a clean stop,
  and the restart policy that exists for exactly this case never fired.
- XC-8/XC-9/XC-10 are the maintainability defects the size findings hid
  (duplicated logic, dead code); fixing them is what G11 verification is for.
