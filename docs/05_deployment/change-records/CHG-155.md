# CHG-155 — The savepoint rollout proves the restore instead of assuming it

- **Status:** recorded — all 16 wave-18 findings fixed
- **Filed:** 2026-09-14
- **Source:** P6 ops/scripts/tests/chaos audit, wave 18 ("Savepoint rollout"): P6-167…P6-174
  (high) and P6-501…P6-508 (medium) in `code/01_platform/04_scripts/rollout-savepoint.sh`
  (the savepoint → stop → redeploy path where a mistake restores-from-nothing rather than
  failing the command).

## What happened

The rollout normalised (resolve the job, sample the baseline), measured (savepoint, stop,
redeploy, verify), then reported (continuity gate) — and at each step a failure used to
mean "carry on with garbage" or "die with the wrong message".

**The job was misidentified (`P6-167`, `P6-171`).** `job_state` took the LAST `"state"` in
the JSON, so per-vertex states shadowed the job-level one and `wait_state` could observe a
subtask; `[A-Z]*` also dropped `_` states. The overview lookup's `.*?` spanned job objects
(ERE has no lazy quantifier) while `JOB_NAME` rode unescaped as regex — with >1 job listed
the extracted jid could belong to a different job. Both now parse with jq (exact name +
state match); the sed fallbacks that remain are single-object (`[^}]*`) and literal
(`grep -F`).

**The waits lied or never ended (`P6-168`, `P6-504`, `P6-174`, `P6-172`).** `wait_state`
knew only FAILED/CANCELED, so FINISHED/SUSPENDED spun to timeout; a non-numeric timeout
aborted under `set -e` with an arithmetic error; any transient curl failure killed the
whole rollout instead of retrying to the deadline. The savepoint poll and the checkpoint
wait had the same single-failure shape, and the checkpoint reads assumed single-line JSON
— pretty-printed answers never matched, so healthy jobs timed out. The pre baseline read
the LAST `state_size` (oldest history entry), so the gate could compare unrelated entries
and false-pass. Timeouts are validated, all four terminal states fail fast, polls retry to
their deadlines, checkpoint reads go through jq (`.latest.completed` first), and the
post-restore read uses the same jq path — the old sed|tail twin was still live there and
is closed in this record too.

**The rollout died wrong (`P6-502`, `P6-501`, `P6-507`).** Every `log` was fatal when the
evidence write failed (full disk, bad LOGDIR override) — including `die`'s own tee, which
could mask the fatal message itself. Numeric timeouts were never validated and died in
`$(( ))`/`seq` with cryptic errors. `HIT_SAMPLE_S` was advertised as the sampling window
but never waited. Evidence writes are guarded (`die` falls back to plain stderr), all five
timeouts validate once after defaults, and the gate sleeps the documented window.

**State crossed trust boundaries unchecked (`P6-173`, `P6-503`, `P6-169`, `P6-505`).** An
exported `SAVEPOINT_PATH` silently skipped savepoint/stop; `TARGET_DIR` rode raw into a
JSON string (quote/backslash breaks the request); `JOB_ID` rode unvalidated into the REST
path; unconditional `--env-file` made a fresh checkout without secrets.env unrollable; GNU
`date -d` aborted the restore-proof loop on BSD/macOS. `SAVEPOINT_PATH` initialises empty
at declaration (never inherited), the savepoint body is jq-encoded with a validated
32-hex JOB_ID, compose passes only existing env files, and the `--since` window tries GNU,
then BSD `-v`, then a `2m` duration fallback.

**Evidence was fabricated (`P6-170`, `P6-506`, `P6-508`).** The Prometheus sampler aborted
under `set -e` when a metric was absent — and worse, `awk 'END{print s+0}'` printed `0`,
so missing metrics reported as valid `0 0 0` evidence and the `[ -z ]` emptiness test was
dead. The T0 loop could abort on a transient curl. The >=50% gate ran `[ -lt` on
possibly-empty strings (exit 2 under `set -e`) instead of delivering a verdict. The
sampler now yields empty-on-absent (pipefail propagates grep's 1, awk exits 1 on zero
rows, `|| var=""` keeps it best-effort — with no `|| true` after grep, which was found by
the new test to reset the pipe and feed raw labels into awk), T0 retries, and the gate
validates each side separately (a `:`-joined single class cannot see emptiness — found by
the new test, fixed in this record) and warns instead of aborting.

## Judgement calls

1. **jq is required, not optional.** Four fixes need real JSON parsing and every fallback
   it replaces misread one of the two JSON shapes Flink emits. The rollout refuses without
   jq at preflight with a clear message; the jq-less sed paths are gone from the evidence
   reads (one single-object `[^}]*` fallback remains for the overview lookup only).
2. **P6-506 keeps the T0 loop.** The finding offered deletion; T0 feeds the session
   hit-rate evidence below, and the "never read" premise is stale — the loop stays, with
   the `|| true` retry.
3. **P6-503's "simpler" nested-subshell form rejected.** Piping jq output through
   `$(cat)` inside `$(api_send …)` nests a subshell in a substitution for no gain; the
   body goes in a named variable first.
4. **P6-508 stays POSIX `case`, not `[[ ]]`.** The suggested `[[ =~ ]]` is bash-only and
   this gate is read by `/bin/sh` tooling; per-side `case` patterns do the same job.
5. **Two test bugs of mine, found by running the tests before committing.** (a) The curl
   stub's `*metrics` arm sat *after* `*/jobs/*`, which swallowed metrics URLs into the job
   fixture — the sampler "summed" raw label text. (b) The harness sourced the script head
   including the argv loop and preflight body, so probes ran the rollout; the harness now
   extracts helpers-marker→preflight only. Both are why the wave rule says
   fix-before-the-commit.
6. **A stray `sleep 300` from an earlier hand-probe was found and killed** before the
   full-suite run (same discipline as CHG-154 judgement 9).
