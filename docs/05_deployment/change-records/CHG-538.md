## What changed

### XC-32 (AS-450) — read-loop auth refresh off-by-one

`main.go` read-loop auth branch incremented `authTries`, ran the refresh, then
passed the **post-increment** budget as `hasRefresh` to
`classifyAuthRefresh(...)`. On the final allowed attempt the refresh ran and
could succeed, but the classifier received `false` and returned
`authTerminalExhausted`: the slot was permanently stopped with a false
`auth_failure: authentication_refresh_exhausted` event. The dial path
(`main.go:431`) retries on the same success, so the two paths disagreed.

Fix: the budget arithmetic is extracted into `readLoopAuthRefresh()` — it
records whether a refresh actually ran (`didRefresh`) and passes that as
`hasRefresh`, with the prior count (`*authTries-1`). The already-exhausted
budget still folds to `didRefresh=false` → `authTerminalExhausted` (P1-028).
`syncAuthBudget` is inlined into the helper (it had one caller).

### XC-33 (AS-371) — dead burst machinery retired; checkpoint analysis un-nested

CHG-534 removed the preview-table parse loop — the only producer of
`buckets_1s`. What was left: `burst_secs` permanently empty, the burst print
always 0, the G6b stall guard unable to fire (its comment still claimed "fully
armed"), every burst-correlation leg inert, and — worse — the **entire
checkpoint duration/B5 analysis nested inside `if burst_secs:`**, so it never
ran either.

Fix: the burst machinery is retired explicitly (one `UNAVAILABLE` entry names
the retired legs; the false claim is gone; the G6b block and every
burst-gated correlation block are deleted). The checkpoint analysis is
de-indented to run unconditionally, keeping its non-burst value (durations,
slow checkpoints, B5 phase attribution). The retired legs cannot be re-armed
without a live landing-timestamp source.

### XC-34/35 (AS-025/026) — checkpoint read discipline

The checkpoint read dropped corrupt JSONL lines with `except ValueError: pass`
and swallowed a missing/unreadable file to `cps=[]`, which then printed
"slow checkpoints (>5s): 0" — an unmeasured leg presented as a clean zero.
New `read_checkpoint_windows(path)` returns `(rows, bad_lines, error)`; the
caller appends an `UNAVAILABLE` note (with the error, or the bad-line count)
instead of a clean zero. Same discipline as `counter_leg_note` (XC-5).

### XC-37 (AS-119) — co-located comment

`holistic-analyze.py` said "byReason counters (8 reasons)";
`RawValidationFunction.invalidReason()` returns 10 distinct reasons
(negative-volume-delta, event-time-overflow-window added).
