## What changed

- `TableContractValidator.validateMergedCandleTable`: mirrors the candle
  validators with `MergedCandleFeaturesColumns` under the new
  `MERGED_CANDLE_CONTRACT` id (`DEC-059, MERGED-CANDLE-FEATURES-SCHEMA-001`).
- `SignalJob.mergedCandleTableInUse(config)`: true when
  `MERGED_CANDLE_FEATURES_ENABLED` is on or the configured context table equals
  the merged table. `preflightTableContracts` validates and reports the merged
  table under that condition; the legacy live/closed checks stay exactly as
  before.

## Discovered constraint (recorded for W-C5a/W-C7)

`FlussSinkBuilder.build()` resolves its table **eagerly at graph-build time**
(measured by the W-C3 drill: `Table 'default.<closed>_absent' does not exist`
thrown from `MultiTimeframeSinks.sinkClosed -> FlussSinkBuilder.build` even
though the branch sits behind a drop guard). Consequence: the guarded legacy
sinks still need `candle_live`/`candle_closed` to exist while they deploy —
true through the W-C6 window; after the W-C7 drop, a redeploy of pre-W-C5a code
would fail, so W-C5a (which deletes the legacy wiring) must land in the same
session, with no fresh submit in between. From W-C5a on, no code path
references the dropped tables.
