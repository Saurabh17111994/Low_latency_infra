# CHG-233 — the execution sandbox tooling stops hiding its own failures

- **Status:** recorded — fixed (2026-09-19)
- **Filed:** 2026-09-19
- **Source:** audit map wave 43 (`execution tooling`, 10 findings, session e3ba8745).

## What was found

The highest-severity defect could report success while checks had failed:
`offline_contract()` in `t9_order_sandbox.py` takes a snapshot of the
module-global `FAILURES` when it starts and returned that snapshot from **both**
of its exits, so any check failing afterwards was absent from the returned list.
The audit's line reference covered only one of the two exits.

The remaining nine: `verify_envelope()` checked that envelope keys existed but
never their types, so an ill-typed `deadline_epoch_ms` (or a non-string
`authentication`) crashed on the comparison instead of reporting a bad envelope;
the documented wire contract said `payload_has`; the `SignalJobConfig.java` read
was unguarded, so a moved file killed the harness; `execution_network_check._names`
returned the whole `"KEY=value"` string for Compose's list-form environment, so a
leaked order-path name never matched `ORDER_ARROW_ENV` and the leak check passed
silently; the resolved config was pinned to `--profile execution-t3`, leaving
services under every other profile unvalidated; that compose call had no timeout
and its exit status was uncaught; `t8_sandbox_contract_check.py` missed
`${EXECUTION_ENABLED:-true}` and quoted forms, printed a summary prefix
(`local-sandbox-contract:`) that no sibling greps for, and treated only the
double-quoted `${VAR}` as a blank placeholder.

## What changed

- `t9_order_sandbox.py`: both exits now return the live union of the snapshot and
  `FAILURES` (order-preserving, deduplicated); `verify_envelope()` type-checks the
  identity strings and the two integer fields; the docstring says `payload_hash`;
  the config read goes through `_read_text()`, which turns a missing file into a
  failing check instead of a traceback.
- `execution_network_check.py`: `_names()` parses `KEY=value` list items and
  mapping entries; the profiles are derived from the compose file rather than
  pinned; the compose call is bounded by `COMPOSE_CONFIG_TIMEOUT_SEC` (default
  60s, env-overridable) and reports timeouts and non-zero exits as message text
  worded so the compose-form contract does not read them as call sites.
- `t8_sandbox_contract_check.py`: one compiled regex covers the substitution and
  quoted `true` forms; the summary uses the documented `t8-sandbox-contract:`
  prefix; `_nonblank_env()` treats `${VAR}` and `${VAR:-}` as blank placeholders,
  quoted or not, while a real default (`${VAR:-value}`) still counts as a value.
