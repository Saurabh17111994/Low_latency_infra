## What changed

| Piece | Change |
|---|---|
| `restore_evidence_lines` (new) | Queries `compose logs --since <iso> flink-jobmanager` for `Restoring job <new-id> from Savepoint` and `flink-taskmanager` for `Restoring state for N split(s)` / `Starting to restore from state handle`; unioned, no tail cap |
| `utc_iso` (new) | One portable RFC3339-UTC timestamp (`date -u +%Y-%m-%dT%H:%M:%SZ`) -- no GNU/BSD `-v` fallbacks needed |
| Body | `restore_since` is captured once immediately before `flink run`; the 15x5 s poll consumes the fixed anchor; the log line names the anchor and the failing message says which sources were searched |
| Tests | 4 failing-first tests (JM+TM evidence found; `--since` present / no `--tail`; `utc_iso` format; static anchor pins) |
| Dossier | `docs/08_implementation/21-savepoint-rollout.md` step 5 + validation row updated |

## Why the fix is safe (not a loosening)

- The evidence sources are unchanged (JM Savepoint line, TM split-restore
  lines); only the search window is corrected: it now always includes the
  whole period since submission, so a restore that genuinely never happened
  still fails closed.
- The client-log `startup mode = RESTORE` / `F005` / `FULL_REPLAY` checks are
  untouched and still run first.
- The 15x5 s poll budget is unchanged; the window only grows, so late restores
  that were previously missed by the sliding window are now visible.
