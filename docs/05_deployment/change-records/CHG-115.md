## Problem (audit finding 2026-08-28)

The low-latency work (T6 proto transport) was proven faster (+30% measured in
Test D: 29.3k vs 22.6k smoke; 27.4k/s sustained 5-min bench) and the bridge
now defaults loudly (CHG-114), but the **containerized ingestion still ran the
old NDJSON path**: `docker-compose.yml`, `docker-stack.yml`, and
`docker-entrypoint.sh` never set `TRANSPORT`, so the bridge fell back to
NDJSON silently (pre-CHG-114) — the production topology was on the legacy
path while only the host-side bench scripts used proto.

## Fix

Flip the container default to proto everywhere:

1. `docker-compose.yml` (ingestion service): `TRANSPORT: ${TRANSPORT:-proto}`
2. `docker-stack.yml` (ingestion service): `TRANSPORT: ${TRANSPORT:-proto}`
3. `docker-entrypoint.sh`: `export TRANSPORT="${TRANSPORT:-proto}"` (explicit
   env wins) + updated header comment (proto primary, pipe rollback)
4. Contract O-4 (line 260): "pipe is the default/primary" → **"proto is the
   default/primary"**, annotated with the CHG-115 flip + T6 measurement
5. `03-ingestion.md`: Go bridge description (proto frames primary), Java
   reader description (sniff), flow step 8, one-raw-table row

`TRANSPORT=pipe` remains the documented, proven rollback path (T6-RB1,
T9-RB2) — an env override on any layer restores NDJSON.

## Impact

- Containers now run the optimized proto path by default (batched writes,
  no per-tick JSON parse/base64/SHA-256 churn).
- Rollback unchanged: `TRANSPORT=pipe` anywhere (compose env, stack env,
  entrypoint env) restores NDJSON — proven operational.
- Images must be rebuilt (entrypoint changed) and the gate re-run.
