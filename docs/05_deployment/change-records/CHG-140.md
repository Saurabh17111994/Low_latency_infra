# CHG-140 — The doc audit fails closed: an unreadable tree is a finding, not a green

- **Status:** recorded — ten findings fixed in one script, a new preflight and concurrency guard
  added, one companion test-pin correction; `make full-audit` now has three distinct exit codes
- **Filed:** 2026-09-14
- **Source:** P6 ops/scripts/tests/chaos audit, wave 3 ("Evidence scripts must fail on an I/O
  error"): P6-005, P6-006, P6-101, P6-394, P6-395, P6-396, P6-397, P6-398, P6-736, P6-737

## What happened

The full doc audit is the command that certifies docs against code, and it could report green
without having read anything. Every finding was re-verified against the script before editing; all
ten were real.

**The two false-green paths (`P6-005`, `P6-006`).** Layer 2a ended its grep pipeline with `|| true`,
so grep exit 2 (missing `$DOCS`, permission denied) became an empty hit list and a PASS. Layer 2b
had the same collapse plus `2>/dev/null`, which hid the diagnosis entirely. Both layers now run the
raw grep first and check its status on its own: exit ≥ 2 is reported as "sweep did not run", and a
later stage exiting 1 (`grep -v` filtering everything out) can no longer mask it.

**Portability (`P6-101`, `P6-395`).** Both sweeps used BRE alternation (`'ranking\|reservation'`) and
placed `--include` after the path operand. Neither is portable: under BSD/macOS grep the BRE form
matches a literal `ranking|reservation`, and options after an operand are a GNU extension. Both
sweeps are now `-E` with options before the pattern and paths.

**Whitelist scoping (`P6-396`).** Layer 2a's suppressions mixed path tokens (`change-records`,
`04-decisions`, `10-ranking.md`, `05-risks`) with content tokens in one `grep -v`, so a prose line
that merely *mentioned* one of those paths was silently whitelisted. Path suppressions are now
anchored to the path field of `file:line:content` and the content whitelist is separate and
case-insensitive.

**Preflight (`P6-005`, `P6-006`, `P6-736`, `P6-737`).** A missing or unreadable input is now
diagnosed before any layer runs: a bash guard placed before `set -u` (under `sh`, `${BASH_SOURCE[0]}`
is unset and `set -o pipefail` unsupported, so a mis-invocation used to die mid-audit), a `python3`
check, the presence of both scanner scripts, and every directory a layer sweeps.

**Layer 3's missing half (`P6-397`, `P6-398`).** The header states that dossiers 13/14 were deleted
2026-08-17 and absorbed into 04, but the script only checked the absorbing file — a resurrected copy
would re-fork the dossier while every positive check stayed green. The retirement is now asserted
against the exact deleted filenames. `trio_check` also reports a missing file as such and passes
`--` to grep, instead of turning a rename into a grep usage error.

**Concurrency (`P6-394`).** Layer 1b's docs-audit reads the surefire XML totals, which a gate run
rewrites. The audit now refuses to start while a gate run is in flight — unless it *is* that gate's
own step, which is exempt by ancestry so the gate keeps working.

## Judgement calls (review these)

1. **The concurrency guard is ancestry-based, not flock-based.** A shared lock on
   `logs/.monday-gates.lock` cannot work here: the gate runs this audit as its own step 10/19 while
   holding that lock exclusively, so a lock-based refusal would fail the gate. The guard therefore
   refuses only when a gate run is in flight **and** this audit is not its descendant; step 10 is
   pinned by `test_the_gate_own_step_stays_exempt`. True mutual exclusion would need a gate-side
   change, which is outside this wave's file cluster.
2. **`P6-396`'s path filter assumes no colon in a docs path.** `^[^:]*/(change-records|…)/` reads the
   `file:line:content` prefix. A path containing a colon would make the filter miss and show up as a
   visible false positive, not a silent pass.
3. **The content whitelist became case-insensitive.** The old list enumerated variants by hand
   (`Historical|HISTORICAL`). Judgement: a case variant of an intentional whitelist word is still
   intentional. The tightening asked for by `P6-396` is the path split, not the case handling.
4. **Exit 2 is new.** "Did not run" (wrong interpreter, missing tooling, gate in flight) is now
   distinguishable from "findings" (exit 1). The gate treats any non-zero as a failed step, so this
   only affects humans and scripts calling `make full-audit`.
5. **The retirement assertion pins the two exact filenames** deleted in `61cc854c` rather than
   globbing `13-*`/`14-*`, so a future dossier that reuses those numbers is not a false failure.
6. **The two `|| true` on the downstream filter stages stay.** They normalise the status of a
   pipeline whose content has already been counted; the stage whose status matters is the raw grep,
   which is captured separately. Removing them would turn "everything filtered out" into an abort.
