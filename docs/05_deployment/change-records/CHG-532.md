## What changed

### XC-1 — `t9_paper_25.rs`: persist only after every invariant holds

`main()` wrote `evidence.json` (with `fsync`) **before** `assert_no_secrets` and
the shadow-invariant asserts. A secret-shaped key would have reached disk before
the panic, and a failed invariant would leave a non-conforming evidence file
claiming success. New `verify_and_write()` (L75) runs `assert_no_secrets` and
the invariant asserts first and writes last; `main()` calls it at L132. This is
the exact rule `t9_paper_25_full.rs` already implements (P3-184).

Guard test `failed_invariant_never_persists_evidence` (L200) proves a failing
check leaves no `evidence.json` on disk.

### XC-2 — `MultiTimeframeAggregateFunction.java`: a missed close is a drop, not an emission

The overnight/session-boundary expiry (P2-141) marks complete prior-session
pending candles in the never-re-emit map and incremented
`compute.candles.emitted` — **without calling `closeAndEmit`/`out.collect`**.
The comment claimed "Emit what's complete, count-drop what's not". Expired
pendings are now counted as `compute.candles.late.dropped` (the emitted counter
moves only in `closeAndEmit`, after `out.collect`), the never-re-emit marking is
kept, and the comment states the actual intent (L812/L824).

Harness test `overnightExpiryCountsDropsNotEmissions` (L622) rolls a 15 s window
into pending with no watermark advance, feeds the next trading day's first tick,
and asserts: pending expired, late-dropped increased, emitted unchanged, no
prior-session row emitted into the new day.

## Why

- XC-1: the P3-184 ordering rule exists precisely so a failed check cannot leave
  a non-conforming evidence file on disk; the older binary predated it.
- XC-2: `compute.candles.emitted` is used as evidence of real emissions
  (CHG-506 and later evidence runs); counting dropped candles as emitted
  over-reports the metric in the missed-timer edge case.
