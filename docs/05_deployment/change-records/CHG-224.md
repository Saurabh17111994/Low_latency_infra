# CHG-224 — gate step 11 keeps its own evidence

- **Status:** recorded — fixed (2026-09-18)
- **Filed:** 2026-09-18
- **Source:** the DDL apply timing investigation (`docs/plans/2026-09-18-ddl-apply-timing-and-concurrency.md`), finding "step 11's per-apply evidence is self-erasing".

## What happened

Step 11 runs `ddl_apply_smoke.py`; each of its scenarios runs a full manifest apply and writes an
`apply.json` record under `DDL_APPLY_EVIDENCE_DIR`. The default for that is repo-root
`logs/ddl-apply`, which any container run leaves container-owned (10001:10001), so the smoke fell
back to `tempfile.mkdtemp(prefix="ddl-apply-smoke-evidence-")`. A certificate's step 11 therefore
kept only its 1 KB summary: run 6's per-apply evidence (three applies × 27 tables, with the matrix
results) was written to `/tmp` and discarded. That is why run 6 could not be profiled after the
fact — the finding that started this whole investigation.

## The change

- `ddl_apply_smoke.py`: the inline writability probe becomes `_evidence_root_writable(root)`, and
  `resolve_evidence_root(default_root, env, is_writable)` decides — an explicit
  `DDL_APPLY_EVIDENCE_DIR` wins, the default is used when writable, a temp dir stays as the last
  resort. The old behaviour was "always fall back", which silently overrode the caller.
- `run-monday-gates.sh` step 11 sets, exports and creates
  `DDL_APPLY_EVIDENCE_DIR="$OUT_DIR/ddl-apply-evidence"`, so the records land in the run directory
  the certificate already references. The assignment starts the line, as
  `test_gate_variable_scoping.py` requires.
- S4 is unaffected by design: it passes `-e DDL_APPLY_EVIDENCE_DIR=/bad` to the container on
  purpose — that path *is* its bad-ownership fixture.

## Verification

- Test-first: `EvidenceRootTest` (4 legs) red — `AttributeError: … has no attribute
  'resolve_evidence_root'` — then green. Legs: explicit wins even when the default is unwritable;
  the default is used when writable; temp is the last resort; a blank explicit value is not a
  choice.
- `Ran 9 tests … OK` for `test_ddl_apply_smoke.py`; `Ran 67 tests … OK (skipped=1)` for the gate
  guards; `bash -n` and `shellcheck -S warning -x` clean on `run-monday-gates.sh`.
- **Live**: a smoke run with the variable set printed `evidence dir …/logs/ddl-bench/smoke/evidence
  (from DDL_APPLY_EVIDENCE_DIR)` instead of the temp-dir fallback, and wrote
  `evidence/ddl-apply-20260918T163010Z-64077/apply.json` (scenario 1) and
  `evidence/ddl-apply-20260918T163035Z-64529/apply.json` (scenario 2). Scenario 4 produced none
  because it timed out — that is CHG-226, not this change.
