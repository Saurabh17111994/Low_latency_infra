## What landed

The FreeBuff worktree `0526f7dc` investigation (`16-signal-chain-e2e-investigation.md`,
492 lines, 2026-08-17) root-caused the `SignalChainLiveE2ETest` failure to a
**harness config gap, not a design bug**: under local/embedded execution (no
`flink-conf.yaml`) Flink defaults `taskmanager.memory.managed.size` to
**128 MB TOTAL**, starving the RocksDB block cache so the job throttles to ≈ the
feed rate, the backlog never drains, and every candle is a KV upsert of a
historical window — `feature_candles_15s` stays flat. Same topology sustains
~100k/s on heap and ~49k/s on RocksDB with a realistic managed budget.

The same investigation also proposed a **design-B (state-authoritative
MapState dedup)** architecture reversal. That was **rejected** (user decision
2026-08-17): DEC-038 stays canonical — Fluss owns the durable dedup set; the
Flink side keeps the bounded working cache. Design B is preserved for reference
on the `experiment/design-b-mapstate-dedup` branch (`30baa10`) and never merged.
**Superseded by CHG-022 the same day** — see the banner above. Only the
architecture-independent harness fixes were ported:

| Piece | Detail |
| --- | --- |
| `TASK_MANAGER_MEMORY_MANAGED_SIZE` passthrough | New `SignalJobConfig` key → `taskmanager.memory.managed.size` in `applyRuntimeOptions`; unset → deployment authoritative; blank → fail closed. |
| `TASK_MANAGER_NETWORK_MEMORY_MAX` passthrough | New key → `taskmanager.memory.network.max` (+ `.min` pinned below it); p16 embedded deploy previously failed with "required 17, but only 13 available" (64 MB local default). |
| E2E count engine | LOG tables counted as the sum of end offsets via `listOffsets` (a LOG batch scan poisons the shared connection for the next KV scan, measured 2026-08-16); KV tables counted as the max over up to 3 scans (concurrent upsert can expose a partial snapshot), per-sample scans lazy (1 pass unless a dip). |
| E2E process plumbing | faketool + ingestion streams drained on daemon threads (synchronous `transferTo` blocked forever on long-lived servers); both streams drained, not just stderr; 250 ms → 5 s scan poll. |
| Runner script | `E2E_RUN_MINUTES` default 5 → 30; `TASK_MANAGER_MEMORY_MANAGED_SIZE` default 2048m + export; `STATE_BACKEND=rocksdb` default + export (production backend — rule 9); `INGESTION_CLASSPATH` actually computed via `dependency:build-classpath -Dmdep.outputFile` and exported (previously exported unset → empty classpath silently killed the ingestion subprocess). |
| Evidence | Investigation dossier copied to `logs/tracker-14/16-signal-chain-e2e-investigation-20260817.md`. |
