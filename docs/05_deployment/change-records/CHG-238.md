# CHG-238 — the load-test collector stops confusing a failed scrape with a stalled feed (wave 48)

- **Status:** recorded — fixed; verification by per-step evidence (no gate run, see below)
- **Filed:** 2026-09-20
- **Source:** audit map wave 48 (`code/01_platform/04_scripts/loadtest-collect.sh`, 10 ids; `test-loadtest-guards.sh`, 12 ids).

## What was found

22 ids across two files: `P6-123…126` + `P6-441…446` (collector, 4 HIGH + 6 MEDIUM)
and `P6-226…230` + `P6-581…587` (guard self-test, 5 HIGH + 7 MEDIUM). **No finding
was stale** — every one reproduces in the 2026-09-20 source — but nine carry a
supporting claim that is overstated or wrong; those are listed under *Deviations*.

### Collector

1. **P6-123 — one predictable scrape file under /tmp.** `feed_rate`,
   `operator_rates` and `p99_snapshot` each curled Prometheus into the same fixed
   path. Two concurrent benches clobbered each other, `>` followed any pre-planted
   symlink, and a failed request left a truncated file that parsed as rate 0.
2. **P6-442 — the HTTP status was never checked** (and the fast parser accepted a
   narrower number class than the p99 one), so an error body with no metric lines
   read as "0 records/s".
3. **P6-125 — a failed scrape became INVALID.** An empty rate fell through
   `[ "$FR" -ge "$LIVE_THRESHOLD_RATE" ] 2>/dev/null` into the else branch, so
   "Prometheus unreachable" was reported as "feed stalled".
4. **P6-126 — a chained operator lost its p99 column.** Flink exposes the
   *sanitized chain* (`fingerprint_dedup____ingest_latency_monitor`); the summary
   looked up the bare operator name, so the column was permanently `n/a`.
5. **P6-124 — the background sampler had no trap.** Only a trailing `kill` at the
   end of the loop; a SIGINT/SIGTERM or an early error leaked the infinite `while :`
   loop, and `VERTICES` failures produced silent gaps.
6. **P6-441 — no argument or out_dir validation.** A non-numeric
   `DURATION_S`/`INTERVAL_S` reached integer tests and `sleep`; a missing `$OUT`
   made every redirect fail silently and still printed a summary.
7. **P6-444/446 — the header was one field.** The header string contained `\t`
   and was written with plain `echo`, which does not expand escapes, so line 1 had
   literal backslashes while the rows had real tabs; rows were assembled with
   `echo -e` and could lose columns when a sub-query failed.
8. **P6-445 — two container-stats calls per snapshot** and `cut -d/ -f1`, which
   left a trailing space and whatever unit the daemon chose (MiB or GiB), so
   `flink_rss` mixed units.
9. **P6-443 — dead code.** `operator_rates()` was never called and hardcoded
   `http://localhost:8081/jobs/…`, ignoring the `FLINK_URL` contract.

### Guard self-test

10. **P6-226/581 — a fixed pid file and `kill -9` on its contents.** The port
    holder forked, wrote its pid to `/tmp/guard-port-holder.pid`, and the test
    killed whatever that file said: a stale file meant killing an unrelated,
    recycled pid. A bare `wait` waited on every job.
11. **P6-227 — G1 never invoked the guard** it claimed to test; it only grepped
    run.sh for the message text.
12. **P6-228 — G3/G7 tested the shell builtin.** `bash -c "test -f
    /nonexistent-ingestion.jar"` exercises `test`, not the runner's preflight.
13. **P6-229/585 — G2/G8 were self-fulfilling.** Both wrote a file and grepped the
    same file back, so the collector's and the runner's real logic was never run.
14. **P6-230 — the sed+eval extraction could silently no-op.** An empty range
    produced `command not found` (127), which `expect_fail` counted as a **pass**.
15. **P6-582 — G6 re-implemented the token count** with
    `cut -d, -f4 | tr ',' '\n' | grep -c .` and never called `count_tokens()`.
16. **P6-583/585 — no trap, and `/dev/null` hid every failure.**
17. **P6-584 — G4 counted with a BRE alternation and `-ge 1`** although the header
    claims each var is defined "once".
18. **P6-586 — B2 asserted only "non-zero"**, not the documented exit 2, and never
    tested the 190s boundary.
19. **P6-587 — B4 leaned on `sleep 1`** to prove the port had been released.

## What changed

**`loadtest-collect.sh`** — one private scrape per interval
(`SCRAPE_DIR=$(mktemp -d)`, written only by `scrape_prom`, which checks
`%{http_code}` and a non-empty body) shared by the feed guard and the p99
snapshot; a failed scrape is a new **UNKNOWN** verdict, counted separately and
excluded from the VALID/INVALID ratios; `validate_pos_int` refuses a bad
`DURATION_S`/`INTERVAL_S` with exit 2 before anything (including `$OUT`) is
created; `require_min_duration` holds the 190s rule (still `lt 190`, still exit 2);
`mkdir -p "$OUT"`; `printf` headers and rows with explicit `n/a` defaults and a
`row_shape_ok` check per row; one `container_stats` call with `TM_CONTAINER`
overridable and `mem_to_mib` normalising B/kB/KiB/MB/MiB/GB/GiB; `p99_snapshot`
now aliases every sanitized chain segment so a chained or renamed operator keeps
its column, and the summary calls out a column that is `n/a` in *all* VALID rows;
`loadtest_summary` is a function (drivable from fixtures); an EXIT trap kills and
waits the sampler and removes the private scrape dir (INT/TERM map to 130);
`operator_rates` is deleted.

**`loadtest-run.sh`** — the G2 block becomes `wait_real_rate <log> <pid> [tries]`
(bounded poll, gives up as soon as faketool dies, tail-not-cat on failure) so the
guard self-test can drive it with synthetic logs. No other runner behaviour
changes; the wave-47 pins on that file stay green.

**`test-loadtest-guards.sh`** — `extract_fn` lifts a function and asserts
`declare -F` afterwards, so a broken extraction is a failure instead of a false
pass; `expect_rc` asserts exact exit codes and every helper prints captured output
when it fails; one `mktemp -d` + one EXIT trap for all fixtures; G1 holds the port
in a single non-forking process (pid from `$!`, no pid file), calls the real
`port_8899_free` and polls for the release; G3/G7 run the real `--check-only` in a
repo-shaped sandbox (missing jar → rc 1 named, missing manifest → rc 1, complete
tree → 0); G6 calls the real `count_tokens` (1024 on the real manifest, 10 on a
10-row one, CRLF/blank lines do not inflate); G2 drives `wait_real_rate`; G8
drives `classify_feed_rate` (VALID/INVALID/UNKNOWN with exact codes) and
`loadtest_summary` on three fixtures; G4 counts with `-E` and requires **exactly
one** definition, after a readability check; B2 asserts rc 2 for 189s, rc 0 for
190s and rc 2 for a 90s run that creates no out_dir; B3 and B4 assert exact codes.
The wave-47 invariants and the `ARROW_INSTRUMENT_TOKENS` absence pin are kept.

**`docs/08_implementation/24-configuration-audit.md`** — M27 and S9 now point at
the new line numbers and record that the threshold and the container name are
env-overridable (the earlier "THRESHOLD is a literal" is no longer true).

## Deviations from the audit's fix text

1. **P6-442 — "large throughputs silently miss" is unproven; the regex class is
   still unified.** Java's `Double.toString` (what the Flink reporter emits)
   switches to scientific notation only at |v| ≥ 1e7 — verified with a throwaway
   `java` program: `9999999.0` prints plain, `1.0E7` prints `1.0E7` — and the
   per-subtask source rates in these runs are ~2–3k/s (observed in
   `logs/soak-e2e-20260904-234313/stages/prom-*.txt`). The fast parser now uses the
   same class as the p99 parser for consistency, not because data was being lost.
2. **P6-126 — not "every key never matches".** In that same stored scrape, four of
   the five lookup keys match exactly (`forming_bar_writer`, `forming_bar_detection`,
   `forming_bar_builder`, `forming_bar_sink:_Writer`); only `fingerprint_dedup` was
   silently `n/a` because the operator is now chained to
   `ingest_latency_monitor` (it exists bare in the 2026-09-03 scrape). The fix
   therefore aliases chain segments instead of replacing the names.
3. **P6-441 — a negative DURATION_S was already refused** by the min-duration
   guard (`-3 -lt 190` → exit 2), so "skips the loop but still prints a summary"
   is wrong. The real gap was non-numeric/blank input and `INTERVAL_S`.
4. **P6-582 — `tr ',' '\n'` was not redundant.** Field 4 of the manifest is a
   comma-joined token list, so the `tr` is load-bearing; the defects were the
   fragility of `cut -d, -f4` and that the assert never touched the real counter.
5. **P6-584 — `ARROW_INSTRUMENT_TOKENS` is not a typo.** The plural is canonical
   (`IngestionConfig.java`, re-verified in wave 46) and its *absence* from the
   runner is a deliberate contract (G3 handoff owns the token set). The absence pin
   is unchanged; only the "exactly once" half of the finding was fixed.
6. **P6-586 — `/tmp` was never polluted.** The guard exits before any write, so
   the "pollutes /tmp" half is wrong; the exit code and boundary halves are fixed.
7. **P6-226/587 — the stated mechanisms were wrong, the hazards were real.**
   `set -u` does not fire on `$(cat missing)`, so the failure is a harmless
   `kill ""`; and no TIME_WAIT is possible because the holder never accepts the
   probe connection. The real hazards are the fixed pid path (stale/foreign kill)
   and the forked child inheriting the listening socket (the port stayed bound for
   its 8s sleep, making the old `sleep 1` assert a latent flake). Both are fixed by
   a single non-forking holder whose pid comes from `$!`, plus a bounded release poll.
8. **Exit-code convention kept deliberately different:** the collector refuses with
   2 (its documented "no verdict" code), the runner with 1. `snapshots.tsv` gains a
   third value in the `feed_valid` column (UNKNOWN) and line 1 now has the 12 real
   columns instead of one literal-`\t` field.
9. **Scope:** `loadtest-run.sh` is touched for the `wait_real_rate` extraction only
   — it is what makes the G2 assert meaningful (P6-229) — and the wave-47 guard pins
   for that file were kept green rather than relaxed.
10. **Two defects introduced during the wave were caught and fixed before the
    tests were declared green:** `shellcheck` found the new snapshot-row `printf`
    had one specifier too many (it would have appended an empty 13th field), and
    the new `ContainerStatsTest` found that `mem_to_mib` did not trim the unit, so
    docker's real `3.3GiB / 4GiB` produced `GiB ` and a spurious `n/a`. Both are
    fixed in the committed revision.
11. **Not changed, recorded:** the collector still exits 0 when every snapshot is
    INVALID or UNKNOWN. The report is the verdict; making that non-zero would need
    runner coordination and is not part of this wave.
