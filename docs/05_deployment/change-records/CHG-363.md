## Notes

- **The root cause was provisioning, not the rule.** The 80% alarm was in the
  catalog since `f0b98334`; the running O2 had zero alerts and no destination.
  The fix makes the provisioning step explicit in every start path (PC manual;
  daily VM §3.4) and provable (probe + delivery history).
- **Fail-closed ordering kept:** the seeder still exits non-zero when a rule
  fails; it only stops letting one domain's missing stream block another's.
- **Capacity action stays open by design:** one real week of growth is the
  measurement that must precede any retention change; `node_filesystem_avail_bytes`
  is already in O2 (90-day retention), so that number is a query.
