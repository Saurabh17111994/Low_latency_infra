## Why

After CHG-334 the gateway can write `Execution_Gate`, but nothing reports to it: the executor's
`/v1/approve` set `ExecState::Enabled` in its own snapshot and the durable row stayed at the
boot state forever. The gateway would then defer every forward (`state != ENABLED`) and the
row's epoch/fence would never match what the executor actually runs with.

## What changed

| Piece | Change |
|---|---|
| `gate_report.rs` (new) | Signed `GATE_REPORT` client: `boot_halt` / `approve` / `halt` / `renew`, the `GateAck` row parse, non-2xx → error with the gateway reason, manual `Debug` redacting the shared secret |
| `http.rs` | `approve` is async and durable-first (report → adopt epoch/fence/lease; a failed report refuses, never completes locally; no reporter keeps the old local path); `safety_halt` halts locally and reports in the background (15 × 2 s, then the lease expiry is the backstop) adopting the durable epoch; `spawn_gate_keeper` runs the boot `BOOT_HALT` retry (hydrating the epoch) and the renew loop (halt-on-loss); `/healthz` adds `durable_gate` |
| `config.rs` | `ACCOUNT_SCOPE_ID` (default `dev-scope`), `GATE_LEASE_TTL_MS` (default 30 000, capped 120 000), `GATE_LEASE_RENEW_MS` (default 10 000, must be < TTL), `EXECUTOR_INSTANCE_ID` (default per-process) — all fail-closed on bad values |
| `main.rs` | Builds the reporter only when endpoint + secret + partition are all present; logs the fallback loudly otherwise; arms the keeper |
