## What happened

environment's seven `*_IMAGE=` lines were then rendered from that file with
`image-publish.sh --merge-env` (Fluss and Flink rewritten in place, the other five appended), and the
tracked `runtime.lock` moved FLUSS_IMAGE and FLINK_IMAGE from the stock base images to the wrapper
digests. Those stock digests remain the two wrapper Dockerfiles' `FROM` -- a different role from the
runtime pin.

## Applied and verified (Fluss half)

- `fluss-coordinator` and `fluss-tablet` recreated on `ghcr.io/saurabh17111994/trading-fluss-runtime:prod@sha256:e1bf98e6c58514641f1baa75c9f62534c64b7eb2e811a53b333c1ca007d52645`; both `running`, 0 restarts.
- `make pin-check` PASS after the flip (6 image refs digest-pinned, versions pinned, no SNAPSHOTs).
- The live money-path job `Babysitter Positions observer` **survived with an unchanged jid** and stayed
  RUNNING (1 running before, 1 after) -- the same tolerance the tablet-only recreates already showed.
- Functional read through the pinned stack: `SELECT COUNT(*) FROM default.raw_table_1` = **9,800,560**
  in 3.36 s via the Flink SQL client.
- **Restart recovery measured at ~88 s**: containers started 14:54:58.33Z, first successful read
  14:56:26Z; the attempt at 52 s failed with `LeaderNotAvailableException: Server -1 is not found in
  metadata cache`, and the coordinator logged 320 `Updated LeaderAndIsr` assignments in the first five
  minutes. The wrapper differs from stock only by the two baked FS-plugin jars that the compose also
  bind-mounts from the host tree, so this lag is restart-induced, not image-induced.
- Pre-existing and not introduced here: `WARN ... Invalid value for boolean: "true" ... fs.s3a`, a
  config-provider warning for the s3 keys (the values themselves are never printed), and
  `ERROR ServerConnection ... ts-0` lines while the tablet is still booting (none in the 120 s after
  startup).

## Not done (Flink half)

for an explicit moment.
