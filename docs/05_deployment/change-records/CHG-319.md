## What changed

| piece | change |
|---|---|
| `stage-profile.sh` | `FEED=faketool|real` knob (default faketool; invalid fails before anything starts) |
| real branch | skips faketool; **one** container (enforced) with `slots = ceil(rows/1024)` bridge connections (2 433 → 3 × 811), `ARROW_FEED=token`, `ARROW_HFT_CONNECTIONS=<slots>`, `ARROW_HFT_MULTI_CONNECTION_APPROVED=true`; non-secret identifiers read explicitly from the stack `.env` (`docker run --env-file` does not strip inline comments), secrets via `secrets.env`; `INSTRUMENT_MANIFEST_PATH` = the full unfiltered universe copy |
| subscription confirmation | real mode waits for **all slots**: `HFT subscribed` line count ≥ slots AND summed token counts == universe (the fake branch's exact `$per_slice` grep is untouched) |
| guards | market-hours guard (09:15–15:30 IST; `ALLOW_OFFHOURS_REAL=1` escape hatch), one-container guard, 3 × 1 024 capacity guard |
| `BRINGUP_ONLY=1` | after the fleet confirms subscriptions, tear down without capture/presence (the off-hours dry run) |
| labels | report title and capture `rate_hz` say "real broker DataStream full" (≈1 Hz/token) instead of the 2 Hz fake label |

## Caveats

- Off-hours real runs can only prove bring-up (stale snapshots are dropped by
  the 5 s event-age gate); never a measurement.
- Real cadence (≈1 Hz/token full mode) is not comparable to the 2 Hz fake
  ladder; report them as separate modes.
- Multi-connection is dev-only per the Java policy; production keeps rejecting
  it until separately approved.
