# CHG-158 — The gate runner stops lying about what PASS means

- **Status:** recorded — all 18 wave-21 findings fixed
- **Filed:** 2026-09-15
- **Closed:** 2026-09-15 — helper suite 776 OK (skipped=9), full_audit green (see Verification)
- **Source:** P6 ops/scripts/tests/chaos audit, wave 21 ("The gate runner itself"):
  P6-186, P6-187, P6-188, P6-189, P6-190 (high) + P6-522…P6-532 (medium) +
  P6-775, P6-776 (low) in `code/01_platform/04_scripts/run-monday-gates.sh`
  (the Monday certificate runner: 19 steps, fail-fast, verdict + evidence manifest).

## What happened

`run-monday-gates.sh` decides what a green gate means — so its own defects change
what a PASS proves. Three defects understated, overstated, or corrupted evidence;
two broke out of quoting; the rest removed timeouts, fail-closeds, and attribution.

**Suite output never reached its log (`P6-186`).** The Go step redirected `>"$GO_LOG"`
outside `bash -c "…"`, so the redirect applied to `timeout`, not the suite: the FAIL
pointer named an empty file and the evidence manifest advertised an unwritten log.
The subshell-cd form below fixes the redirect placement too — the log now records
the suite.

**Env-controlled dirs interpolated into `bash -c` source (`P6-187/188/190`, `P6-529`).**
Nine invocations built `bash -c "cd '$VAR'"` from `CODE_DIR`/`BRIDGE_DIR`/`PROJECT_ROOT`/
`EXECUTOR_DIR`/`COMPUTE_DIR`/`MOCK_ARROW_DIR`, all env-overridable: a single-quote in
the value breaks out and runs arbitrary commands with the gate's privileges. All nine
are subshell `(cd "$DIR" && …)` now — no interpolated string, so there is nothing to
break out of. The drill block (`FLUSS_BOOTSTRAP='$DRILL_BOOTSTRAP'`) was the same shape
unlisted; fixed identically via `env FLUSS_BOOTSTRAP="$DRILL_BOOTSTRAP"`.

**Named gates passed on zero tests (`P6-189`, `P6-190` half).** Both the schema/perf pin
and the shutdown pin passed `-Dsurefire.failIfNoSpecifiedTests=false` while claiming to
"fail loudly if a future pom/surefire change silently drops" the classes: a renamed or
deleted class yields `No tests to run` + `BUILD SUCCESS`. Both pins now pass `=true`,
and the pre-existing `require_tests_run` assertions (non-zero `Tests run:` from the log)
stay as the second leg.

> **Correction, 2026-09-15 (CHG-160).** `=true` does not survive a real reactor run and
> was replaced. Both pins use `-pl <service> -am`, which pulls `common` into the build;
> the `-Dtest` pattern matches nothing in `common`, so surefire aborts that module with
> `No tests matching pattern ... were executed!` and the pin failed on a healthy tree.
> This record's claim above was verified only against a stub `mvn`. The flag is back to
> `false`; the strictness now lives in `require_class_ran`, which asserts a non-zero
> `Tests run:` line for each *named* class. See CHG-160 for the real-run evidence.

**Three full reactors per run (`P6-532`).** Full gate + schema/perf pin + shutdown pin
each compile the reactor under the full `JAVA_TIMEOUT_SEC`. The pins run 2–3 classes;
they now default to 1200 s via `SCHEMA_PERF_TIMEOUT_SEC` / `SHUTDOWN_TIMEOUT_SEC`
(env-overridable), documented as subset pins in the step banners.

**Nine more timeouts without `--kill-after` (`P6-526`).** The fix round covered the suite
timeouts first; the test then showed memo lookup/record, preflight, image-staleness,
full-audit, DDL smoke, pin-check, and both step-18 `make` invocations still ran bare
`timeout N`. Every `timeout` in the script now carries `-k` (30 s for the 60 s memo
calls, 60 s elsewhere), and the hardcoded python/entrypoint gates are env-overridable
(`PY_TIMEOUT_SEC` 300, `ENTRYPOINT_TIMEOUT_SEC` 300, `E2E_BUILD_TIMEOUT_SEC` 600).

**Empty discovery passed (`P6-527`).** `grep -q "^OK"` passes on `Ran 0 tests` + `OK`.
Step 3 now also fails on `Ran 0 tests|FAILED \\(` — verified behaviourally against four
stub unittest outputs (green passes; empty/failed/skip-only fail).

**No docker killed the compose validation (`P6-524`).** Step 2 ran `docker compose`
unconditionally while steps 7/8/18 degrade gracefully. It now probes `command -v docker`
first; the missing-docker path keeps its WARN (a missing FILE is a repo problem, a
missing BINARY is an environment one).

**Static log corruption, two sites (`P6-525`).** Compose-config stderr (`2>>$STATIC_LOG`)
and the docker-build smoke (`2>>$STATIC_LOG`, and its FAIL pointer named the static log)
both wrote non-static output into the static evidence. Each stage has its own log now
(`compose-config.log`, `docker-build-smoke.log`), all assigned up front with the other
per-run paths and advertised in the final manifest — which also gains the E2E-build and
ownership logs.

**E2E build: no timeout, wrong log (`P6-530`).** Two `go build`s ran unbounded, appended
compiler output into `$GO_LOG`, and pointed failures at it. They run under
`E2E_BUILD_TIMEOUT_SEC` (default 600) into `$OUT_DIR/e2e-build.log` now. Binaries still
land in the source tree (`faketool/faketool`, `arrow-bridge`): no later step consumes
them from elsewhere, so relocating would break the contract — documented in-test.

**Temp list leaked on abort (`P6-522`).** `mktemp` cleanup sat mid-step after the only
`EXIT` trap was already taken by `_harness_abort` — a second `trap … EXIT` would have
silenced the harness abort. The temp removal rides on the existing harness trap
(`trap '_harness_abort; rm -f "${_script_list:-}"' EXIT`), which fires on every exit
path including `gate_fail`.

**macOS bash 3.2 aborts on `mapfile` (`P6-523`).** Both `mapfile` sites branch on a
`BASH_MAJOR` probe (uppercase: the scoping test requires step reads to resolve to
step-or-shared assignments) with a `while IFS= read -r` fallback. `SCRIPTS=()` is
initialised beside `mktemp` so the fallback appends on both shells.

**shellcheck WARN spammed N times; PASS overstated (`P6-775`).** The per-file
`command -v shellcheck` probe printed one WARN per script and the PASS line claimed
`shellcheck clean` while `-S warning` ignores info findings. One probe before the loop
(`SHELLCHECK_OK`), one WARN total, PASS says `shellcheck -S warning clean`.

**Ownership shared the DDL log (`P6-776`).** `evidence_ownership_check.py` appended to
`$DDL_SMOKE_LOG`, so a DDL SKIP + ownership FAIL was unattributable and the manifest
listed one path for two gates. It writes `$OUT_DIR/evidence-ownership.log` (own `-k`
timeout too) and the manifest lists both.

**Staleness SKIP was already SKIP (`P6-531` stale).** The finding quotes a
`PASS: image staleness SKIPPED` line; HEAD prints `SKIP: image staleness
(no docker/compose) — unverified, not green` with `note_skip 8`, and the verdict
counts skips. Pinned behaviourally by the scoping-adjacent suite; no edit.

## Judgement calls

1. **Subshell-cd over `bash -c … "$1"` arg-passing** (the finding offers both). One
   fewer quoting layer, matches the E2E-build step's existing shape, and the redirect
   lands on the suite instead of the `timeout` process.
2. **P6-526 fixed everywhere, not just the named gates.** The finding cites the python
   line, but a stuck memo/preflight/audit blocks the gate exactly like a stuck suite.
   The wave-21 test asserts zero bare `timeout N` invocations, so this cannot regress
   one site at a time.
3. **P6-531 closed as stale, not patched.** Editing an already-correct SKIP line to
   satisfy a stale quote would churn evidence strings other tooling greps. The ticks
   still count it: the wave is 18/18 because the tree already satisfies it.
4. **Two test bugs of mine, fixed pre-commit:** (a) `assertNotIn("…=false")` matched the
   helper function's own comment text — the pin now inspects only `mvn` invocation
   lines; (b) the STATIC_LOG probe tripped on the `2>&1` half of `>"$LOG" 2>&1` — only
   bare `2>>` appends corrupt, which is what it asserts now.
5. **Scoping-test IGNORE extended by one word, not worked around.** `BASH_VERSINFO`
   is caller-shell state like the already-ignored `BASH_SOURCE`; teaching the test the
   one new builtin (with a comment) beats renaming the probe to dodge the regex.
