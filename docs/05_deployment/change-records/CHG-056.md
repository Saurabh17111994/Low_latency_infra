## Summary

Adds the Item F **disaster drills** capability: a repeatable, approval-gated
fault-injection runner (`disaster_drills.py`, `make disaster-drills`) that
practices the chaos rules from `09-production-swarm.md` against the local
compose stack — every drill injects a real fault, asserts the documented
fail-closed / recovery behavior, measures RPO/RTO, and writes dated evidence
under `logs/disaster-drills/` with all required fields (fault time UTC,
detected signals, gate state, versions/topology/workload, reconciliation,
recovery proof, alerts, approvals).

Drills: `DR-001` Fluss coordinator loss/restart (leader failover),
`DR-002` tablet loss/restart (serving fault), `DR-003` ZooKeeper quorum loss
(single-node dev quorum — quorum destruction is the deliberate test),
`DR-004` OpenObserve outage (observability loss never authorizes orders and
never blocks the durable data path), `DR-005` executor gateway crash/restart
(boot fail-closed: gate stays HALTED, no duplicate-run), `DR-006`
coordinator–tablet network partition and heal.

## Guards

- Fault injection requires `--approve`; `--dry-run` prints the plan and touches
  nothing; a failed pre-check aborts the suite (exit 1) before any fault.
- Batched faults never include simultaneous quorum destruction unless the
  drill is the quorum-loss drill itself; no live-money/broker involvement.
- Evidence is redacted (secrets never reach `logs/disaster-drills/`).
- No auto-resume: the runner only performs each drill's documented recovery
  step; anything else is left as the evidence describes.

### Runner hardening (from live-run faults, 2026-08-21)

- A probe bug could produce a misleading PASS: the DR-006 connectivity check
  probed the wrong network name and reported DOWN while the tablet was actually
  still attached — a no-op "fault". The probe now asserts real detachment
  (`tablet_on_trading_net` → expect DOWN only when `attach: none`).
- A suite once wedged >1 h when a docker CLI timeout killed only the top
  command, leaving helpers holding the stdout pipe so `communicate()` blocked
  forever. `run()` now spawns in its own process group and SIGKILLs the whole
  tree on timeout (`killpg`); the suite carries a 20-min wall-clock budget
  (`SUITE_BUDGET_S`) and prints per-round poll progress. Superseded runs were
  removed from `logs/disaster-drills/` for accuracy (the invalid `101519Z`
  DR-006 PASS included).
