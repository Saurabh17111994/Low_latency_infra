## Why

The leak found on 2026-09-21 was 48 files holding the four live Arrow values with no name beside most of
them. The shipped scanner could not have found any of them: it searches secret *names* and four token
*shapes*, and the copies were bare values. What found them was a throwaway script — the wrong shape for a
standing property, and wrong in its own way, as the new mode then showed.

Built test-first, and its first real run justified it twice over.

Repository scan: 5,131 files read, 4 hits, all in-repo — `code/01_platform/01_docker/secrets.env` and
`code/01_platform/01_docker/.env.bak-20260828`, holding the password and the TOTP key. Both are
git-ignored (`.gitignore:31`, `:32`, `:89`) and no commit has ever touched either, so nothing was
published — but the throwaway scan missed both, so its "48 files" was an undercount. A names-and-shapes
scan cannot see those files at all, because the values sit in them without their names.

Session scan: 635 files, 74 hits, all outside the repository — the corpus the rotation is for.

Four design choices follow from what the mode is for. Values come from a 600-mode file outside the
repository and are never printed, never previewed and never placed in the JSON: a masked preview is four
characters of a live value, which is four too many when the value is real rather than a documented decoy.
A missing, unreadable or placeholder-only values file is rc=2 rather than zero hits, because a scan that
did not compare cannot certify anything, and every value it could not search is counted in the report
instead of being dropped. A hit fails the scan whether or not the file is inside this repository — the
supplied list holds live values, so there are no decoys in it. And the 2 MB size cap does not apply: a
value does not care how large the file around it is, and that cap is what left 12,714 files unread in the
name scan's own 2026-09-21 run.
