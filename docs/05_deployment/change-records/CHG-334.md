## Why

The gateway's intent forward leg reads `Execution_Gate` from Fluss; with no row it flips
`readiness.fluss(false, "key not found")` and `/v1/events` refuses for the process lifetime
(CHG-331 attempt 3). Nothing in the deployed topology writes the row: nautilus runs the
in-memory gate, and the gateway wires the non-authoritative placeholder. Two pieces were
missing on the writer side:

1. **The row must exist before the replay.** The pending-intent replay runs at startup and a
   `NOT_FOUND` lookup is a one-way readiness flip, so creating the row lazily on the first
   report was not enough — the gateway now opens the gate store and `init`s the HALTED boot row
   before the reader starts (never clobbering an existing fenced row, P3-151).
2. **The enablement path had no first steps.** `approveAndEnableIfComplete` promotes only from
   `APPROVAL_PENDING`, and no store mutator could produce that state — the live wiring would
   have had to jump `HALTED → ENABLED`, which `GateState.legalTargets()` declares illegal.
   `GateStateStore.transition(...)` now performs one sanctioned step durably (legal targets
   only, epoch +1, CAS witness honored, fence columns preserved), so the endpoint walks
   `HALTED → RECONCILING → APPROVAL_PENDING → ENABLED` exactly as the contract's state machine
   requires.

## What changed

| Piece | Change |
|---|---|
| `GateStateStore` | + `transition(partitionId, expected, target, reason, evidenceHash, nowTs)` — legality via `GateState.legalTargets()`; illegal step or stale CAS is a no-op returning the current row; null row → null |
| `InMemoryGateStateStore` | The reference implementation: legal-target guard, epoch +1 via `withState`, `TRANSITION` audit record |
| `FlussGateStateStore` | Durable leg mirroring `halt`: durable-first hydrate, delegate step, persist-or-rollback, `verifyPersisted` (a version-dropped write must not report success) |
| `GatewayStartup` | `Stores` now holds the gate store (opened with the single-operator allow-list, closed last); `openStores` creates the HALTED boot row (epoch 0, unfenced, no evidence — the first approval defines the binding) |
| `ExecutionGatewayMain` | The enabled path passes `stores.gates()` + authoritative=true to the server; the disabled path still boots offline |
| `GatewayHttpServer` | `POST /v1/gate`: signed `GATE_REPORT` envelopes only; `BOOT_HALT` (init + halt-over-ENABLED, never resumes), `APPROVE` (fence acquire → sanctioned steps → single-operator promotion; stale epoch/fence conflict/unauthorized/evidence mismatch fail closed), `HALT` (unconditional, idempotent), `RENEW` (lease extension, conflict on stale token/owner); returns the persisted row for adoption; disabled 503 / non-authoritative 501 / lease cap 120 s |
| `GatewayProtocol` | `GATE_REPORT` joins the HMAC allow-list; the endpoint checks its own type so a report can never be consumed as a projection event |
