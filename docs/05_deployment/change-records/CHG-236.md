# CHG-236 — the 3x20k day-load bench is re-runnable (wave 46)

- **Status:** recorded — fixed, verification **partial** (see the deferred-verification block)
- **Filed:** 2026-09-19
- **Source:** audit map wave 46 (`test-d-3x20k-run.sh`, 7 findings, session e9f995f4).

## What was found

The bench builds a faketool, starts three of them on 8899-8901 and three
ingestion JVMs, feeds for `TEST_D_DURATION_S`, then prints the writers' close
lines. Six real defects:

- **P6-222**: no trap. With `set -e`, a `go build` failure, a JVM-not-ready exit
  or a SIGINT during the feed left 3 faketools + 3 JVMs holding 8899-8901 for the
  *next* run.
- **P6-223**: the faketool readiness retry discarded its own result, so a
  faketool that never came up still produced a 5-minute measurement that read as
  a throughput regression.
- **P6-225**: the wait checked `/tmp/ingestion.ready$i` while the JVM was launched
  with `READINESS_FILE_PATH="${READINESS_FILE_PATH-/tmp/ingestion.ready$i}"` —
  an inherited value collapsed all three JVMs onto one file, the paths did not
  match, and a leftover file from a previous run satisfied the check instantly
  (`IngestionService.java` reads exactly that variable).
- **P6-578**: `ROOT` was an absolute developer-machine path and nothing was
  checked up front, so a missing jar/manifest/bridge failed *after* half the
  topology was built.
- **P6-579**: `ARROW_APP_SECRET`/`ARROW_PASSWORD`/**`ARROW_TOTP_KEY`** were
  committed in cleartext (including a real-looking base32 TOTP seed) and exported
  to every child.
- **P6-580**: the evidence step printed close lines and proved nothing — and under
  `set -o pipefail` a journal without the pattern made the whole run exit non-zero
  after the fact. The header cited `logs/tracker-14/test-d-evidence-20260828.md`,
  which is **not in the tree** (logs/ is gitignored), so the headline rows/s and
  0-loss claims were unverifiable.

**P6-224 is premise-wrong.** It reads `ARROW_INSTRUMENT_TOKENS` as a typo for a
missing-S variant. The plural form *is* canonical: `IngestionConfig.java:198`
reads it, `IngestionService.java:750` hands it to the arrow-bridge, and
`docker-compose.yml`, `.env.example` and `run-ingestion-full.sh` all use it.
Renaming it would have broken the disjoint-thirds isolation this bench exists to
prove. (`INSTRUMENT_MANIFEST_PATH` is likewise the name
`InstrumentManifestLoader.java:55` reads — the script was right there too.)

## What changed

- `trap cleanup EXIT` (+ `INT/TERM` → `exit 130`) with one idempotent `cleanup()`
  that TERMs the JVMs, waits bounded, KILLs them and the faketools; the drain path
  calls the same function (P6-222).
- Readiness now tracks success per port and aborts with the port and the last log
  lines (P6-223).
- `READINESS_FILE_PATH="$R/ingestion.ready"`, `rm -f` before launch, and the wait
  reads the same path — per run, per JVM, under the run dir (P6-225).
- `SCRIPT_DIR`-derived `ROOT` (overridable with `TEST_D_ROOT`), the out-of-tree
  manifest overridable with `TEST_D_MANIFEST`, and a `preflight()` that checks the
  jar, manifest, bridge dir and `java`/`go`/`python3` **before** anything is
  created or started — the output dir is now made only after preflight passes
  (P6-578).
- Credentials come from the gitignored
  `code/01_platform/01_docker/secrets.env`, with the canonical reader's hardening
  copied from `run-ingestion-full.sh` (symlink refusal, 600/400 only, BSD `stat`
  fallback). Placeholders are used only when the values are still unset **and**
  `ARROW_FAKE_BROKER=1`; otherwise the run fails with an explicit message
  (P6-579).
- `summary_of_journals <elapsed_s>` parses the JSON-lines journals, sums each
  writer's close record (`appended=`, `errors=`, `uncertain=`, `pending_remaining=`),
  prints the aggregate and `AGG_ROWS_PER_S`, tees it to `$OUT/test-d-summary.txt`
  and **exits non-zero** on a missing close line or any non-zero
  error/uncertain/pending count (P6-580). The header now documents that the
  historical evidence file is not in the tree.

## Deferred verification (open)

Written down deliberately so it is picked up later rather than assumed done:

- **Missing**: `code/01_platform/04_scripts/tests/test_d_3x20k_wave46.py` — a
  hermetic module in the style of `test_pipeline_lib_wave44.py` /
  `test_eod_controller_wave45.py`, covering: the trap fires on an early exit and
  kills started children; the readiness loop aborts on a never-ready port; the
  wait uses the path the JVM was given and ignores a stale file; `preflight`
  fails before creating anything; the secrets resolver's three cases; and
  `summary_of_journals`'s clean/doctored/missing cases. Estimated ~20-30 min,
  mostly encoding the spot-checks above.
- **Why deferred**: the wave owner chose a short wave (spot-checks + a written
  gap) over the ~60-minute full cycle.
- **Also open, and not resolvable by this wave**: the bench is host-side (3 host
  faketools + 3 host JVMs on 8899-8901) while CHG-122 requires a fully
  containerized data path — `pipeline-lib.sh:101,117` — and the lib's G26 check
  refuses to run the pipeline while host data-path processes exist. Fixing the
  seven findings keeps a bench that today's policy forbids. Retiring it in place
  (the W40 C′ pattern) is the alternative; that is a scope decision, not a bug.
