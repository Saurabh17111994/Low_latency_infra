# CHG-237 — the load-test runner reaps before it asserts and never lies about liveness (wave 47)

- **Status:** recorded — fixed; verification by per-step evidence (no gate run, see below)
- **Filed:** 2026-09-19
- **Source:** audit map wave 47 (`code/01_platform/04_scripts/loadtest-run.sh`, 18 finding ids → 9 unique issues, session e9f995f4).

## What was found

The 18 ids are nine issues reported twice: the draft `P6-127…134` and the saved
`P6-447…456`, and each draft names its saved twin. Both texts agree on all nine.
**No finding was stale and none was premise-wrong** — every one reproduces in the
2026-09-19 source. This is the runner the 20,480/s load sweeps are measured with
(`make loadtest-20k-regression`, `make check-loadtest-env`), so a silent wrong
measurement here is worse than a crash.

1. **P6-127/128 — the reap was unreachable.** `port_8899_free || fail …` ran
   *before* `pgrep -x faketool`, so a stale faketool holding :8899 made the script
   die instead of recovering, and there was no re-check after the reap.
2. **P6-129/133 — fixed readiness path.** `READINESS_FILE_PATH` was the constant
   `/tmp/ingestion.loadtest.ready` and the only `rm -f` lived in the EXIT trap, so
   a `kill -9`ed run left a marker the next run read as "ready" — measuring a JVM
   that had not started.
3. **P6-130/132 — two counting idioms.** The manifest preflight counted with
   `wc -l` while the slice assert counted with `grep -c .`, and the slice came
   from `head -1025`, which trusts the manifest's shape.
4. **P6-131/134 — leaked children and dead time.** `cleanup()` killed only the JVM
   and the faketool; the collector and the liveness watcher were never reaped, and
   the teardown waited the watcher out to t+180 — up to 2 minutes after a collector
   that had already finished.
5. **P6-447/452 — inline credentials.** `ARROW_APP_SECRET=testd`,
   `ARROW_PASSWORD=testd-pass` and a TOTP seed sat in the JVM's environment and
   were therefore readable in `/proc/<pid>/environ`.
6. **P6-448/454 — the bind wait used /dev/tcp.** The same probe B4 exists to
   avoid, and a faketool that died instantly still burned the whole 15s.
7. **P6-449/456 — waits ignored JVM death.** The readiness loop (60 × 2s) and the
   subscription loop (30 × 1s) polled a corpse for up to 150s.
8. **P6-450/455 — the G2 assert raced the log.** One `grep -q real_rate=true`
   immediately after bind could miss a buffered write, and the failure path `cat`ed
   a log that grows at 20k lines/s.
9. **P6-451/453 — unchecked argv and colliding output.** `DURATION_S`/`INTERVAL_S`
   went straight to `sleep` and to `collect.sh`'s `[ "$DURATION_S" -lt 190 ]`, and
   `OUT` had second granularity only.

## What changed

All nine, in `loadtest-run.sh` alone:

- Strays are reaped **first** (`pgrep -x faketool`, exact name only), then the port
  is asserted with the existing `port_8899_free` and the pinned message (1).
- `READINESS_FILE="$OUT/ingestion.loadtest.ready"` — per run, `rm -f` before the
  launch, the same path handed to the JVM and polled by the wait; `cleanup()` and
  the waits use that variable (2).
- One counter, `count_tokens` (data rows, CR stripped), used by `--check-only`, the
  run preflight and the slice assert; the slice is built from a validated header
  plus the first 1024 data rows (3).
- `cleanup()` now reaps the watcher's children (`pkill -9 -P`) and then the
  watcher, then the collector; the teardown no longer waits the watcher out and
  takes a final `liveness_check t+end` on both PIDs instead (4).
- `resolve_arrow_credentials()` sources the gitignored 0600 secrets file before the
  JVM starts; the credential keys are no longer in the env block (5).
- The bind wait uses `port_8899_free` (ss, B4) and breaks early when faketool dies
  (6); the readiness and subscription waits break on JVM death and name the dead
  PID in the failure message (7).
- G2 polls for `real_rate=true` for up to 10s and dumps `tail -20` on failure (8).
- `validate_pos_int` rejects non-numeric/zero durations and intervals **before**
  anything is created, and `OUT` carries `-$$` (9).

## Deviations from the audit's fix text (four, each for a native reason)

1. **Secrets source.** The audit proposes a new `$ROOT/.env.loadtest`. Reused the
   repo's existing gitignored 0600 `code/01_platform/01_docker/secrets.env` — the
   same file `pipeline-lib.sh:81` calls `LIB_SECRETS_FILE` and
   `run-ingestion-full.sh:36-55` sources — with that reader's hardening
   (symlink refusal, 600/400, GNU-then-BSD `stat`). One further difference: the
   canonical reader also demands `ARROW_APP_ID`/`ARROW_USER_ID` from the file, but
   this file has neither, so only the three credential keys are required from it
   and the two identity values stay in the env block, where they were.
2. **Stray reaping stays narrow.** `pgrep -x faketool` + `kill -9`, no broader
   sweep: `-f` would match our own command line, and the port is fixed, so one run
   at a time means a peer run's faketool cannot be mistaken for a stray.
3. **The watcher fix does more than add two PIDs.** Adding them to `cleanup()`
   would still leave the 2 minutes of dead time, so the teardown also stops waiting
   the watcher out and replaces that verdict with one synchronous `alive` check on
   both PIDs — which additionally covers a death after t+180. Residual, documented
   in the code: a `kill -9`'d watcher can outlive itself as a bare `sleep` (no side
   effects, bounded by the original 120s).
4. **The slice mirrors the library.** Rather than only making two counters agree,
   the slice build copies `pipeline-lib.sh`'s P6-473 shape (header comma check,
   ≥2 fields, CR-stripped data rows), so both harnesses slice identically; the
   parity between the runner's counter and the lib's slice idiom is asserted in the
   new test module.

## Cross-file observations (out of scope, recorded not fixed)

- `pipeline-lib.sh:501` counts the manifest with `wc -l` while `:526` counts the
  slice with `grep -c .` — the same mixed idiom P6-130 fixes here. The lib's slice
  build already carries the P6-473 fix, so the two can only disagree on a manifest
  with blank or CRLF lines. Left alone: the lib's guard contract is pinned by
  `test-pipeline-lib.sh` and this wave owns the runner.
- `tiering-smoke.sh:193` still `cat`s `$OUT/faketool.log` on a startup failure — the
  same P6-450 shape in a sibling host harness.
- Same policy tension as CHG-236: this runner is host-side (a host faketool on 8899
  plus a host JVM) while CHG-122 requires a containerized data path, and
  `pipeline-lib.sh`'s G26 refuses to run while host data-path processes exist.
  Retiring it in place (the W40 C′ pattern) or containerizing it is a scope
  decision.

  `test-d-3x20k-run.sh` defaults to `NSE_CM_EQUITY.csv` (2,433 rows, and it *does*
  carry LotSize, so it loads) while its own header documents 1,024 tokens and
  341/341/342 thirds. Pointing that default at the `NSE_CM_EQUITY (1024).csv` this
  runner uses would make the bench self-consistent.
