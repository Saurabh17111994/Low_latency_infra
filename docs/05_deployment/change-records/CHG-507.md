# CHG-507 — `make day` ignores terminal SignalJob archive entries

- **Status:** implemented — day-run suite 65 passed; live board I5 green
- **Filed:** 2026-10-02
- **Source:** found by the CHG-506 live smoke: the first restore attempt left a
  FAILED job (`eca91511`) in the JobManager archive, which the singleton
  checks counted as a second SignalJob. Flink cannot cancel a terminal job
  (`PATCH ?mode=cancel` → 409) and the default memory job store has no REST
  delete, so I5 stayed red and `make day ARGS="start"` would have refused all
  the way to the next JobManager restart.

## What changed

- **`day_run.py`** — new `TERMINAL_JOB_STATES = {FINISHED, CANCELED, FAILED}`
  and `_live_signal_jobs(jobs)`: only non-terminal SignalJobs count toward the
  singleton rules. Used by `decide_signaljob` (keep/restore/refuse),
  `wait_signaljob` (ready wait) and `_checkpoint_age_ms` (I5 age read). A
  retained FAILED job can no longer be mistaken for split-brain, and the
  restore proceeds from the latest savepoint/checkpoint.
- **`docs/06_operations/01-runbooks.md`** — the singleton rule and the I5
  recovery row now distinguish live duplicates (cancel) from terminal archive
  entries (ignored).
