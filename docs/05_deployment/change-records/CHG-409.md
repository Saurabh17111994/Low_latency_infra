## Notes

- **The defect class:** the loop recomputed `next_fire(now)` every iteration, so a slot that
  passed while the scheduler was down (or a fire that failed) was silently skipped until
  tomorrow — the day's only archive chance lost, with a heartbeat that stayed green through it.
- **Why the heartbeat was dishonest:** `write_heartbeat` runs before and after a fire, success
  or not, so a fresh heartbeat only ever proved "the loop is running". The fix keeps that
  liveness signal (the container healthcheck is unchanged) and adds the archival truth behind
  `--last-run`, where the operator's stop gate already looks.
- **Idempotency stays the controller's:** the extra fire is safe by construction — the
  controller's lease and state table own "already archived today"; the scheduler decides only
  when. No new lock, no new mode.
- **Test harness:** the first version waited on `select` + `readline` and was flaky — `readline`
  buffers ahead, so `select` can report "not ready" while the awaited line sits in the
  `TextIOWrapper` buffer (measured: 2 failures in 5 runs, 30 s timeouts). A reader thread feeding
  a queue removed the race; 10/10 green and no orphaned schedulers.
- **missed vs catch_up:** `missed` is a durable fact about the slot ("it was not archived at the
  time"); `catch_up` is the transient state of the recovery attempt. A caught-up slot keeps
  `missed: true` so the record does not rewrite history.
