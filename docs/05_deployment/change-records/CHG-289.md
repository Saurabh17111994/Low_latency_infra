## Why

The plan specified T2 and T6 as *documented commands*, not code, and this record is that rule applied
rather than broken: the check outgrew a command because it has to be run repeatedly, once per session and
once per purchase, and a check that is run by hand is a check whose number drifts. The number had already
drifted once — `B4.7` still claims "nine session transcripts … 34 value-shaped matches", measured with an
ad-hoc pattern set over 130 files, while the corpus is now 624 transcripts.

Four decisions shape the tool:

- **A value never reaches the output, not even on the way to a report.** That is what makes the scanner
  usable on a real corpus: the operator reads a count, not a page of secrets. The corollary is the `decoy`
  column. The plan's own controls plant `dummy…`-shaped values and its documentation repeats them, so a
  report that cannot separate those from a real value is unreadable by construction — and the value cannot
  be shown to help.
- **Inside this repository is a class, not a failure.** The tree is public and reviewed, and its fixtures
  (`AKIAFIXTUREACCESSKEY`, `AKIAIOSFODNN7EXAMPLE`) and documented decoys are deliberate. Such hits are
  printed and counted; `--strict` fails on them too when the question is a public-repo leak instead of a
  workstation one.
- **A scan that did not run is not a clean result.** A missing `--root` or an unparseable `--since` is
  rc=2. This is the plan's own warning, and it is the failure mode that would matter most: an empty result
  that reads like proof.
- **The corpus decides the classes, and the sweep is what said which ones.** A first full pass over
  `$HOME` — 509,050 files — returned 3,045 hits, and reading them is what turned a number into a
  classification: 384 are boto3 type stubs under editor extensions, ~939 are chat transcripts from four
  different agent tools, 159 are token-shaped and nearly all test fixtures, 13 are shell history. Two
  limits are part of the result rather than a footnote: 12,714 files over 2 MB were skipped and 2,290 were
  unreadable, so on a corpus this size "zero hits" is never an absolute claim — it is a claim about the
  files that were actually read.

The tests earned their place during development by catching four real defects in the scanner, all of which
would have produced a confident wrong number: the rc=2 paths used `sys.exit(<string>)`, which exits 1; the
JSON `name` field carried the whole regex match, so it leaked the value it was reporting; a shell form such
as `${O2_PASSWORD:?operator sets this at S7}` survived classification as a value because the form is cut at
its first space and only its prefix remains; and `--since` crashed on `pathlib.date`, which does not exist,
so the date-filtered run printed nothing at all — an empty result that would have read as "no credentials
in new transcripts".

The field produced two more fixes that no unit test would have. The sweep hung for 26 minutes inside
`open()` on `~/.steam/steam.pipe`, a FIFO that blocks until a writer appears, so the scanner now opens only
regular files (`stat.S_ISREG`), counts everything else as `skipped_special` and names that count in its
output — a skipped file class is disclosed, never silently dropped. And the sweep's hits were dominated by
shapes that cannot be values: a placeholder the operator is meant to replace, a relative path to a `.env`
file, a bare brace reference, and `smoke_secret` from the project's own smoke tests. Each was a false
positive that inflated a security number, and each is now pinned by a test — with base64 as the guard that
the path rule cannot swallow a real secret.
