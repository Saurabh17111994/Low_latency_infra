## Notes

- **Fingerprint pinning is deliberate:** the fill copy happens *after* `fingerprint(...)`, so the
  identity keys still hash the raw postback (contract 06 vector 1 stays byte-for-byte valid).
- **Case bug caught by the fixture:** the first implementation upper-cased `orderStatus` but
  compared lowercase literals; the fixture failed `COMPLETE`/`REJECTED` rows on the first run —
  the exact class of drift this fixture exists for.
