## Why

CHG-331's drill proved the bridge leg and found the projection leg fail-closed:
`GatewayHttpServer.events()` answers `503 execution disabled via EXECUTION_ENABLED` while
the gateway's master switch is false. Compose mapped the *same* `${EXECUTION_ENABLED:-false}`
to the gateway and to nautilus, whose Rust config refuses the flag set true at boot — so a
sanctioned window could not open the gateway's projection intake without a per-service
switch. The harness also required `Execution_Attempts`, which the direct-to-nautilus route
never writes (nautilus keeps a file-backed attempt store); `Order_Lifecycle` is the correct
required table.

## What changed

| Piece | Change |
|---|---|
| `docker-compose.yml` (gateway) | `EXECUTION_ENABLED: ${GATEWAY_EXECUTION_ENABLED:-false}` — its own variable, default false; nautilus keeps `${EXECUTION_ENABLED:-false}` (boot guard) |
| `t9_order_sandbox.py` | required table = `Order_Lifecycle`; `Execution_Attempts`/`Fills`/`Positions` reported; a 202 whose `event_emission` starts with `failed` fails immediately with the gateway reason |
| `t8_sandbox_contract_check.py` | +2 checks: gateway switch decoupled and default false; nautilus boot guard not moved to the gateway variable |
| `.env.example` | documents `GATEWAY_EXECUTION_ENABLED` (commented; default false) |
| runbook §Execution mode hop | gateway-enable step + revert, canonical compose form with `--no-deps`, `Order_Lifecycle` poll, intent-replay note for the live sandbox |

## Safety

- Both switches default false; `t8` fails if either defaults true (the regex also catches
  the `GATEWAY_` form).
- Enabling the gateway is a targeted single-service recreate (`--no-deps`); the executor
  never receives the gateway switch.
- Enabling the gateway also enables its intent-forwarding path: `IntentReader` replays
  `Execution_Intent` from offset zero with durable dedup — paper mode turns any pending
  intent into a fake order; for the live sandbox this is a release-gate step (settle the
  intent table first), documented in the runbook.
- The daily runner still refuses all hop postures (`EXECUTION_ENABLED=true`,
  `EXECUTION_BRIDGE_MODE=fake|live`); do not run `make day` in a drill window.
