## What changed

|---|---|

## Results (58,392 rows/variant, 64 features/row — full detail in `logs/feature-spike-20260927/REPORT.md`)

| variant | log bytes | B/row | write rows/s | decode p50 | decode p99 | round-trip |
|---|---|---|---|---|---|---|
| array (ARRAY<DOUBLE> + version) | 20,310,840 | 348 | 2,270 | 24 µs | 104 µs | 500/500 |
| map_int (MAP<INT,DOUBLE>) | 20,925,616 | 358 | 2,317 | 35 µs | 150 µs | 500/500 |
| json (STRING) | 21,381,696 | 366 | 2,241 | 330 µs | 1,790 µs | 500/500 |
| map_str (MAP<STRING,DOUBLE>) | 29,973,528 | 513 | 2,165 | 80 µs | 376 µs | 500/500 |

Findings: string keys cost +43% over id keys; array is 2.9% below map_int but needs the version
column and positional mapping; JSON is 2.1% above map_int with ~9x slower decode; write side is
variant-independent. Recommendation on record: **MAP<INT,DOUBLE>** (bytes within 3% of minimum,
fastest decode, add/remove stays one registry line). Operator picks the encoding; DEC-056 is
updated with the choice.

## Findings recorded (not fixed here)

- Each KV table preallocates ~320 MiB of `.index`/`.timeindex` (16 buckets x 2 x 10 MiB). Raw
  table-dir size says nothing about payload; only `.log` files compare encodings.
- `kv.snapshot.interval=0s` in dev leaves the KV snapshot unbuilt during a short run (~104 KB of
  empty RocksDB metadata for every variant), so KV-state bytes were not comparable here.
- Write acks and lookups both show a ~100 ms p50 floor independent of the variant — client
  request cadence on this dev cluster, not an encoding cost; compare variants, not absolutes.
- The spike tables are scratch (`zz_feature_spike_*`) and dropped after each run; `drop` removes
  the tablet dirs asynchronously.
- A feature-writer path exists on the client side (`GenericMap`, `GenericArray`) and the connector
  side (pinned test); the real table encoding is not chosen until the operator picks one.
