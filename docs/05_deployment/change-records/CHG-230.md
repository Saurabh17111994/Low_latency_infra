# CHG-230 — wave-42 ops tooling: reconcile window deltas, O2 provisioning/ingest contracts, stage-capture parsing

- **Status:** recorded — fixed (2026-09-19)
- **Filed:** 2026-09-19
- **Source:** the wave-42 audit findings P6-428, P6-457–P6-462, P6-572, P6-748,
  P6-757–P6-760, P6-791, P6-792 against five `code/01_platform/04_scripts` tools.

## What happened

Fifteen findings across the ops tooling that the gate and the operator screens depend on.
Each one made a check weaker than it read:

- **`ing-tcp001/reconcile-compare.py`** — **P6-428**: `--pre` had no fail-closed guard, and an
  empty/truncated pre-probe parses to `{}`, so every delta became `post − 0` and a real loss still
  cleared the default `>=` comparison (the bridge and post files were guarded; the baseline was
  not). **P6-748**: the quarantine-mode `RAW>0` check was absolute, so rows written by an earlier
  run on a reused cluster failed a window that lost nothing.
- **`local_int_004_smoke.py`** — **P6-457**: the DDL loop's body was `pass` and the two checks
  after it covered two of the three projections, so a missing `13_order_correlation.sql` passed
  the contract silently. **P6-458**: the "drive the lifecycle" loop iterated a literal list whose
  empty-sequence branch was unreachable — it asserted nothing.
- **`o2-provision.py`** — **P6-459**: `api()` returns the raw body (a `str`) on `HTTPError`, so
  `full.get("hash")` raised `AttributeError` and aborted the whole run — every dashboard after it
  never ran. **P6-460**: `SEED_HISTOGRAM` carried 7 `bucketCounts` for 7 `explicitBounds`; OTLP
  requires `len(bounds)+1` (the +Inf bucket, R-036 in `OtlpMetricsEmitter`), so the collector
  rejects the seed. **P6-461**: the health gate caught only `HTTPError`, so a stopped O2 raised
  `URLError` as a traceback instead of the documented "not ready" + exit 1. **P6-757**:
  `METRIC_TYPES`, `stream()` and `make_panel()` are defined and never called. **P6-758**: the rule
  is a byte rate (`rate(node_network_transmit_bytes_total[5m])`) but its description claimed
  ">80% capacity" and the threshold was 80 *bytes*/s — keep-alives trip it. **P6-759**: a failed
  dashboard PUT was still followed by "dashboard converged" and the run exited 0.
- **`o2_ingest.py`** — **P6-462**: a non-JSON 200 body (proxy/portal) raised `JSONDecodeError`
  through the caller instead of the documented exit 4. **P6-760**: the refusal message always
  named the built-in default secrets file, even when `O2_SECRETS_FILE` pointed elsewhere.
- **`stage_capture_parse.py`** — **P6-572**: a blank/malformed epoch reached the consumers as
  `None` and raised `TypeError` in `sort()`/subtraction. **P6-791**: several sources emit latency
  for the same operator subtask and the metric name carries the source id that the `(task, sub,
  op)` key drops — the last series in the scrape won instead of the max. **P6-792**: `stages.tsv`
  was parsed up to four times per run (default window, divergence, B2 read lag, `--json`).

Measured before the change (2026-09-19): the wave test is red on 13 of 17 legs against the
unmodified tools; `Ran 15 tests` → `FAILED (failures=10, errors=3)`.

## The change

- `reconcile-compare.py`: fail closed on an empty/truncated `--pre` probe; the quarantine-mode
  check now compares the RAW **window delta** (`post − pre`) instead of the absolute value.
- `local_int_004_smoke.py`: one real check for all three DDL projections; the no-op lifecycle loop
  and the sample that existed only for it are gone.
- `o2-provision.py`: `provision_dashboards()` returns the number of dashboards that failed to
  converge (non-dict GET body, failed create/seed/add-panel/rewrite) and the caller exits 1;
  `SEED_HISTOGRAM` gains the +Inf bucket count; a failed health gate catches `URLError`/`OSError`;
  the three dead definitions are deleted; the net rule keeps its expression with an honest
  description and an absolute 80 MB/s threshold.
- `o2_ingest.py`: one `_secrets_path()` resolver used by both the read and the message; a non-JSON
  200 body returns 4.
- `tests/test_alert_threshold_parity.py`: the INFRA-warn-net-80 parity record moves to 80_000_000 —
  the setpoint is bytes/s, and the doc row now says so.
- `stage_capture_parse.py`: rows with an unusable epoch are dropped; latency keeps the max across
  source series; `main()` parses `stages.tsv` once and passes the rows to the report builders
  (optional parameter — standalone callers are unchanged).

Limitation: `local_int_004 --offline` and `reconcile-compare.py` can now FAIL where they previously
passed — that is the fix, and it is the intended direction. The net-80 rule is an absolute rate,
not a capacity ratio: per-host capacity needs a `node_network_speed_bytes` series this stack does
not scrape yet.

## Verification

- `test_o2_tooling_wave42.py`: **17 legs, offline** (no cluster, no network, no docker) —
  `Ran 17 tests … OK`.
- The two suites the gate runs at step 3 (`tests/test_reconcile_compare.py`,
  `tests/test_stage_capture_parse.py`) pass **unchanged** against the fixed scripts: `Ran 20 tests
  … OK` (the `RAW>0` message token and blank-counter tolerance are pinned by them and preserved).
- `py_compile` clean on all five scripts; `local_int_004_smoke.py --offline` PASS against the real
  DDL directory (all three projections present).
- Red-first evidence: the same wave test against the unmodified tools is `FAILED (failures=10,
  errors=3)`.
