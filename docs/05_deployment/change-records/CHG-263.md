# CHG-263 — the infrastructure log stream was empty, not quiet

## Why

The collector's `filelog/infrastructure` receiver reads host log files and routes them to
OpenObserve's `infrastructure_logs` stream, and the observability dossier lists that stream as
delivered. Measured on this cluster, **the stream did not exist**: OpenObserve held four log streams
(`flink_logs`, `fluss_logs`, `platform_logs`, `trading_alerts`) and nothing else.

The receiver had nothing to read, for two independent reasons:

```text
# what it pointed at                        # what the container could see
include: [/data/infra/logs/*.log, /var/log/*.log]
$ grep -rn "infra-logs" docker-compose.yml docker-stack.yml
docker-compose.yml:298:  infra-logs:                      # declared
docker-compose.yml:1160:      - infra-logs:/data/infra/logs:ro   # mounted by the collector
                                                             # ... and written by nobody at all
$ docker inspect prod_otel-collector --format '{{.Spec.TaskTemplate.ContainerSpec.User}}'
10001:10001
```

The `/var/log/*.log` half was worse than dead config: a bind mount the collector **never had**, while
the receiver's own comment called it "optional". And even with a bind, the glob could not have
matched `/var/log/syslog` — 47 MB on the rehearsal host, actively written, no `.log` suffix — so the
system log itself was unreachable by construction.

## What changed

- **`code/01_platform/01_docker/docker-stack.yml`** — the collector mounts the host's `/var/log`
  **read-only** (`type: bind`) and gains `user: "0:4"`. Both halves are forced by measurement: the
  files that matter are not world-readable (`auth.log` and `kern.log` are `640 syslog:adm`, `boot.log`
  is `600 root`) while the image defaults to uid 10001, and a stack file cannot add a supplementary
  group. The comment records the schema measurements (below) instead of the usual "this should work".
- **`code/01_platform/01_docker/otel-collector-config.swarm.yaml`** — the include list becomes
  exactly what the mount contains: `/var/log/*.log` plus `/var/log/syslog`. The
  `/data/infra/logs/*.log` entry is gone, because the volume it names has no writer anywhere.
- **`code/01_platform/01_docker/docker-compose.yml`** and **`otel-collector-config.yaml`** — the
  development stack gets the same bind, the same `user` and the same include list, so the two
  environments cannot drift on this again. The dead `infra-logs` volume is deleted.
- **`code/01_platform/04_scripts/tests/test_09_stack.py`** — `TestCollectorHostLogs` closes the whole
  class of failure, not this instance: every `filelog` receiver's include directory must be covered
  by a mount of the collector service; the only host path it may mount is `/var/log`, read-only; and
  `user` must be set, because the image default cannot open the files the receiver names.
- **`docs/05_deployment/PROD_VM_PROVISIONING.md`** — S4 step 4 names the mount and the privilege, S8
  describes what `infrastructure_logs` carries and the per-node boundary (see Limitation).
  **`docs/08_implementation/10-observability.md`** gains a dated correction, because its evidence
  rows named a stream that was empty.

## Measured

The schema, measured with a throwaway probe stack rather than guessed:

```text
$ docker stack deploy -c probe.yml schemaprobe
services.probe Additional property group_add is not allowed        # inexpressible
$ docker service inspect probeA_probe --format '{{.Spec.TaskTemplate.ContainerSpec.User}}'
0:4                                                                # accepted
$ docker inspect <task> --format '{{range .Mounts}}{{.Type}} {{.Source}}->{{.Destination}} rw={{.RW}}{{end}}'
bind /var/log->/var/log rw=false                                   # restored read-only
```

The host files, measured on the rehearsal host:

```text
-rw-r----- 1 syslog adm  38126 Sep 20 20:35 /var/log/auth.log     # 640 — needs the adm group
-rw-r----- 1 syslog adm   15 M Sep 20 20:42 /var/log/kern.log     # 640
-rw------- 1 root   root 43485 Sep 20 16:19 /var/log/boot.log     # 600 — root only
-rw-r----- 1 syslog adm   47 M Sep 20 20:42 /var/log/syslog       # no .log suffix
$ systemctl is-active rsyslog
active
```

## Limitation

**Host logs are per node, and this covers one node.** The collector is `mode: global` but pinned to
`observability == true`, which in this topology is VM4 alone, so a four-VM deployment carries VM4's
`/var/log` and not VM1–VM3's. The same boundary applies to the service log volumes
(`flink-logs`, `fluss-logs`, `ingestion-logs`): Swarm named volumes live on the node that writes
them, so a task on VM2 writes a volume the collector on VM4 cannot read. Closing that gap means
running the collector (or at least a filelog agent) on every node — a placement change, not a mount
— and it is left as an explicit decision rather than smuggled in here.

**The collector now runs as root:adm in its container.** It was uid 10001, which is why it collected
nothing from these files, and `group_add` cannot be expressed in a stack file, so the choice was this
or no host logs. The mount is read-only, the image has no shell, and ZooKeeper, Fluss and OpenObserve
already run as root in this stack — but it is a widening of this service's privilege, and it is
recorded as such rather than presented as free.

**journald is still not read.** There is no journald receiver, so only what rsyslog writes to
`/var/log` is covered. On this host that is everything relevant; on a host with `journald` only, the
system journal would still be missing.
