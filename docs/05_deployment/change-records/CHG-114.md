## Problem

The Test D bench driver initially omitted `TRANSPORT=proto`, and the Go bridge
silently fell back to the NDJSON pipe (the old, slower path) with only a
low-key INFO log line. The bench ran on the wrong transport without anyone
noticing until log inspection. Benches must not be able to silently run the
old path.

## Fix

`initBridgeEmitter` now distinguishes three cases:
- `TRANSPORT=proto|grpc` → proto frames (unchanged)
- `TRANSPORT=pipe` → NDJSON (deliberate rollback path, quiet — unchanged)
- **TRANSPORT unset/unknown → NDJSON fallback + LOUD stderr WARNING**
  ("UNSET/unknown; proto is the low-latency path, set TRANSPORT=proto explicitly")

The fallback behavior (unset → BridgeEmitter) is unchanged for compatibility;
only the visibility of the decision changed. New test asserts the warning
appears for unset and is absent for explicit `pipe`.

## Impact

- Any bench/run that forgets `TRANSPORT=proto` now shows the WARNING in the
  bridge stderr (captured into the JVM's java.out), making the mistake
  impossible to miss.
- Rollback (`TRANSPORT=pipe`) stays quiet — deliberate, not accidental.
- No throughput/latency change: transport selection logic is identical.
