## Notes

- **Measured effect (smoke `logs/chg486-smoke-20261001-111805`, 120 s, 2 Hz x
  2 433, presence PASS):** `candle_features` FIFTEEN_S +8,658 rows/min vs
  +301,888 rows/min in the CHG-484 smoke under the same protocol (~35x fewer);
  every other TF unchanged (they were seal-only already). The readability
  probe observed **zero** unsealed rows (its "skipped forming" line never
  fired). The live path metrics were unchanged: aggregator
  `compute.candles.live.tick.emitted` ~70-75k/subtask, host
  `compute.features.updates.tick` ~72-77k/subtask, `compute.merged.rows.emitted`
  ~5k/subtask (~6.6% of ticks, i.e. seal-only). S1-S7 latency unchanged
  (S5 p99 67 ms, S6 p99 82 ms).
- **No data loss by design.** Every closed candle and its close-cadence
  features are persisted; forming values are transient and rebuilt per tick in
  Flink memory (intentional amnesia).
- **S10 follow-up.** The stage-profiler's live-readability leg now resolves
  every TF through the previous *sealed* window (staleness up to the TF size)
  because no forming row exists to read. Presence still passes; the leg's
  meaning is stale and should be repointed (e.g., latest-sealed age) or retired
  in a harness-only follow-up — not part of this change.
- The 900 s round was not run under the operator's scope (implement -> suite ->
  smoke); the next 900 s round measures the table growth on this build.
