### Judgement (per W1's `WRONG IF`)

- **Median win, both KPIs**: ingest p50 **33 → 29 ms**, p99 median **75 → 71 ms**;
  tick p50 **47 → 45 ms**, p99 median **93 → 89 ms**; smoke confirms the same direction.
  Consistent with removing the 18 ms source wait.
- **The tail is not attributable to the lever**: the same class (single windows > 100 ms,
  both KPIs moving together) appears today at the **20 ms default** (C4 smoke: 2/13
  windows, max 186 ms) and on the tick path of the 09-29 night baseline (6/60, max
  211 ms). Inside the W1 run every signal-job source subtask read 2 ms, no fetch errors,
  checkpoints clean, no restarts.
- **Honest caveat (not hidden):** W1's worst single window (416 ms) is larger than any
  observed today at 20 ms (186 ms) or in the night baseline (82 ms ingest); small-sample,
  causality unproven but not excludable.
- **Not an SLO pass**: 0/60 windows ≤ 50 ms. The p50 is now below 50 ms; the tail drives
  p99 ≈ 71 ms and belongs to the W3/W4 targets (checkpoint materialization churn / TM
  contention).

**Recommendation before W2:** one **20 ms control run at the same protocol and
time-of-day (900 s)** to measure today's tail rate like-for-like (60 windows). Comparable
> 100 ms windows in the control ⇒ W1 passes cleanly (keep; propose the default change for
W6). A clean control ⇒ step to 5 ms per this item's fallback. The pass-through plumbing
(default 20) is harmless and committed either way.
