## What changed

- `session_now()` reads `DAY_SESSION_OVERRIDE`; only the exact value `open`
  forces the session (`open: true`, `forced: true`, loud
  `FORCED-OPEN (drill: DAY_SESSION_OVERRIDE=open)` label). Any other value
  never forces — fail-closed.
- `preflight()` validates the override before anything runs: an unknown value
  is refused, and `open` is refused when `DEPLOYMENT_ENV` is
  `prod`/`production`. Both `start` and `status` go through preflight.
- `render()` prefixes the verdict with `DRILL ` whenever the session was
  forced; `facts.json` carries `session.forced=true` and the loud label.

## Why

D5 makes I3/I4 PENDING outside the session because an idle feed is expected
off-hours. During an **off-hours drill the pipeline is fed on purpose** (fake
broker + a `MULTITF_SESSION_BYPASS=true` job), and the operator wants the board
to judge those predicates then — without weakening the default PENDING and
without letting a stalled pipeline pass. The `DRILL` marker keeps every such
run distinguishable in the board and its evidence.
