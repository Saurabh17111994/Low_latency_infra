## Why combined-first (operator decision)

- Serial rounds cost ~25 min each, and only W1/W2 are ready today — W3 (checkpoint
  materialization) and W4 (TM CPU contention) are design items, W5 (shuffle removal) is a
  code change, so none of them can join a combined round yet.
- Attribution is preserved by subtraction: W1-alone (2/10,
  `logs/w1-fetchwait-main-20260930-101707`) and the 20 ms control
  (`logs/w1-control-main-<ts>`) are measured the same day on the same protocol, so
  W2's marginal effect = combined (2/2) − W1-alone (2/10).
- Fallback: if the combined round regresses (throughput, checkpoint times, busy), bisect
  with one W2-alone round (20/2). The one-variable-per-round rule remains the fallback for
  the remaining levers, not the default for ready env levers.

  below the control's — it does not trip W2's WRONG IF operationally, but it is the first
