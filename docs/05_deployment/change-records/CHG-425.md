## Notes

- **The clobber is a real race, not a theory:** the interval ticker calls `reportTickCounts()` from its own
  goroutine while main calls `finalTickCountReport.Do(reportTickCounts)` at shutdown. With counts only
  growing, a stale write means the reconcile reads fewer emitted ticks than the bridge actually emitted
  — the ING-TCP-001 evidence would under-report, which is exactly the failure mode the evidence exists
  to rule out.
- **Determinism took two shapes:** the first version of the clobber test released both reports at once
  and passed under the bug by lock-acquisition luck. The hook now holds A inside the lock and, when the
  buggy order lets B snapshot early, releases B first and waits for its write before releasing A — the
  assertion is then the same in both orders, and only the buggy one fails.
- **The read-only-dir test distinguishes the two writers:** `os.WriteFile` opens an existing file
  for write and succeeds even in a read-only directory (truncate + write in place), while
  `CreateTemp` needs directory write permission and fails cleanly — so the test fails under the old
  writer and passes under the atomic one.
- **`p1_review_fixes_test.go` (final Once semantics) needed no change:** it asserts the disabled path
  writes nothing and the enabled path writes once; both hold under the new writer.
