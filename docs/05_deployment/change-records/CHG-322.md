# CHG-322 -- Ingestion survives a not-yet-ready Fluss: bounded startup readiness wait

- **Status:** landed 2026-09-26 -- failing-first red (test-compile) -> green
  (`make test` rc=0, common 743 / ingestion 508 surefire); static-check 0
  failures; docs-audit all pass. The compose-recreate behaviour drill runs with
  the daily-runner validation (plan P4-3/P4-4).
- **Filed:** 2026-09-26
- **Source:** the documented `make up` hazard (Makefile, 2026-09-24): when the
  Fluss layer is recreated, `fluss-coordinator` and `fluss-tablet` come back
  with no elected leader for `raw_table_1`'s buckets. Ingestion starts into
  that window, the schema step fails, the process exits 1, and the
  `on-failure:3` policy retries into the same wall -- the feed stays down until
  the ingestion service is recreated by hand. Nothing made ingestion wait, and
  the Fluss services publish no healthcheck. Compose `depends_on` conditions
  cannot fix this: Swarm ignores them.

## What changed

| piece | change |
|---|---|
| `FlussStartupReadiness` (new) | bounded wait before the schema step: read-only `admin.getTableInfo(raw_table)` probe (the same predicate `pipeline-lib.sh`'s `FlussReadyProbe` uses), retry only on `RetryClassifier.RETRYABLE`, capped exponential backoff (250 ms -> 5 s), budget `FLUSS_STARTUP_WAIT_MS` (default 180 000 ms, range 0..600 000); fatal fails fast, unknown fails closed (R-285), a missing table ends the wait and lets the schema step create-or-report |
| `IngestionService.main` | step 2b: run the wait (skipped when the budget is 0) before schema verification |
| `IngestionConfig` | `FLUSS_STARTUP_WAIT_MS` parsed, builder default 180 000, diagnostics-map entry |
| `RetryClassifier` | `isTableMissing(Throwable)` public helper; the table-absent patterns are extracted so `isFatal` and the readiness wait share one source of truth (classification outcomes unchanged) |
| `FlussClientAdapter` | `parseTablePath` private -> package-private so the probe reuses the same parsing |
| `Makefile up:` comment | hazard note updated: the race is absorbed by the wait; manual recovery guidance retained |

## What did NOT change

- Append-time retry semantics and every `RetryClassifier.classify` outcome (the
  refactor is behaviour-preserving; pinned by the existing suite plus the 4 new
  `isTableMissing` tests).
- The zero-ack watchdog boundary: the wait ends before the writer and bridge
  start, so "never appended" semantics are untouched.
- Schema verification, DDL bootstrap, manifest loading, the bridge path, and
  the compose service topology.
