# CHG-301 — FIP-27 (lake clean schema): adopt by sequencing, verification only

## Summary

FIP-27 is the Fluss 1.0 change that creates newly tiered lake tables with a clean
physical schema (user columns only) instead of appending the legacy `__bucket`,
`__offset`, `__timestamp` system columns. It is already implemented inside the Fluss
1.0.0 binaries we run -- this record adopts it by verifying the required component
order and the scheduling rule, not by changing anything. No Fluss source file was
read for modification and none was modified; the `Fluss_v_1.0.0` worktree was not
touched. This executes plan decision D2 (take FIP-27 in this upgrade).

## Component order (the documented sequence, already the actual order)

1. Lake-reading Flink connectors and lake storage plugins -- on 1.0.0, no coordination needed.
2. Tiering service -- script pin on 1.0.0; restart only after readers are on 1.0 (satisfied).
3. Fluss cluster -- on 1.0.0.

## Scheduling rule

Create no new lake table until every reader is on 1.0. That single rule converts the
rollback hazard into a sequencing note: the only dangerous combination is an old reader
facing a new clean table, and with zero lake tables being created it cannot arise.
