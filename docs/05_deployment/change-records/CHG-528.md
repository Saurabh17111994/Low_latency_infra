## What changed

- `stub_chronyc` (test-only helper): after writing and chmod-ing the stub,
  it performs one warm-up `Command::new(&path).arg("tracking").output()` and
  retries only `raw_os_error() == 26` (ETXTBSY) with a 5 ms backoff (200
  attempts max). One successful exec proves no process still holds the file's
  write descriptor, so every later exec in the tests is safe. A non-ETXTBSY
  result (including the stub's own non-zero exit) ends the loop immediately.

## Why

- `std::fs::write` closes the stub before the test execs it, but a concurrent
  test thread's `fork` can inherit the write descriptor for the instant
  between create and close; the kernel then refuses `exec` with ETXTBSY. Under
  the gate's pooled load the fork→exec window is wide enough to lose the race.
