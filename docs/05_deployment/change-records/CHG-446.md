## What changed

1. **`SignalStrategy` — the request side.** New default
   `onLiveTick(RowData live, ContextView context, FeatureView features, Collector out)`
   delegating to the existing feature-aware overload. This overload is required for the
   plan's flow — without it a strategy has no way to *ask* on its tick (a new
   `onContextReady` alone would be unreachable). Same DEC-056 default-delegation pattern,
   so non-fetching strategies are byte-identical; the host calls this form.
2. **`SignalStrategy` — the ready side.** New default no-op
   `onContextReady(live, context, out)` plus the feature-aware form the host calls. Its
   Javadoc pins the hard re-entrancy rule: the same `(instrument_token, last_event_time)`
   may be evaluated more than once (a live tick plus one or more ready wake-ups) and
   implementations must be idempotent — emitted rows are deduped by their deterministic
   `candidate_id`. Only data-ready transitions call it: timeout/absent/failure is counted,
   cooled down, and re-evaluated on normal live ticks.
3. **`ContextView`** — now handed to every live tick. With the flag off it is a disabled
   singleton (`isEnabled() == false`, every read `null`, nothing scheduled), matching the
   plan's rollout-flag sentence.
4. **`ContextProvider`** — `drainArrivals()` now returns exactly the keys promoted in that
   pass (C2 re-dispatches those), plus `hasPendingForToken(long)` for the host's
   snapshot/timer decision. Mailbox discipline unchanged.
5. **`StrategyHostFunction`** — at the top of `processElement1` completed fetches are
   promoted before the fan-out (a promotion landing between ticks is still visible on the
   very next live tick of the same window); the fan-out calls the context-aware overload;
   after it, while the token has a pending request the host retains a private
   field-by-field copy of the live row and arms at most one keyed processing-time wake-up
   (`CONTEXT_WAKEUP_DELAY_MS = 2`, armed-flag bookkeeping, no timer when nothing pends).
   `onTimer` promotes arrivals, calls `onContextReady` on the retained live snapshot for
   every promoted token whose slot exists, re-arms while the firing key is still pending
   and drops snapshots that have no pending work left. Timer dispatch is isolated per
   strategy (same failure accounting as `onLiveTick`).

## Note on plan wording

The plan's C2 text names only the `onContextReady` addition; the implementation also adds
the context-aware `onLiveTick` overload, because the request side otherwise does not
exist (a strategy could never trigger a fetch). It follows the plan's stated pattern
("same pattern as the DEC-056 feature overloads") and changes no non-overriding strategy.
