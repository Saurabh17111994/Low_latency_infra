## Problem

The dedup state TTL (`DEDUP_TTL_MS`) was pinned at `300000` ms (5 minutes).
At the 60,000 ticks/s design envelope, the dedup MapState would hold
~18M entries ≈ 2.45 GB — the entire managed-memory budget — and the
`SIGNAL-warn-dedup-state` alert threshold (6.5M entries) was derived from the
old 20,480 t/s × 300 s envelope, making the alert fire at 2.8× below the new
design envelope. The 300 s value was a conservative safety margin for a
broker-replay risk that is now ruled out by evidence.

## Evidence (broker replay horizon)

`Arrow_broker/llms-full.txt/index.md` (the broker's complete API docs, 9,115
lines, all searched):

- `sub` command = "Start receiving data for specified tokens" (line 5325) — live-only, no replay.
- Reconnect flow: client re-subscribes from its local subscription map after `on_open`; server sends only a 540-byte binary ack packet (lines 2981, 3954).
- No initial-data / buffered / catch-up / missed-data language anywhere in the docs (full sweep, 0 hits).

Per user decision (2026-08-28): **broker never replays old ticks on reconnect.**

Duplicate horizon therefore = checkpoint restore rewind (≤ 10 s checkpoint
interval) + connector rewind + ingestion retry — all bounded well under 60 s.
60 s TTL = 6× margin over the 10 s checkpoint bound.

## Fix

1. `PlatformConfig.DEDUP_TTL_MS` `300_000L` → `60_000L` (javadoc updated). All
   startup validation (`validateLoadBearing`, `SignalJobConfig` pin) follows
   the constant automatically.
2. 30 test files: `DEDUP_TTL_MS` env value `"300000"` → `"60000"`.
3. 6 test files with a `TTL_MS = 300_000L` constant or value assertion →
   `60_000L` (FingerprintDedupFunctionTest, DedupRocksDbThroughputMemoryIT,
   DedupBaselineMeasurementTest, DedupExpiryTest, SignalJobConfigTest,
   SignalHarnessContractTest).
4. `docker-compose.yml` ingestion env `DEDUP_TTL_MS: "60000"`.
5. `o2-provision.py` `SIGNAL-warn-dedup-state` threshold `6500000` →
   `3600000` (60,000 t/s × 60 s ≈ 3.6M entries) + description updated.
6. Dashboards `dedup-state.json` / `manifest.json`: "5-minute"/"300000" →
   "1-minute"/"60000".
7. DDL `24_fingerprint_dedup.sql` comment: value refs updated + marked
   HISTORICAL (DEC-038 era, superseded — not a live startup dependency).
8. Docs truth-lines (9 files): 300000/5-min → 60000/1-min, including runnable
   recipes (`21-savepoint-rollout.md`, `01-runbooks.md`, `04-signal-job.md`
   JobGraphDump).
