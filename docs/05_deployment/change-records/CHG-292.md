## Why

The operator pastes these blocks on VM day. Until now nothing tested whether they could run: the
documents were reviewed as prose, and the one rule that existed — every fenced shell block passes
`bash -n` — lived only in the author's memory.

## What C18 checks

Over the provisioning guide and every `docs/06_operations/*.md` runbook: each `bash`/`sh`/`shell` block
passes `bash -n`; carries no `<...>` placeholder; references repository paths that exist; and starts every
command with a word that resolves on the workstation, is a shell builtin, or is on
`TOOLS_NOT_ALWAYS_PRESENT` (`aws`, `chronyc`, `docker`, `docker-compose`, `journalctl`, `mc`, `scp`,
`ssh`, `systemctl` — tools that legitimately live on a VM or a CI runner rather than here). `console`
blocks are excluded on purpose: they hold a transcript, so `bash -n` over one would fail on its output.

## Measured scope

A census ran before the check was written, and it decided the design: 10 files, 33 shell-tagged blocks,
54 distinct command words. The census — not guesswork — is what named the parser requirements
(continuations joined, heredoc bodies dropped, quoted separators not split, `$VAR` first words accepted)
and the tool list. The check also fails when the document set is empty or when no shell block exists
anywhere, so a rename cannot turn it into a check that passes while measuring nothing.

## The findings, and which side was wrong

The first run over the real documents produced 9 findings. Each was traced to its line before anything
changed. Six were the checker being wrong, and each is now pinned by a test:

- `docker logout ghcr.io   # … the token need not stay cached` — the `;` inside a trailing comment
  started a phantom command (guide line 644).
- `IMAGE="${IMAGE_NAME:?set the locally built project image name}"` — a quoted assignment value holding
  spaces made `the` look like a tool name (guide line 654).
- `O2_PASSWORD=$(grep … | cut -d= -f2) make …` — the `|` inside `$( … )` was split (alert-routing
  runbook line 50).
- `docker logs … 2>&1 | grep …` — the `&` of a redirection was read as a separator, inventing a command
  named `1` (runbooks line 103).
- `--expect code/01_platform/04_scripts/prod_vms.json` — the inventory the guide tells the operator to
  write at S1; it is an input, not a repository file (guide line 1063).
- `# the clone S4 step 0 made` — a trailing comment after an assignment (guide line 955).

The remaining three were the same two shapes as the first two. Zero findings is therefore a result of
fixing provably wrong classifications, not of weakening the check to reach zero: the must-fail controls
still fail, and `docs-audit` now fails on any of them.

## Known ceiling

The command check validates the tool word, not its subcommand: `docker stak` passes because `docker`
exists. Catching that would mean encoding each tool's interface, which is not worth its maintenance here.
`console` blocks are not checked at all, and the plan's second piece of evidence for T17 — "a fresh reader
can name the first three actions" — is a person reading the guide, which is VM-day work.
