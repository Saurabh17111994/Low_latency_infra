## Notes

- **Why the constructor owns the invariant:** the DDL sentence is prose; the record is the boundary every
  writer and reader shares. Putting the iff there means a non-canonical pair cannot travel further in
  either direction (write or read), instead of each call site deciding.
- **Readers needed no behavior change for legitimate rows:** a legacy NULL is only legitimate where the
  quantity is 0 (the old contract), and that pair still decodes to 0 and constructs fine. A NULL beside
  a live quantity was always corrupt; it now fails closed (the compute deserializer counts it as a
  malformed skip, the store throws).
- **The gateway writer is the only nullable surface:** `NormalizedExecutionEvent.Position` carries
  `Long` averages (Nautilus images), while every other path uses primitive longs — so the
  canonicalization lives there, and its javadoc qualifier now states the one derived value.
- **Fixtures were the real fallout:** four test files built non-canonical pairs (zero price with a live
  quantity). Correcting them surfaced that `TestPositionsRows` (compute) fed NULL averages beside live
  quantities — the exact shape the new invariant rejects; the rebuilt-common compute run confirms the
  corrected fixtures.
