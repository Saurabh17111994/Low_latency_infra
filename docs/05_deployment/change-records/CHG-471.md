## What changed

1. **`DdlBootstrap`** (ingestion service, the second create path after the DDL
   corpus): `raw_table_1` and `candle_closed` descriptors now ship
   `table.datalake.enabled=false` (with the DEC-060 note). This was the gap that
   survived S4: a fresh stack was still created archive-on through this path.
   The lake options (`format`/`freshness`/`auto-compaction`) stay, so a later
   enable-through-the-sync works (proved live on `candle_closed`, CHG-465).
2. **`DdlBootstrap` registry**: the corpus gained DDL 35 (W-B1) and
   `DdlBootstrapSchemaAgreementTest.everyDdlIsRegistered` requires every
   committed DDL to be registered — `candle_features` is now registered
   (`CANDLE_FEATURES_SCHEMA`: 17 columns = candle_closed's 15 + `features` +
   `sealed`, PK/bucket `instrument_token`, 3 d, kv v2, lake options present and
   `enabled=false`), **registry-only** like `feature_values`: existence-checked,
   never bootstrap-created (A4.4). New pin:
   `candleFeaturesRegistryMatchesDdl` (red -> green with the registry entry).
3. **`DdlText` javadoc**: the dev forcing note now says DEC-060 ships
   `enabled=false` in the production definitions too, so the forcing only
   matters for fixtures that still declare `true`.
3. **Manifest-size pins in common** moved 27 -> 28 (W-B1 follow-up; they failed
   loudly, exactly as their comment intends).
