# CHG-125 — Wave 2: broker-facing boundary hardening (68 findings)

## Why

Wave 2 of the P3 audit covered the boundary the executor shares with a venue: the Go
execution bridge (`06_execution_bridge`) and the Rust bridge client it speaks to
(`04_executor/src/bridge`). 68 findings across command validation, credential re-auth,
HTTP/WebSocket framing, the fake broker and the report path. They are not one bug; the
common shape is a boundary that answered with more confidence than the evidence
supported — a body shorter than its own Content-Length reported as a complete shorter
body, a bare `101` accepted as a protocol upgrade, a fill attributed to whichever order
happened to share a client ref, an unbounded report channel that turned a stalled
consumer into unbounded memory growth, and two validators (Go and Rust) that disagreed
about the same envelope.

## What changed

Commits on the wave branch only: 46 commits for the first 56 findings (models, postback,
broker, reauth.go, server.go, main.go, fake_broker.go and their tests), 1 commit for the
docs write-back, and 11 commits for the final 12 Rust findings
(`7cc599d4 d1e9f552 55f72d68 a21f1e9f 6dca4bd6 2a1b5a68 4306bce2 fa479ac7 402b7464
07092466 faf5e75c`).

Behaviour that callers can observe, and that the completeness of this record rests on:

- The Go and Rust validators now return the same verdict for the same envelope
  (`validateOrderCommand` ported field-for-field into `OrderCommand::validate`). The
  Rust side refuses envelopes it previously accepted - padded exchanges, whitespace or
  oversized symbols, quantities outside i64, stop-loss order types, non-numeric/zero/
  negative LMT prices - and accepts MKT `0.0`/`00` and a padded transaction_type it
  previously refused.
- Unknown protocol fields are ignored on both sides (version skew is `contract_version`'s
  job), so a field added on the Go side no longer fails Rust decoding.
- The report channel is bounded (`BRIDGE_REPORT_BUFFER`, 4096) and producers await the
  send: backpressure reaches the caller instead of becoming memory growth.
- HTTP reads stop as soon as a Content-Length response is complete and refuse a
  truncated body; chunked bodies remain EOF-terminated.
- The WebSocket handshake requires a real upgrade reply (Upgrade/Connection/accept-key
  shape) and refuses non-minimal frame lengths.

## Limitations, disclosed

- P3-433 is partial: the upgrade reply's header shape is enforced, but
  `Sec-WebSocket-Accept` is not verified against `base64(sha1(key + GUID))` - the crate
  has no SHA-1 and adding one is a dependency decision, so a value-shaped forgery still
  passes on a loopback-only socket.
- P3-426 was closed as a falsified premise, with no code change: the trait's futures are
  spawned (`http.rs:568`, `:688`), so the `Send` bound in the finding was genuinely
  required.
- P3-431 (CSPRNG nonce/masks) has no behavioural red; the change is verified by the
  module suite plus its entropy source, not by a failing-then-passing test.
- Go's `request_id` length bound (128) is still not mirrored in Rust, deliberately left
  out of P3-188's scope rather than folded in.
