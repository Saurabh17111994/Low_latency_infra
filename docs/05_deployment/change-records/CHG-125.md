# CHG-125 — One stack, one writer: stricter step 8, a stack lock, canonical compose, a replay memo

_Nothing here changes trading behaviour. All four changes are in the verification
harness and the way the shared stack is driven; the product code is untouched._

## Why

Four separate findings on 2026-09-13, each measured before it was changed:

* **Two certificate runs died at the preflight, not at a step.** Both printed
  `DRIFT compose would RECREATE 01_docker-flink-jobmanager-1,
  01_docker-flink-taskmanager-1, 01_docker-compute-1` and finished in ~2 s
  (`stack_generation=6be4450751022f02`). The same check reported 0 recreations a
  minute before and after both, 12 consecutive dry-runs reported 0, and no
  container was created or recreated in 25 minutes (`RestartCount=0` on all three;
  `docker events` showed only a one-shot `compute` starting at 14:56:04 and dying a
  second later). A second worktree was rebuilding images into the shared stack —
  work that no gate step depends on. The gate was refusing over services it never
  touches.
* **Gate step 8 accepted a clock as evidence.** The check ran
  `image_staleness_check.py` without `--require-stamps`, so an image built without
  stamps reported `FRESH (timestamp proxy: no build stamp)` and exit 0. Measured
  both ways on the committed command: with the flag `NO-STAMP` exit 1, with only
  the flag removed `FRESH … (timestamp proxy)` exit 0. `make images` already
  demanded stamps for all eight images; the gate's own step did not.
* **Four compose sites drove the stack through a different config.**
  `run-full-suite.sh` (build / `up -d` / `stop ingestion`) and `start-all.sh` used
  the bare `-f` form, which does not load `secrets.env`. This is the same
  divergence that recreated the coordinator mid-drill at step 11 (the
  `ddl_apply_smoke.py` fix): a stack started under one config and driven under
  another. They were registered as debt by `test_compose_form_contract.py`.
* **A replay was indistinguishable from new evidence.** Two green runs on the same
  (tree, stack) pair are one fact, not two, and nothing in the harness said so.

## What changed

1. **Step 8 demands a build stamp.** `--require-stamps` is now passed, scope
   unchanged (`--service ddl-apply`). The step's NOTE states that the stamp — not
   the build clock — is the evidence, and that the other seven images are covered
   by `make images` and `make check-image-stale` at release.
2. **`make up`, `make down`, `make clean`, `make images`, `make ddl-image` take the
   gate's lock first.** New `code/01_platform/04_scripts/stack-lock.sh` locks the
   same inode the gate uses (`logs/.monday-gates.lock`) and `exec`s the command, so
   the lock lives exactly as long as the mutation. Fail-closed: another holder →
   `STACK BUSY` and exit 4 with nothing run; `flock(1)` missing → refuse.
   `STACK_LOCK_HELD`, exported by the gate once it holds the lock, is a
   pass-through so a run cannot deadlock against commands it starts itself.
   `make clean` (`compose down -v`) was the dangerous one: it could have deleted a
   running certificate's catalog.
3. **Every compose invocation site uses the canonical form.** All four sites now
   carry `--env-file .env --env-file secrets.env`; `start-all.sh` refuses loudly if
   `secrets.env` is missing instead of failing obscurely inside compose. The
   registry rows in `test_compose_form_contract.py` moved with them, so the test now
   fails in *both* directions: a DIVERGENT row that became canonical, and a
   canonical row that drifted back. Debt report prints none.
4. **A certificate cannot be replayed as new evidence.** The preflight prints the
   pair it certified as `fingerprint=<tree_hash>:<stack_generation>`.
   `gate_memo.py` records it in `logs/.gate-memo.jsonl` (untracked, so remembering
   cannot dirty the tree); the first certificate for a pair wins. A run whose pair is
   already recorded prints `REPLAYED@<time> — first certified in <run dir>` and
   continues; with `--no-replay` it refuses before step 1 (exit 4, `GATE_DECIDED`
   set, no verdict line — nothing was verified). The memo is written only by a clean
   certificate (`GATE RESULT`, 0 skipped), so a subset or sweep run never enters it.
   A missing or half-written memo is never fatal: unreadable lines are skipped.

## Evidence

* Step 8, both directions, on the command extracted from the committed script:
  stamp-less image → `[FAIL] ddl-apply … NO-STAMP: image carries no build stamp`
  exit 1; same command with only `--require-stamps` removed → `[OK ] ddl-apply …
  FRESH: image … >= source … (timestamp proxy)` exit 0. `make ddl-image` restores
  the stamp and the committed command exits 0 with
  `FRESH: stamp b9bbc30baa15… matches the sources`.
* Stack lock, 9/9 assertions against the real lock file and the real targets: under
  a held lock `make up` exits non-zero printing `STACK BUSY` and the holder's pid,
  with every container ID and the ddl-apply image ID unchanged; `make ddl-image`
  rebuilds nothing; `STACK_LOCK_HELD=1 make ddl-image` passes through; after release
  `make up` exits 0 and the catalog guard reports healthy. `down`/`clean` were
  **not** executed (they destroy the stack) — their wiring is asserted instead.
* Compose form, both directions: with the sites fixed but the rows still DIVERGENT,
  `FAILED (failures=2)` naming `run-full-suite.sh:410: this site now carries both
  env files — remove it from the DIVERGENT registry` and the unregistered
  `--env-file secrets.env up -d zookeeper …` command; with one site reverted in
  place, `FAILED (failures=2)` naming `run-full-suite.sh:396`. The file was restored
  byte-identical (sha256-checked).
* Replay memo, 11/11 by extracting the two gate functions verbatim from the
  committed script: unknown pair silent; first record writes one line; a replay
  prints `NOTE: REPLAYED@…`; `--no-replay` exits 4 printing the marker and the
  remedy; the committed body sets `GATE_DECIDED`; a second record is a no-op; an
  empty fingerprint never looks up; a different pair is not a replay. Writing the
  memo into the real `logs/` leaves `git status --porcelain` empty.
* Preflight recreate scope: a churn-only plan now prints `WARN compose would
  recreate …` and passes, while a coordinator/tablet/zookeeper recreation still
  refuses (8/8). Gate static step: 56 scripts clean. Doc audit: PASS. Python suite:
  `Ran 436 tests … OK`.

## Limits

* The recreate check samples once, at the start: a Fluss container recreated
  *during* a run is still not detected. It refuses on the services the verdicts
  depend on (coordinator, tablet, zookeeper) and only warns about the rest — which
  is what removes the false refusals above.
* The memo guards from the moment it exists. The certificates written before it
  (including `813f3b2`, the six hardening commits) are not in it, so re-running
  *those* trees would not be flagged.
* The lock only helps if stack mutations go through it. Scripts that call
  `docker compose` directly (e.g. `run-full-suite.sh`'s ingestion up/stop) are now
  canonical but still unlocked; extending the lock to them is a follow-up.
