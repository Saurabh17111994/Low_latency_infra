## 1. The clean-break drill accepted a `tables` value it could not use (P6-348)

`clean_break_drill.py` type-checked its manifest fields except `tables`, so a
string arrived where a list was expected and the drill failed later with a
confusing error. It is now a list of non-empty strings or a named FAIL, with 15
tests (5 discriminating).

## 2. The soak evidence kept one series out of many (P6-200)

`soak-o2-evidence.py` flattened an O2 query response into a single JSONL record
carrying scalar `n_points/first/last/min/max`, so a query returning several
series recorded one of them and the scorecard's medians were computed over a
fraction of the data. Each series is now its own record with additive `series`
and `series_labels` fields, and the historical scalar fields are still written
per record so existing consumers are unaffected. An answered-but-empty query
still writes one record with `n_points: 0` — "the query returned zero series"
must stay distinguishable from "the query never ran".

## 3. A non-JSON body crashed the run instead of being recorded (P6-547)

`json.JSONDecodeError` (and `UnicodeDecodeError`) escaped the per-query handler,
so one HTML error page from a proxy aborted the whole evidence run. `ValueError`
is now caught: the body is recorded as a query failure and the run continues.

## 4. A reported CRLF secret leak that does not reproduce (P6-788)

The finding said a secret read from a CRLF-encoded file kept its trailing `\r`
and was compared/emitted with it. Tested directly: Python opens files with
universal newlines, so the `\r` is already gone before `rstrip("\r\n")` runs —
for CRLF files and for `\r`-only files alike. The call was kept as
belt-and-braces with a corrected comment, and the test is demoted to `# pin`.
The commit body states the non-reproduction rather than claiming a fix.

## 5. Cleartext Basic auth to a remote host (P6-789)

`soak-o2-evidence.py` sent its Basic Authorization header over whatever scheme
`O2_URL` named. A plain `http://` URL on a non-local host is now a REFUSED
(exit 2) with a message naming the header and the host, and
`O2_ALLOW_INSECURE_HTTP=1` downgrades it to a WARN for a deliberate lab setup.
localhost / 127.0.0.1 / ::1 / 0.0.0.0 stay allowed.

## 6. The end-to-end soak's universe arithmetic (P6-217, P6-566)

| Was | Now |
|---|---|
| `split -l 811` into a fixed `slice_aa/ab/ac` loop, with the universe file at a developer-machine absolute path | the universe size is read from the file, `PER_SLICE=$((UNIVERSE_ROWS/3))` is derived, a size not divisible by three is a named FATAL, the slices are enumerated from what `split` actually produced and the run requires exactly three, and each manifest's token count is checked against `PER_SLICE`. A grown universe no longer hides a fourth slice nothing loads; a shrunk one fails immediately and legibly. `NSE_PATH` overrides the library default `LIB_MANIFEST` |

## 7. Credentials on the command line (P6-218)

`ARROW_APP_SECRET`, `ARROW_PASSWORD` and `ARROW_TOTP_KEY` were passed as `-e`
literals — visible in `ps`, `docker inspect` and shell history. They come from
`--env-file "$LIB_SECRETS_FILE"`, matching the compose path already fixed by
P6-146; the app/user ids stay overridable and are no longer baked in.

## 8. The tick leg was a ratio test that a uniform stall satisfies (P6-219, P6-220)

| Was | Now |
|---|---|
| each token's count was compared against the median of all tokens. Every token at half rate has an identical ratio to the median, so the drill passed | the leg additionally requires (a) full slice coverage, (b) `total` equal to the sum of the per-token counts, (c) per-container tick lifetimes, and (d) an implied active window that accounts for the container's life within `TICK_STARTUP_BUDGET_S` (default 45 — 19 archived runs show 3.2–33.2 s of legitimate startup and idle). A uniform stall now fails with "GLOBAL rate shortfall". The budget knob is validated as an integer |

## 9. Both REST polls discarded their own errors (P6-567, P6-569, P6-570)

| Was | Now |
|---|---|
| `curl` stderr was dropped and replies were compared as unvalidated strings, so a malformed body produced "integer expression expected"; a FAILED job was polled for the full 200 s before reporting "never RUNNING"; readiness and subscription gates waited out their timeout on a dead container with no cause; an empty `JOB_ID` made the poll query `/jobs/` (a list) and silently skipped the cleanup cancel, leaving the job running after a "passed" drill | errors are kept in files under the run's output directory, replies are validated as numbers, terminal job states (FAILED, FAILING, CANCELED, CANCELLED, SUSPENDED, FINISHED) fail fast naming the state (RESTARTING is not terminal), both waiting gates check container liveness and print the log tail on deadline, and `JOB_ID` is validated before use |

## 10. Leaked log mirrors and a swallowed cancel failure (P6-568)

The three `docker logs -f` mirrors were never tracked, so every run leaked three
orphaned tails once `docker rm -f` removed their containers; a failed job cancel
was discarded. Mirror PIDs are now tracked and killed in cleanup, and a cancel
failure is a named WARN.

## 11. The host-N7 census parse (P6-571)

`cut -d= -f3` broke on any format drift and left `[ -ge ]` to die on a
non-numeric value. The count is parsed with an anchored `sed`, the census is
dumped on failure, the probe's stderr is kept, and a bad parse is a clear fatal
rather than an arithmetic error.

## 12. The clean-break simulation reported convergence on evidence that proves nothing (P6-287, P6-288, P6-679, P6-680, P6-681)

| Was | Now |
|---|---|
| the three-argument `run()` derived both the reference and the replayed projection from the same `log` instance, so a mutated log trivially reconverged — the class Javadoc claimed the opposite; LWW overwrote in list order, so a reordered log picked an arbitrary winner and still compared equal to itself; a null event or null table threw NPE out of the run; projections were keyed `"table\|key"` and selected with `startsWith`, so a table named `a\|b` leaked into a selection for `a`; and each table re-streamed the whole log twice while `apply()` did a linear `List.contains` per event | `RunResult` carries `immutabilityVerified` (false exactly when the reference came from the replayed log) and the Javadoc states which overload can prove what; the LWW winner is decided by `(offset, sourceVersion)`; nulls are reported as violations with `converged=false` instead of throwing, and an empty table list is a violation too; keys are a `(table, key)` record; the counts come from one pass and the table lookup is a `Set` |
