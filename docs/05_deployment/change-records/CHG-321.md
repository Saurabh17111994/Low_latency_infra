# CHG-321 -- DataStream full snapshots with a zero last price are quotes, not invalid trades

- **Status:** landed 2026-09-26 -- failing-first red -> green (`make test`, 495
  tests); scoped suite, static-check and docs-audit green
- **Filed:** 2026-09-26
- **Source:** the first real-broker bring-up dry run (2026-09-26, `FEED=real`,
  DataStream `ARROW_FEED=token`, 2 433 tokens) logged
  `proto tick processing error: VALID_TRADE requires lastPricePaise > 0` for
  real ticks with `ltp_paise = 0`. The classifier (`IngestionService`) labelled
  every `full`-mode snapshot `VALID_TRADE`, and `TickPacket.validate` requires a
  positive last price for that validity -- so a scrip that has not traded yet
  (before its first trade, illiquid, off-hours) had its snapshot quarantined as
  an `INTERNAL_ERROR` and never reached `raw_table_1`. The fake broker never
  emits a zero price in `full` mode, so no test covered this path.

## What changed

| piece | change |
|---|---|
| `IngestionService` validity classifier | `full` + `ltp_paise <= 0` now classifies `VALID_NON_TRADE` (row stored as `QUOTE`); `full` + positive price stays `VALID_TRADE`; `ltp`/`ltpc` keep their `INVALID_VALUES` requirement; `quote` mode is untouched |
| `IngestionNoSilentDropTest` | corpus case for the real-DataStream shape: feed `token`, mode `full`, `ltp_paise = 0` -> `APPEND` |

## What did NOT change

- Candle/signal behaviour: `CandleAggregateFunction` accumulates only
  `tick_type = 'TRADE'`, and a zero-price snapshot has no positive
  `volume_delta`, so it stays `QUOTE` -- no candle is touched.
- Quarantine reasons, metrics, fingerprints, schema, and the `ltp`/`ltpc`
  zero-price rejection.
