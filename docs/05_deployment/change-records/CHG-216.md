# CHG-216 — the two rebuilt local images re-pinned in runtime.lock

- **Status:** recorded — fixed (2026-09-18)
- **Filed:** 2026-09-18
- **Source:** certifying gate run 6 (19/19 PASS) and the `make gate-fast` run that
  followed it.

## What happened

Gate step 18 rebuilds all eight images. Ingestion and execution-gateway are the
two whose content changed in this batch — the wave-36/37/38 fixes landed in
those modules — so their image IDs changed while `runtime.lock` still pinned the
2026-09-15 IDs. `test_local_build_pins_match_the_local_images` caught exactly
that, and only for those two images: nautilus and execution-bridge still match,
because their code did not change.

```
FAIL: test_local_build_pins_match_the_local_images (…) (image='INGESTION')
AssertionError: 'sha256:91e5247e82db…' != 'sha256:ddf59dc8953d…'
: INGESTION_IMAGE pins sha256:91e5247e82db… but 01_docker-ingestion:latest is sha256:ddf59dc8953d…
```

The pins are the designed "rebuild, then re-pin" step of the release workflow,
not a defect in the images. Re-pinned to the live IDs; `pin-check: PASS` (8 refs
digest-pinned) and `test_pin_check.py` 10/10 now pass.
