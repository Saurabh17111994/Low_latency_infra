## Notes

- **Why the old check false-positived:** the bridge sets `assigned_token_set_hash` per socket
  (`SetSlotTokenHash(s.SlotID, TokenSetHash(s.Tokens))`, `main.go`), while Java compared it to the
  full-set digest. With ≤1024 tokens everything lands in `hft-0`, so the defect was invisible until
  a multi-socket plan — the real 2433-instrument universe needs 3 sockets.
- **Real datastream pinned:** `code/testdata/slot-token-hashes.json` carries `datastream-2433`
  (3 sockets: 1024+1024+385) generated from the Go carve; the daily VM's `UNIVERSE=full` mode is
  recorded under H4-2.
- **Fixture generation:** written by a temporary Go test (from `BuildSubscriptionPlan` +
  `TokenSetHash`), then deleted; the permanent pin is `slot_token_hashes_fixture_test.go`. The
  Python validator shares no code with Go or Java, so a change that drifts both in the same way
  still fails (mutation 3b).
- **Warn-only stays:** events are never rejected on a verdict; the counters are the evidence
  (`TOKEN_HASH_MISMATCH`, `TOKEN_HASH_UNKNOWN_SLOT`, `TOKEN_HASH_EMPTY_SLICE`).
