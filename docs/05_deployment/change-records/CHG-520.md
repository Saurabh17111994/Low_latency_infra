## What changed

- `test_bench_throughput_wave33.py` gains a `PGREP` shim (registered in
  `Sandbox.__init__` with the existing `docker`/`go`/`mvn`/`java` shims). It
  answers the bench's double-run pattern
  (`pgrep -f com.trading.ingestion.IngestionService`) from the sandbox's own
  world (nothing running) and delegates every other pattern to `/usr/bin/pgrep`,
  so the bench still sees processes it started itself. This is the same
  process-view ownership `test_ingestion_launchers.sh` already uses.
- The module-level skip is untouched: it still skips loudly when a live
  IngestionService is up **at import** (pinned by `test_the_live_stack_probe`).
  The shim covers the case the skip cannot see — a service that appears after
  import.

## Why

- `bench-throughput.sh`'s preflight (copied from `run-full-suite.sh` Stage 0)
  runs a host-global `pgrep -f 'com.trading.ingestion.IngestionService'` and
  refuses as a double-run.
- Gate step 9's Java suite runs `FullStackE2ETest`, which spawns that JVM via
  `ProcessBuilder` (`FullStackE2ETest.java:171-173`); its surefire report is
  timestamped 16:34:15.
- The failing bench preflights ran at 16:33:59–16:34:00 — inside that JVM's
  lifetime. Serially step 3 ran before step 9, so the two never met; the
  CHG-519 pool made step 3 overlap step 9 and exposed the hidden host coupling.
- The sandbox already owns its toolchain, ports, O2 server and Fluss probe; the
  host-global process view was the one environmental input left, and the repo
  already has the pattern for removing it.

## Verification

- Failing evidence (pre-fix): `monday-gates-20261002-163219` — SUMMARY carries
  the flushed `FAIL: python unit suites`, `python-tests.log` shows both failures
  with the preflight line `!! an IngestionService is already running ...`.
- Shim isolation check: with a dummy process whose argv matches the guard
  pattern live, the shim reports "not found" for the guard pattern and still
  finds other patterns (delegation to `/usr/bin/pgrep`).
- Bench suite with the dummy service live: the two guard failures are gone
  (verified during implementation with the skip temporarily removed; the skip
  was restored because `test_the_live_stack_probe` pins it).
- Bench suite without any live service: full file run —
  `python3 code/01_platform/04_scripts/tests/test_bench_throughput_wave33.py`
  → `Ran 26 tests ... OK` (2026-10-02, 52.9 s).
- Full certifying gate with the pool re-run to follow; evidence under
  `logs/soak/`.

## Residuals

- The module skip still means a live platform at import skips the whole bench
  file (deliberate, pinned). The sandbox shim does not change that; it only
  stops a mid-run service from failing the tests.
- Other cross-step couplings between the pooled steps and the serial chain are
  not known beyond this one; the first full run found only the pgrep coupling.
