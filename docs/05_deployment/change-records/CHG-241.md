## Deviations from the audit's fix text

1. **P6-818 needed a stack change**, contrary to the wave's test-only framing. Scoping the
   check exposed that `otel-collector` — a declared exception — carried no marker (5 markers
   for 6 exceptions; the global search is exactly what hid it). The added comment states only
   verified facts: the image has no shell (probed with `runtime --rm --network none`, neither
   `/bin/sh` nor `/busybox/sh` can exec) and its `health_check` extension listens on
   `0.0.0.0:13133` (`otel-collector-config.yaml:116`, wired at `:297`). Approved by the wave
   owner before the edit.
2. **P6-615**: the audit said drop `or True`; the surviving clause would only re-check
   `high-availability.cluster`, a substring of the `cluster-id` asserted one line above. The
   assertion now pins the backend and the ensemble instead — stronger, and not a duplicate.
3. **P6-817**: the audit offered "assert exactly two blocks" or "parse the value properly".
   The second was taken: `fluss_properties()` parses every service's value, so no count is
   hard-coded and no indentation is guessed.
4. **P6-816**: the audit suggested asserting non-root on the Dockerfile, which has no `USER`
   line — the drop lives in `ddl-apply-entrypoint.sh`. The test pins the real wiring.
5. **P6-596**: the audit suggested asserting "a marker that is only emitted when a real live
   run occurred". No such marker exists or can exist without changing the harness: its live
   path performs no live assertions by design (`local_int_004_smoke.py` L89-97 documents that
   the live proof is the Flink checkpoint + Fluss read, elsewhere). The test therefore skips
   without the stack, which is the honest half of the suggestion. **Consequence, accepted by
   the wave owner**: the suite's local skip count rises 11 → 12. Gate-safe: `skip_inventory.py`
   names each skip and has no reason allowlist (verified: `SKIPS: 1 — 1× execution-t3 fake
   stack not up…`), and no live document pins the number.

## Observations recorded, not fixed

- `local_int_004_smoke.py --live`'s help says "require execution-t3 fake stack", but a down
  stack yields a contract-only PASS rather than a refusal. The test now defends itself by
  gating; the flag's semantics still differ from its help text (harness change, not this wave).
- Only the `otel-collector` marker's justification was verified first-hand. The other five
  markers' prose is unverified; the check pins that a reason exists and says `none`, not that
  the reason is accurate.
- The remaining literal-`python3` invocations elsewhere in the suite (`l4`, `l10`, `l2`,
  `o2_tooling`, `repair_tablet`, `stage_capture`, `eod_controller`) are out of this wave's
  scope; several are deliberate fixtures that must *not* change.
