## Notes

- **Why the first fixture run passed under the mutation:** the bad-time ticks carried no payload
  hash, so the later admission gate rejected them with `MISSING_PAYLOAD_HASH` and the append count
  stayed 0 — a confounded fixture, not a passing guard. The helper now carries the real
  `sha256Hex(payload)` hash, which is what made the restored fall-through observable (`2` appends).
- **What the grace is for:** the startup snapshot burst plus subscription latency can legitimately
  exceed the 5 s freshness window in the first seconds. The grace keeps that transient from
  emitting a quality-unsafe halt, but bad-time data still never reaches a trade decision.
- **One arming point:** both production sites now call `armFreshnessGrace()`, so the 30 s window
  has a single definition (the seam the test drives).
