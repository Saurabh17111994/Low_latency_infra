## 1. Three regressions, one symptom

The benchmark gates on evidence it reads out of the ingestion journal: the
1024-token subscription ack before any window starts, then the error and warn
counts the suite reads afterwards. Three changes landed after the last recorded
pass — `logs/soak/bench-20260831-212352`, 2026-08-31 — and each one emptied
that read on its own. A healthy stream therefore looked like a dead one, and
the failure was reported as `no full subscription ack in journal`.

The recorded pass predates all three, so no bench evidence in the tree
exercises them. Today's `monday-gates` run (`logs/soak/monday-gates-20260915-130326`)
failed at preflight and never reached the bench.

### 1.1 The journal directory was not writable by the container

`bench-throughput.sh` creates `$OUT/bench/journal` with the invoking user's
umask — mode 0775, owner uid 1000 — and hands it to the ingestion container as
a bind mount. P1-137 (`c54ddc75`, 2026-09-08) dropped that container to uid
65532, and `docker-entrypoint.sh` probes `LOG_DIR` before starting Java:

```text
ingestion: FATAL — LOG_DIR not writable: /data/ingestion/logs
  (run as 65532:65532; pre-P1-137 root-owned volume? see Dockerfile NOTE)
```

Exit 2, so the container never became healthy and the bench aborted with
`0/3` windows. The Dockerfile's note prescribes `docker compose down -v` or a
one-time `chown` for a root-owned **named volume**, but the bench uses a host
bind mount the image cannot chown — the note does not cover this path.

Fix: `chmod 0777` the journal directory the script just created. Measured
directly rather than assumed: a container as uid 65532 could not write to the
0775 directory (`touch: Permission denied`) and could write to it after the
chmod. With the fix the container ran and ingested **1,235,968 ticks with
errors=0**.

### 1.2 The journal filename is per-host

P1-132 (`ed65fa8e`, 2026-09-07) renamed the appender target to
`ingestion-${HOST}-${VM_ID}.json` so a volume shared with the collector cannot
have two writers interleaving one file. Every reader kept the old fixed name.

- `bench-throughput.sh` tested `[ -f .../ingestion.json ]`, false forever, so
  the ack gate reported 0 on a stream that was demonstrably running.
- `run-full-suite.sh` had ~20 call sites on the same name: the bootstrap,
  marathon and container ack waits, the reconnect baseline, the per-window
  error/warn reads, and four `LOG_FILE=` handoffs to `soak-monitor.sh`.

Fix: resolve once instead of at every call site. The bench globs
`"$JOURNAL_DIR"/ingestion*.json` (`-h` keeps the filename out of the count).
`journal_stats` resolves the real per-host file from the fixed name it is
given, which corrects all ~20 sites in one place, and `journal_file` does the
same for the callers that need the **path** — the `[ -f ]` guards and the
monitor handoffs. Newest file wins, and an unmatched path passes through
unchanged so a genuinely missing journal still reads as zeros.

### 1.3 The appender buffered, and the exit hook was off

P1-278 (`4fc7fe35`, 2026-09-08) made the JSON_FILE appender buffered —
`bufferedIO="true"`, `bufferSize="262144"`, `immediateFlush="false"` — to take a
per-event syscall off the 50k/s hot path. The configuration header still
carried `shutdownHook="disable"` from 2026-08-01, when writes were unbuffered
and the hook was redundant.

Together those drop the buffer. Measured on the running stack: the journal was
**0 bytes for a 45s live window**, and **still 0 bytes after `docker stop -t 40`
completed a graceful drain**. The ack was present on the console appender
(synchronous) and absent from the file, which isolates the loss to the buffered
appender rather than to logging generally.

Fix, in two parts:

1. `shutdownHook="enable"` — the hook fires once per JVM exit, not per event,
   so the hot path is unaffected. Verified on the **soak** path (buffered, as
   before): 0 bytes live, then **35,478 bytes / 80 lines** after a graceful
   stop. That evidence previously went in the bin.
2. `immediateFlush` / `bufferedIO` become env seams
   (`LOG_IMMEDIATE_FLUSH`, `LOG_BUFFERED_IO`) with the buffered defaults
   unchanged, and `docker-compose.bench.yml` sets both so the bench can read
   live. The soak path does not, so its hot path keeps buffering — confirmed by
   diffing the two resolved compose configurations.

A flush-at-exit hook alone would not have been enough: the ack gate reads
*before* the windows start, so the bench needs evidence while the process is
still running.

## 2. Verification

- **Live end to end** (`/tmp/w33-live5`): preflight OK → healthy container →
  `acks: 1` → three windows at 20,411 / 20,445 / 20,411 rows/s against an
  expected 20,480, `p50=5ms p99=5ms`, zero decode-error delta → `RESULT: PASS
  (all windows)` → teardown freed :8899 → exit 0.
- **A later run of the same tree failed, and said something untrue about it**
  (`/tmp/w33-final`): window 1 reported `decode_errors delta=-4 != 0`, which the
  verdict reads as the feed sending junk. The feed was fine — O2's newest
  sample still belonged to the PREVIOUS container, so the baseline and window
  1's opening read came from a dead process (`append_latency_ms_count=0`
  alongside `decode_errors=7`, a pair no live process can produce) while the
  closing read came from the running one. Fixed and re-measured under CHG-176,
  which also quiesces the three regressions above against a live stack.
- **Journal writability** proven by attempting the write as uid 65532, not by
  reading the script: 0775 refused, 0777 accepted.
- **Genuine evidence, not by construction**: the ack line was confirmed present
  in the journal file during a live run (`grep subscription_ack` → 1 match),
  which was structurally impossible before 1.3.
- **Soak path unchanged**: resolved compose shows the flush vars unset there,
  and a buffered run flushed 35KB on exit.

## 3. Not covered

- The buffered default still loses in-flight events on a `SIGKILL` (no hook
  runs). The bench overlay avoids this by flushing per event; a hard-killed
  soak still loses its tail. Documented, not fixed.
- The suite's journal display lines (`journal=$OUT/.../ingestion.json` in the
  marathon summary and evidence line) still print the fixed name even though
  the reads behind them resolve correctly. Cosmetic; left alone.
- The bench was run on this host's dev stack, not under production load.
