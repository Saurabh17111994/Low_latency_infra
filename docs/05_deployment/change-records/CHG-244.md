# CHG-244 — Wave 54: the last ten ops-script test modules stop lying

**Findings (22, all verified real — no stale entries this wave):** P6-617, P6-624,
P6-625, P6-626, P6-627, P6-819, P6-820, P6-821, P6-822, P6-823, P6-824, P6-825,

This wave is about alarms that could not ring. Seven of the ten modules carried an
assertion that a broken script would still have passed, one guard emptied itself
silently, one fail-closed path had never been executed, and one helper inherited
whatever git configuration the host happened to have.

## Assertions that could not fail

| Finding | Was | Now |
|---|---|---|
| P6-617 | the removal used a quoted argument — `replace("'state.backend.incremental: true\n'", "")` — which never matches the unquoted line, so the property under test was untested | the unquoted line is removed; the substitution is asserted to have happened |
| P6-624 | `SERVICE_SOURCES.get("compute", [])` — a renamed key would empty the loop and the test would pass over zero files | the key is indexed, so a rename raises instead of passing |
| P6-625 | the probe parser used `\d+`, which cannot match the Fluss `-1` sentinel: the row was dropped, so the `t != -1` tolerance it guards was never reached | the field accepts `-?\d+`, the sentinel is excluded from `raw_nonzero` exactly as `extra` already did, and the parser test asserts `-1` is in the map. The CLI is now exercised both ways: a sentinel row exits 0, an unexpected token still exits 1 |
| P6-627 | the dashboard secret scan carried a hard-coded four-file list against an eight-dashboard corpus | the corpus is derived from `manifest.json`, with a floor assert so a shrunken manifest fails loudly |
| P6-842 | `assert pid not in seen` passed for a panel with no id at all (`None` was never in `seen`) | a missing id is its own failure, before the duplicate check |
| P6-835 / P6-836 / P6-837 | each asserted only that *some* error was raised | each asserts the rule's own message: the internal-network rule, the leaked `ARROW_APP_SECRET` key, and the published-host-port rule |

## A fail-closed path that had never run

| Finding | Was | Now |

## State and environment that leaked between tests

| Finding | Was | Now |
|---|---|---|
| P6-825 | the alert consumer's test overwrote `STORE_PATH` and never restored it, and left the HTTP server socket open (a dangling global for every later test in the session, plus a `ResourceWarning`) | the original value is saved in `setUpClass` and restored in `tearDownClass`, which also closes the server |
| P6-828 | the module `setdefault`-ed a dummy `O2_AUTH_BASIC` credential for the whole pytest session, silently authorizing bogus requests made by other tests | the original value is captured, a dummy is installed only around the module exec, then restored (or removed if it was absent). Verified in-process: the environment is unchanged after the module loads |
| P6-838 | the throwaway git repo inherited the host's global config — this machine sets `core.autocrlf`, so the commit rewrote line endings and the content hash the test compares differs per host | `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null` and explicit `-c commit.gpgsign=false -c core.autocrlf=false`. Verified: a committed file is read back with LF only |
