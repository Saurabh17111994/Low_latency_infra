# CHG-196 — alert-routing-selftest cleanup deletes a real O2 alert_id (was leaking the probe)

- **Status:** recorded — fixed and proven live (2026-09-17 PASS run)
- **Filed:** 2026-09-17
- **Source:** found while running `make alert-routing-test` after the CHG-195 re-seed:
  the first attempt was killed mid-run by the session runner, and the leaked
  `selftest-g6-routing-probe` could not be re-deleted by replaying the script's own
  cleanup path — O2 answered `DELETE /api/v2/default/alerts/None` (404).

## What happened

O2 v0.91.5's v2 alert **list** payload keys each alert as `alert_id` (no `id` field —
verified against the live instance: keys are `alert_id, alert_type, condition, …`).
`alert-routing-selftest.py` deleted the probe with a bare `a.get("id")` in both cleanup
sites (leftover check, step 3 idempotent start; final cleanup, step 6), so:

- every delete was issued as `DELETE alerts/None` → 404 → `fail(...)` — **the tool could
  never pass against the O2 version it runs on**; the always-firing probe was left
  enabled on every run that reached step 3;
- the wave-25 fake (`test_alert_routing_selftest_wave25.py::_Api`) modelled the payload
  as `{"id": ...}`, so the test corpus agreed with the bug instead of with O2.

`seed_alerts.py:130` already handles the same quirk (`get("id") or get("alert_id")`) —
the selftest was the deviation.

## What changed

- `code/01_platform/04_scripts/alert-routing-selftest.py` — both delete sites resolve
  `aid = a.get("id") or a.get("alert_id")` (the `seed_alerts.py` idiom), with the quirk
  written down where it bites.
- `code/01_platform/04_scripts/tests/test_alert_routing_selftest_wave25.py` — the fake
  now defaults to the **real** payload shape (`alert_id`) and models either spelling;
  two new pins: `test_cleanup_deletes_a_real_o2_alert_id_payload` (an `alert_id`-keyed
  leftover is deleted, not `alerts/None`) and `test_cleanup_still_accepts_the_legacy_id_payload`
  (the old shape keeps working). 8 → 10 tests.

## Residual limitation

The selftest's 4-minute poll budget assumes O2's ~1-minute evaluation granularity; a run
killed externally before cleanup still leaks the probe (the script deletes leftovers on
the *next* run's step 3, which now works thanks to this fix). The session runner cannot
host the full 4-minute budget directly — run it via `setsid nohup … &` and read the log.
