## What was wrong (measured, not inferred)

With `state.changelog.storage = memory` (the TM default, because the stock image has no
filesystem factory — CHG-443 finding 2), the memory changelog accumulates changes in the
TaskManager and **every checkpoint re-serializes the whole accumulated changelog**:

| evidence | value |
|---|---|
| checkpoint `state_size`, cp1 → cp18 (10 s cadence, 3 min) | 1.5 MB → 38.1 MB, monotonic |
| checkpoint `_metadata` on disk (cp18) | 49 MB (CT-2 OFF baseline: 1.5–3.2 MB, flat) |
| checkpoint `end_to_end_duration`, cp1 → cp18 | 167 ms → 1 227 ms |
| RPC effect | Pekko "Transient association error" bursts at 17:29:25/55 — exactly the cp19/cp20 expirations |
| outcome | cp19–cp22 expired (30 s timeout); tolerable-failure threshold (3) → job RESTARTING → capture failed closed |

The CT-2 OFF baseline (RocksDB) held `state_size` flat at 1.5–3.2 MB over 900 s, so the growth
is the memory-storage serialization behavior, not application state growth. The filesystem
storage uploads changelog segments to the base path as files; the checkpoint metadata only
carries references, which is why it is the production-supported option.

## What changed

1. `flink-dstl-dfs-2.2.1.jar` (Apache Flink 2.2.1, sha256
   `aa467887d059d348d1f52d134d7ba1c0664e072054dae3748c5d498d63f997ad`) vendored under
   `code/01_platform/01_docker/flink-plugins/dstl-dfs/` (README documents provenance; `*.jar`
   is gitignored like the other host plugin binaries).
2. `docker-compose.yml`: the jar is bind-mounted read-only into the `flink-taskmanager`
   service at `/opt/flink/plugins/dstl-dfs/flink-dstl-dfs-2.2.1.jar` (the storage is a
   TaskManager-level service; the JobManager does not need the plugin).
3. `docker-compose.yml` shared `FLINK_PROPERTIES` (rendered into the cluster config):
   `state.changelog.storage: filesystem` and
   `state.changelog.dstl.dfs.base-path: file:///checkpoints/changelog`. Comments stay outside
   the literal block (G22b); values unquoted.

Recreate path used: `make up` (taskmanager recreated; catalog-guard green).

**Production prerequisite (recorded, not done here):** `docker-stack.yml` needs the same TM
plugin classpath and cluster keys before any production adoption. The dev compose change is
the trial harness only.
