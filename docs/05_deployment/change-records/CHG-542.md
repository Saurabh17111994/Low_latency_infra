## What changed

1. `docker-stack.yml` **JobManager** `FLINK_PROPERTIES` — the critical one: the REST-submitted
   SignalJob `main()` runs in the JM JVM and reads `CheckpointConfig` defaults from the merged
   cluster config. Mirrored on the **TaskManager** block so both decks carry the same key.
2. `docker-compose.yml` dev shared anchor (`flink-common`, JM + TM + compute) — the same key
   for the dev deck.

## Why (evidence, full 900 s @ 10 s cadence)

- Certified residual after the changelog flip (CHG-541): the per-checkpoint in-flight dump of
  unaligned checkpoints — async waves, **618 subtasks > 50 ms across 35/94 checkpoints**,
  `tick_to_strategy` max **359 ms**, 45/50 snapshots > 100 ms.
- **Aligned-only** (`w3e3-main`): 0 wave checkpoints, async p90/p99 19/32 ms, tick max 115 ms.
- **Hybrid** (`w3hybrid-main`): **0 conversions** (all 94 checkpoints `CHECKPOINT`), async
  p90/p99 18/30 ms, tick max 120 ms, >100 ms 35/50 — matches aligned-only within run noise
  (that run's ingestion S5 was p50 33 vs 26 ms, i.e. the host was ~20% slower).
- **Safety:** normal alignment is ≤ 30 ms, so the 10 s timeout never fires in normal running;
  under real backpressure the checkpoint converts to unaligned automatically (the CHG-318
  protection retained). Checkpoint timeout is 30 s, so 10 s leaves room to complete unaligned.

## Verification at the production start window

- JM/TM config render carries the key; the first checkpoints report type `CHECKPOINT` (not
  `UNALIGNED_CHECKPOINT`); no checkpoint failures; throughput/presence parity.
- Rollback: remove the line + recreate JM/TM (or `UNALIGNED_CHECKPOINTS=false` for a
  checkpoint-mode-freeze kill switch).
