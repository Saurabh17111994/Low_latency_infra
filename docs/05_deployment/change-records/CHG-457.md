## Why

- **W3-c** (CHG-454): two 900 s rounds showed no KPI gain; the in-window materialization
  rounds the key was meant to remove were absent in both rounds anyway (a single startup
  batch; the scheduler staggers the next ones outside the window). Visible effect was cost
  only: changelog base path grew to 1.9 GB and restore replay lengthens.
- **CT-4B** (CHG-455): no demonstrated win — body within noise, spikes persist (worst steady
  455 vs 236 ms), tablet CPU flat; checkpoint e2e regressed 37 -> 82 ms med in the bundle
  round (not cleanly attributable to one lever).
- **CT-5** (CHG-456): no latency win; no memory benefit by design; TM CPU avg +8 %.
- Anti-overoptimization rule: keep only measured winners. The next bundle (CHG-458:
  changelog hygiene + `dstl.dfs` tuning) targets the machinery all three rounds point at.

  `dstl.dfs.base-path: file:///checkpoints/changelog`) stay.
- `SignalJob.java` — removed both `client.writer.batch-timeout` sink options. Verified
  byte-identical to the pre-CT-4B revision: `git diff f1ad5a15^ -- SignalJob.java` = empty.
- Pins — removed `test_signal_sink_linger_is_pinned`,
  `test_buffer_debloat_enabled_is_pinned`, `test_changelog_materialization_interval_is_pinned`.
