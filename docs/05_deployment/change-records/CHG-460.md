## Why

- Measured (`logs/w3ac-main-20260930-124510`, `logs/chg458-main-20260930-135319`):
  ~4 900 timer fires + re-registrations per second (2 kinds × ~2 400 active keys), each a
  managed-state mutation → ~20 MB/min of changelog, checkpoint state 94 MB med, 1 297
  registry WARNs/round, TM CPU bursts. Live emissions measured at 29 211 rows/s =
  `6 Timeframes × 2 timer kinds × ~2 400 keys` — the timer model, confirmed numerically.
- The candle/dedup structures are heap-only by design and never checkpointed — they are
  not the source (design note §1–§3).

## What changed

- `MultiTimeframeAggregateFunction`: the per-key live `registerProcessingTimeTimer` /
  `registerEventTimeTimer` calls are removed. The heap due markers
  (`Slot.nextLiveProcTimer` / `nextLiveEventTimer`) now feed
  `maybeScanLiveMirrors(Context)`, driven from the record path (trade ticks after
  accumulation; quote ticks) with operator-scope minima (`nextDueProcMs` /
  `nextDueEventMs`) preserving the 1 s cadence at O(1) per-record overhead. Due slots
  emit on any record (any key) exactly as the timer callback did; a clock jump emits at
  most once per scan (the skipped steps carried identical content). `emitLiveForTimerSlot`
  → `emitLiveForSlot(Context)`; the onTimer live branches and demux booleans are removed
  (a restored live timer falls into the stale branch and dies).
- Tests: new `liveMirrorsAreScanDriven` (no rows without a record; one record emits every
  due slot; no re-emission before the next due time); the smoke test and
  `driveThreeTradesAndClose` trigger the scan with quote records (quotes never touch OHLC).
