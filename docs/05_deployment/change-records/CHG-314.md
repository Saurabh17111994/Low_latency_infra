## What changed

- `stage-profile.sh` — one command: preflight (Fluss ready, fresh taskmanager,
  image stamp) → table purge → fleet (`sp-faketool` + 3× ingestion) → job
  submit → warm-up (raw-log growth, bounded) → `stage-capture.sh` collection →
  raw tail sample → teardown → presence gate (fail-closed) → report.
  `PHASES=smoke,main` (default) selects the phases; `PHASES=smoke` runs only
  the smoke phase and reports it.
- `stage_profiler.py` — pure core: Java OTLP stage parsing, percentiles,
  presence gate, report render (`profile.md` + `profile.tsv` + `presence.json`).
- `RawSampleReader.java` — bounded S1 tail sample of partitioned `raw_table_1`
  (the stock Fluss reader cannot read a partitioned LOG table in Fluss 1.0).
- `tests/test_stage_profiler.py` — 36 offline tests (36 passed 2026-09-26).

## Why it is safe

- No existing file is edited (the README states the non-goals); the fleet uses
  the proven `docker run` lines, and submission/collection reuse the existing
  entry points. Teardown cancels the job and removes its containers.
- The tool is read-only toward the pipeline: it purges tables exactly as the
  proven soak harnesses do, and its own evidence lands under `logs/`
  (git-ignored).
