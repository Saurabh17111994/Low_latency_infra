## What changed

- **`MultiTimeframeAggregateFunction`** — `updateMarketSnapshot` now returns
  whether any stats or depth value actually changed (the same booleans that
  stamp `statsChangedAt`/`depthChangedAt`, so trigger and state cannot
  disagree). In the non-trade branch, when
  `STRATEGY_MARKET_TICK_ENABLED && MULTITF_FAST_LIVE_FEED` and the snapshot
  changed, it emits one market-only row to the existing `LIVE_TICK_TAG` side
  output: `CandleLiveColumns` layout, `TF="MKT"`, identity + the 44-column
  market section + clocks, a zero-defaulted candle prefix (type-safety on the
  NOT NULL layout; never read) and the real event time. A repeated identical
  quote emits nothing; an accepted trade never emits one (its forming rows
  carry the section). New counter `compute.market.tick.emitted`. No new
  operator, no timers, no state.
- **`CandleLiveColumns`** — `TF_MARKET_TICK = "MKT"`, the transport-only
  discriminator (never a real timeframe, never persisted, never parsed by
  `Timeframe.fromCode`).
- **`StrategyHostFunction`** — a `TF="MKT"` row refreshes the slot's
  `MarketSnapshot` and fans out to the new callback only; it never touches
  features, the KPI, the context provider, or `onLiveTick`.
- **`SignalStrategy`** — new `default void onMarketUpdate(RowData market,
  StrategyView view, Collector<RowData> out)` (no-op), so every strategy
  written before the callback is byte-identical. A strategy that wants to fire
  on book/stat moves overrides it; the host's per-rule dedup and failure
  isolation apply exactly as on the other callbacks, and the signal still
  fires only on a rule match.
- **`SignalJobConfig` / `SignalJob`** — `STRATEGY_MARKET_TICK_ENABLED` (default
  false) fails closed unless `STRATEGY_HOST_ENABLED=true`; the flag is passed
  into the canonical aggregator constructor (now 6-arg; the 5-arg overload
  keeps the feature off). The dev `.env` enables it for the live smoke; the VM
  example documents it off.
- **`docs/06_operations/07-lake-archive-ops.md`** — the CHG-503 deletion
  runbook's delete example no longer carries a `<prefix>` placeholder
  (docs-audit C18 rejects placeholders in bash blocks); it now shows a concrete
  prefix, matching the preview example above it.
