# CHG-133 — Executor stop grace period (Docker SIGKILLed the clean-shutdown sequence)

- **Status:** recorded — production shutdown behaviour changed for the `nautilus` service
- **Filed:** 2026-09-14
- **Source:** live end-to-end stop test of the D7 path (wave-4 follow-up round); finding, not a plan item

## What changed

`nautilus` (the Rust executor) declared no `stop_grace_period`, so Docker used its 10 s default. The
executor's own drain is longer than that, and the difference is not cosmetic:

| Stop command | Drain | Exit | Log |
|---|---|---|---|
| `docker stop` (default 10 s) | 10 s, SIGKILL | **137** | no `clean shutdown complete` line |
| `docker stop -t 90` | 15–16 s | 0 | `clean shutdown complete: … unresolved_attempts=0 gate_state=Halted` |

With the default, the process dies inside the D7 sequence, so the queued-attempt accounting that
sequence exists to produce never happens — attempts that never reached the broker are abandoned with no
report, the case `ShutdownCoordinator` was written to prevent. The Kubernetes/Docker-visible effect is
an unclean stop (137) that no test noticed, because unit tests call the coordinator directly and never
involve a container runtime.

The fix declares `stop_grace_period: 30s` on the service (measured worst case 15–16 s: the vendored
Nautilus kernel waits up to 10 s for residual events, then the HTTP task's `HTTP_DRAIN_GRACE_SECS` = 5 s
window elapses), and adds `shutdown_budget_grace_tests` — the Rust analogue of ingestion's
`ShutdownBudgetGraceTest`: it reads the real compose file and the real constant, so raising a budget
without raising the grace fails in CI rather than in production.

## Evidence

- Run log: `/tmp/d7-live.log` (default grace: exit 137), `/tmp/d7-live2.log` (90 s grace: 15–16 s, exit 0,
  `unresolved_attempts=0 gate_state=Halted`), `/tmp/d7-live3.log` (after the fix, plain `docker stop`:
  `StopTimeout=30`, rc=0, exit 0, clean-shutdown line present).
- The same live run verified the D5 signer on the approve path:
  `/v1/approve accepted: {"approved":true,"gate_state":"ENABLED","approved_by":"saurabh","gate_epoch":2}`
  and `/healthz` → `trading_ready: true`, then a clean stop from `ENABLED` (restart-safe).
- Suite after the fix: `cargo test --offline` 316 passed / 0 failed; `cargo clippy --all-targets -D warnings` clean.
