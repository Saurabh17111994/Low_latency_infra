# CHG-316 -- low-latency in-memory signal feed (per-tick `LIVE_TICK_TAG` to the strategy host)

- **Status:** recorded -- landed 2026-09-26 (compute suite green; 2 Hz smokes green)
- **Filed:** 2026-09-26
- **Source:** the operator KPI is **broker tick → signal operator reading Flink
  state in memory** (the candle mirrors are explicitly out of scope). The
  strategy host read live state only from the aggregator's `LIVE_TAG` snapshot
  stream, whose effective fire gap is ~1 s (event-time and processing-time
  timers both at the 1000 ms interval), so the state an operator read could be
  up to a full interval stale — measured at 2 Hz:
  `compute.latency.tick_to_strategy` p50 564 / p95 1 592 / p99 2 288 ms
  (run `034308`).

## What changed

| piece | change |
|---|---|
| `MultiTimeframeAggregateFunction` | new `LIVE_TICK_TAG` side output: one smallest-TF (15 s) forming row per **accepted trade tick**, built from the same `CandleAccumulator` the snapshots use; new counter `compute.candles.live.tick.emitted`; gated by `emitLiveTick` |
| `StrategyHostFunction` | new histogram `compute.latency.tick_to_strategy` = `now − LAST_EVENT_TIME` sampled at every live read — the KPI, in-process, no probes/Fluss |
| `SignalJob` | when host + flag enabled, the host consumes the fast side output (`candle-live-tick`); the 1 s `LIVE_TAG` stream still feeds the Fluss mirror unchanged |
| `SignalJobConfig` + `ConfigKeys` | `MULTITF_FAST_LIVE_FEED` (default `true`; `false` restores the snapshot feed) |
| `pipeline-lib.sh` | passthroughs `MULTITF_FAST_LIVE_FEED` and `BUFFER_TIMEOUT_MS` |
| `stage-profile.sh` | `RATE_HZ` default 20 → **2** (2 ticks/s per stock) so the profiler measures at the operator's target feed rate |

## Measured effect (2 433 instruments @ 2 Hz, 200 s; same image)

| `compute.latency.tick_to_strategy` | snapshot feed (run `034308`) | fast feed, pre-bridge-fix (`031649`) | fast feed + CHG-317 (`033605`) |
|---|---|---|---|
| p50 | 564 ms | 66 ms | **49 ms** |
| p75 | 831 ms | 85 ms | 61 ms |
| p95 | 1 592 ms | 551 ms | **80 ms** |
| p99 | 2 288 ms | 576 ms | **93 ms** |
| p99.9 | 3 091 ms | 591 ms | 105 ms |
| samples | 5 636 375 (6 TF rows per fire) | 491 449 | 464 557 |
| smoke presence | PASS | PASS | PASS |

- In the fast runs the KPI sample count equals `compute.candles.live.tick.emitted`
  — every emitted fast row reached the host (no shuffle loss).
- The snapshot-feed sample count is ~12× because every timer fire reads all six
  TF rows per key; those reads measured 564 ms median state age at 2 Hz.
- The fast-feed median dropped further after CHG-317 (66→49 ms p50, 551→80 ms
  p95) because the ingestion transport tail was the remaining contributor.
- Not the KPI: the Fluss `candle_live`/`candle_closed` mirrors keep their 1 s
  snapshot cadence — deliberately untouched (a 10× mirror-rate experiment
  collapsed on `candle_live` at ~184 k rows/s; the fast feed never touches Fluss).

## Notes

- Cost: one extra in-memory row per accepted trade (~4.9 k rows/s at 2 Hz).
- Coverage: ~49 % of post-dedup rows are positive-volume trades; only those
  mutate OHLC and emit fast rows (the fake broker writes per-frame qty while the
  bridge computes deltas from cumulative volume). Not a loss — `late_dropped=0`
  — and the signal-relevant population is exactly what the KPI samples.
- Residual: the checkpoint-bound sink tail (~0.9–1.2 s p95/p99, ~1.5 % of the
  timeline) remains a separate lever.

**Annotated 2026-10-01 (CHG-484):** the fast feed now emits every timeframe's
forming row per accepted trade tick; the "smallest TF only" scope above is the
2026-09-26 landing state.
