# CHG-305 — G7c parity reconciles against the aggregator's drop counter instead of failing on every per-window difference

- **Status:** recorded — fixed, tested and validated end-to-end (2026-09-23)
- **Filed:** 2026-09-23
- **Source:** the T6.2 re-measure of the Fluss 1.0 upgrade. Run
  `logs/tracker-14/holistic-measure-20260923-180457` failed G7c on 1188 of 62,464 fully-closed
  (token, window) pairs, with the candle side 1-5 ticks short of ~150 per window.

## What happened

That failure was the first time the leg ever ran against a *populated* candle side (CHG-194's run 11
mismatched 22,528 windows from an *empty* side), and the same output already carried its explanation:
`G7b late: sent=80 raw-observed=80 counter-delta=6699` with the analyzer's own note that the counter "is
6619 above the 80 injected late ticks ... those are natural feed re-feeds the aggregator drops by design
(monotonic gate)". G7c compared each window's candle tick count against an unadjusted raw recount, so every
tick the aggregator deliberately refused - out-of-order arrivals the monotonic gate drops, older-window
drops, slot-cap drops, session-filter drops - counted as data loss. The shortfall over those 1188 windows
(averaging 3.3 ticks in the ten printed) is the same order as the 6,699 counted drops, so the leg was
measuring a mix of design and loss and could not tell them apart.

Per-window attribution is impossible: `compute.candles.late.dropped` is a job metric, not a per-key ledger.
A totals reconciliation is not.

## What changed

- `code/01_platform/04_scripts/holistic-analyze.py` —
  (a) `g7c_compare` accepts an optional `stats` collector and records, for the pairs that must match
  *exactly* (the partial first window stays excluded), `compared_raw_ticks`, `compared_candle_ticks`,
  `shortfall` and `candle_excess`.
  (b) new module-level `g7c_reconcile(shortfall, candle_excess, drop_delta)` decides the leg: a candle can
  never count more ticks than the raw recount holds (impossible direction, always fails, checked before any
  allowance), and the ticks missing from fully-closed windows must be covered by the in-window drop
  counter - anything the counter never counted is unaccounted for, which is what loss looks like. It
  returns the failure message and, on a pass, a note giving both numbers and how many drops were re-feeds
  of ticks already counted.
  (c) the per-window list stays printed (`- G7c detail:`) for localisation but no longer decides pass/fail,
  and the `- G7c parity:` line now carries `tick shortfall=N vs M counted drop(s) in-window`.
  (d) the allowance is exactly `compute.candles.late.dropped`: exact duplicates are already excluded from
  the raw baseline by the fingerprint dedupe, and validation rejections are asserted separately by F6, so
  nothing is excused twice.
- `code/01_platform/04_scripts/tests/test_holistic_g7_parity.py` — 6 new cases (`G7cReconcileTests`):
  covered shortfall passes, unexplained shortfall fails and names the unaccounted count, no counted drops
  tolerate no shortfall, the impossible direction fails even with a huge allowance, a clean run reconciles
  to zero, and `g7c_compare` reports the totals it used (with the partial first window excluded).

## Known limitation

The pass is one-sided by construction: drops of ticks that were *already counted* (re-feeds of a live tick)
inflate the allowance, so a green run means "no loss this measurement can see", not "every drop was
necessary". That is why the reconciliation line is printed on every run rather than only on failure. Volume
is deliberately not reconciled: a window's raw volume includes the dropped ticks' volume, so a volume
shortfall carries no independent signal.

## Verification

- `python3 -m pytest -q` over every `test_holistic*.py` and `test_analyzer*.py` suite → **138 passed**,
  6 subtests (6 of them the new cases); `ast.parse` clean; `make static-check` 0 failures.
- End-to-end: `logs/tracker-14/holistic-measure-20260923-184211` → **`make holistic rc=0`**,
  `G7c parity: 62464 ... 0 informational mismatch(es); tick shortfall=0 vs 80 counted drop(s) in-window`,
  `G7c reconciliation: shortfall=0 ... covered by 80 counted drop(s)`, `G7: data-quality guards passed
  (dedup exact, late-drop covered, tick-set parity reconciled)`, G6/A2/A5/D6 green, 3 legs UNAVAILABLE by
  design.
- The run that motivated the change did not reproduce its drop population: `G7b counter-delta=80` (exactly
  the injected late ticks, was 6,699) and 0 mismatches (was 1,188). Recorded as an observation - the
  reconciliation now prints both numbers, so a recurrence is visible immediately.
