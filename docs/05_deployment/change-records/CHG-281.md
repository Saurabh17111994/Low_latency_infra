## Why

Phase 2 ran `deploy_preflight.py` against the real deck and the real deploy environment for the first time,
and it failed:

```
[FAIL] ${FLUSS_BOOTSTRAP} is referenced by the stack with no default and the environment is empty — docker would deploy an empty value
```

The message is false. The only braced `${FLUSS_BOOTSTRAP}` in `docker-stack.yml` is inside the comment at
line 719; every one of the eleven real values is the literal `fluss-coordinator:9123`, and the rendered
config (`docker stack config`) confirms it. `stack_references()` ran its regex over the file's raw text,
comments included, so a comment *about* a variable was reported as an unset variable.

This matters more than a cosmetic false alarm. The preflight is the gate that decides whether a deploy may
proceed, and it is the gate VM day depends on. A gate that fails a correct deck teaches its operator to
ignore it, which is how a real failure gets waved through. The defect has been latent since `1a8fb823`
(CHG-250..CHG-256), the commit that added that comment.

## What this changes

`stack_references()` now parses the stack file as YAML and collects `${VAR}` from string values only, so
comments are not references and block scalars still are. If the file will not parse, it falls back to the
raw scan, which can only over-report — never under-report.

## Verification

Measured, not asserted:

- `test_13_deploy_preflight.py` → 20 passed (17 before the three additions).
- `deploy_preflight.py --env-file ~/.p6v/p2/prod.env` on the real deck → rc=0, 43 references resolved.
- Mutation A — a real `${MUTANT_VAR}` value appended to the real deck → rc=1, named in the FAIL.
- Mutation B — the same name appearing only in a comment → rc=0, no mention in the report.

## Note on the retracted finding

An earlier reading of the same failure concluded that the deck was missing a seventeenth required variable
and that `stack_selfcheck.sh` was therefore incomplete. That was wrong, and it was retracted as soon as it
was measured: the rendered config shows all eleven `FLUSS_BOOTSTRAP` values set, and the script's sixteen
required names are correct. The defect was in the checker, not in the deck.
