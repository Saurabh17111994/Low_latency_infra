## What changed

Fluss 1.0 removed the per-bucket `currentOffset` gauges
(`fluss.reader.bucket.<n>.currentOffset`, `fluss.reader.partition.<id>.bucket.<n>.currentOffset`).
Two consumers still referenced them:

1. `o2-provision.py`'s "Fluss reader current offset (source lag proxy)" panel queried
   `max(flink_taskmanager_job_task_operator_fluss_reader_bucket_currentoffset)`; it now uses
   `currentFetchEventTimeLag` (the metric the notes name for read lag, already used elsewhere in
   the same file).
2. `test_compute_identifier_parity.py`'s `ALLOWLIST_STREAM_EXACT` listed the dead identifier; the
   entry is removed (the surviving identifier was already listed).

## Verification

- `python3 -m pytest code/01_platform/04_scripts/tests/test_compute_identifier_parity.py -q` -> 10 passed.
- The removed gauge no longer appears under `code/01_platform/04_scripts/` (the allowlist removal
  makes a reappearance fail the suite).

## Notes

- Root cause of the miss (recorded in the plan's Batch-33 section): the earlier sweep's evidence
  named `current_offset` with an underscore while the identifier is `currentoffset` without one.
- This also closes the check B18-N3 queued ("confirm the gauge still emits"): it does not - the
  query moved to an aggregate that exists.
