## What changed

The multi-TF aggregator's operator-scope live-mirror scan runs **two
independent steplines** per slot (processing-time due marker + watermark due
marker), so the effective emission rate is **2 per interval**. At the old
1000 ms default the job wrote ~2 rows/s per key (14 598 keys -> 29 247 rows/s
measured). The change flips the default `MULTITF_LIVE_SNAPSHOT_INTERVAL_MS`
**1000 -> 2000 ms** (two steplines per 2 s = 1 Hz/key). The scan math is
unchanged and interval-agnostic; only the config default and its comments move.
