# CHG-318 -- unaligned checkpoints landed (checkpoint-window p99 814->430 ms)

- **Status:** recorded -- landed 2026-09-26 (falsification run + suites green)
- **Filed:** 2026-09-26
- **Source:** the 2 Hz low-latency workstream (CHG-316/317) left one periodic
  tail: every checkpoint produced a latency spike in the signal path
  (`compute.latency.tick_to_strategy` p99 294–814 ms inside the checkpoint
  windows vs p99 89–93 ms steady state). The native Flink feature for this is
  **unaligned checkpoints** — barriers overtake in-flight data instead of
  stopping the pipeline to wait for alignment. The B5 falsification wiring
  existed since 2026-08-31 but had never been executed; the 2026-09-26 run
  executed it and this record lands the result.

## What changed

| piece | change |
|---|---|
| `SignalJobConfig` | `UNALIGNED_CHECKPOINTS` boolean read from env, **default true**, fail-closed parse (junk = startup error) |
| `SignalJob` | `env.getCheckpointConfig().enableUnalignedCheckpoints(config.unalignedCheckpoints())` |
| `ConfigKeys` | `UNALIGNED_CHECKPOINTS` registry constant |
| `pipeline-lib.sh` | kill switch passed through to the job (`-e UNALIGNED_CHECKPOINTS="${UNALIGNED_CHECKPOINTS:-true}"`); the B5 `-Dexecution.checkpointing.unaligned=true` append removed (job config is authoritative for every submit path) |
| `test-pipeline-lib.sh` G12 | asserts pass-through present + default ON (was: experiment wiring present + defaults OFF) |

## Measured effect (2 433 instruments @ 2 Hz, 200 s, same image)

Falsification pair: `logs/stage-profile-20260926-100925/` (unaligned) vs
`logs/stage-profile-20260926-033605/` (aligned baseline). Every checkpoint in
the unaligned run was confirmed `checkpoint_type: UNALIGNED_CHECKPOINT`.

| metric | aligned baseline | unaligned |
|---|---|---|
| checkpoint-window p99, worst | 814 ms | **430 ms (−47 %)** |
| checkpoint-window p99, mean of spike windows | 532 ms | 350 ms (−34 %) |
| checkpoint-window p99.9, worst | 847 ms | 436 ms (−49 %) |
| spike windows (of 12, excl. startup) | 4 | 3 |
| steady state p50 / p95 / p99 | 49 / 80 / 93 ms | 47 / 74 / 89 ms (noise) |
| checkpoint e2e / state size | 636–899 ms / 3.1–11.0 MB | 653–741 ms / 3.4–11.2 MB |
| throughput / presence gate | 4 868 rows/s / PASS | 4 868 rows/s / PASS |

Consistency check: the checkpoint-phase evidence (holistic run 2026-09-23) said
alignment was ~35 % of the checkpoint stall (156 of 451 ms summed phase maxima;
start-delay dominated) — the measured reduction (34–47 %) matches the alignment
share. The residual spike is the sink-side start-delay, which no native
checkpoint flag removes.

## Caveats

- Spike **frequency** is unchanged (once per checkpoint interval; production pin
  is 10 s, the profiler submits 60 s — production sees it ~6× more often).
- Savepoints: Flink does not support *unaligned savepoints*; savepoints stay
  aligned (no state-format impact). Verify in the rollout drill.
- Checkpoint size +5–10 % (in-flight data included) — modest at this state size,
  grows with backlog.
