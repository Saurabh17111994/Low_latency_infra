## Notes

- **Why the guard lives in the example, not only the compose form:** the `:?` form can be satisfied by
  any non-empty string, so a placeholder in `.env.example` would re-open the same hole one step earlier —
  the deck would start with a fake password instead of refusing. The example test pins both the empty
  value and the REQUIRED comment.
- **Interpolation reads `--env-file` pairs, not `env_file:`:** `env_file:` only injects into containers;
  Compose interpolates `${...}` from `.env` + `secrets.env` (the Makefile/gate pass both). The
  missing-secrets run above is the proof that the guard sees the real resolution path — and that the
  existing dev layout (password in `secrets.env`) still renders.
- **The stack form is deliberately different text:** `?set O2_PASSWORD` (stack, deploy environment
  exports it) vs `?set O2_PASSWORD in .env/secrets.env (make env + secrets-bootstrap.sh)` (compose,
  where the file pair is the documented path). Each names its own fix; the tests pin each form.
