## Why

The 24×7 default posture runs the stack with the gateway locked. A freshly booted nautilus
then retries its `BOOT_HALT` report until the gateway is enabled — correct and fail-closed,
but the retry loop logged a WARN every 5 s (cap), which is ~17k lines/day for an *expected*
posture. Attempt 4 measured exactly this window (16:53–16:54 IST: refused 404s until the
gateway came up).

## What changed

| Piece | Change |
|---|---|
| Boot retry log | First failure `WARN` ("retrying quietly (gateway may be locked)"); subsequent failures `DEBUG`; the adoption `INFO` carries `attempts` |
| Backoff cap | 5 s → 30 s (a locked gateway is a posture, not an incident; the first retry is still ~500 ms, so a gateway that comes up is picked up quickly) |
| Test | `gate_keeper_retries_a_refused_boot_report_then_hydrates`: 503 then 200, epoch 7 adopted |

## Evidence

- `cargo test --locked` → 336 lib tests, 0 failures (+1).
- Live boot smoke of the rebuilt image: restart nautilus with the gateway locked (one WARN,
  then quiet), enable the gateway → `durable_gate:true` with the row's epoch, revert.
