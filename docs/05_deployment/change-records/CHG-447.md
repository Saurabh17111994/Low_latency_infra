## What changed

1. **`ContextProbeStrategy` (`ctx-probe-v1`)** — the first on-demand context consumer,
   deliberately a probe and not a trading rule. On the live forming row of window `W`
   it asks the view for the previous window of the **live row's own TF**
   (`W − tf.windowMs()`):
   - a miss emits **nothing** (the fetch is scheduled, single-flight, retried on later
     ticks after the cooldown);
   - when the value is ready — a later live tick (cache hit) or the host's context-ready
     wake-up — it emits **one** 22-column `Signal_Candidates` row with deterministic
     `candidate_id = ctx-probe-v1:<token>:<tf>:<prevWindowStart>` (embeds the token,
     P2-176), `detection_ts` = the live candle's last event time and action `ENTRY`; a
     per-instance `EnumMap<Timeframe, Long>` guard keeps it to **one logical signal per
     (token, window)** — the realistic strategy shape, no dedup/state churn;
   - a snapshot at or past its window close **never** emits (counted
     `ready_after_close`); the probe has no `onClosedCandle` path.
   Counters: `misses`, `ready_before_close`, `ready_after_close` (plus the host's own
   `strategy/ctx-probe-v1.emitted`; in Prometheus the rule id is the `strategy` label
   value). The host's emitted-id dedup safety net itself is unchanged and stays pinned by
   the existing `Repeater`/`Churner` host tests (40 replays of one id → 1 emitted, 39
   suppressed).
2. **`Strategies`** — one registry line, inert unless a `STRATEGIES` list names the id.
   The canonical filter admits config-listed ids, so smoke rows reach the signal tables
   exactly like any other strategy's.

## Smoke iterations (all kept as evidence)

1. `logs/context-c3-smoke-20260930-092526` — **functional miss** (kept): the probe was
   gated to `ONE_M` and never evaluated. Root cause verified in code: the host's fast
   live feed is `MultiTimeframeAggregateFunction.LIVE_TICK_TAG`, which carries **only the
   smallest-TF (FIFTEEN_S) forming row per accepted trade** (`SignalJob.java:331`,
   `MultiTimeframeAggregateFunction.java:107`); the 1 s `LIVE_TAG` mirror feeds the
   `candle_live` sink, not the host. Fixed by using the live row's own TF; a standing
   fact for every future consumer: on the current job graph a strategy's live ticks are
   FIFTEEN_S rows.
2. `logs/context-c3-smoke-20260930-093905` — **functional pass, load too high** (kept):
   `ready_before_close` 793 188, `ready_after_close` **0**, `failed` 0, `hits` 793 188,
   `fetches` 57 859, `completed` 31 125 — but the probe re-emitted the same candidate on
   every tick and the host absorbed **733 489** repeats of dedup-ledger traffic; the
   strategy-host checkpoint sync rose to 882–1294 ms (C2 smoke, no consumer:
   37–614 ms; 900 s baseline: 0–24 ms) and two checkpoint-adjacent snapshots spiked
   `ingest_to_monitor` p99 to 607/526 ms. Fixed by the once-per-window guard above.
3. `logs/context-c3-smoke-20260930-094949` — **final evidence, clean**: `SMOKE EXIT=0`,
   presence PASS, job `53d0ab225f0c696e39d46279013e5a52` (market-hours window with the

   row per completed fetch), `misses` 240 056, host `suppressed` **0** — nothing was

   `timedout` 1 228 (2.5 %), `rejected` 187 256 (in-flight cap during first-touch
   bursts — by design), `cooldown_skips` 1 753.
   KPIs (max across subtasks, all 13 snapshots): `ingest_to_monitor` p99 76–84 ms
   (report p50 39 / p95 73 / p99 84) and `tick_to_strategy` p99 94–104 ms — inside the
   provider-idle C2 smoke and baseline bands, **no checkpoint spikes**.
   Note for the record: strategy-host checkpoint sync read 567–1183 ms in this run, but
   the same bursts exist in the provider-idle C2 smoke (37–614 ms) and in pre-context
   smokes (`logs/stage-profile-20260929-191631`: up to 533 ms) — the smoke/replay
