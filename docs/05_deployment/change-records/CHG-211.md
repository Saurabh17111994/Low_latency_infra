# CHG-211 — Wave 38 commit 7: checkpoints, bridge age, freshness, durations (P6-563/564/565/790)

## Changes (`stage-capture.sh`)
- P6-790: `DURATION_S` / `CAPTURE_INTERVAL_S` validated as positive integers
  at the header — one clear FAIL instead of cryptic mid-run errors.
- P6-563: bridge-age timestamp extraction handles full dates AND bare clock
  times (old `cut -c1-12` mangled full dates, fail-opening the check);
  bare times reading as future roll back one day (midnight rollover).
  Deviation: the audit sketch nested the future-check in the parse-fallback,
  which never fires (bare times parse as today successfully) — the check is
  explicit and full dates are exempt (future full date = clock skew, and
  subtracting a day would invent a stall).
- P6-564: checkpoint leg appends only ids newer than `.cp-last-id` (was full
  history every tick, O(ticks x checkpoints)); consecutive fetch failures
  WARN each tick and exit 2 at 5 (was `|| true` silence). Malformed bodies
  keep the old quiet-skip (fetch failure vs body parse stay distinct).
- P6-565: end-gate prom-freshness budget = 5x `CAPTURE_INTERVAL_S`, 25s floor
  (was hardcoded 25s — spurious failures on slow cadences).
- Test knob `BRIDGE_CHECK_AT_S` (default 65) so the bridge check is reachable
  in 8s hermetic runs. P6-863 needed no change: the whole-file WARN/FAIL→
  stderr guard passes over all new lines.
- Stub: `W38_CURL_MAX_ALIVE` (scrape dies mid-run), `/checkpoints` branch
  (`static`/`grow`/`dead`).
