## Notes

- **Why the stack, not just compose:** `fluss-fs-s3`'s `S3DelegationTokenProvider` reads
  Hadoop-style keys (`REGION_KEY = fs.s3a.region`), and CHG-306 applied the mirror to compose
  only. The dev deck could mint file-access tokens; the production deck could not — the exact
  dev-works/prod-fails class the production-parity wave exists for.
- **Values are references, not secrets:** `fs.s3a.access.key`/`secret.key` interpolate
  `$${env.AWS_ACCESS_KEY_ID}`/`$${env.AWS_SECRET_ACCESS_KEY}`, matching the `s3.*` keys above and
  compose; no literal credential enters the file.
- **Comment placement:** the first draft put the rationale inside the block scalar and the
  CHG-252 guard caught it (`test_properties_blocks_carry_no_comment_text`); the prose now sits
  above `FLUSS_PROPERTIES: |` in all four services.
