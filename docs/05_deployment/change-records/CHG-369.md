# CHG-369 — H1-2 + H1-4: typed send-failure taxonomy; UNKNOWN is never a terminal rejection

- **Status:** complete — the executor→bridge boundary now has a typed two-class send outcome. Only
  a provably-not-sent failure is retried; a timeout/reset/EOF/malformed/other-status outcome is
  `Unknown`, is never retried, halts the gate **process-wide** (the served forward leg included)
  through a new halt notifier, and emits **no** terminal order event — the order stays pre-send
  and reconciliation (or the true async postback) resolves it.
- **Filed:** 2026-09-29
- **Source:** H1-2 and H1-4 from `logs/full-project-audit-20260928/REPORT.md` via
  `docs/plans/2026-09-28-high-findings-remediation.md`.

## Notes

- **Fail-closed default preserved:** `HaltNotifier` unbound (offline slice / unit tests) is a
  no-op; the client's own gate always halts first, and the durable report rides the bound
  `ServerState::safety_halt`.
- **One halt policy inside the client:** the uncorrelated-report, uncached-order, and
  unknown-postback halts now use `safety_halt_with_reason` too — they are the same ambiguity class
  and must stop the served forward leg, not only the boxed gate (C1's dispatch is untouched).
- **Contract reconciliation:** contract 07's table listed 401/403 as never-retried `UNKNOWN`
  while the approved plan (D3) classifies pre-dispatch rejections as retry-safe. Authority order
  (code+tests > decisions > contracts) resolved it; both docs updated and the conflict recorded in
  `01-foundation.md` rather than silently re-interpreted.
- **Mutation lesson (second of the wave):** a side metric the defective path never updated cannot
  witness the defect; assert the observable the defect actually produces.
