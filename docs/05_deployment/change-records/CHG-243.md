## Deviations from the audit's fix text

1. **P6-826** — the audit offered "make hermetic" or "move to an integration suite".
   Both were declined in favour of hermetic **plus** one explicitly-named
   repo-integrity test: moving the cases out would have deleted the only place a real
   dossier rename is noticed.
2. **P6-830** — the audit said drop the return value; I used it instead (assert 5 jars),
   because a fixture that checks its own output beats a deleted line.
3. **P6-619** — the audit allowed "implement the intended check". No rule was ever
   specified and inventing one is scope creep, so the line is gone; recorded below.
4. **P6-856** — narrowed after measuring: the audit's "a legitimate pinned value that
   contains TO_BE_VERIFIED" is contrived, and **nothing in `code/` calls `VersionGate`
   yet** (only its own test), so the blast radius today is the unit test. The real
   defect was code contradicting its Javadoc, which is what the fix addresses.
5. **P6-645** — verified by build rather than by inspection, as promised.

## Observations recorded, not fixed

1. `assert "log" not in …` was never specified as a rule anywhere; if a log-leak
   structural check is wanted, it should be designed against `render_evidence`'s actual
   sections rather than guessed here.
2. After the P6-628 fix the probe's tier is `LINE-ANNOTATED`, not LIVE-STALE — the
   date annotation on the line is what keeps it out of LIVE-STALE. The test therefore
   guarantees "not LIVE-STALE", which is what it asserts, and not "no hit at all".
3. The 48 leaked `/tmp/tmp*.tsv` files from before the fix are still on disk (the fix
   stops new ones). They can be removed on request.
4. `mvn -pl common,02_services/01_ingestion test -Dtest='VersionGateTest,*SchemaManifest*'`
   exits 1 with "No tests matching pattern … were executed!" because the filter matches
   nothing in `ingestion` — a harness trap worth knowing before quoting its exit code.
