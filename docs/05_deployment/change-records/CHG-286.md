## Why

CHG-283 states the acceptance for per-node attribution in prose: *"On two nodes this is the acceptance test: the
query must return one address per node."* On VM day that sentence has to become a command, because the query was
otherwise a line typed once into a shell — and a remembered query cannot be re-run against a 3-node fleet, cannot
say what the expected count is, and cannot notice the failure mode it exists to catch.

That failure mode is specific. The collector used to scrape the per-task Swarm name `tasks.node-exporter`, and
**that is still the shape a `dns_sd_configs` job produces if the bare service name is used**: the bare name
resolves to the service VIP, one address, so one random node would be sampled per scrape. A check that only
counted instances would pass on a fleet where every instance is that VIP. This one fails if any instance is still
a `tasks.` name, so the pre-CHG-283 shape cannot return unnoticed.

## What it does

`pernode_attribution_check.py --expect <node count>` asks OpenObserve's metrics search for
`select distinct(instance) from "node_boot_time_seconds"` and fails unless at least `--expect` distinct
instances came back **and** each one is `host:port`. Exit 0 passes, exit 1 is a failed check, exit 2 means the
check never ran (usage, no credential, refused plain-http transport, or O2 could not answer) — an outage is not a
failed check.

It follows the conventions the other O2 tools already set: `O2_AUTH_BASIC` from the environment or
`O2_SECRETS_FILE` (default `code/01_platform/01_docker/secrets.env`), the credential never printed, and
plain-http on a non-local host refused unless `O2_ALLOW_INSECURE_HTTP=1`. `?type=metrics` is mandatory: without
it the search goes to the log streams and answers `400 Search stream not found` (measured 2026-09-21).

## Reuse considered and rejected

`perf_evidence_parse.query_o2()` already speaks this API, and reusing it was the first plan. It is scalar-only —
it reads `hits[0]["value"]` and returns a float — and it hardcodes `size: 5`, which would silently undercount a
fleet larger than five nodes. Extracting a rows variant would have changed tested code for one caller, so the
new script keeps the request shape and the auth convention instead.

## Not verified

It has never run against a real deployment: no VM exists here, and the deck is torn down. Its request shape and
exit codes are what the tests assert; the first VM day is when it meets real data.
