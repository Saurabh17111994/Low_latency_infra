## What changed

1. Top-level `configs:` gains `flink-dstl-dfs-jar` sourced from
   `./flink-plugins/dstl-dfs/flink-dstl-dfs-2.2.1.jar` (sha256
   `aa467887d059d348d1f52d134d7ba1c0664e072054dae3748c5d498d63f997ad`, README provenance).
   A Swarm config, not a host bind: the repo path differs per VM, and a bind source
   missing on the node the task lands on is a recorded production failure
   (`PROD_VM_PROVISIONING.md` S8b). Immutable by design — a new plugin version needs a
   new config name.
2. `flink-taskmanager` mounts it at
   `/opt/flink/plugins/dstl-dfs/flink-dstl-dfs-2.2.1.jar` (the storage is a
   TaskManager-level service; the JobManager does not need the jar — CHG-443/444).
3. `flink-taskmanager` `FLINK_PROPERTIES` gains
   `state.changelog.storage: filesystem` and
   `state.changelog.dstl.dfs.base-path: file:///checkpoints/changelog` — the same
   values as the certified dev deck.

## Limits recorded (not solved here)

- The base path is the node-local `flink-checkpoints` volume (correct for the
  single-node deck; the real 4-VM rig needs a shared base path before adoption there).
- The jar is gitignored: a deploy needs it present in the working tree; the VM golden
  recipe already proves `flink-plugins/dstl-dfs` (CHG-493).
