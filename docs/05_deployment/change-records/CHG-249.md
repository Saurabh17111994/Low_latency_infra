# CHG-249 — production Swarm stack brought up for the first time: ZooKeeper recipe, secret file wiring, manifest delivery

## Why

The committed Swarm stack had never been started. A local rehearsal — the real
`code/01_platform/01_docker/docker-stack.yml` on a single-node Swarm, with only resources overridden —
brought it up repeatedly and recorded four independent failures, each reproduced more than once:

1. **The ZooKeeper ensemble never formed.** Four separate causes, all measured: `ZOO_SERVERS` was
   `;`-separated, which the image's entrypoint writes as one invalid line
   (`ConfigException … does not have the form server_config or server_config;client_config`, exit 2);
   `ZOO_CFG_EXTRA` did not exist, so the generated `zoo.cfg` had no `clientPort` and nothing listened
   on 2181 (`Client port not found in the server configs`); each member tried to bind `:3888` on its
   own service name, which Swarm cannot resolve before the task is Running
   (`<unresolved>:3888 … electionPortBindRetry`, exit 14); and the healthcheck ran
   `zkServer.sh status`, which needs quorum — while Swarm publishes a DNS name only for tasks that
   are already Running *and* healthcheck-passed. The ensemble deadlocked, was killed after ~170 s
   (`task: non-zero exit (143): dockerexec: unhealthy container`), and never once reached `Running`.
2. **The instrument manifest never reached ingestion.** `configs:` was never wired into the service
   and the image's `COPY` of the manifest had been removed, so the service died with
   `FATAL — readable manifest FILE is required: /instruments/NSE_CM_EQUITY.csv`.
3. **Money-path secrets were mounted but never read.** `execution-gateway` and `nautilus` mounted
   `gateway_shared_secret` at `/run/secrets/…` while only `GATEWAY_SHARED_SECRET` from the plain
   environment was consulted, and the ingestion Go bridge did the same for the three `ARROW_*`
   credentials — which it requires even in fake-broker mode. The counterpart precedent
   (`EXECUTION_BRIDGE_AUTH_TOKEN_FILE`) already existed in the tree; these three services had not
   followed it.
4. **OpenObserve crash-looped.** `panicked at src/job/mod.rs:308:13: Please set root user email-id &
   password using ZO_ROOT_USER_EMAIL & ZO_ROOT_USER_PASSWORD environment variables.` — v0.91.5 has no
   `_FILE` form, and the stack set only the email.

The rehearsal also disproved two assumptions: `docker stack config` compiles a bad healthcheck
without complaint (rc=0), and `docker stack deploy` with two `-c` files **appends** list-valued
fields (`healthcheck.test`, `configs`, `secrets`, `ports`) instead of replacing them, so a resource
override silently produced a four-element healthcheck test that never validated what it claimed.

## What changed

- **`code/01_platform/01_docker/docker-stack.yml`** — ZooKeeper now uses a recipe that is
  self-sufficient: `ZOO_SERVERS` whitespace-separated; `ZOO_CFG_EXTRA` supplying
  `clientPort=2181 quorumListenOnAllIPs=true admin.serverAddress=127.0.0.1 admin.serverPort=8080`;
  and a liveness-only healthcheck (`bash -c 'exec 3<>/dev/tcp/127.0.0.1/8080'`) that depends on
  nothing but its own process. Ingestion mounts the manifest as a Swarm config at
  `/instruments/NSE_CM_EQUITY.csv` and reads its three Arrow credentials through `_FILE` variables.
  `execution-gateway` and `nautilus` read `GATEWAY_SHARED_SECRET_FILE`. OpenObserve takes
  `ZO_ROOT_USER_PASSWORD: ${O2_PASSWORD:?…}` and no longer mounts a secret it cannot read.
- **`code/01_platform/01_docker/instruments/` (new)** — the manifest becomes a repository artifact
  (`NSE_CM_EQUITY.csv`, 2434 lines) delivered as a Swarm config, with a 1025-line (1024-instrument)
  variant for tests.
- **`code/02_services/01_ingestion/go-bridge/main.go`** — `secretFromEnv` implements the file
  contract used elsewhere in the tree: the `_FILE` form is preferred and wins over the plain
  variable, the value is trimmed, and an unreadable or empty file fails loudly instead of starting
  credential-less. `secret_file_test.go` (new) pins all four behaviours.
- **`code/02_services/06_execution_gateway/…/GatewayConfig.java`** and
  **`code/02_services/04_executor/src/config.rs`** — the same file contract for the gateway secret
  in Java and Rust, each with tests for file-present, file-wins, plain-variable fallback and
  loud failure.
- **`code/01_platform/04_scripts/tests/test_09_stack.py`** — eight tests: whitespace `ZOO_SERVERS`,
  a ZooKeeper config that actually yields a client port, the liveness-only rule applied to every
  service in the stack, the manifest mounted where the application looks for it, every mounted
  secret consumed by one of the two supported mechanisms, and the three file-reading services.
  The pre-existing `test_healthchecks_can_actually_run_where_declared` rule was narrowed rather than
  dropped: a `/dev/tcp` probe must still be bash, but its address must match the bind — `$HOSTNAME`
  for the Fluss shape, `127.0.0.1` only for a listener whose own environment says it is
  loopback-bound (the ZooKeeper admin server, via `admin.serverAddress=127.0.0.1`). Deleting that
  setting from `ZOO_CFG_EXTRA` makes the test fail, so the exception cannot outlive the recipe.
- **`docs/01_project/04-decisions.md`** — DEC-047 (healthchecks may not depend on another service or
  on cluster formation), DEC-048 (secret file form, and mounted implies consumed), DEC-049 (the
  ZooKeeper recipe), DEC-050 (deploy inputs come from the repository and Swarm objects only).
- **`docs/05_deployment/PROD_VM_PROVISIONING.md`** — §2 rule 6 states the liveness rule; S6's
  consumer list is corrected (it previously claimed ingestion consumed the `arrow_*` secrets) and
  records that `o2_password` is created but no longer mounted; S7 lists the rehearsal's traps.

## Limitation

The rehearsal proved each part of the ZooKeeper recipe and then the ensemble end-to-end on a
single-node Swarm: three members, one leader and two followers, port 2181 reading, peer names
resolving, and a real client read through the quorum returning the three znodes. It has still never
run on more than one node, so leader election across nodes and the constraint `node.labels.role ==
worker` are exercised only as declared placement. The Fluss coordinator was found to bind
`bind.listeners` to its own service name and to abort with `UnresolvedAddressException` for the same
reason as ZooKeeper; that discovery is recorded here for the follow-up and is **not** part of this
change set. Three services (ingestion, `execution-gateway`, `nautilus`) cannot be proven by this
change alone: the rehearsal images predate these edits, so their next run is the first that
exercises the new readers.
