## Why (verified in the tree)

- Compose defaults: `MULTITF_ENABLED:-false` (`docker-compose.yml:82`),
  `STRATEGY_HOST_ENABLED:-false`, `STRATEGIES:-''`,
  `EXECUTION_INTENT_ENABLED:-false` (`docker-compose.yml:93-95`).
- The golden build copies `.env` from `.env.example`
  (`vm-golden-build.sh:157-161`), and `.env.example` carries none of the four
  flags; `day_run.universe_env` does not pin them either.
- `SignalJobConfig` defaults them false and "Candle production requires
  `MULTITF_ENABLED=true`" (`docs/08_implementation/04-signal-job.md`);
  `STRATEGY_HOST_ENABLED=true` additionally requires a non-empty `STRATEGIES`
  list and `MULTITF_ENABLED=true` (fail-fast otherwise).
- `.env.vm.example` already declares `EOD_TABLES=candle_features` ("the durable
  candle record"), which the off-default boot could not produce.
- Full parity is safe on the daily VM: `EXECUTION_ENABLED` stays `false`
  (`.env.example:154`), the gateway remains the send boundary, and the
  execution identity comes from the compose anchor's dev defaults
  (`docker-compose.yml:37-39`).
