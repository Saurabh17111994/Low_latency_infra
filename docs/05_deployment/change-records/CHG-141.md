# CHG-141 — The checkers that gate our own process stop passing on near matches and silent skips

- **Status:** recorded — thirteen findings fixed across six files, four test files extended, one
  public value class turned into a validated record, plus one sibling defect surfaced while filing
  this record and fixed in the same wave
- **Filed:** 2026-09-14
- **Source:** P6 ops/scripts/tests/chaos audit, wave 4 ("The checkers that gate our own process"):
  P6-272, P6-273, P6-325, P6-326, P6-367, P6-416, P6-690, P6-716, P6-724, P6-725, P6-726, P6-727,
  P6-745

## What happened

Every finding was re-verified against the current code before editing; all thirteen were real. The
work is grouped by the file each finding lives in, one commit per group.

**The evidence record was a bag of public fields (`P6-272`, `P6-273`).** `EvidenceRecord` — the
format every release-gate claim is recorded in — had eleven public mutable fields with implicit
`null` defaults and no constructor, so any caller could store a record with no work item, no result
and no owner, and readers could NPE on `requirementIds` or mutate the requirement linkage of a
record that had already been accepted. It is now a record: the canonical constructor refuses any
null or blank field (the spec gives every field required content) and copies the requirement list,
so the accessor cannot be used to mutate an accepted record.

**Change control could not resolve half of what it validates (`P6-325`, `P6-326`, `P6-716`).** The
repo-wide fallback compared a *path-shaped* artifact token against bare filenames from `os.walk`, so
a token like `src/main/java/Foo.java` could never resolve and a real artifact was reported as
unknown. The fallback now matches the repo-relative path or any path ending in `/<token>`, backed by
one lazily built index (the walk was previously paid per token). `TRACKER_RE` also matched any word
ending in "tracker" plus digits, so `tasktracker-5`, `non-tracker-5.md` and `backTracker_3` all
triggered spurious "no `docs/08_implementation/<n>-*.md` exists" failures; a lookbehind admits only
standalone `tracker-<n>` tokens.

**The ownership gate could skip evidence and die on its own configuration (`P6-367`, `P6-725`,
`P6-727`).** `os.walk` without `onerror` swallowed read errors, so an unreadable subtree hid every
record inside it and the gate still reported PASS; an unreadable path is now a violation. A
non-numeric `DDL_APPLY_UID`/`GID` raised an uncaught `ValueError` at import; it is now a named
`FATAL` on stderr with exit 2 (did not run, distinct from 1 = findings), while an absent or blank
value keeps the documented default. The printed remediation also skipped the failure it reports
loudest — `chmod` cannot change an owner — so it now names `chown -R 10001:10001` through the image.

**The implementation gate's claim and its needle disagreed (`P6-416`, `P6-745`).** Task 2 claimed to
pin "INGESTION_MAX_BATCH_RECORDS=1" while searching only for the constant name, so a drift to 1000
stayed green. The value is now pinned where it lives (`PlatformConfig.INGESTION_MAX_BATCH_RECORDS =
1`), and a failure in the final task no longer prints "downstream tasks 8..7 BLOCKED".

**The live-run harness passed an argument nothing reads (`P6-690`).** `SafetyHaltJob.main` derives
its wiring from the environment and never inspects `argv`, so `--bootstrap localhost:9123` looked
like cluster selection but was discarded, and the harness comment credited itself with a
`CHECKPOINTS_DIRECTORY` it never set. It now passes no arguments and states what must be exported.

**A tracker id inside a path was read as a tracker reference (surfaced while filing this record).**
`plan_tasks: …, logs/tracker-14/SafetyLiveJobRun.java` was rejected with "plan_tasks references
tracker-14 but no docs/08_implementation/14-*.md exists". The regex is right to anchor on a
standalone token (`P6-716`), but the check ran over the whole value, so an artifact under any
`logs/tracker-<n>/` became a demand for a dossier. Tokens containing a path separator are artifacts
and are resolved as such; bare `tracker-<n>` tokens are still validated.

**C6 measured the compute suite twice (`P6-724`).** `surefire_total(compute)` ran once for the check
and once for the message, each time globbing, parsing and walking the compute test tree; the value
is now computed once.

## Judgement calls (review these)

1. **`P6-325`: suffix match, not the suggested basename fallback.** The finding proposed extracting
   `os.path.basename(name)` for path-shaped tokens. That would resolve `a/b/Foo.java` to *any*
   `Foo.java` in the tree — a silent false pass in a gate. The fallback requires the token to line
   up with the real path (`…/a/b/Foo.java` or any suffix of it) and returns unresolved otherwise;
   a test pins that a wrong directory stays unresolved even when a same-named file exists.
2. **`P6-726` is a documentation fix, not a behaviour change.** The module docstring said the
   evidence-root check is "enforced only when the corpus is container-owned", which reads as a
   record-count scope the code never had. The finding proposed gating the dir check on
   `container_written > 0`. Judgement: a root-owned evidence root is a container-run defect on its
   own — it will be inherited by the next write — so it must fail even when every record inside is
   host-owned. The docstring and `_dir_problem` now say that; a test pins it; the behaviour is
   unchanged.
3. **`P6-416` was fixed by adding a value pin, not by weakening the text.** The existing name-only
   check stays (it pins the env-key wiring) with an honest description, and a second check pins the
   value at its owner. The bounded-backpressure sibling keeps a name-only needle on purpose: its
   bound is a range, pinned by `IngestionConfigTest`, and inventing a number pin for it would fight
   the config-surface work of CHG-138.
4. **`EvidenceRecord` changed shape with no consumer.** Grep confirms the class is referenced only by
   its own file and two doc rows, so no caller breaks; had it been released, a public field-to-
   accessor change would be `INCOMPATIBLE` rather than `COMPATIBLE_WITH_LIMITATION`. The class stays
   "Evidence: Untested" in the foundation row — the new unit test exercises construction, not a
   release claim.
5. **`P6-690` edited a dated evidence artifact.** The change is a comment plus `new String[0]`; the
   2026-08-18 run is unaffected because `argv` was ignored then too, so the recorded evidence
   stands. The dated row in `04-signal-job.md` still cites the file's size at capture (674 B) and
   was left alone; the new size is 1184 B.
6. **Exit code 2 for a broken uid override.** The script's own contract is 0 = pass, 1 = findings;
   a malformed override means the check could not run at all, which is now 2 rather than a traceback
   or a silent default.
