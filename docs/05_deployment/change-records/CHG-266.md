# CHG-266 — S4 as a script that can refuse, with the clock asserted instead of assumed

## Why

S4 ("bootstrap hosts") was prose: a list of commands in a document the operator follows by hand on
four VMs. A document cannot fail. Two consequences were already recorded as open gaps in this
runbook's own gap table — nothing installed Docker or enabled NTP, and nothing checked the clock
offset, although TOTP is clock-based and the platform halts itself beyond the offset limit. A host
whose clock is not disciplined therefore passes every check this repository owns and fails later, at
a time nobody correlates with the bootstrap.

The sysctl step had the opposite problem: it is marked "not yet defined" and says, correctly, *do not
paste a list nobody recorded*. That instruction is only enforceable by something that refuses.

## What changed

- **`code/01_platform/04_scripts/vm-bootstrap.sh`** (new) — S4 for one node, two modes. `--apply` is
  idempotent and runs exactly the commands S4 already prescribed (git + clone, Docker from Docker's
  repository, chrony + `enable --now`). `--check` is read-only, exit code = number of FAILs, and
  verifies: docker usable by this user without `sudo`; `timedatectl` reports a synchronised clock;
  `chronyc tracking` offset within `--max-offset` (default 1 s); the repository clone is present;
  `/var/log/syslog` exists and belongs to group `adm` (the collector's read path, CHG-263); the Swarm
  ports (plus any `--extra-free-ports`) are free; `daemon.json` is valid JSON and, when `--registry`
  is given, lists the plain-HTTP registry. It deliberately does **not** touch sysctls, does not join
  the Swarm (S5), creates no secrets (S6) and never opens an SSH connection.
- **`code/01_platform/04_scripts/tests/test_12_vm_bootstrap.py`** (new) — 18 hermetic tests. Every
  path is rooted at `$VM_BOOTSTRAP_ROOT` and every external command is resolved through PATH, so the
  tests run the real script against fakes: no root, no Docker, no clock, no node.
- **`docs/05_deployment/PROD_VM_PROVISIONING.md`** — S4 gains the invocation and a statement of what
  is scripted and what is not; the gap-table row now names the sysctl decision alone.


Two of the tests were wrong before they were right, and both were fixture faults rather than script
faults — the kind that would have produced a *false PASS* if left alone:

- the fake `tee` exited without reading stdin, so `echo … | tee` died of `SIGPIPE` and `pipefail`
  turned a working pipeline into a reported failure. Real `tee` drains the pipe; the fake now does too.
- the fake `systemctl is-active` always reported chrony as active, so the `enable --now` branch was
  never exercised. It is now controllable per fixture, and the prepared-node test asserts that
  nothing is enabled.

## Limitation

**This script has never run on a node.** There are no VMs, so the evidence above is hermetic tests
against fakes plus the script's own self-check output on a synthetic tree. Everything it does in
`--apply` is a command S4 already prescribed, but the first real run is still the first real run:
run it on VM4 first, and read the four `[PASS]` lines rather than trusting the exit code alone.

**The 1 s clock threshold is a decision, not a measurement.** It is deliberately loose (a disciplined
host sits in the ms range) and deliberately tight compared with any TOTP window. If the authenticator
turns out to tolerate more or less, the number is `--max-offset`, and the change is one argument.

**`--check` reports the sysctl gap as a FAIL, permanently, by design.** A host can therefore never
print `0 failure(s)` until the production sysctl list is decided and recorded (§6.1). That is the
point — but it does mean an operator running `--check` today sees one expected FAIL, and the runbook
now says so instead of leaving it unexplained.

**It does not verify what it cannot see.** The firewall rules, the registry itself (S4 step 5),
`docker swarm join` (S5), the nine secrets (S6) and the deployed cluster (S8b, CHG-264) are all
someone else's check; this one only guarantees the host it runs on.
