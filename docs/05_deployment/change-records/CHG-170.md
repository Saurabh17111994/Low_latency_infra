## 1. A skipped test is not a PASS (P6-049, P6-052)

| Finding | Was | Now |
|---|---|---|
| P6-049 | the live leg ran `mvn -Dtest=TabletKillChaosIntegrationTest -DfailIfNoTests=false test` and treated exit 0 as the invariant; the IT is `@EnabledIfEnvironmentVariable`-gated and `assumeTrue`s its bootstrap, docker and `raw_table_1`, so a skipped run left a green build that the drill reported as PASS | `run_live_test` greps the IT's own `TABLET-KILL-CHAOS-03: RESULT=PASS` sentinel; an assumption failure or a skip becomes a named SKIP (exit 3) carrying the maven line that explains it, and a green build with neither sentinel nor skip is a FAIL |
| P6-052 | same defect, stating the fix as "grep for the sentinel or use `-DfailIfNoTests=true`" | the sentinel is required (the flag alone would only turn a missing class into a failure, not a skipped test) |
| P6-049 (message) | the PASS line claimed "acked rows still readable, LOG count never shrank" unconditionally, which at RF1 is not what the IT asserts — an unclean kill there does lose the just-acked tail | the message names what holds at RF1 (LOG never shrank, table readable again) and says the tail loss is reported, not asserted away |

## 2. Which container may die (P6-050, P6-051, P6-334, P6-338)

| Finding | Was | Now |
|---|---|---|
| P6-050, P6-051 | liveness was `docker ps --format '{{.ID}} {{.Names}}' \| grep -q "${TABLET_CONTAINER}"`: a substring match with no allowlist, no `-F`, no `--`, so a typo, a stale id or a regex (`.*`) passed and was then passed to `docker kill -s KILL` inside `TabletKillChaosIntegrationTest` | `verify_tablet` resolves the value with `docker inspect --format '{{.Name}} {{.State.Running}}' -- <container>` and requires a `*fluss-tablet*` name that is `true`; a value that does not resolve, is not a tablet, or is not running is refused before any kill |
| P6-334, P6-338 | `docker ps --filter name=fluss-tablet --format '{{.ID}}' \| head -n 1` picked an arbitrary replica when several tablets run (order is not stable) and logged only an id, so the run did not say which tablet it killed | `list_tablets` lists names sorted and logs them; with more than one candidate and no pin the drill refuses (exit 2) and asks for `TABLET_CONTAINER`; the chosen container is named on stdout and in the maven environment |
| P6-050 (pinned) | a pinned override that named nothing fell through to the same SKIP as an absent stack, hiding the typo in the caller's config | a pinned override that does not resolve is a config error (2); an auto-discovered tablet that is gone or stopped is a SKIP (3) |

## 3. Knobs that would make the drill vacuous (P6-336, P6-337)

| Finding | Was | Now |
|---|---|---|
| P6-336, P6-337 | `TABLET_KILL_ROWS=0` wrote no acked rows, so `ackedAfter.containsAll(acked)` held on an empty set — a PASS with no chaos injected; a non-numeric value or `CHAOS_SCAN_LIMIT_ROWS < TABLET_KILL_ROWS` failed late inside Java with a `NumberFormatException` or a tail-window message | `validate_knobs` requires a positive integer for `TABLET_KILL_ROWS` and `CHAOS_REPLICATION_MIN`, allows `CHAOS_SCAN_LIMIT_ROWS` to be `-1` or a positive integer that is not smaller than the acked batch, and normalises `CHAOS_REPLICATION_REQUIRED` to `true`/`false`; all of it before anything is read |

## 4. The compile probe fails fast (P6-335, P6-339)

| Finding | Was | Now |
|---|---|---|
| P6-335, P6-339 | the offline `mvn -o test-compile -q` failure silently retried online: no `mvn` precheck, no diagnostic, no timeout, and `-q` hiding the cause, so a missing local artifact could hang an unattended chaos run instead of failing it | `have mvn` is checked first; the retry announces itself with the bound, runs under `timeout "${CHAOS_COMPILE_TIMEOUT_S}"` (default 300) without `-q`, and warns explicitly when `timeout` itself is missing |

## 6. The runner counts what ran (P6-058, P6-059)

| Finding | Was | Now |
|---|---|---|
| P6-059 | the final verdict only checked `FAIL_COUNT == 0`, so four SKIPs printed `RESULT=PASS EXIT=0` — zero coverage reported as proven resilience | `run_one` keeps PASS/SKIP/FAIL/PARTIAL counters; the summary line reports all of them, and when no drill passed the runner exits 3 with `RESULT=SKIP ... (0 passed, N skipped — no coverage proven)` |
| P6-058 | chaos-02's documented "0 or a named leg-B SKIP" was invisible to the runner, which reported the skipped live leg as a plain PASS | each inventory entry may carry an in-band skip marker (`TM-KILL-CHAOS-02: [leg B] SKIP`); when a child exits 0 but prints its marker the result is PARTIAL, counted separately and named in both the stream and SUMMARY.txt. A child exit 2 is a FAIL — a misconfigured drill is not an absent prerequisite |

## 7. Evidence that can be trusted (P6-344, P6-345, P6-346, P6-721)

| Finding | Was | Now |
|---|---|---|
| P6-344 | `LOGDIR=logs/chaos/chaos-$(date -u +%Y%m%d-%H%M%S)` has one-second resolution, so two runs in the same second shared a directory and clobbered each other's SUMMARY.txt; a failing `mkdir -p` died under `set -e` with no message | the directory is suffixed with `$$` and its creation failure is reported before exiting 1 |
| P6-345 | `shellcheck -S warning "${f}" 2>>"${SUMMARY}"` dropped the diagnostics (shellcheck writes to stdout), so a self-check failure landed in the audit trail with no reason; and a missing shellcheck skipped the check silently, making the gate machine-dependent | stdout is captured into SUMMARY.txt as well, and a missing shellcheck emits `SELF-CHECK WARN` so the difference between "clean" and "not checked" is visible |
| P6-346 | the drill inventory appeared in the self-check `for f in ...` loop, in four `run_one` calls and in a hardcoded `[N/4]` total — three edits per added drill, and silent drift | one `TESTS` array (name, script, optional skip marker) drives the self-check, the run order and the derived `TOTAL` |
| P6-721 | the verdict read only `PIPESTATUS[0]`, so a failed `tee "${log}"` (unwritable LOGDIR, full disk) left a truncated log and still reported PASS under `pipefail`; the `RESULTS` array was written and never read | `PIPESTATUS` is captured as an array and a non-zero tee exit is an `EVIDENCE FAIL` that forces `RESULT=FAIL EXIT=1`; the dead `RESULTS` array is gone |
