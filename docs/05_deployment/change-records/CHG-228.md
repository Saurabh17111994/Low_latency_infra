# CHG-228 — the corpus pin must see the whole corpus, and never truncate itself

- **Status:** recorded — fixed (2026-09-19)
- **Filed:** 2026-09-19
- **Source:** the wave-40 audit findings P6-060, P6-061, P6-349 against
  `code/01_platform/04_scripts/corpus-pin.sh`.

## What happened

`make pin-check` is a gate step (`run-monday-gates.sh` → `pin-check.sh:28` →
`corpus-pin.sh --verify`). Three defects made that guard weaker than it reads:

- **P6-060** — `sha256sum -c` only checks the paths the manifest *lists*. A new file under the
  corpus directory left the check green while the corpus and its pin diverged, so the "versioned
  and reproducible" guarantee (foundation L553) had a hole exactly where a decoder change lands.
- **P6-061** — `--regenerate` wrote `(...) >"$MANIFEST"`: the redirect truncates the committed pin
  file before the pipeline produces a byte, so any mid-pipeline failure left a corrupted manifest.
  The glob also skipped dotfiles, expanded to a literal `*` on an empty directory, made
  `sha256sum` fail on a subdirectory, and relied on implicit glob order.
- **P6-349** — `case "${1:-}"` accepted `--verify anything` and silently ignored the extra word.

Measured before the change (2026-09-19): the committed manifest is in sync with the corpus
(6 pinned paths = 6 files on disk) and every line is strict-form (64 hex + two spaces).

## The change

`corpus-pin.sh` now:

- requires exactly one argument (0, 2+, or an unknown verb → usage, exit 2);
- verifies with `sha256sum --strict -c`, then compares the pinned path set against
  `find <corpus> -type f` and fails with a `diff` naming the unpinned/renamed file;
- regenerates into a `mktemp` file beside the manifest (`find -print0 | LC_ALL=C sort -z |
  xargs -0 -r sha256sum --`) and `mv`s it into place atomically, refusing to pin an empty corpus.

Limitation: GNU-only, exactly as `sha256sum` already is (`--strict`, `xargs -r`, `find -print0`).
This is Linux tooling — macOS ships `shasum`, not `sha256sum`.

## Verification

- `corpus-pin.sh --verify` on the committed corpus: rc 0, all 6 files `OK`.
- Temp-repo legs (the script derives its root from its own location): a new unpinned file → rc 1
  and `diverged` in the message; re-pin → rc 0; a malformed manifest line → non-zero (`--strict`);
  a dotfile is pinned; two regenerates are byte-identical.
- Atomicity, measured: with one corpus file at mode 000, `--regenerate` exits 123 and the
  committed manifest is **unchanged** — the old form left it truncated. No temp file remains.
- `test_import_corpus_wave40.py`: 14 legs, offline, no cluster.
