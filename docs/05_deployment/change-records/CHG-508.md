## What changed

- **`Dockerfile`** — the runtime stage now copies the whole compiled probe
  output (`COPY --from=java-builder /probe-classes/ /app/probe/`) instead of
  only `FlussReadLagProbe.class`. The probe catches its nested
  `InputException` in `main`, so the JVM resolves that class when the main
  class initialises; the single-class copy crashed it with
  `NoClassDefFoundError: FlussReadLagProbe$InputException`.
- **`vm-golden-build.sh --check`** — proves both classes before a VM snapshot
  is taken (previously only the outer class), so a golden image that cannot
  run the daily probe fails at build time instead of at the 09:15 board.
- **Test pins** — `test_ingestion_probe_image.py` asserts the directory copy
  and rejects the single-class form; `test_vm_golden_recipe.py` asserts the
  nested-class check.
- **`CLOUDPE_DAILY_VM.md`** — the toolchain paragraph now names the probe
  classes, not one file.

## Why the checks missed it

The Dockerfile pin and the golden check both named the outer class only; both
passed while the image could not start the probe. The new pins close both
sides (build recipe + golden recipe).
