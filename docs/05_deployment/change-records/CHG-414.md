## Notes

- **Stricter merge:** an env file whose demanded images are covered by neither stdin nor the lock now
  exits 3 instead of passing silently — that is the intended tightening, recorded as COMPATIBLE
  because the deploy path that supplies the fragment (CI's `images.published.env`) already covers
  every app image.
- **Why three seams:** the finding was that `.env.example` shipped a bare O2 tag and nothing in the
  chain enforced the lock — pin-check checked only the lock's *shape*, and preflight deliberately
  exempted upstream images. Each seam now fails closed on its own: the merge never writes an
  uncovered/bare value, preflight rejects a deploy env that disagrees with the lock, and pin-check
  rejects a stack that demands an image neither pushed nor pinned.
- **`--coverage-check` is the shared rule:** `--self-check` and pin-check `[5/6]` call the same
  function, so the workstation check and the gate cannot drift. It is offline (no docker).
- **Bare means bare:** a lock line without `@sha256:<64 hex>` is not coverage and is not overlaid —
  a tag is "whatever the registry happened to serve". Pinned by unit cases in both directions.
- **The certifying pull stays a landing step:** this change makes the digest *enforced*; the one
  `docker pull` of the recorded O2 digest happens when the deploy env is rendered on the VM
  (S4/S7). A digest that does not resolve there is a STOP, never an invented substitute.
- **Dev is reported, not fatal:** preflight's lock rule follows the existing `--expect dev`
  convention (`[INFO]`), so the gate's dev-mode preflight against `.env.example` stays green.
