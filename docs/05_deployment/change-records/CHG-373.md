# CHG-373 — H1-5: identity-mixed fill version (same-ms fills no longer collide)

- **Status:** complete — a fill's projection `sourceVersion` is now
  `receiveTime * 1_000_000 + floorMod(fnv1a64(postback_event_id), 1_000_000)`, bounds-checked.
  Two distinct fills received in the same millisecond carry distinct versions instead of the equal
  version that the KV protocol read as CONFLICT → quarantine + permanent scope halt; a replayed row
  yields the identical version (DUPLICATE), a truncated-mix collision stays the loud CONFLICT, and
  ordering across milliseconds is unchanged.
- **Filed:** 2026-09-29

  `docs/plans/2026-09-28-high-findings-remediation.md` (`FillEventMapper.java:17,73-75,99` used

## Notes

- **Residual same-ms ordering (accepted):** the mix is an identity, not an ordering. Two distinct
  same-ms fills whose mixes sort in arrival order both apply (pinned); if the second's mix sorts
  lower it is a soft `STALE` (counted/quarantined, **never** the CONFLICT/halt this finding is
  about), because the snapshot stores one `(version, event id)` pair and cannot remember arbitrary
  same-ms peers. Production positions are Nautilus-owned; this Java projector is the documented
  reference, and the collision path (`sameVersionDifferentContentIsConflictViolation`) is
  unchanged. Making same-ms distinct fills order-independent would need per-ms peer state, which
  the accepted formula deliberately does not introduce.
- **Legacy versions:** a snapshot written before this change holds a bare receive-ms version
  (~1.7e12); every scaled version is far larger (~1.7e18), so the next fill applies as newer.
- **Why bounds:** `receiveTime * 1_000_000` overflows a signed long past ~9.22e12 ms (year 2262);
  the explicit ceiling turns that into a mapper rejection instead of a negative version.
