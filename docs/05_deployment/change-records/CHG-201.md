# CHG-201 — step-3 OK-check anchored: test chatter no longer fails a green suite

- **Status:** recorded — fixed and guarded (2026-09-17)
- **Filed:** 2026-09-17
- **Source:** the `make gate` re-run after CHG-200: step [3/19] failed although
  the suite reported `Ran 1473 tests ... OK (skipped=9)` with zero failures.

## What happened

Step 3's non-empty-OK assertion was `grep -qE 'Ran 0 tests|FAILED \('`. The
`FAILED \(` leg was unanchored, so it matched test chatter mid-line — a DDL
test exercising a failure path prints `DDL APPLY FAILED (exit 3)` — and failed
a genuinely green suite. Real unittest failures print their summary at line
start (`FAILED (failures=9, errors=1, skipped=8)`), which the old pattern also
matched; only the chatter was a false positive.

## What changed

- `code/01_platform/04_scripts/run-monday-gates.sh` — the leg is now
  `^FAILED \(` (line-anchored, with a comment citing this record).
  Fail-closed behavior for real failures, empty discovery, and missing-OK is
  unchanged.
- `code/01_platform/04_scripts/tests/test_gate_runner_wave21.py` — the
  source pin updated to the anchored string; the behavioural truth table
  gains the chatter-passes case and now evaluates with `re.M`, because grep
  is line-oriented and the old flagless model could not express anchoring.
