# CHG-159 — start-all.sh stops executing a credentials file, and stops calling a socket "ready"

- **Status:** recorded — all 17 wave-22 findings closed (16 fixed, 1 stale)
- **Filed:** 2026-09-15
- **Closed:** 2026-09-15 — helper suite 790 OK (skipped=9), full_audit green (see Verification)
- **Source:** P6 ops/scripts/tests/chaos audit, wave 22 ("Start-up"):
  P6-298, P6-299, P6-300, P6-301 (high) + P6-698…P6-706 (medium) +
  P6-858, P6-859, P6-860, P6-861 (low) in `start-all.sh` (the one-command start
  path: credentials → Fluss → build → DDL → pipeline).

## What happened

`start-all.sh` is the first script a new checkout runs, so its defects are the ones
everyone meets first. Three of the four HIGHs are one root cause each: a credentials
file was executed as shell, the fallback parser mangled ordinary hand-edited files,
and "Fluss is up" meant "something is listening on the port".

**The credentials file was code (`P6-298/300`).** `source "$SECRETS_FILE"` ran whatever
`~/.env.arrow` contained with the caller's privileges — a truncated, tampered, or
Windows-edited file executes metacharacters — while the compose fallback three lines
below went to the trouble of `export "$key=$value"`. Both paths now share
`parse_arrow_line`, which exports one assignment at a time through the single
argument form, so a value never reaches the shell parser. The same finding's second
half: nothing checked that the file was actually `chmod 600` or owned by the caller.
`warn_unless_private` now names the mode (`is mode 644 — expected 600`) and the
ownership mismatch; it warns rather than dies, because the values are inert now.

**The fallback parser mangled ordinary files (`P6-299/301`).** `awk '/^ARROW_[A-Z_]+=/'`
plus `${line%%=*}`/`${line#*=}` kept `\r` (Windows-edited files → an auth failure whose
only symptom was `ARROW_APP_SECRET` mismatch), kept surrounding quotes and whitespace,
rejected digits in the key, and dropped a final line with no trailing newline. The two
`secrets.env`/`.env` loops also logged two overlapping lines, so which file won was
undeclared. One parser now strips CR, `export `, whitespace on both sides of `=`,
quotes, and a trailing unquoted ` #comment`, allows digits, and reads a final line
without a newline; the precedence (secrets.env parsed second, so it wins) is stated
once in the source line.

**TCP-open is not Fluss-ready (`P6-698/701`).** `fluss_up` only proved a socket accepts
connections, and the coordinator accepts them while zookeeper and the tablet are still
initializing — so Java's `DdlBootstrap` raced a half-ready cluster, and the check was
skipped entirely in the case that actually races (port open, cluster not ready).
Readiness now also requires the `fluss-tablet` container to be running, is checked
before *and* after the compose `up`, and the poll waits on it. The host parse also took
`${VAR%:*}`/`${VAR##*:}`, which breaks on `host1:9123,host2:9123` and on IPv6; the
first endpoint is taken and brackets stripped.

**No trap behind a clean-stop promise (`P6-699/706`).** The header says "Press Ctrl+C to
stop everything cleanly" and there was no trap: SIGINT/SIGTERM left the java process
and its `tee` pipeline behind. There is now a `cleanup` trap that TERMs java, waits a
bounded 5 s grace, KILLs, and exits with the pipeline's status. The launch also moved
from `java … | tee` to process substitution, because with a pipeline `$!` is *tee's* pid
and the trap would have signalled the wrong process.

**Builds, logs, and dead config (`P6-700/702/703/704`, `858/859/860`).** The section
comment promised "if stale" and the code rebuilt every time; `needs_rebuild` now
compares the output against its sources. `GO_FLAGS`/`MVN_FLAGS` were unquoted (a
multi-word flag split wrongly) and are split once into arrays; neither build checked
that it produced anything, so a failed build surfaced as an obscure
`java -jar: file not found` — both artifacts are checked now. The log said "offline"
while R-228 made the default online. `COMPOSE_FILE` was documented as overridable and
never read (a custom stack file was silently ignored); it is named in the `up` and in
the readiness probe. `DDL_DIR` was dead — DdlBootstrap owns the DDL — and is removed.

**Template window (`P6-861`).** The credentials template was created world-readable and
then chmod'ed 600, and used an unquoted heredoc delimiter. It is created under
`umask 077` with `<<'EOF'`.

## Judgement calls

1. **`P6-705` is stale, not fixed — `ARROW_INSTRUMENT_MANIFEST` is the correct name.**
   The finding reads the export as a missing letter against `INSTRUMENT_MANIFEST_PATH`.
   Grep says otherwise: `docker-entrypoint.sh:37-51` reads `ARROW_INSTRUMENT_MANIFEST`,
   compares it to `INSTRUMENT_MANIFEST_PATH` (the divergence guard is the point), and
   exports both; `FullStackE2ETest:216` sets both. No spelling of "INSTRUMENTS" exists
   anywhere in the tree. "Fixing" it would break the guard. No edit; closing the
   finding as stale.

2. **Degraded readiness is announced, not silent.** If the compose plugin is absent —
   a stack started by `docker run` or k8s — no container exists for `ps` to find, and
   dying on that would break a working setup the old script accepted. TCP reachability
   stays the hard gate there, but only with an explicit
   `WARN: docker compose unavailable — accepting TCP reachability … (tablet probe skipped)`.
   Silent degradation is what the finding objects to; announced degradation is the
   honest version.

3. **Containers are left running (a decision the finding asks for).** `start-all.sh` is
   also the "restart just the pipeline" path; stopping the cluster on exit would
   silently undo step 2. `make down` stops them. Written into the trap comment.

4. **The trap delivers the signal; the JVM's shutdown hook stops the bridge.** The Go
   bridge is a child of java, not of this script, so killing java's grandchildren would
   be guesswork about a process tree. The trap TERMs java, waits for its hook, then
   KILLs; `BridgeShutdownHookTest`/`BridgeShutdownRegressionTest` cover the hook. The
   hermetic test's java stub mirrors that contract (a TERM handler that stops its own
   child) — an earlier stub that did not forward TERM leaked a `sleep` holding the tee
   pipe, which is a harness artifact, not a product finding.

5. **`mvn -q` stays, with a jar check added.** The finding names `-q` as hiding build
   errors; its own fix text asks for the existence check. The check gives the actionable
   failure (`produced no jar: … (re-run with MVN_FLAGS= to see the build log)`), so
   dropping `-q` would trade that for noise.

6. **A test seam for the poll.** `FLUSS_READY_TRIES`/`FLUSS_READY_SLEEP_SEC` default to
   30 × 2 s; the hermetic test drives the not-ready path in milliseconds instead of a
   minute. Same shape as the W20 `PROBE_READ_DEADLINE_MS` seam.

7. **Four of the fourteen tests do not discriminate against the pre-fix script**, and
   are named here rather than counted as proof: `test_template_is_private_from_creation`
   (HEAD also ends at mode 600 — the umask *window* is not observable after the fact,
   so the fix is verified by reading the source), `test_running_tablet_makes_the_open_port_ready`
   (the ready path), `test_stale_source_triggers_a_rebuild` (HEAD rebuilt unconditionally,
   so a rebuild assertion passes), and `test_flags_survive_as_one_argument_each` (HEAD's
   word-splitting produced the same argv for these flag values). The other ten fail
   pre-fix.
