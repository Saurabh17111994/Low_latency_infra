# CHG-152 — The suite runner stops hiding its own failures

- **Status:** recorded — all 21 wave-15 findings fixed
- **Filed:** 2026-09-14
- **Source:** P6 ops/scripts/tests/chaos audit, wave 15 (`run-full-suite.sh`):
  P6-015, P6-016 (critical); P6-177, P6-178, P6-179, P6-180, P6-181, P6-182, P6-183, P6-184, P6-185
  (high); P6-513, P6-514, P6-515, P6-516, P6-517, P6-518, P6-519, P6-520, P6-521 (medium);
  P6-774 (low)

## What happened

The unattended runner for stages 0–4 — the one script whose verdict is supposed to be trustworthy
when nobody is watching — could fail in ways that read as success, and could destroy tables on the
way. Two of those are critical: it always exited `0` even after writing `FAIL` into `SUMMARY.txt`
(`P6-016`), and its "drop tables that drifted" branch ran an irreversible DROP with stderr
discarded (`P6-015`), so a connect or auth failure looked exactly like "nothing to drop".

**The runner now fails loudly and cleans up after itself.** A non-PASS result exits non-zero
(`P6-016`). The EXIT trap no longer just writes a summary: it kills the broker, monitor and java
children it started, stops the ingestion container *if this run started it* (`P6-178`, `P6-183`,
opt-out `SOAK_KEEP_CONTAINER=true`), and removes the credential file (`P6-179`). A `set -e` abort
that never reached a verdict is reported as `FAIL (aborted before a verdict)`, not `RUNNING`
(`P6-514`).

**The destructive branch is guarded, not merely noisy (`P6-015`, `P6-518`).** It requires
`ALLOW_DESTRUCTIVE_DROP=true`, refuses to run against a non-local `FLUSS_BOOTSTRAP`, propagates a
dropper failure as a stage FAIL, and no longer suppresses the dropper's stderr.

**Evidence checks read evidence.** Journal counters are parsed field-wise out of the log4j2 JSON
(`event=subscription_ack` / `epoch=(\d+)` in the `message` field) instead of grepping for a
substring (`P6-180`), a missing journal reports zero instead of printing nothing (`P6-516`), and the
marathon gate counts **distinct epochs** — `max_epoch >= 100` did not prove 100 reconnect cycles
(`P6-180`). The soak verdict (`P6-185`) requires ≥11 snapshot rows, a non-empty monitor log, a
numerically *advancing* append counter (`P6-521`, which also widens that query's window from 1h to
8h) and an ERROR count within `SOAK_ERROR_BUDGET` (default 20).

**Startup and readiness are checked, not assumed.** `faketool_up` waits for the port to bind and
fails the stage if it never does (`P6-181`), including the post-interruption restart (`P6-184`); the
soak container is `up -d --force-recreate` (`P6-182`) and its id is discovered via
`compose ps -q ingestion` rather than assumed (`P6-513`); the preflight also refuses to start when a
container is already running (`P6-517`) or when `ss` is missing (`P6-515`); and the O2 credential is
read without the `awk -F=` truncation that ate base64 padding, then written to a `0600` curl config
file so it never appears in `argv` (`P6-177`, `P6-179`). One malformed shell construct that could
abort the suite mid-poll became an `if` (`P6-520`), `GATES_EVIDENCE` falls back to `none` (`P6-519`),
`wait_until` steps by 5s instead of 20s and warns on a clock jump (`P6-774`).

## Judgement calls

1. **The credential goes in a `curl -K` config file, not `-H @file`.** One finding suggested
   `-H @file`; curl has no such syntax (`-H @file` sends a literal `@file` header, and `-K` is the
   config-file flag). The file is created under `umask 077` and deleted by the EXIT trap.
2. **The destructive drop is refused, not merely announced.** The finding asked for a warning before
   the DROP; a warning in an unattended log is not a control, so the branch needs both an explicit
   opt-in and a local broker.
3. **`exit 1`, not `exit 2`, for a failed run.** The runner keeps the Monday gate's convention
   (0 = PASS, non-zero = FAIL); the probes' 2 = "unusable input" convention does not apply to a
   stage verdict.
4. **The marathon gate counts distinct epochs.** `max_epoch >= 100` passes on a single jump to 100,
   so it could not distinguish 100 cycles from one. `max_epoch` stays in the summary as a diagnostic.
5. **The soak thresholds are policy, and the budget is tunable.** ≥11 rows and a non-empty monitor
   log are structural; `SOAK_ERROR_BUDGET` (20) reflects three forced feed interruptions and is an
   environment knob because the right number depends on how the soak is run.
6. **The soak-end counter is read over 8h rather than tightening the soak's own clock.** The 1h
   default cannot see a counter written 7h earlier, which made the comparison vacuous.
7. **The test seam is test-only.** `RUN_FULL_SUITE_LIB=true` defines the helpers and returns before
   any stage; it is unset in production and the trap is cleared in that mode. It exists because the
   runner otherwise needs Fluss :9123, docker and an hour of gates, and a suite runner with no
   hermetic test would be the one thing this wave cannot check.
8. **The compose registry needed two rows, and one substring had to be shortened.** Adding
   `--force-recreate` orphaned the soak-`up` row, and the two new discovery sites differ in their
   `-f` list, so a `ps -q ingestion` substring is the only one that matches both. Found by running
   `test_compose_form_contract`, not by the audit.
9. **Two patched lines lost their tails on the way in** (a `grep -c ': ok '` clause and an
   `if …; then`), caught by `bash -n` and by a line-by-line diff against `HEAD`. Recorded because
   the same class of error — retyping a line instead of editing it — is what the script's own new
   tests are meant to catch in *it*.
10. **No live run of the suite.** It needs the Fluss stack, docker and the gate stage; the helpers
    are covered hermetically, and the stage sequencing, guards and exit contract are pinned
    statically.
11. **One new test does not discriminate, and is named as such.** Pre-fix there is no `cleanup` at
    all, so `test_soak_keep_container_leaves_it_running` ("no docker call was made") passes on the
    old script for the trivial reason.

  read from `ps -o stat=`.

  result — 722 tests / 0 failures / 2 skipped — remains the C6 reference. No live Fluss connection,
