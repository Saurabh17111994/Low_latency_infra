## Notes

- **The two knobs were fused:** the old constructor derived PEAK from `tickRatePerSec >= 30`, so
  the workload shape and the wire rate could not move independently — fixing the cap would have
  silently turned PEAK into BASELINE. The profile is now an explicit argument.
- **The shape was already inside the cap:** `SyntheticWorkload.nextIntervalMs` gives PEAK
  51–54 ms (≤19.6/s) and BASELINE 55–65 ms (≤18.2/s) since MOCK-UNIT-002; only the scheduler's
  batch rate violated DEC-045.
- **Measured guard, generous bound:** the wire test uses 25 % headroom over the cap so scheduler
  jitter cannot flake it while the retired 30/s (~330 lines) still fails it.
