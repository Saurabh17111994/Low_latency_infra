## What changed

1. **Planner (`EodPlanner.plan`)**: the protected bound is now the earliest
   unverified day's source-expiry bound, and nothing else. When every day on
   file is verified the plan has no bound (`null` / `Long.MAX_VALUE`) and
   `requiresExtension=false` -- the 3-complete-trading-day floor is retired.
   An unverified day extends (one ALTER) when its remaining margin falls below
   the runway (`EOD_SAFETY_FLOOR`).
2. **Defaults (`EodControllerTool`)**: `EOD_TTL` live-fallback 7d -> 3d;
   `EOD_SAFETY_FLOOR` 7d -> 1d (runway; Q36's <=24h replay window).
   `EodRetentionPolicy.MIN_COMPLETE_TRADING_DAYS` removed.
3. **Partition-aware extension (`EodControllerTool.alterTtl`)**: a partitioned
   table ages out by TWO clocks -- `table.log.ttl` and
   `table.auto-partition.num-retention` (day-granular partition GC). Extending
   only the TTL would leave the partition to drop at its original count, so the
   guard now raises both in the same ALTER, gated on the table's partition keys
   (retention = ceil(newTtl days)).
4. **DDL + contract text**: `02_raw_table_1.sql` 9d/9 -> 3d/3 (comments updated);
   `schema_manifest.json` regenerated with the documented `ddl_apply.py --force`;
   storage contract, dossier statement and runbook step updated.
5. **Apply tool**: `fluss-repair/SetRawRetention.java` -- one-off ALTER for
   operator retention moves (before/after readback), the counterpart of
   `EnableTiering.java` (the guard itself only raises).
