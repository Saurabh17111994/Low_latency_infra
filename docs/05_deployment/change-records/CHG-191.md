# CHG-191 — the measurement harness runs the candle path it gates on (wave 36)

- **Status:** recorded — fixes a pre-existing defect found during wave 36
- **Filed:** 2026-09-17
- **Source:** found while running the wave-36 acceptance run of
  `code/01_platform/04_scripts/holistic-measure.sh` (run 8, 2026-09-17
  04:39:46). This is the layer behind CHG-185/186/187/188/189/190: with those
  fixed the run reached the smoke inject gate for the first time in the
  harness's history and failed there.

## What happened

Run 8 passed every precondition and reached the inject gate for the first time
ever. The dedup half passed exactly; the late-drop half was structurally
unsatisfiable:

```text
smoke inject gate: want dups=200 late=20; got dups=200 late=0; tolerance dups=+-10 late=+-1
!! SMOKE INJECT GATE FAIL: late-drop counter 0 differs from injected 20 by 20 (tolerance 1)
```

The counter was not short by 20 — **the metric did not exist**. The scrape
(`tm-prom-dedup-late.tsv`, 32 557 bytes, sampled every 15s across the whole
smoke phase) contained exactly two operator metric names,
`flink_taskmanager_job_task_operator_compute_dedup_duplicates` and
`..._compute_dedup_first`, and `compute_candles_late_dropped` had **0
occurrences**. `grep -rla candles` over the whole run directory returned
nothing, and no earlier run in `logs/` had ever captured the metric either
(0 of every `tm-prom-dedup-late.tsv` on disk).

Why: `compute.candles.late.dropped` has exactly one registration site —
`MultiTimeframeAggregateFunction` L159 — and that operator is wired only inside
`if (config.multiTfEnabled())` (`SignalJob.java` L271), which reads
`MULTITF_ENABLED`, **default false** (`SignalJobConfig` L139). The harness never
set it (`git log -S MULTITF_ENABLED -- holistic-measure.sh` is empty), and
`pipeline-lib.sh` L1163 submits with `-e
MULTITF_ENABLED="${MULTITF_ENABLED:-false}"`. With both `MULTITF_ENABLED` and
`STRATEGY_HOST_ENABLED` off the job is a three-operator ingest stub —
`raw-validation → fingerprint-dedup → ingest-latency-monitor` — with no candle
window at all.

The counter used to belong to the 15s candle path, which was **unconditional**.
`0f3e5952` ("retire 15s candle path, forming stack, and position gate") deleted
`CandleLateDrop.java` (the old counter owner) and moved the counter into the
multi-TF operator — behind the flag. That commit touched **no file under
`04_scripts/`**, so the harness went on asserting a counter its own job graph no
longer created. The gate is not wrong about the pipeline; it is stale about the
topology. The wave-36 plan (L148) explicitly forbids deleting it, and never
mentions `MULTITF_ENABLED` — that is the plan's blind spot, not a harness error
to route around.

## The fix

The harness now opts the candle path **in**, because it is the path the harness
documents and gates on (header: `window_start → preview cadence`,
`window_end → settlement`; L120-124 widens `ARROW_MAX_EVENT_AGE_MS` precisely so
late ticks survive ingestion long enough for the candle window to drop them;
L136 sizes the inject margin as "15s candle window + one POLL_S sample").

1. `export MULTITF_ENABLED="${MULTITF_ENABLED:-true}"`, with the coupling
   recorded in the comment.
2. An explicit opt-out is **refused** up front (`fail`, before any evidence
   directory exists) rather than run and failed later with "late-drop counter 0
   differs from injected 20" — a counter that is absent by construction read as
   a counter that is 20 short.
3. `run_phase` purges and then ensures `candle_live`/`candle_closed` before
   ingestion starts, mirroring `stage-soak-e2e.sh` L131-140. Both are
   LOG-append tables, so a run that only "ensures" accumulates every previous
   run's rows, and the job preflights both (`TableContractValidator`, behind
   `MULTITF_ENABLED`) and refuses to submit when either is missing.

## Verification

* **The failure and its cause are measured, not inferred**: 0 occurrences of the
  metric name in the run's own 32 KB scrape, 2 dedup metric names present in the
  same scrape, 0 candle metrics anywhere in the run directory, 0 of every
  historical scrape.
* **The metric genuinely counts what the gate injects**: the operator drops and
  counts window-late ticks at L269 (`windowStart + windowMs + allowedLateness <
  watermark`) and monotonic-gate re-feeds at L280 — the two paths the injected
  old-timestamped ticks hit.
* **Four new tests** (`test_holistic_measure_wave36.py::TestCandlePathIsWired`)
  run the real script in the sandbox: the submitted job carries
  `MULTITF_ENABLED=true`; an explicit `MULTITF_ENABLED=false` exits non-zero by
  name and creates no evidence directory; the candle tables are purged and
  ensured in order before `INGESTION_STARTED`; and the metric's single
  registration site is still inside the `multiTfEnabled()` branch.
* **Mutation-checked**: default → false fails the first; deleting the refusal
  guard fails the second; deleting the purge/ensure block fails the third.
* Suite: `code/01_platform/04_scripts/tests/test_holistic_measure_wave36.py`
  49 passed; the full `04_scripts/tests` suite from the repo root is green
  (the two failures seen from a `04_scripts` cwd are pre-existing relative-path
  assumptions in `test_gate_preflight.py` / `test_change_control_check.py`, and
  pass from the repo root).

## Why this is a change record

The trigger list in `docs/08_implementation/01-foundation.md` (L323-336) includes
*Deployment topology*: the harness now sequences candle-table purge/ensure into

measurement run accepts as valid evidence.
