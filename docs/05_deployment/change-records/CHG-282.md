rollback_behavior: revert this commit and a malformed access block crashes with a traceback again. Nothing that is running changes: no stack, image or live service is touched, and no inventory is rewritten.

## Why

Phase 2 ran the per-node check against a hand-written inventory whose `access` was the string `"local"` — a
placeholder meaning "no SSH from here". The schema wants an object, and `load_inventory` defaults a *missing*
`access` to `{}`, so the file parsed and the check started. It then died in the runner:

```
  File ".../prod_node_check.py", line 92, in run
    if self.access.get("ssh_port"):
AttributeError: 'str' object has no attribute 'get'
```

A traceback from inside a gate tells its operator nothing about the file they wrote. The inventory is the
operator's artifact on VM day, so the failure has to name it.

## What this changes

`load_inventory` checks that `access` is an object and raises a `ValueError` naming the type and the value it
found. `main()` catches that `ValueError` — from the load or from resolving the manager host — prints
`error: <message>` on stderr and exits 2, matching the branch that reports a missing inventory file. Before
this record, a malformed inventory reached the top of the process and Python printed a traceback with exit
1, which is the code that means drift.

## Verification

Measured, not asserted:

- `test_10_prod_node_check.py` → 27 passed (26 before the addition).
- The CLI against a copy of the original malformed inventory → the named failure, exit 2, **zero** tracebacks
  (`grep -c Traceback` → 0).
- The corrected inventory → `reachability FAIL ssh rc=255`, which is the honest answer on a workstation that
  cannot SSH to itself as root.

## Note

This was my error before it was the tool's: the inventory was wrong. The tool's failure mode is what this
record fixes, because the next person to write that file will be an operator under time pressure on VM day.
