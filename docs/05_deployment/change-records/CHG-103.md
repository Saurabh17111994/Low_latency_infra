## Change

1. **VM-PYTHON-002 pin drift resolved.** The ddl-apply runtime stage apt-get-installed
   the distro python on `eclipse-temurin:17-jre` (Ubuntu 26.04) — drifted to 3.14.4, and
   Python was never actually in `versions.pin` (so nothing enforced the 3.11.9 pin).
   Fix: runtime stage builds on `python:3.11-slim` (3.11.16, Debian trixie — the official
   image *is* the pin series) + `openjdk-21-jre-headless` (trixie has no JRE 17; the
   precompiled Java 17 engine runs on 21 — `validate` + `self-test` PASS). Added
   `PYTHON_VERSION=3.11.9` to `versions.pin` and a `ddl-apply version` subcommand that
   asserts the running python series matches the pin (fails loudly on future drift).
   (Deadsnakes PPA tried first — `GPGKeyTemporarilyNotFoundError` in Docker builds; the
   python-base switch is strictly more robust.)

2. **VM-IMAGES-012 re-scan + SBOM closure.** Re-scanned all 13 runtime images with the
   cached trivy DB (2026-08-25). The base switch cut the ddl-apply image vulns
   81/12 -> 14/3 (trixie, all `fixed=None` = latest patch); webhook-receiver
   `python:3.11-slim` 50/3 -> 14/3. Captured the missing OpenObserve SBOM via trivy SPDX
   (`openobserve-20260825.spdx.json`). Library-layer (Java) scan stays `scan-unavailable`
   (Java DB mirror network-blocked — same as 2026-08-24).

3. **SEC-IMAGE-001 vulnerability policy pinned** (was TO_BE_VERIFIED): CRITICAL-with-fix
   **blocks** deployment; CRITICAL-no-fix and HIGH-with-fix require a dated, owner-signed
   waiver in the scan evidence; HIGH-no-fix is accepted risk, documented each scan.
   Dated waivers recorded for the fixable findings (golang, zookeeper, cadvisor, fluss,
   openobserve, minio) — none blocks promotion under the policy.

4. **ddl_apply_smoke.py stale count fixed.** The smoke pinned `TABLES=26` in scenarios
   1/2/3 but the live apply reports 27 (the 27th table landed since the pin was written).
   Updated to `TABLES=27`; live re-run against `fluss-coordinator:9123` — scenarios 1-4
   all PASS.
