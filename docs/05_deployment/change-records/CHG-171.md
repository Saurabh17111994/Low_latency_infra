## 1. A gate that did not run is not a gate that passed (P6-041)

| Was | Now |
|---|---|
| six `go -C "${BRIDGE_DIR}" test -run TestFoo -count 1 -v` calls; exit 0 was the whole verdict. `go test` exits 0 when the regex matches nothing (`no tests to run` / `no test files`), `-run` is an unanchored regex (so `TestFoo` also matches `TestFooBar`), and without an explicit package only the bridge's own package is searched. A renamed, moved or deleted test was therefore reported as PASS, and a test living in a subpackage was silently never run | `run_gate` requires the gate's own `=== RUN <name>` and `--- PASS: <name>` lines in the captured output, for the anchored regex `^<name>$` over `./...`. Exit 0 with neither is a FAIL that says which gate ran nothing and that no invariant was proven; a gate that emitted `--- SKIP:` is a named SKIP (3) quoting Go's reason. Measured: with `go test` exiting 0 and printing `[no tests to run]`, the pre-wave script printed `PASS` and exited 0, the fixed one exits 1 |

## 2. The PASS line promised a kill the drill never performs (P6-042)

| Was | Now |
|---|---|
| `SLOT-KILL-CHAOS-01: PASS — 1-of-3 slot kill: terminal isolated, peers healthy, reconnect clean`, on a run that sends no signal, kills no process and does not talk to a broker. An operator reading a green chaos suite would take blast-radius isolation as proven | the PASS line reads `offline resilience gate only: all N Go gates ran to their own --- PASS (no live slot kill, no signal, no partition was performed); go vet <result>`, and the header states the same scope. The drill was not given a live fault: the wave's finding offered "rename or add a real kill", and adding a real kill would duplicate drills 02–04 while changing what this drill needs (a running stack) — the honest label is the smaller correct change |

## 3. Configuration and environment failures (P6-327, P6-328)

| Was | Now |
|---|---|
| `BRIDGE_DIR` was never checked. If the layout moved or the script was copied elsewhere, `go -C <missing>` failed with a generic `no such file or directory` and each of the six gates reported a misleading test FAIL | the bridge directory is checked before anything else: absent is a config error (2) naming the path, distinct from a test that actually failed (1). The absence check runs before `mktemp`, so a broken host cannot hide it |
| exit 3 for SKIP is non-standard and looks like a failure to a harness that treats any non-zero as red | the exit contract is written down in the header (0 PASS, 3 SKIP, 2 config, 1 FAIL) with the note that chaos-run.sh maps it. 3 was kept rather than changed: it is the contract the whole suite and its runner already document and map (CHG-170), and the finding's alternative (0 + a SKIP marker) is what the runner now reads for chaos-02's leg B — changing this sibling too would mean two conventions in one suite |

## 4. Bounded gates (P6-329)

| Was | Now |
|---|---|
| no `-timeout` anywhere: a hung reconnect test ran under Go's implicit default (10m) per invocation, so a wedged gate could stall the whole chaos suite with no diagnostic tying it to the drill | every gate passes `-timeout "${CHAOS_GO_TEST_TIMEOUT}"`, default `5m` (roughly 40× the measured 6s for all six gates, so it cannot flake on a slow machine). A hung gate now fails with Go's own timeout output, which is echoed. An empty value falls back to the default: `${VAR:-5m}` reads empty as unset, and an empty timeout cannot make a gate vacuous |

## 5. vet is a static-analysis signal, not a resilience signal (P6-330)

| Was | Now |
|---|---|
| `go vet ./...` was a hard FAIL gate. Since it covers every package in the module, a vet warning in a package this drill never touches flipped the slot-kill drill to FAIL, and the operator could not tell from the exit status or the message whether sharding / isolation / reconnect had held | vet still runs, after the gates, but is advisory: a failure prints a `WARN` with the full diagnostics and the drill continues, and the final line names `go vet clean` or `go vet DIRTY (advisory, not a resilience failure)` so the result is visible rather than silently dropped. The hard static gate stays where it belongs — the `go vet` step of the T0–T8 hardening target |
