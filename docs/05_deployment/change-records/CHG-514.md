# CHG-514 — raw writer populates vwap_paise and open_interest

- **Status:** implemented — failing-first red (`expected: <234100> but was: <0>`), focused green; `make test` (common + ingestion) running
- **Filed:** 2026-10-02
- **Source:** found during the CHG-513 fake-broker verification (operator test
  request, 2026-10-02). The sealed candle rows stored feature ids 9 (vwap) and
  10 (open interest) as 0 while every other stats/depth value was present. The
  proto→packet builder chain simply never set those two fields, so the raw
  columns `vwap_paise` / `open_interest` have been 0 for every feed, every row,
  since the field was introduced — including the strategy market view
  (CHG-501/502) and the CHG-512 feature storage.

## What changed

- `IngestionService`'s `TickPacket.Builder` chain gained
  `.averagePricePaise(ev.getVwapPaise())` (after the OHLC block) and
  `.openInterest(ev.getOpenInterest())` (after `totalSellQty`). The packet
  fields, the `TypedFlussRowConverter` mapping (`row.vwap_paise = ...`,
  `row.open_interest = ...`) and both raw DDL columns already existed; only the
  proto→packet copy was missing.

## Why

`vwap_paise` and `open_interest` are consumed by the strategy market view and
now by the stored feature map. A missing copy made both read as "not provided"
forever, silently. The new test pins the copy from a non-zero proto value so a
future refactor cannot re-open it.

## Notes

- No backfill: raw rows already written keep their 0; the fix applies to new
  rows. Feature ids 11/12 (`oi_day_high`/`oi_day_low`) remain absent on the HFT
  feed by protocol (the Go bridge maps them for the standard/token feed only) —
  they return on the datastream feed, not a defect.
- Verified live after the fix: the CHG-513 fake-broker smoke's sealed rows carry
  non-zero ids 9/10 (evidence with the CHG-513 smoke).
