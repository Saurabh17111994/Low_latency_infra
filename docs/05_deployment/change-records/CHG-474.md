## What changed

- **`CandleFeaturesTableProbe.java`**: creates/describes/tails/upsert-checks the
  merged table with DDL 35's exact shape -- candle_closed's 15 columns +
  `features MAP<INT,DOUBLE>` + `sealed BOOLEAN`; PK
  `(instrument_token, tf, window_start)`; 16 buckets routed by
  `instrument_token`; 3 d log TTL; `table.kv.format-version=2`;
  `table.datalake.enabled=false` (+ format iceberg, so a later enable through
  the DEC-060 sync works). Modes: create, describe, tail (rows + sealed/forming
  counts), upsert-check.
- **`candle-features-table.sh`**: the host-side runner (compiles the probe
  against the ingestion classpath, runs it inside the trading network; mirrors
  `feature-values-table.sh`, including the 0755 build-dir fix).
- **Runner tests**: the same contract pins as the feature_values runner.

## Notes / follow-ups

- Why the table had to exist: CHG-471 registered `candle_features` in the
  ingestion bootstrap's registry, and `verifyTables` existence-checks every
  registry entry (by design, `allowRuntimeDdl=false`) -- so the service (and
  `FullStackE2ETest` in gate step 9) refuses to boot until the table exists.
  The probe creates it through the operator-approved scratch route instead of
  applying the DDL.
- W-B5 (the Wave B live smoke) can now run: `MERGED_CANDLE_FEATURES_ENABLED=true`
  against this table.
- The DDL hazard stands: DDL 35 is still an unapplied proposal; this is a dev
  scratch provision, not a schema-lifecycle claim.
