## Notes

- **Why per-session writers:** the pool gave every client the same unbounded queue and no write
  deadline, so one stalled peer could hold a pool thread forever while every tick batch queued
  behind it. One writer + one bounded outbox makes the blast radius one session.
- **Drops are marked:** an overflow drops the batch and increments the session's counter (logged
  at DEBUG with the running total) — the same "counted, never silent" rule as the ingestion drop
  paths.
- **Deterministic stall test:** a real wedge depends on kernel send/receive buffers and would flake;
  the test pauses one session's writer (a documented test-only seam) and asserts the real 1 s
  sweep evicts it after 5 s while the healthy peer keeps receiving.
