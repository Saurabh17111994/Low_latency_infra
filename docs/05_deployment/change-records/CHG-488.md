## What changed

| piece | change |
|---|---|
| `FlussClientAdapter.append` (generic path) | `bs(raw.payloadHash())` -> `bs("")` — empty cell |
| `TypedFlussRowConverter.append` (typed path) | `row.payload_hash = raw.payloadHash()` -> `""` |
| DDL `02_raw_table_1.sql` | v6 header note + column comment; **column set and order unchanged**, Schema version stays 4; manifest regenerated |
| nothing else | the column stays in `RawTableSchema`, compute `RawTableColumns`, bootstrap/repair descriptors and the lake schema — zero index churn |

## Why this is lossless

- The digest is a pure function of `raw_payload` (`sha256.Sum256(raw)` in
  `go-bridge/batch.go`), which is retained.
- The integrity check that matters (`PayloadHashValidator`) runs in memory at
  admission on the proto bytes and is unchanged.
- Read-only audit: no Java/Go/Python consumer reads the stored value;
  `RawTableColumns.PAYLOAD_HASH` is only a column-index constant.
- The stored text was a lossy UTF-8 rendition of 32 random bytes
  (`toStringUtf8()`), i.e. neither the digest nor hex.

## Effect (measured)

- 200 s smoke `logs/chg488-smoke-20261001-132511`: raw_table_1
  **+134.18 MB/min** vs the CHG-487 smoke's `+146.90 MB/min` and the 900 s
  baseline's `+148.42 MB/min` — **−12.72 MB/min (−8.7 %)**, i.e. ~**−43
  bytes/row** (503 -> 460 B/row at 4,866 rows/s). The saving is bigger than the
  20-35 B/row estimate because the UTF-8-mangled digest text (replacement
  characters) survived compression better than expected.
- Latency stays in family and shows no regression: S4 (Java -> Fluss ack)
  p50 16 / p99 33 ms; S5 end-to-end p50 19 / p99 43 ms (the 900 s run: S4
  p50 31 / p99 59; smoke conditions differ, the point is no regression).
- Per-session budget at the test rate: ~50 GB per 6h15m session (was ~56),
  local steady state ~3 days ≈ **~150 GB** (was ~170).
