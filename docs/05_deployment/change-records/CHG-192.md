# CHG-192 — the late-drop gate compares a superset as a superset (wave 36)

- **Status:** recorded — fixes a pre-existing defect found during wave 36
- **Filed:** 2026-09-17
- **Source:** found in run 9 (2026-09-17 10:22) of
  `code/01_platform/04_scripts/holistic-measure.sh`, the first run in the
  harness's history to reach the inject gate with the candle path wired
  (CHG-191).

## What happened

Run 9 wired the candle path and the counter appeared — for the first time ever a
run captured `compute_candles_late_dropped` (32 series, `operator_name="multi_tf_aggregator"`).
The gate then rejected the run:

```text
smoke inject gate: want dups=200 late=20; got dups=200 late=134; tolerance dups=+-10 late=+-1
!! SMOKE INJECT GATE FAIL: late-drop counter 134 differs from injected 20 by 114 (tolerance 1)
```

The injection was **counted perfectly**. The per-subtask series show it exactly:

| subtask | 10:25:55 | 10:26:10 | 10:26:25 | 10:26:40 |
|---------|----------|----------|----------|----------|
| 1       | 112      | 175      | 210      | 226      |
| 2       | 0        | 0        | 20       | 20       |

The injection fires at ~10:26:20; all 20 injected frames are unique tokens that
hash to one subtask, and subtask 2 went 0 → 20 in the first sample after it. The
gate's 134 is the phase-wide delta summed over subtasks, i.e. **20 injected + 114
natural**, and subtask 1 had already accumulated 112 of those *before* the
injection fired.

`compute.candles.late.dropped` counts **every** late/out-of-order drop the
multi-TF aggregator makes, not just the injected frames: the operator's monotonic
gate drops any tick whose event time is not greater than the last seen for that
token, loudly and by design (REQ-FC-006, `MultiTimeframeAggregateFunction` L280).
The assertion was therefore comparing a superset against a subset. It could never
pass on a live feed — the same false assumption sat in the analyzer's G7b
(`late_delta != late_in_window`), which would have failed the main phase for the
same reason.

## The fix

The inequality is the only sound comparison, in both places:

* `holistic-measure.sh` (P6-487): the late half fails only when the counter is
  **below** the injected count — the run-8 defect it exists to catch (candle path
  absent, counter never moves). A surplus is reported as
  `natural-late(not injected)=N`, not failed: each injected frame is a unique
  token counted at most once, so over-count cannot be attributed to the
  injection. The dedup half stays two-sided, because dedup drops *are*
  exclusively the injection (run 9: exactly 200 on one subtask, 0 elsewhere).
* `holistic-analyze.py` (P6-487): the two G7b verdicts are extracted into
  `g7b_verdicts()` (the `g7c_compare` precedent) and the counter check becomes
  `late_delta < late_in_window`. The zero-loss authority stays G7c, which
  recounts ticks from the raw table instead of trusting a counter.

## Verification

* The failure and its cause are measured from the run's own scrape: per-subtask,
  per-sample values (table above) put the injected 20 on subtask 2 exactly and
  112 natural re-feeds on subtask 1 *before* the injection.
* Five new tests. `test_holistic_measure_wave36.py::TestLateGateIsOneSided`
  drives the real gate with run 9's exact numbers (134 vs 20 must pass and report
  `=114`), the run-8 shortfall (0 vs 20 must fail on stderr), an exact cover, and
  a dedup over-count (must still fail).
  `test_holistic_g7_parity.py::G7bLateSupersetTests` pins the superset semantics
  and the wiring of the extracted helper.
* **Mutation-checked**: the harness gate back to two-sided fails the surplus
  test; the analyzer helper back to `!=` fails the surplus test; unwiring the
  helper from `main()` fails the wiring test.
* Suites: `test_holistic_g7_parity.py` + `test_holistic_measure_wave36.py`
  88 passed.
