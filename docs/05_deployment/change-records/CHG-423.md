## Notes

- **The fast path was already correct:** `LIVE_TICK_TAG` rows are built with `Timeframe.FIFTEEN_S`, so the
  guard is a no-op there — the fix only removes the fallback's six-fold recomputation. That is why the
  existing fast-path tests (one tick row → one update) stayed green unchanged.
- **"FIFTEEN_S wins" is deterministic now:** before the fix the stored value depended on the order the
  six rows arrived in; the new test pins the canonical row as the one that updates.
- **The counter is the observable contract:** `compute.features.updates.tick` is a KPI (S4 latency
  report reads it); counting only real updates keeps a fallback-mode run comparable with a fast-mode
  run instead of reading 6× high.

**Annotated 2026-10-01 (CHG-484):** the fast path now emits all six TFs per
tick; the L3-4 rule this record lands (only FIFTEEN_S updates the
timeframe-independent tick features) is unchanged.
