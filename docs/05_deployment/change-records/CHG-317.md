# CHG-317 -- bridge T2 age-flush ticker wiring (partial batches no longer wait for the next tick)

- **Status:** recorded -- landed 2026-09-26 (Go bridge suite + 2 Hz smoke green)
- **Filed:** 2026-09-26
- **Source:** the 2 Hz stage profiler measured S1 (`fake broker -> Java accept`)
  p50 20 ms against p90 481 ms — a ~10–20 % fraction of rows riding **exactly one
  tick period** (500 ms). Root cause: the bridge's T2 batcher flushed on
  `MaxEvents`/`MaxBytes` only — `Batcher.Tick`/`maybeAgeFlush` (`MaxAge`, default
  1 ms, env `BRIDGE_BATCH_MAX_AGE_MS`) existed but had **no production caller**
  (only unit tests called `.Tick(`), so the remainder of each burst waited for
  the next tick to arrive: 500 ms at a 2 Hz feed, 50 ms at 20 Hz. The same
  defect, period-scaled — invisible at 20 Hz, material at 2 Hz.

## What changed

| piece | before | after |
|---|---|---|
| age flush | `Batcher.Tick` never called in production — a partial batch waited for the next `Add` to cross count/bytes | `ProtoEmitter.startAgeFlush` runs a ticker at `MaxAge` calling `Batcher.Tick`; a partial batch flushes within ~MaxAge |
| shutdown ordering | n/a | `StopAgeFlush()` is synchronous (waits for the goroutine) and `main.go` calls it **before** the final drain, so no batch can be written after the `bridge_shutdown` marker (P1-158 discipline) |
| lifecycle | n/a | `Close()` stops the ticker then drains; `newProtoEmitterWithLimits()` is the single wiring point (env limits in production, tiny `MaxAge` in tests) |
| error handling | n/a | a ticker flush failure is retained by `flushLocked` and retried on the next tick, with at most one stderr line per second |

The one-period shoulder is gone; the residual ~945 ms sink/tracker tail is the
checkpoint pause (repair already scoped as its own lever). Evidence
`logs/stage-profile-20260926-031649/` (before) and
`logs/stage-profile-20260926-033605/` (after).

## Why 20 Hz never showed it

At 20 Hz each ingestion connection receives the universe slice as one burst per
50 ms; a partial batch waited for the next tick — 50 ms, visible only as S1 p90
49 ms. Lowering the synthetic feed to 2 Hz (one line per stock per 500 ms) scaled
the same wait 10× and made it the dominant tail.
