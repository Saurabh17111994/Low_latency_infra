## What was wrong

The loadgen image carries a content stamp = sha256 of its build inputs, written to the image label and `/app/build-stamp` from the same `LOADGEN_BUILD_STAMP` env var. Two different programs computed that value:

| | input set | value on 2026-09-29 |
|---|---|---|
| `image_staleness_check.py` (used by `make images`; gate steps 8/18) | compose-declared COPY set: `code/pom.xml`, `code/common`, `code/02_services/01_ingestion`, gateway pom, + `Dockerfile.loadgen` + context `.dockerignore`; git-ignore-based exclusion of host build outputs | `b2e950fa…` |
| `pipeline_loadgen_input_stamp()` (used by the G27b preflights) | hand-kept list: Dockerfile + two poms + go-bridge (minus `arrow-bridge`/`*.test` by name) + `src` + `common/**/*.java` — **missed `code/pom.xml`** and `.dockerignore` | `853c415b…` |

They disagreed by construction, so whichever builder ran last decided which check passed: `make images` bakes the checker's value (gate green, G27b refuses); the harness `pipeline_preflight` build bakes its own (G27b green, the gate's step-8 check flags the image stale and rebuilds). Measured on 2026-09-29: after the gate's `make images` (CHG-435 changed `common`, so loadgen was rebuilt), the stage-profiler smoke refused to start — the failure mode this fix removes.

## The fix

`pipeline_loadgen_input_stamp()` now calls `image_staleness_check.py --git-root "$ROOT" --service loadgen --print-stamps-env` and extracts `LOADGEN_BUILD_STAMP` — one definition for the build arg, the label, the G27b preflight, and the soak/loadtest gates. The P6-143 fail-closed property is preserved and extended: the four listed inputs must exist before delegating (`code/pom.xml` joined the list because the Dockerfile has always COPYed it), and the returned value must be a 64-hex sha256, else the function fails with the reason.

No image rebuild was required: `pipeline-lib.sh` is not a loadgen input, and the checker's stamp over the current tree already equals the label baked by the last `make images` (`b2e950fa…`) — verified live before the change was committed.

## Notes

- **Why the checker is the canonical side:** it hashes the compose-declared COPY set and excludes host build outputs via git-ignore (the repo's own declaration of generated files — the 2026-09-12 fix for spurious `go build` stamp moves), while the hand-kept list was a second implementation that drifted (missing reactor pom and context `.dockerignore`).
- **Consumers covered by delegation:** the stage profiler preflight, `stage-soak-e2e.sh`'s image-freshness gate, `holistic-measure.sh` (via `pipeline_preflight`), and `pipeline_verify_loadgen_image` (G27b) — all read the same function.
- **Guard:** `test_stamp_is_the_checkers_stamp` compares the bash function against the checker on the same fixture tree, so a re-implemented stamp fails in step 3 (seconds) instead of at the next measurement preflight.
