## Correction note (2026-09-15): P6-304's stated symptom does not reproduce

The audit records P6-304 as `check-ingestion-clean` "exits 0 / false green". It does
not. The target ran under `set -e`, and the failing step's output was sent to
`2>/dev/null`, so a missing or exited container aborted the recipe — rc=1 — with
**no output at all**: the operator saw `make: *** [Makefile:<line>: check-ingestion-clean] Error 1`
and nothing else. Measured live before the fix, and again with the docker stub in
`test_makefile_wave25.py` (`ps-empty` mode). The real defect is *fails with no
reason*, not *passes when it should fail*; the OK line was never reached pre-fix
either. The fix and its test address the defect that exists: the target now names
which of the three situations it hit (`docker compose ps` failed / no running
`ingestion` container / `docker exec` failed on `<cid>`).

## Judgement calls

1. **`check-loadtest-env` captures instead of streaming.** Streaming would interleave with
   a `head -20` bound; capturing is what makes "full output on failure" possible. The file
   is a `mktemp` that is removed on both paths.
2. **`stream_type` validated in `seed_alerts.py` (P6-779), not defaulted.** All three
   fields are printed or POSTed, so all three belong in the file validator; a default would
   hide the typo the finding is about.
3. **Both seeders now require a reachable O2 for `--dry-run`.** Unavoidable if the plan is
   to be truthful — the list is a read-only GET, and an unreachable org already fails a real
   run. Neither target is on any gate or workflow path (`seed-dashboards` is wired only to
   `make seed-dashboards`; `seed_alerts.py` has no make target), so nothing that runs
   unattended changed.
4. **`seed_dashboards.py`'s unguarded `json.loads(body)` on the list response was left
   alone.** It is P6-305-class but belongs to a different script and is not one of the 15
   findings; scope stayed with the map.
5. **`_warn_insecure_url` warns rather than refuses.** http://localhost is the documented
   default and the normal local stack; the finding asks for visibility, not refusal.
6. **New wave test files are `unittest.TestCase`.** pytest-style files under
   `code/01_platform/04_scripts/tests/` are not collected by `unittest discover`, which is
   what the wave suite runs — a pytest-only file would be invisible to the gate.
7. **`test_makefile_wave25.py` sandboxes real `make`** (copied Makefile, stubbed `docker`,
   `PATH` limited to a symlink toolbox, absolute `make`) because three `rg` installs exist
   on this host and `/bin/rg` would defeat a PATH-ordered stub. It stubs `shellcheck` with
   an exit-0 binary so the suite does not depend on a 1.2s-per-file external tool.
