## Why

- The measured surface the operator asked for did not exist: S8 mixes timeframes
  and is quantized by the 5 s KV poll; `feature_values` readability is never
  observed; per-operator/table state growth has no series (only per-checkpoint
  `state_size` and ad-hoc `du`).
- "Readable" must mean **a fresh reader sees the row** (operator decision) — the
  probe is that reader, one definition across all 6 timeframes and the features.

## What changed

- **`FlussReadabilityProbe.java`** (new, long-lived): per sweep (~1 s) KV point
  samples `candle_live` for **every TF** of a token sample (current + previous
  window fallback) → `liveread.tsv` staleness = read − `last_event_time`. Log
  tails `candle_closed` and `feature_values` (subscribed buckets from the
  current log end; fallback to from-beginning with a 5 min age filter if
  `listOffsets(latest)` fails) → `closeread.tsv` / `featureread.tsv` with
  latency = first read − `window_end` (feature rows derive `window_end` from
  `window_start + tf`; the row's map provides the feature ids). Columns resolved
  by name (P6-371); `UPDATE_BEFORE`/`DELETE` skipped; first sighting per
  `(token, tf, window)`; input validation exits 2 before any RPC.
- **`FlussTableStatsProbe.java`** (new, one-shot): `Admin.getTableStats` row
  count per table; partial census is exit 3 + stderr, never silent.
- **`stage-capture.sh`**: compiles the two probes with the existing compile
  block; starts the readability probe with the capture (bounded stop after the
  loop + in the EXIT/INT/TERM trap); samples state growth every 3rd tick
  (`flink.changelog.bytes`, `flink.rocksdb.bytes`, `fluss.tablet.bytes`,
  `fluss.table.rows` → `state-growth.tsv`); declares the four new outputs
  (readability TSVs WARN-only on emptiness mid-run, `state-growth.tsv`
  required); new knobs `READ_PROBE_*`, `STATE_*`, `*_CONTAINER_FILTER`.
- **`stage_profiler.py`**: S10 (live readability), S11 (closed + feature
  close→read), S12 (state growth) rows; per-TF / per-feature / state-growth
  detail tables; per-window 75 ms SLO scoring (live samples scored in their
  timeframe window; each stored row = one window for close legs). Presence
  rules S10.live_read / S11.closed_read / S11.feature_read / S12.state_growth
  make the smoke fail-closed on an empty measurement leg.
- **Per-timeframe state meter** (same change, operator follow-up): the probe's
  tails subscribe **all buckets** and count rows + changelog bytes per
  timeframe (`state-tf.tsv`, snapshot every 5 s) while latency logging stays
  bucket-sampled; `FlussTableStatsProbe` gains a `tf-census` mode (KV snapshot
  rows per timeframe) run for `candle_live` every 60 s →
  `state-tf-live.tsv`; the report adds a **Per-timeframe state growth** table,
  the S12 per-TF series count, and a `S12.state_tf` presence rule. Axis
  framing: low latency + high throughput + less state growth are the three
  judged axes, and the facility is their three measurement faces.
- **Tests:** profiler parsers/stats/growth pinned (including the
  negative-staleness drop, subtask-summing normalization, and the per-TF
  state parser/rate); the probe compile pin list now includes both new
  probes; input-validation contract tests.
