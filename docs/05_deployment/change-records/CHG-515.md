  without it; `make test` rc=0; `make static-check` 0 failures
- **Filed:** 2026-10-02

## What changed

- `EodControllerTool.Options.parse(String[])` now delegates to a new
  `parse(String[], Function<String, String> env)`; the CLI entry passes
  `System.getenv()::get`, so runtime behavior is unchanged.
- `parseEnvTtl` and the new `envOr` helper read through that lookup.
- `EodControllerToolTest.parseDefaultsStateTableAndZone` calls the overload
  with `key -> null`; the new `parseHonorsTheTablesEnvironment` proves the
  `EOD_TABLES` path still parses (trimmed, empty entries dropped).

## Why

The DEC-060 preflight requires `EOD_TABLES` (raw_table_1 is datalake-enabled),
and the gate inherits the process environment for every step. A unit test that
reads the ambient environment turns the archive list into a gate failure even
though nothing is wrong with the code. The fix keeps the production contract
(the tool reads the environment) and makes the test hermetic.

## Verification

- Failing-first (gate evidence): `EodControllerToolTest.parseDefaultsStateTableAndZone`
  failed with `["raw_table_1"]` against the ten defaults when the env was
  exported (java-suite.log of the 2026-10-02 run).
- Focused: `mvn -o test -pl common -Dtest=EodControllerToolTest` → 9/9 green,
  run twice (with `EOD_TABLES=raw_table_1` and without).
- Gate step 3: `test_09_stack.py::test_the_scheduler_and_the_controller_agree_on_the_trading_day`
  re-pinned to `envOr(env, "EOD_ZONE", "Asia/Kolkata")` — same default, new form
  (the gate run `monday-gates-20261002-134455` caught the old literal pin).
- `make test` (common + ingestion) rc=0; `make static-check` 0 failures.

## Residuals

- The test still cannot *set* environment variables (Java 17 has no portable
  way); it now injects the lookup instead, which is the supported seam.
- `EodControllerTool.Options.parse(String[])` keeps reading the real
  environment — behavior for operators is unchanged.
