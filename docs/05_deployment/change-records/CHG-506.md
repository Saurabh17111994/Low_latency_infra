## What changed

- **`StrategyHostFunction.decodeMarketSnapshot`** now returns `boolean` and
  starts with an arity guard: a row shorter than
  `CandleLiveColumns.FIELD_COUNT` (the legacy 16-column live row) is not
  decoded — nothing to decode, the snapshot keeps its previous values and the
  next new-format canonical row refreshes it. The row itself is still a valid
  candle tick and fans out to every strategy exactly as before.
- **`StrategyHostFunction.processElement1`** counts a skipped decode as
  `compute.market.row.legacy` (heap mirror for tests), on both the canonical
  and the `TF="MKT"` branch, so the upgrade artifact is never silent.
- No producer, sink, table, operator UID, or managed-state change.

## Why this happened (and why it is not caught by unit tests)

Unaligned checkpoints are enabled by default (CHG-318). They persist in-flight
channel records, so a checkpoint written by a job that predates the market
section replays **16-column live rows** into the new host. The unit harness
feeds rows directly and bypasses the serializer, so only a real restore
reproduces it. The `LiveSideOutputSerializationTest` pin now proves the wire
preserves arity, which is what makes the short row unambiguous (old data, not
truncation).
