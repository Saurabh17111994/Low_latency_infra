# CHG-229 — retire the pre-v3 instruments loader instead of repairing it

- **Status:** recorded — fixed (2026-09-19)
- **Filed:** 2026-09-19
- **Source:** the wave-40 audit findings P6-010, P6-110–P6-115, P6-417–P6-424, P6-746, P6-747
  against `code/01_platform/04_scripts/import_instruments.sh`.

## What happened

All 17 findings were verified against the script on 2026-09-19 (every line reference accurate),
but checking the *table* showed that repairing it would have been the wrong call:

- The script emits one positional 12-value statement per manifest row, against a 14-column table
  in a different order, with `manifest_version` and `schema_version` NOT NULL and unsupplied — it
  cannot succeed against the live table. Its documented prerequisite (`11_instruments.sql`) no
  longer exists; the file is `20_instruments.sql`.
- The table has one documented loader — `InstrumentManifestWriter`, reached through the ingestion
  service with `INSTRUMENT_MANIFEST_PATH` (`docs/08_implementation/03-ingestion.md`, ING-INT-004
  live proof 2026-08-15) — and `20_instruments.sql` pins the load contract to it: lot_size > 0;
  tick_size_paise NULL-or->0; option_type CE|PE iff instrument_type=OPT; expiry NULL iff EQUITY; a
  single `is_active=TRUE` row per instrument_token (deactivate-prior load sequencing); monotonic
  `manifest_version`; duplicate-composite-key rejection; KV-shape preflight. Bash cannot enforce
  the sequencing rules, so a repaired script would be a second loader with weaker guarantees than
  the documented one.
- Nothing calls the script (its statement is the only write into `instruments` anywhere), but
  `docs/commands/COMMANDS.md` and `code/01_platform/05_instruments/README.md` document it as the
  operator import command — a documented trap, not merely dead code.

## The change

- `import_instruments.sh` is retired in place: it prints a refusal naming
  `InstrumentManifestWriter` and `INSTRUMENT_MANIFEST_PATH`, then exits 2 (the repo's "you cannot
  use this" code). It contains no SQL and no client invocation — fail-closed, it never writes.
- The two references now present it as retired and point at the loader.
- The 17 findings close as **superseded**, not repaired.

## Verification

- The script refuses with exit 2, empty stdout and `Nothing was imported` — with or without
  arguments.
- The file contains no `INSERT` and no `psql` (pinned by the wave test); its header records the
  retirement, the live file (`20_instruments.sql`) and where the contract lives.
- Both doc references name the retirement or the loader.
- `test_import_corpus_wave40.py`: 14 legs, offline, no cluster.
