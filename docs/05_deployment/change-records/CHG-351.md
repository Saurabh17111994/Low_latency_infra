## Method (short)

| Item | Value |
|---|---|
| KPI | `compute.latency.tick_to_strategy` (broker event time → strategy-host live read) |
| Universe / rate | 2,433 instruments × 2 Hz = 4,866 ticks/s (real-life list; 3 connections) |
| Runs | layer OFF ×2 (`e9b46be7`, `a23a1aa5`), layer ON ×2 (`c5dfdb8d`) |
| Window | 240 s feed; steady window = probes at t+80…t+220 s (8 probes/run) |
| Aggregate | median across 8 subtasks of each probe's per-subtask quantile, then median across probes |

## Result

| Run | median | p95 | p99 | windows with p95 > 200 ms |
|---|---|---|---|---|
| layer OFF (1) | 58 | 144 | 174 | 3/8 |
| layer OFF (2) | 64 | 92 | 102 | 0/8 |
| layer ON (1) | 65 | 264 | 300 | 5/8 |
| layer ON (2) | 63 | 298 | 318 | 7/8 |

Reference baseline (CHG-316, profiler job): p50 49 / p95 80 / p99 93 ms. The dev job sits at
median ~60–65 ms on both sides (environment difference, not the layer); calm tails are close.

## Verdict

- No material median cost; calm-window tails unchanged.
- Reproducible tail-burst cost from enabling the layer (12/16 vs 3/16 probe windows).
- Not a production blocker by itself, but the layer must not add tail bursts at the 50k t/s
  SLO envelope: re-measure with real ticks (P4-4, 2026-09-28) and, if bursts persist, isolate
  sink vs allocation and tune the sink — scoped follow-up.
