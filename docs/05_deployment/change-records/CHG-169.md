| Finding | Was | Now |

## 3. Per-record reset and the cap-side alert (P6-195, P6-540, P6-543, P6-787)

| Finding | Was | Now |
|---|---|---|
| P6-195 | `assigned`/`acked` were only assigned when a field was present and never reset per matching record, so a wrapped or truncated ack line silently reused the previous line's counts and was counted again in every statistic | the awk pass resets `assigned`/`acked`/`slot` at the start of each record and skips records without a positive assignment; a truncated line after a parseable ack no longer inflates `samples` |
| P6-540 | `CAP="${CAP_TOKENS:-1024}"` passed a zero or non-numeric value straight into `used_cap = acked*100/cap`, yielding a division by zero or NaN | `resolve_cap` refuses a non-numeric or non-positive `CAP_TOKENS` with a FATAL before any file is read or evidence written |
| P6-543 | the AT CAPACITY test only looked at `acked/assigned`, so `assigned=2048 acked=1500` (73% of the assignment, ~146% of the 1024-token cap) reported positive headroom and never warned | the cap side is alerted on separately: at or above 100% of the per-connection cap the report names the cap overflow even when assignment headroom remains |
| P6-787 | the spare-token figure was `cap - cap*max_cap/100`, i.e. `cap - acked`, so an over-cap ack printed "-476 spare tokens" as if the arithmetic had failed | the figure is clamped: over the cap the line reads "OVER cap by N tokens of cap" and never goes negative |

### Red leg — what it proves and what it does not

All 20 `disc`-marked cases fail against the pre-wave script; 8 probes carry no marker and are documented as non-discriminating. Those 8 are contract and shape pins (the positional journal argument, a missing journal being fatal, the two section headers, the summary landing in `OUT_DIR`, an ack below capacity passing with exit 0, an empty `CAP_TOKENS` falling back to the default, an expanded cap reporting headroom again, and the explicit first-row seeding where the old `|| min_used==""` fallback happened to agree). They pin behaviour the wave must not break; they are not evidence that anything was wrong. Behavioural evidence for the findings is the audit's line-level readings quoted in the tables above, plus one demonstration below.

The transcript is in `/tmp/w29-demo/result.txt`. ## 7. Residual, not closed here

- The per-slot block aggregates by the `slot=` token as written in the journal; a session that reuses one slot id across connections still merges those rows. The connection epoch is in the journal and could split them, but nothing downstream needs that split today.
- `CAP_TOKENS` remains a single global cap for all slots: the script reports each slot against the same per-connection limit, which is correct while every slot is one connection, and would need a per-slot table if the cap ever differs by slot.
- The new exit statuses (3 at capacity, 4 with no data) reach the caller for the first time. `run-full-suite.sh` swallows them with `|| true`, so the stage still passes; wiring the status into a gate decision is a caller-side change and out of scope here.
