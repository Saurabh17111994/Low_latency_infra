## Notes

- **Scope decision (recorded):** a row whose `execution_partition_id` differs from the gateway's
  (including a null/global-scope row) is audited `REJECTED` with a warning, never applied. The
  plan's H1-1 decision names the partition as part of the scope check; a future global-halt
  feature would need its own explicit contract rather than inheriting the partition path.
- **RECOVERED audit:** recorded as `APPLIED` (the request is processed and complete) with the
  `state` column keeping the distinction visible; it never touches the gate and never enables.
- **DUPLICATE on retry:** a same-process re-scan (crash between halt and audit) writes the missing
  audit without a second halt; a fresh process re-applies the idempotent halt. Both directions are
  pinned in `aWriteFailureThrowsAndTheRestartReappliesThenAudits`.
- **Epoch dimensions:** per `(source_component, source_instance)` — the dossier's key — with the
  partition dimension enforced by the scope filter, so a sibling gateway's APPLIED rows in the
  shared table cannot fence this gateway's epoch stream.
