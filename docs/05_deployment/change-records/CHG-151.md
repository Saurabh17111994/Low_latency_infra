# CHG-151 — The rest of storage tooling stops guessing when it cannot read

- **Status:** recorded — all 7 wave-14 findings fixed
- **Filed:** 2026-09-14
- **Source:** P6 ops/scripts/tests/chaos audit, wave 14 ("DDL apply, tiering enable and log scan"):
  P6-350, P6-351, P6-723 (ddl_apply.py); P6-352 (ddl_apply_smoke.py);
  P6-382 (fluss-repair/EnableTiering.java); P6-383, P6-735 (fluss-repair/LogScan.py)

## What happened

Four tools that decide what to do about state they cannot fully read. In each finding the answer was
reachable without the fact behind it: an unparseable manifest read as an absent one (so the drift
gate regenerated it and exited 0), a pin-file failure that the `except OSError` clause could never
catch, two evidence records colliding on a one-second stamp, a docker probe with no timeout, an
argument read before it was checked, and a segment scanner advertising `TRUNCATE_TO=0` for a file
with nothing left in it.

**The DDL drift gate could be walked around by corrupting its input (`P6-350`).** A manifest that
exists and cannot be parsed was treated as "absent", which set `needs_write` and rewrote the file
with the computed manifest — no `--force`, exit 0. That is exactly the case the gate exists for:
the structural check already refused valid-JSON-without-`tables`, but a truncated or mangled file
sailed through. `load_existing_manifest()` now distinguishes "no manifest yet" (returns `None`) from
"cannot be parsed" (raises `ManifestUnreadable`), and `main()` refuses with exit 2 unless `--force`
says the loss is intended.

**The sweep branch could not be reached by its own error handling (`P6-351`).** `load_versions()`
re-raises I/O failures as `RuntimeError` and a non-UTF-8 pin file raises `UnicodeDecodeError`, so
`except OSError` never fired — and because the sweep dispatch sat *outside* `main`'s guard, an
unreadable `versions.pin` in sweep mode escaped as a raw traceback instead of exit 2. The catch now
names the exceptions that are actually raised and the dispatch moved inside the guarded block.

**Evidence could be overwritten by an immediate retry (`P6-723`).** The apply evidence directory was
`ddl-apply-<second-resolution stamp>`, so two applies in the same second — a retry, or the smoke
drill running the orchestrator twice — shared `apply.json`. The directory is now
`ddl-apply-<stamp>-<pid>`, with a counter suffix when even that exists, so a previous record is never
silently replaced.

**The S4 drill could hang instead of skipping (`P6-352`).** Its two docker probes ran with no timeout
and no exception handling while every other docker call in the same file used 120s/900s timeouts, so
a daemon that accepts the socket and never answers hung the whole drill. Both probes now time out
after 120s and return a SKIP reason.

**The tiering enabler read its argument before checking it (`P6-382`).** `EnableTiering` with no
arguments threw `ArrayIndexOutOfBoundsException` — no usage line, no exit contract. It now validates
the table name before any connection attempt.

**The segment scanner invited a caller to wipe a live file (`P6-383`).** A segment with no complete
batch printed `last_complete_batch_end=0` and then `TRUNCATE_TO=0`; a caller applying that value
would shrink the file to zero bytes. It now prints `NO_COMPLETE_BATCH=<path>` instead and never a
zero truncation target.

## Judgement calls

1. **`EnableTiering` exits 2 for a missing argument, not the finding's `exit(1)`.** Its only in-tree
   mention is a doc comment, so no caller depends on the code; 2 = unusable input matches the other
   operator CLIs in this tree (the probes in wave 13, `repair-tablet.sh`'s argument checks).
2. **`--force` stays the way to accept a corrupt manifest.** P6-350 offered "refuse (requiring
   `--force`) or at least return a non-zero exit"; the first is kept, because the regeneration is
   legitimate when an operator says so — it is only illegitimate when it happens silently.
3. **`NO_COMPLETE_BATCH=<path>` carries the path**, so a caller can key on the marker and know which
   file it refers to without parsing the preceding line.
4. **The in-tree caller needs no change.** `repair-tablet.sh`'s awk parser already accepted only
   `TRUNCATE_TO=[1-9][0-9]*`, so `TRUNCATE_TO=0` was never applied — it was also never *counted* as
   torn, which stays true for `NO_COMPLETE_BATCH`. Its header comment now names the new marker
   (incidental documentation of the same change).
5. **A message string is still a compose invocation site to the contract scanner.** The new timeout
   message originally read `"docker compose config did not run: …"`, and
   `test_compose_form_contract` refused it as an unregistered invocation site — found by running the
   helper suite, not by the audit. The message is now `"the compose config probe did not run: …"`;
   no registry row was added, because the line is not an invocation.
6. **P6-735 is a behavior-preserving change and has no red test.** The rewrite removes the absolute
   `f.seek(pos)` per batch (it made the buffered reader discard and refill once per batch) in favour
   of a relative body skip. The new tests pin that the boundary, the marker and the exit code are
   exactly what the old arithmetic produced, at 500 batches and at the header-only edge; a test that
   "proved" the speedup would be a benchmark, not a contract.
7. **No docker, Fluss or R2 call was made.** The docker probes are exercised by injecting
   `TimeoutExpired`, the Java tool by its argument path only, and the scanners against synthetic
   segments; the S4 drill itself, the real apply and a real tablet segment remain untested here.
