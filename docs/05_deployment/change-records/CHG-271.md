## Why

Found while smoke-testing CHG-270. `docker-stack.yml` declares **16** `${VAR:?}` variables;
`stack_selfcheck.sh`'s `required_vars` listed 15 and its compile-only placeholder block set 15. The missing
one, `O2_PASSWORD`, is not a Swarm secret: the stack interpolates it directly into
`services.openobserve.environment.ZO_ROOT_USER_PASSWORD`. So in a shell that had not sourced the deploy
environment, the script died at `docker stack config` **before reaching a single check** — the offline
path it exists for was unusable, and the failure looked like a stack error rather than a missing list entry.

## What changed

- `stack_selfcheck.sh`: `O2_PASSWORD` joins `required_vars` (16) and gets a compile-only placeholder and an
  export, so the offline path renders the stack; `DEPLOY=1` now refuses an empty one like every other
  required value. The comment claiming all credentials have no env fallback is corrected: the ones that
  arrive as Swarm secrets do, this one is interpolated.
- `tests/test_stack_selfcheck.py`: two invariants instead of a third hand-maintained list — the set of
  `${VAR:?}` names in `docker-stack.yml` must **equal** `required_vars`, and every name in `required_vars`
  must have a compile-only placeholder. A variable sharing a line with others is parsed, not skipped.
- `PROD_VM_PROVISIONING.md`: 15 → 16 required values, 7 → 8 missing (`O2_PASSWORD` has no value in `.env`
  either), with a row saying why that matters.

## Not verified

- **A deploy with a real `O2_PASSWORD`.** No production value exists in this repository, so what is proven
  is that an empty one is refused, not that a real one starts a working OpenObserve.
- `deploy_preflight.py` keeps its own deliberately narrower list (six values the platform cannot invent)
  and still does not check `O2_PASSWORD`, so a deploy environment missing it is caught by
  `stack_selfcheck.sh`'s `DEPLOY=1` gate rather than by the preflight. Noted, not changed here.
